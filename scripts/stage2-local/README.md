# Stage 2 本地隔离入口

这些入口只用于本机 Stage 2。不要使用它们部署生产，也不要把普通 `npm start` / `npm run dev` 当成具有相同隔离能力。

## 配置（由用户手动完成）

1. 在项目根目录创建 `.local/stage2/`。
2. 将本目录 `config.template.json` 复制为 `.local/stage2/config.json`，仅在目标文件不存在时复制。
3. 用编辑器填写 `DB_PASSWORD` 和独立本地 `JWT_SECRET`（至少 32 字符），不要在聊天、终端参数或日志中输入秘密。JSON 字符串内的反斜杠和双引号必须正确转义。
4. 其他四项固定为已确认的 `127.0.0.1:3306 / xmumdorm_stage2_dev / xmumdorm_dev`。不要加入连接串或其他变量。

`.local/` 已被仓库忽略。入口不创建、不覆盖配置，不加载现有 `.env*`。不能使用 `git add -f` 提交秘密。

## 下一轮经用户确认后才能运行

从项目根目录执行：

```powershell
node scripts/stage2-local/launch.cjs check
```

这只校验配置，不导入数据库驱动，不连接、不启动服务、不创建目录。只输出校验结论，不打印配置。

根目录后端依赖需单独批准安装；当前隔离入口不会安装任何依赖。前端依赖也需完整可用。

后续获准启动时，在两个终端分别执行：

```powershell
node scripts/stage2-local/launch.cjs backend
node scripts/stage2-local/launch.cjs frontend
```

访问 `http://127.0.0.1:5173/about`。使用独立浏览器配置或干净站点存储，避免旧 Service Worker、登录缓存干扰。已有同端口服务应由用户核实并停止；前端 strictPort 不自动换端口，入口不杀进程。

## 隔离机制及范围

- 父进程只白名单传递 OS 必需变量，不传递任何应用环境、NODE_OPTIONS、代理、AWS、数据库连接串或 VITE 环境变量。
- 配置只从专用 JSON 读入子进程；未知键、错误主机/端口/库名/用户、未填写秘密均拒绝。
- 后端子进程再次拒绝连接串，并在 MySQL 驱动创建池/连接前检查目标；禁用 socketPath、自定义 stream、URI 和集群。
- 后端子进程专用的 CommonJS hook 令 dotenv 不读取旧文件；不会修改安装的依赖或影响其他进程。
- 后端 TCP 仅允许本机 3306，禁止 UDP；对象存储导出函数显式拒绝，即使误调用也不创建远程客户端。树洞等已有本地上传回退仍可写本地文件，校园/头像云上传会失败，不能测试带图发布以免留下半成品记录。
- server.js 仅在该入口标志下跳过资料状态同步及其定时器；其余后台任务由固定 `ENABLE_BACKGROUND_JOBS=0` 关闭。
- 资料仓库、邮件、Push 和预览数据库凭证均不继承；网络边界额外阻止意外远程 TCP 请求。
- 前端 programmatic Vite 使用 `configFile:false / envDir:false`，不读取原 Vite 配置和 `.env*`，不读取数据库密码/JWT。只代理本机 4040，屏蔽 `/api/preview` 和 `/api/materials`。
- 浏览器 CSP 限制远程页面资源/API，远程图片、CDN、字体可能因此不显示；这是本地隔离预期。它不是对用户点击外链、浏览器扩展或第三方程序的系统级防火墙。
- 前后端仅监听 127.0.0.1；前端缓存写 `.local/stage2/vite-cache`。Vite 文件服务显式禁止 `.env*`、`.git` 和 `.local`，避免通过 `/@fs/` 读取本地凭证。启动后后端仍可能创建本地 uploads/public 目录，并运行 `SELECT 1`；正常业务请求可以写入测试库。

## 验证与已知限制

当前交付只做语法与差异检查，不声称隔离已通过运行验证。下一轮应先批准离线单元验证，再批准本机连接/启动；检查配置拒绝、池目标拒绝、出站拒绝、代理/CSP、资料定时器未创建及旧环境文件未加载。

空库没有业务表，入口不自动迁移、初始化、建账号或导入。`/health` 只能证明进程存活，不能证明数据库目标或业务可用；数据库身份仍应通过用户已有交互式 MySQL 验证或单独批准的只读检查确认。

Node 网络 hook 属于项目内防误操作边界，不是对恶意依赖、原生插件和任意子进程的 OS 安全沙箱。不要给此环境配置生产凭证。若要求操作系统级零出站，应另配置防火墙/容器。

移除专用入口并撤回 server.js 的条件分支即可撤销代码；本地凭证只由用户自行保管。保留原 `.env*`，恢复普通入口时原有行为不变。
