# Dorm 公众号推文模板

给 XMUM Dorm 写微信公众号推文用的排版模板。不需要买秀米/135 的会员，也不需要装任何工具。

```
marketing/wechat/
└── dorm-wechat-template.html    ← 双击打开，改文字，复制进公众号
```

## 怎么用

1. **双击** `dorm-wechat-template.html`，用 Chrome / Edge 打开
   （不要用微信内置浏览器打开，那里没有复制按钮要的那套剪贴板接口）
2. 直接在页面上**改文字**——用浏览器的「检查元素」或者直接编辑 HTML 源文件都行。
   改完刷新就能看到效果，右边的白卡片就是手机上看到的样子（按 375px 宽模拟）
3. 点右上角 **「复制全文到公众号」**
4. 打开公众号后台 → 新建图文消息 → 在正文区 `Ctrl+V`

粘贴后样式会保留，因为正文用的全部是**内联 style**。

> 只想改文字的话，最省事的做法是直接用编辑器打开这个 HTML，把里面的中文替换掉。

## 为什么必须写成内联样式

微信编辑器会**过滤掉**这些：

| 会被吃掉 | 后果 |
| --- | --- |
| `<style>` 标签 | 整段 CSS 失效 |
| `class` / `id` 选择器 | 同上 |
| 外部 CSS 文件 | 同上 |

只有**写在标签上的 `style="..."`** 能活下来。所以本模板正文区（`#articleBody` 里面）
一个 `class` 都没有，全部内联——这不是我啰嗦，是不这么写就会掉格式。

> `<style>` / `class` / `id` 这件事**微信官方从未正式声明过**，是开发者社区与工具源码的
> 一致结论。官方唯一给出的是[编辑器插件开发规范](https://developers.weixin.qq.com/doc/subscription/guide/product/plugin_spec.html)，
> 里面写的是「什么不该做」。两者都记在调研文档里，标注了哪条是官方、哪条是社区共识。

模板里还避开了一批微信不可靠支持的写法：`position`、`float`、`::before`/`::after`、
`@media`、`animation`。圆点列表也是用 `<span>` 画出来的，没用 `<ul>`——微信经常把
`list-style` 吃掉，那样列表就变成一堆没有圆点的缩进文字。

### 另外几条官方明说的坑，模板已经避开

| 官方规则 | 模板的做法 |
| --- | --- |
| **不建议设置任何字体族** | 全文没写 `font-family`，用公众号自己的字体栈 |
| **不建议用 `!important`** | 一处都没用 |
| **「固定宽度」属于违规**（会让居中不一致、内容溢出被截断） | 容器用 `max-width:677px;width:100%`，图片 `max-width:100%` |
| 同标签名、同样式、单子节点的嵌套**超过 10 层会被自动精简** | 本模板最深处只有 4 层 |
| 建议给 `<img>` 加 `data-w`（图片原始像素宽） | 吉祥物写了 `data-w="503"` |
| Dark Mode 下**不要用渐变做文字背景** | 顶部品牌条用纯色 `#C9E0FA`（原来是渐变，已改） |

依据同样在 `docs/06-Analyze/content-research/` 的调研文档里，逐条标了出处。

### 已用微信官方校验器跑过

[`wechatjs/verify-article-structure-spec`](https://github.com/wechatjs/verify-article-structure-spec)
是微信官方唯一的 HTML 结构校验器。**注意它没有发布到 npm**
（`@tencent/verify-article-structure` 在 npmjs 和腾讯镜像都是 404），
要用得先 clone，再进 `cli/` 目录 `npm install`：

```bash
git clone --depth 1 https://github.com/wechatjs/verify-article-structure-spec.git
cd verify-article-structure-spec/cli
PUPPETEER_SKIP_DOWNLOAD=true npm install   # 用系统 Chrome 就不用下 Chromium
PUPPETEER_EXECUTABLE_PATH="/path/to/chrome" npx tsx src/index.ts ./article.html --json
```

本模板跑完的结果：**只剩一条 `line-height` 报警，且已确认是该校验器自身的误报**
（它把 `<strong>` 的文字算了两遍，行数虚高）。逐帧测量的证据在
`docs/07-Implement/公众号推文模板与微信号统一.md`。

> 跑之前记得只取「复制范围」——本文件里 `#articleBody` 到「复制范围到这里结束」
> 之间那一段才等于真正会进公众号的 HTML。外层工具栏和手机壳带 `<style>` 和 class，
> 整个文件丢进去会被判一堆无关的违规。

页面里那段 `<style>`（工具栏 + 手机壳）**不在复制范围内**，只负责让预览好看。

## 图片怎么处理（唯一需要手动的一步）

公众号**不认站外图片链接**，会直接拦掉。所以：

- 复制过去的正文里，图片位是一个虚线框占位
- 到公众号编辑器里，把它删掉，用编辑器自己的「图片」按钮从**素材库 / 本地上传**
- 上传后微信会给你一个 `mmbiz.qpic.cn` 的地址，那才是能用的

顶部那个吉祥物也一样：它在复制过去的正文里**可能显示不出来**，
到编辑器里重新传一次 `frontend/public/icon-512-removebg-preview.png` 就行
（这张是透明底 PNG，正好能压在浅蓝渐变上）。

## 外链怎么处理

公众号正文里的站外超链接点不动（会被去掉）。
所以正文里不要指望放 `https://...` 当入口，正确做法是：

> 编辑器右上角 → 「阅读原文」→ 填上 Dorm 的网址

推文里的引导话术建议写成「点击左下角 **阅读原文** 直达」。

## 配色（跟 App 图标一致）

从 `frontend/public/icons/icon-512.png` 里提取的实际色值：

| 变量 | 色值 | 用途 |
| --- | --- | --- |
| 深蓝 | `#122D78` | 标题、强调字、小节竖条 |
| 天蓝 | `#ACD3F8` | 品牌主色、圆点、虚线框（图标里占比最高的饱和色） |
| 浅蓝 | `#EAF4FE` | 高亮块底色 |
| 奶油白 | `#F9F9F0` | 引用/导语块底色 |
| 深灰 | `#3F3F3F` | 正文（社区共识：正文别用纯黑） |
| 灰 | `#8A94A6` / `#9AA4B2` | 次要文字、图注 |

正文实测排版值：**15px / 行高 1.75 / 字距 0.5px**，都在社区推荐区间内（字号 14–16、
行高 1.5–2、字距 0.5–1.5px）。

换主题色：在 HTML 里全局替换上面这几个色值即可，正文区里每一处都是写死的。

## 模板里带了什么

一套完整的推文骨架，示例内容就是「加入我们」的招募推文，可以直接改：

1. 顶部品牌条（浅蓝渐变 + 吉祥物 + 厦马小筑）
2. 主标题 / 副标题 / 日期
3. 导语块（奶油底 + 天蓝左边条）
4. 小节标题 `01 / 02 / 03`（深蓝竖条）
5. 正文段落
6. 圆点要点列表
7. 高亮块（浅蓝底 + 深蓝字）
8. 引用 / 金句块（居中 + 奶油底）
9. 图片位 + 图注
10. 圆点分隔符
11. CTA 联系卡片（微信 `xmumdorm666` + 邮箱 `yejianqin61@gmail.com`）
12. 页脚（品牌署名 + 「学生独立开发 / 不代表校方立场」）

## 已知限制

- **只能手动改文字**，没有可视化编辑器。要更省事就去看
  `docs/06-Analyze/content-research/公众号推文排版模板与编辑器调研.md` 里推荐的
  Markdown 排版工具（写 Markdown 一键转换）。
- **图片必须重传**，见上。
- 复制用的 `navigator.clipboard.write` 需要安全上下文，`file://` 和 `http://127.0.0.1`
  在 Chrome 里都算安全上下文，双击打开即可；换了别的浏览器如果不支持，
  会自动回退到「选中 + 复制」的老办法，按钮上会提示。
