# 07 — 通知系统跨端回归与上线验收

**What to build：** 对通知治理后的共享 API、Capacitor App 信箱和既有 Web 调用方进行完整回归，形成可复现的上线验收记录，确认性能、分页、聚合、已读和本地化行为可以进入生产。

**Blocked by：** 02 — 三分类缓存、清理与持续加载；03 — 同帖互动组原位展开；04 — 聚合通知批量已读闭环；05 — 无效标题与公告重复文案收束；06 — 查询计划、条件索引与性能验收

**Status：** ready-for-agent

## 交付行为

- 使用固定测试账号准备互动、事务、系统三类通知，包含同帖点赞评论、多页历史、已读/未读、无标题和公告边界数据。
- 验证共享 API 的鉴权、三个类别、稳定分页、目标过滤、响应内未读汇总、批量已读和清理边界。
- 在 Capacitor App 实机验证首次进入、弱网、类别切换缓存、加载更多、互动展开、独立查看帖子、批量已读和失败恢复。
- 在 Web 端验证共享 API 兼容，没有因响应新增字段或排序调整造成信箱、顶栏未读和公告入口回归。
- 中文与英文分别执行完整信箱场景。
- 引用任务 06 的性能数据，确认请求数和冷请求门槛达标。

## 测试数据矩阵

- 同一帖子至少包含 2 条点赞和 2 条评论，其中部分未读。
- 至少两个不同帖子，防止错误聚合。
- 互动类别超过 20 条，验证主列表下一页。
- 单个帖子互动超过一页，验证展开明细下一页。
- 事务通知至少覆盖二手或活动通知。
- 系统通知至少覆盖有标题公告、无标题公告和正文为空公告。
- 包含已删除或不可访问的帖子目标。

## 验收标准

- [ ] 后端通知目标测试和全量测试全部通过。
- [ ] App 首屏只有一个通知数据请求，首次默认互动类别。
- [ ] 页面只有互动、事务、系统三个 Tab，且无数字徽标。
- [ ] 三类通知均可加载到最后一页，不重复、不遗漏。
- [ ] 同帖互动正确聚合、展开、分页和导航。
- [ ] 一组多条未读只产生一个批量已读请求。
- [ ] 无标题通知和公告不显示无效占位或重复“公告”。
- [ ] 清理当前类别不影响其他类别，系统公告保留。
- [ ] 弱网和请求失败时已有内容不消失，用户可以恢复操作。
- [ ] 中文与英文无混搭，最长文案不溢出或遮挡。
- [ ] Web 既有通知与公告入口继续工作。
- [ ] 任务 06 的性能门槛全部达成并附测试条件。
- [ ] Android 实机返回、滚动、展开和 Tab 切换无明显卡顿。

## 必跑检查

- [ ] 通知路由集成测试。
- [ ] 全量后端测试。
- [ ] App 生产构建。
- [ ] Capacitor Android 同步与 APK 构建。
- [ ] Chrome DevTools 网络和性能检查。
- [ ] Android 实机中文、英文、弱网场景。
- [ ] Web 端信箱、顶栏未读、公告跳转回归。

## 验收记录要求

- 记录构建提交、测试时间、环境、测试账号的数据规模和设备型号。
- 记录自动化测试结果、性能中位数/P95、请求数和失败项。
- 截图或录屏不得包含 Token、密码、校园邮箱或其他敏感信息。
- 未通过项必须回到对应任务修复，不在本任务中用临时绕过掩盖。

## 非目标

- 不在验收阶段增加新功能或重做信箱视觉设计。
- 不验收已弃用 React Native 客户端。
- 不申请系统级通知权限，不测试外部推送服务。
