# 03 — 同帖互动组原位展开

**What to build：** 将同一普通帖子的点赞和评论收束为一个互动组，并允许用户在信箱内原位展开该帖子的完整互动明细，再通过独立操作进入帖子详情。

**Blocked by：** 01 — 首屏单请求与稳定分页契约；02 — 三分类缓存、清理与持续加载

**Status：** ready-for-agent

## 交付行为

- 普通帖子通知以稳定帖子目标键分组；同帖点赞和评论进入同一组，不同帖子绝不合并。
- 公告、事务通知和未知目标保留独立分组规则，不误并入普通帖子互动组。
- 组摘要展示真实帖子标题（如有）、参与者摘要、点赞数、评论数、最新时间和未读状态。
- 点击组标题只切换展开/收起，不再直接跳转。
- 展开后从服务端按帖子目标读取互动通知，展示动作类型、发送者、评论摘要、时间和未读状态。
- 展开明细支持分页，能够查看超出信箱首批列表范围的互动历史。
- “查看帖子”作为组内独立操作进入详情页；帖子删除、隐藏或不可访问时显示不可用状态，不进入空白页面。

## 接口边界

- 通知列表支持同时按互动类别和帖子目标过滤。
- 帖子目标参数只接受正整数，并且只能返回当前登录用户拥有的通知。
- 展开响应沿用列表分页结构和稳定排序，不创建语义重复的第二套通知 DTO。
- 评论通知返回既有通知数据中可安全展示的评论摘要；点赞通知不伪造评论内容。

## 验收标准

- [ ] 同一帖子的一条点赞和两条评论在主列表中只占一个互动组。
- [ ] 不同帖子、公告和事务通知保持独立。
- [ ] 点击组标题原位展开，再次点击收起，均不改变当前路由。
- [ ] 展开明细按时间和 ID 稳定倒序排列。
- [ ] 评论显示发送者、评论摘要和时间；点赞显示发送者、动作和时间。
- [ ] 展开明细存在下一页时可继续加载且不重复。
- [ ] “查看帖子”是独立、可识别、可触达的操作。
- [ ] 帖子不可访问时不会跳到空白详情页。
- [ ] 展开一个组不会清空其他类别或主列表缓存。

## 最小验证

- [ ] 路由集成测试覆盖目标过滤、用户隔离、非法目标、跨页结果和不可访问目标。
- [ ] 分组逻辑的可运行测试覆盖同帖合并、异帖隔离、公告隔离和未知目标隔离。
- [ ] App 浏览器验收覆盖展开、收起、加载更多和独立查看帖子。

## 非目标

- 不在本任务改变通知已读状态；批量已读由任务 04 完成。
- 不为食堂点评、社团活动或二手会话建立新的详情聚合模型。
- 不修改帖子详情页自身的 UI。
