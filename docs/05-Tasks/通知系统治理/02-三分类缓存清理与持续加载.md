# 02 — 三分类缓存、清理与持续加载

**What to build：** 将 App 信箱收束为互动、事务、系统三个类别，使用户切换后可以立即复用已加载内容，并能持续加载所有历史通知；清理操作只影响当前类别。

**Blocked by：** 01 — 首屏单请求与稳定分页契约

**Status：** ready-for-agent

## 交付行为

- 顶部只保留 `interaction`、`transaction`、`system` 三个 Tab，默认选中互动。
- 删除 `All` Tab 和类别标题后的未读数字徽标。
- 未读反馈保留在全局信箱入口和具体通知项，不通过 Tab 数字重复表达。
- 按“当前用户 + 类别”保存查询缓存；返回已访问类别时立即显示已有列表，后台刷新不得清空现有内容。
- 首批 20 条之后，根据 `hasMore` 提供稳定的继续加载行为，新页追加到当前类别，不覆盖前页。
- 防止重复触发下一页请求；到底后不再发送请求。
- 清理按钮只清理当前类别。系统公告不得因普通清理被物理删除，已读与删除保持不同语义。

## 实施约束

- 复用项目现有服务端状态查询能力，不新增状态管理或请求库。
- 三个类别必须使用共享分类常量，不能在页面另写一套类型列表。
- 切换类别时保留各自的列表、分页位置、错误状态和下一页状态。
- 加载更多失败只能影响增量区域，不能把已经成功展示的列表替换成整页错误。

## 验收标准

- [ ] 页面不存在 `All / 全部` Tab。
- [ ] 三个 Tab 后均不显示数字徽标。
- [ ] 首次进入默认展示互动通知。
- [ ] 首次访问某类别时请求数据，返回该类别时立即复用缓存，不重新显示整页骨架屏。
- [ ] 后台刷新时旧列表保持可见，新结果到达后正确更新。
- [ ] 加载下一页后通知顺序正确且没有重复 ID。
- [ ] `hasMore=false` 后加载入口消失或禁用，且不再发起请求。
- [ ] 当前类别清理成功后只更新该类别缓存和相关未读状态。
- [ ] 系统公告不会被普通清理动作删除。
- [ ] 中文和英文 Tab、加载状态、失败状态均使用当前语言。

## 最小验证

- [ ] 浏览器行为检查覆盖首次切换、返回缓存类别、后台刷新、加载下一页、到底状态和增量失败。
- [ ] 后端回归覆盖三个类别的清理边界，特别验证系统公告保留策略。
- [ ] Network 面板确认返回缓存类别时不会重复发起无意义的汇总请求。

## 非目标

- 不改变全局信箱入口的视觉样式。
- 不在本任务实现同帖互动展开。
- 不新增下拉刷新、实时 WebSocket 或系统推送。
