# 通知系统性能与信箱体验治理任务索引

**父规格：** `通知系统性能与信箱体验治理规格`

**父 Issue：** GitHub #17

**状态：** ready-for-agent

本目录把通知系统治理拆成可独立验收的纵向任务。每个任务必须在自己的范围内同时完成契约、用户行为和回归检查，不允许只改前端或只改 SQL 后把不可用的半成品交给下一任务。

## 任务清单

| 编号 | 任务 | 阻塞于 | 独立交付结果 |
|---|---|---|---|
| 01 | 首屏单请求与稳定分页契约 | 无 | 打开信箱只请求一次即可得到互动列表和未读汇总 |
| 02 | 三分类缓存、清理与持续加载 | 01 | 三个 Tab 可切换、可复用缓存、可查看全部分页通知 |
| 03 | 同帖互动组原位展开 | 01、02 | 同一帖子点赞评论可在信箱内展开完整明细 |
| 04 | 聚合通知批量已读闭环 | 03 | 展开或查看帖子时一次确认整组未读通知 |
| 05 | 无效标题与公告重复文案收束 | 无 | 无 Untitled、无重复公告标题，中英文一致 |
| 06 | 查询计划、条件索引与性能验收 | 01、03、04 | 用真实基线证明提速，只在必要时增加索引 |
| 07 | 通知系统跨端回归与上线验收 | 02、03、04、05、06 | API、App 实机和 Web 兼容性全部通过 |

## 依赖关系

```text
01 首屏单请求与稳定分页契约
 └─ 02 三分类缓存、清理与持续加载
     └─ 03 同帖互动组原位展开
         └─ 04 聚合通知批量已读闭环
             └─ 06 查询计划、条件索引与性能验收
                 └─ 07 跨端回归与上线验收

05 无效标题与公告重复文案收束 ───────────────┘
```

## 当前可开发任务

- `05 — 无效标题与公告重复文案收束`

## 通用完成要求

- 不修改已弃用的 React Native 客户端。
- 不接入系统级推送、JPush、HMS Push、FCM、Redis或消息队列。
- 新增或修改后端契约必须有 Jest + Supertest 回归测试。
- 数据库结构变更必须使用新迁移，并同步全新数据库初始化结构。
- 中英文模式分别验收，不得中英混搭。
- 只提交与当前任务相关的文件，保持每个任务可单独回滚。
