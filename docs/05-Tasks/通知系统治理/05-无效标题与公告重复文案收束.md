# 05 — 无效标题与公告重复文案收束

**What to build：** 清理信箱中的无效模块文案：无真实标题时不显示“无标题 / Untitled”，公告不再重复显示类别标签和标题，同时保证中英文内容完整一致。

**Blocked by：** None — can start immediately

**Status：** ready-for-agent

## 交付行为

- 普通通知没有真实标题时完全省略标题行，互动正文使用“你的帖子 / your post”等自然宾语。
- 公告卡片移除额外的“公告 / Announcement”类别标签。
- 公告有真实标题时展示一次标题；没有标题时直接展示正文，不生成“公告”占位标题。
- 公告正文为空时才显示本地化的空正文状态。
- 公告保留发送者和时间，不展示模块解释、功能说明或 Site-wide announcements 一类冗余文案。
- 中文模式只出现中文用户文案，英文模式只出现英文用户文案。

## 实施约束

- 真实标题判断必须去除首尾空白；只有空字符串、空值才视为无标题。
- 不用 CSS 隐藏无标题占位，渲染树中不应产生该标题节点。
- 复用现有公告摘要契约，不额外拼接第二份公告标题。
- 保持公告详情跳转和已读行为不变。

## 验收标准

- [ ] 无标题普通帖子通知不出现“（无标题）”或 `(Untitled)`。
- [ ] 无标题通知正文语法自然，不出现连续空格、空引号或空书名号。
- [ ] 标题为“公告”的公告卡片只出现一次“公告”。
- [ ] 有真实自定义标题的公告显示一次标题和正文。
- [ ] 无标题公告直接显示正文，不生成类别标题。
- [ ] 空正文公告显示当前语言的空正文状态。
- [ ] 中文、英文模式均无混搭，无 Site-wide announcements 文案。
- [ ] 公告点击仍可进入正确详情页。

## 最小验证

- [ ] 使用有标题、空标题、空白标题、标题为“公告”、空正文五组数据验收渲染结果。
- [ ] 中英文各执行一次信箱公告与普通互动通知检查。
- [ ] 公告详情跳转和已读状态执行回归检查。

## 非目标

- 不重做公告弹窗。
- 不修改管理员发布公告界面。
- 不改变通知卡片整体视觉风格。
