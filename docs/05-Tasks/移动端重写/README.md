## 一、目标与成功判据

**目标**：以新宪法为准，从零重写 `mobile/` 的全部 UI 与导航架构，全模块完成后上架 Google Play（时间可延长，不以工期换质量）。

**成功判据**

1. 每屏通过宪法第 9 条验收（暗/亮双主题、无障碍、44pt、无字面量、深链直达、返回栈正确、命中布局原型）。
2. 宪法第 7 条 8 项合规红线全部落地（含 2 项后端改动）。
3. 首次商店提交**之前**完成唯一一次原生重建窗口（宪法第 5 条）。
4. 不再出现"装了动画库但 0 处引用"这类状态——动效必须是设计要求，不是可选装饰。

### P2 —— 唯一一次原生重建窗口（宪法第 5 条，版本按 SDK 57 官方 pin）

- [ ] 上传封闭测试 → **≥12 名测试者连续 14 天** → 生产访问审核 → 发布

### P5 —— 上架

## 四、协作切分原则（人类团队 + Agent 团队）

1. **一个模块 = 一个写作用域 = 一个负责人**；共享物（令牌、原型组件）由单一所有者维护，其他人只读。
2. **禁止并行改同一文件**，尤其 `tokens.ts`、根 `_layout.tsx`、`src/api/*`、原型组件。
3. **原型先行**：12 种原型未稳定前不开模块，否则每模块会长出自己的样式方言——这正是旧版 1144 处硬编码色值的成因。
4. 每模块交付四件：路由文件、屏组件、该模块测试、`docs/07-Implement/` 实施记录。

## 六、环境阻塞（**需先解决，否则 P1 之后无法推进**）

当前会话的执行沙箱**只能写仓库根目录**，`mobile/`、`docs/`、`.git/` 均被拒绝写入。已实测失败：

```
git tag mobile-v1-pre-rewrite
→ fatal: cannot lock ref 'refs/tags/...lock': Permission denied
```

**根因**：早先一次权限修复只给工作区**根目录**补了当前用户的完全控制；Windows 的继承**不会追溯**到已存在的子目录，因此 `.git/`、`mobile/`、`docs/` 这些"老目录"仍缺权限。而给父目录授权同样不会自动下发到已有子目录，所以"逐目录修复"需要几十次授权，不现实。

**后果**：文件内容可用编辑器工具改写，但 `git`（tag/commit/branch）、`npm install`、`expo prebuild`、`EAS build` **全部无法执行**。

**处置**：所有者已选择「把本会话切到完全权限」，但**该设置尚未在本会话生效**（复查仍被拒）。需在 GUI 中确认已应用；若需重启会话才能生效，则重启后继续。
