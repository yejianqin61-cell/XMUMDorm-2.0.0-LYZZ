# M03-Task008 - 吃货广场媒体优先内容流

**What to build:** 学生能在食堂首页连续浏览同学的食评，并以普通发布动作发起食堂话题分享；有图片时图片成为内容重点，无图片时正文仍保持紧凑可读。

**Blocked by:** M03-Task006 - 食堂分区地点入口轻量化。

**Status:** ready-for-agent

- [ ] 保留现有食堂话题查询、已登录发布、未登录跳转登录、帖子详情跳转、真实互动计数、分页、加载/失败/空状态及中英文文案。
- [ ] 区段标题右侧发布入口改为普通文字动作或等价写作图标，点击区域至少为 44px；不得再使用药丸式发布按钮。
- [ ] 移除面向用户解释模块用途的提示文案；空状态只保留必要的空状态信息和一个明确发布动作。
- [ ] 每条食评按照作者与时间、正文、可选媒体、互动信息的阅读顺序连续呈现，条目之间仅使用细分隔线，不使用白底阴影卡。
- [ ] 有封面图时以接近内容全宽的媒体显示，媒体圆角最多 6px；无图食评不生成灰色占位卡或多余留白。
- [ ] 仅展示接口已有且可靠的作者、时间、点赞、评论和地点数据；没有可靠地点数据时不显示地点占位信息。
- [ ] “加载更多”采用无填充的文字操作或等价连续加载交互，继续分页不会重复、丢失或打乱已有食评。
- [ ] 在 375px、390px、430px 宽度下，正文、作者、时间和互动数据不溢出；图片加载、帖子详情和发布登录拦截均可用。
- [ ] 现有生产构建通过。
