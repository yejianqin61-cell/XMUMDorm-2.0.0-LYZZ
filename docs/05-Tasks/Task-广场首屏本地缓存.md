# Task：广场首屏本地缓存与后台刷新

## 目标

优化 Capacitor App 首次进入广场时的首屏体验：优先显示最近一次成功获取的广场轮播图、学校通知和学院通知，同时后台请求接口更新内容。

## 实施范围

- `frontend-app/src/utils/squarePersist.js`
- `frontend-app/src/pages/SquareHome.jsx`
- `frontend-app/src/components/canteen/CanteenBannerCarousel.jsx`

## 行为要求

- 学校通知和学院通知分别缓存，不能互相覆盖。
- 轮播图单独缓存；仅广场投放位使用该缓存，食堂轮播不受影响。
- 有缓存时不得先显示整页 skeleton；接口请求在后台完成。
- 接口成功返回新数据后替换当前数据并更新缓存。
- 接口失败时保留已有缓存内容，并允许用户手动刷新。
- 接口成功返回空列表时覆盖旧缓存，避免已下线内容长期显示。
- 轮播数据更新时按当前轮播项 ID 保持位置；当前项已不存在时再回到有效位置。
- 缓存只保存 JSON 数据与时间戳，不保存图片二进制。

## 验收

- 第一次无缓存进入广场，行为与当前接口加载一致。
- 第二次进入广场，轮播图和当前通知 Tab 的内容立即出现，随后完成接口刷新。
- 切换学校通知/学院通知时各自显示对应缓存，再分别刷新。
- 手动刷新不会清空已有内容或强制轮播回第一张。
- 删除或下线内容后，接口返回结果能覆盖本地旧数据。
- Capacitor App 构建通过，Web 端不受影响。
