# P1-07 - 信箱公告文本与详情跳转治理

## Parent

GitHub Issue #5：补全公告弹窗与信箱展示内容链路

## What to build

在信箱中为系统公告提供清晰、简洁且完整的展示文本，并确保点击后进入对应公告详情，而不是被聚合为点赞、评论或系统更新等无关文案。

## Blocked by

- P1-05 - 公告通知标题与正文数据契约统一

## Acceptance criteria

- [ ] 公告通知卡片明确标识为公告，展示正确标题和正文预览。
- [ ] 正文预览优先使用公告正文，缺失时按约定回退到标题或固定空内容状态，不显示乱码和 raw JSON。
- [ ] 公告卡片点击后进入对应帖子详情，并在进入时按现有规则标记相关未读通知。
- [ ] 公告不会与普通帖子互动通知错误聚合，清空互动通知不会误删公告。
- [ ] 信箱全部、系统分类和空状态下的公告表现一致，并支持中英文模式。

## 实施与验证记录

- [x] 公告行独立展示公告标签、标题、正文预览、发布者和相对时间，不再使用互动聚合文案。
- [x] 正文优先读取公告正文；历史数据缺少正文时显示稳定的中英文空正文状态，不显示 raw JSON、`undefined` 或乱码。
- [x] 公告行继续使用通知目标路径进入 `/post/:post_id`，单条进入时沿用现有已读标记逻辑。
- [x] 公告识别同时覆盖 `announcement`、`system_announcement`，在全部和系统分类中使用同一展示规则。
- [x] `frontend-app` 生产构建通过：`npm run build`（在 `frontend-app` 目录执行）。
