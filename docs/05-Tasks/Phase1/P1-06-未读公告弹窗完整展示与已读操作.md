# P1-06 - 未读公告弹窗完整展示与已读操作

## Parent

GitHub Issue #5：补全公告弹窗与信箱展示内容链路

## What to build

完善用户登录后出现的未读公告弹窗，让用户在确认前看到完整、可读的公告标题和正文，并能分别确认单条公告或全部公告。长正文、空正文和多公告状态都必须有稳定表现。

## Blocked by

- P1-05 - 公告通知标题与正文数据契约统一

## Acceptance criteria

- [ ] 弹窗展示公告标题、正文、发布者和时间；正文过长时可在弹窗内部阅读，不撑破屏幕。
- [ ] 单条“知道了”只标记当前公告为已读；“全部知道了”只处理当前弹窗中的公告。
- [ ] 标记成功后对应公告立即从弹窗中消失；请求失败时恢复未读状态并给出可理解的反馈。
- [ ] 多条公告、历史空正文公告和无公告状态均有明确表现。
- [ ] 中英文模式下弹窗操作文案和辅助标签不混搭，公告正文原文不被错误翻译或截断。

## 实施与验证记录

- [x] 弹窗展示公告标题、正文、发布者和发布时间；长正文在弹窗内部滚动，空正文显示明确回退文案。
- [x] 单条和批量已读均使用乐观更新；请求失败时恢复未读列表并显示错误提示。
- [x] 中文和英文模式分别渲染对应的弹窗标题、按钮和空状态文案，公告正文保持原文。
- [x] 后端通知路由回归通过：`npx jest __tests__/routes/notifications.test.js --runInBand`（8 tests passed）。
- [x] App 生产构建通过：`npm run build`（在 `frontend-app` 目录执行）。
