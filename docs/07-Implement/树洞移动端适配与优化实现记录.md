# 树洞页面移动端适配与优化 实现记录

> 2026-09-27 · 需求：「树洞页面，做一下移动端的适配与优化」（明确指 **Web 端** `frontend/`
> 在手机浏览器宽度下的那套移动端壳层，即 `<Layout mode="mobile">` + tab-stack + 底部 TabBar）。

## 一、先量，再改

用 Playwright 的 **真机分支** 实测（`--mobile`：`(pointer: coarse) = true`、`ontouchstart` 存在，
视口 360×732 / 390×844 / 430×900 / 320×900）。这一点很关键：`isCoarse` 在普通桌面 Chromium 里是
`false`，仅仅把窗口调窄测到的是「窄屏桌面分支」，和真机走的是不同代码路径。

改之前实测到的 6 个问题：

| # | 现象 | 实测数据 |
|---|---|---|
| 1 | **最后一张卡片被底部 Tab 栏压住** | 卡片底部 732 / Tab 栏顶部 646 → **被遮 86px** |
| 2 | **卡片贴屏幕边缘**，没有左右留白 | 两列各 174px，首卡 `x=0`、右列右边界 360（= 视口宽） |
| 3 | **整页图片全部 `loading="eager"`** | `eager 146 / lazy 0`（桌面端反而是 146 lazy） |
| 4 | 标签胶囊触控目标偏小 | 胶囊高 **37px**（iOS 建议 ≥44px） |
| 5 | 卡片作者名过小 | `font-size: 10px`（卡片仅 ~160px 宽） |
| 6 | 搜索框没有任何占位提示 | `placeholder` 为空，只有一个放大镜图标 |

### 根因

1 和 2 是**同一个根因**：`TreeHole.css` 里 `.treehole-content` 一直带着移动端内边距
（`padding: 10px 12px calc(var(--tabbar-height) + …)`，`PostSearch.jsx` / `PostTagFeed.jsx` 也在用），
但 `TreeHole.jsx` **漏了这层包裹** —— 于是这条规则在树洞主页面上没有作用对象，
左右留白与底部让位一起失效。

另外原规则少了底栏的 `10px` 底部偏移（`.tab-bar` 是 `bottom: 10px` + `height: 76px`，
实际占底部 86px），即便补上包裹层也只减 76px，仍差 10px。

3 是 `eager={isCoarse}`：`isCoarse` 是整表共用的，触屏设备上等于给一次渲染的 146 张卡片
全部标 eager；而瀑布流没有虚拟化（`USE_VIRTUAL_MASONRY = false`），一次就是 150+ 张。

## 二、改动

| 文件 | 改动 |
|---|---|
| `frontend/src/pages/TreeHole.jsx` | 补回 `.treehole-content` 包裹层（只包 `ListPageLayout`，debug HUD 与错误态仍在外面保持原边距）；新增 `EAGER_CARD_COUNT` + `eagerCardIds`，卡片 `eager` 改为「仅首屏前 8 张」 |
| `frontend/src/pages/TreeHole.css` | `.treehole-content` 底部内边距补上底栏的 `10px` 偏移并留 16px 呼吸位（`76 + 10 + safe + 16`）；新增窄屏 `@media (max-width: 767px)`：作者名 10px → 11px、省略宽度收到 `8em` |
| `frontend/src/components/TreeHoleToolbar.css` | 窄屏下标签胶囊 `min-height: 44px` + 垂直居中（原有 `py-1.5` 只有 37px） |
| `frontend/src/components/TreeHoleToolbar.jsx` | 搜索框补 `placeholder`（窄屏上原本是一个没有提示的空白胶囊） |
| `__tests__/frontend/treeholeMobileLayout.test.js` | 新增 9 条守卫，把上面两个回归钉住 |

刻意**没有**做的：

- **没有把瀑布流改成单列**。两列错落是这个页面的既定视觉，改成单列是产品决策而非适配修复；
  窄屏通过加左右留白把卡片从 174px 收到 162px 已经够用。
- **没有改 `warmImage()` 的预取窗口**（触屏首次挂载会预热 28 张缩略图）。它的存在是为了消
  「滑到一半出现灰块」，属于稳定性取舍，不在本轮改动范围。
- **没有把标签栏做成 sticky**。工具栏含 48px 搜索框 + 标签行（约 137px），在 732px 高的手机上
  sticky 会吃掉近 1/5 屏；要做得先和产品确认，本轮只记录为后续建议。
- **没有动 `isRootTabPage`**（`/treehole` 不在其中，直接输 URL 打开时不会走 tab-stack 壳层）。
  全仓库没有任何链接指向 `/treehole`，实测该路径的底部间距由 `.app-layout` 自己兜住，不属于本轮问题。

## 三、验证

### 实测对比（真实触屏分支）

| 指标 | 改之前 | 改之后 |
|---|---|---|
| `.treehole-content` | 不存在 | 存在，`padding: 10px 12px 102px` |
| 首卡左边界 / 右列右边界（360px） | 0 / 360 | **12 / 348** |
| 两列宽（360px） | 174 | 162 |
| 最后一张卡片被 Tab 栏遮盖 | **86px** | **让出 16px** |
| 标签胶囊高度 | 37px | **44px** |
| 卡片作者名字号 | 10px | **11px**（胶囊宽 90px < 卡片 162px，不撑满） |
| 图片 `loading` | **146 eager / 0 lazy** | **7 eager / 139 lazy**（首屏前 8 张里 1 张无图） |
| 搜索框 placeholder | 无 | `搜索帖子…` / `Search posts…` |

四个宽度（320 / 360 / 390 / 430）复测：`documentElement` 与滚动 pane 的横向溢出均为 **0**，
底部让位均为 **+16px**。英文模式复测同样通过。

### 回归验证

| 检查 | 结果 |
|---|---|

| 标签点击筛选 | 点「今日吃啥」→ 卡片 160 → 10，选中态落在第 3 个胶囊，44px 高度不影响点击 |
| 懒加载是否导致灰块 | 列表中部滚动后 `complete 146 / failed 0`，缩略图全部加载成功（`posts/thumbs/*.webp`），无灰块 |
| `npx jest` | **40 suites / 583 tests 全绿**（原 39 / 574，新增 1 suite / 9 tests） |
| `npx vite build` | 通过 |
| `node scripts/check-frontend-no-undef.js` | `[no-undef] OK — frontend/src 下 249 个文件没有未定义标识符` |

### 未验证 / 说明

- **没有在真机上验证**，用的是 Playwright 的 Chromium 触屏模拟（`(pointer: coarse)` 为真）。
  真机 Safari 的地址栏收缩（`100svh` 变化）与 `env(safe-area-inset-*)` 需要真机复核，
  本轮 `--safe-bottom` 实测为 0。
- 依旧没有做截图目视比对（本会话 `modlens_read_image` 不可用），结论全部来自 DOM 实测数据。

## 四、顺带记录（本轮未改）

- 瀑布流不做虚拟化，一次渲染 150+ 张卡片（`USE_VIRTUAL_MASONRY = false`，另有一份约 250 行
  的虚拟列表死代码）。图片改为 lazy 后首屏压力小了很多，但 DOM 节点数仍是移动端的长期负担。
- 触屏首次挂载会 `warmImage()` 预热 28 张缩略图，属于首屏流量的一部分。
- 工具栏不 sticky：长列表里切换标签要先滚回顶部。
- 连续自动加载（预取 effect + 滚动监听 + 近底 effect 三条触发路径）会把整份 feed 拉完
  （实测 160 条、`hasNextPage` 变 false），因此「加载更多」按钮在移动端几乎不会出现。
