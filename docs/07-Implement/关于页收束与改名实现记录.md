# 「关于」页收束与改名实现记录

> 日期：2026-09-27
> 范围：Web（`frontend/`）+ Capacitor App（`frontend-app/`）
> 需求来源：用户口述裁定 —— 「把 /about/profile 这边的团队介绍，编者的话，特别鸣谢，联系我们，全部去掉。然后关于我们改成关于」
> 补充裁定（同一轮问答）：① 连页面、路由、「我的-特别鸣谢」入口一起删干净；② 「关于我们」→「关于」要覆盖页面大标题 + 页面标题 + 「我的」页入口；③ 只做 Web + App 两端，RN（`mobile/`）不动。

---

## 1. 改之前是什么样

`/about/profile`（页面标题「关于我们」）是一张纯入口列表，7 行：

| 行 | 目标路由 | 处理 |
| --- | --- | --- |
| 团队介绍 / Team | `/about/team` | **删** |
| 编者的话 / Editor's Note | `/about/editor-note` | **删** |
| 评分算法说明 / Scoring Algorithm | `/about/algorithm` | 留 |
| 等级算法说明 / Level System | `/about/level-algorithm` | 留 |
| 特别鸣谢 / Special Thanks | `/about/thanks` | **删** |
| 免责声明 / Disclaimer | `/about/disclaimer` | 留 |
| 联系我们 / Contact us | `/about/contact` | **删** |

另外「我的」页「更多」分组里有两个入口：`关于我们 → /about/profile`、`特别鸣谢 → /about/thanks`。

一个容易踩的坑：`pages/AboutEditor.jsx`（一份更早的「编者的话」静态页）**从来没有接进路由**，属于死文件 —— `ContactUs.jsx` 反过来又只被 `/about/contact` 一条路由引用。删的时候要按"文件"而不是"路由"来清，否则会漏。

## 2. 改了什么

### 2.1 页面

- `frontend/src/pages/AboutProfile.jsx`、`frontend-app/src/pages/AboutProfile.jsx`
  - 大标题 `关于我们 / About us` → `关于 / About`
  - 删掉 4 个 `<AboutRow>`，只剩算法说明 ×2 + 免责声明
  - 清掉随之失效的 `lucide-react` 图标导入（`Users` / `FileText` / `HeartHandshake` / `Mail`）与 `Mail` 的 `softIcon` 色值
  - `aria-label` 由「关于我们入口」改为「关于入口」

### 2.2 路由

- 两端 `src/routes/layoutRoutes.jsx`
  - 删 `about/team`、`about/editor-note`、`about/thanks`、`about/contact` 四条 `<Route>`
  - 删对应 4 个 `lazy(() => import(...))` 常量
  - 未注册的 `AboutEditor.jsx` 一并按文件删除

### 2.3 标题与高亮

- `frontend/src/config/pageTitles.js`：`'/about/profile'` → `关于` / `About`；删掉 `/about/thanks`、`/about/team`、`/about/editor-note` 三个分支
- `frontend-app/src/components/Layout.jsx`：同上（App 是另一份独立的标题表 + if/else 分支）
- `frontend/src/components/shell/siteShellNav.js`：从「广场」的 `matchPrefixes` 里摘掉已下线路径，避免废弃路径继续触发高亮
- `frontend-app/src/components/TabBar.jsx`：`MY_ZONE_ABOUT_ROUTES` 同步摘掉 4 条，只留 `profile / algorithm / level-algorithm / disclaimer / schedule / diary`

### 2.4 「我的」页

- `frontend/src/pages/MyZone.jsx`：删「特别鸣谢」`MoreRow` + `aboutThanks` 文案 + 已失效的 `Sparkles` 导入；`aboutProfile` 文案改「关于 / About」
- `frontend-app/src/pages/MyZone.jsx`：本来就只有「关于」一行，改文案
- 两端顺手删掉早已无人引用的 `aboutContact: '联系我们'` 文案常量（页面已不存在）

### 2.5 删除的文件（每个端各 7 个，共 14 个）

```
src/pages/AboutTeam.jsx           src/pages/AboutTeam.css
src/pages/AboutThanks.jsx         src/pages/AboutEditor.jsx
src/pages/AboutEditorNote.jsx     src/pages/AboutEditorNote.css
src/pages/ContactUs.jsx
```

`AboutTeam.css` / `AboutEditorNote.css` 只被这几个页面引用（`AboutThanks`、`AboutEditor` 复用 `AboutTeam.css`），所以样式一并删除，不留孤儿 CSS。

## 5. 副作用与已知影响

1. **旧收藏链接不再有落地页**：这四条路径现在走 `path="*"` 兜底 → 跳回根 tab（实测落在树洞首页），不是 404 白屏，但也不再是原内容。有分享过 `/about/contact` 的场景需要另行安排（比如统一到「加入我们」）。
2. **Web / App 端不再有独立「联系我们」页**：原来那页承载微信号 `xmumdorm666`、电话与邮箱。现在这两端的对外联系方式只剩「加入我们」（微信号 + 邮箱）与隐私政策页内的邮箱。
3. **`pageTitles.js` 本身是死代码**（`resolvePageTitle()` 的结果从未写进 `document.title`，见 `brandAndJoinUs.test.js` 顶部注释），同步改名只是为了不留两套说法；真正影响浏览器标签页的是 `frontend/index.html` 的静态 `<title>Dorm</title>`。
4. **RN（`mobile/`）未动**：`AboutProfileScreen` / `AboutThanksScreen` / `AboutInfoScreen` 与 `MyZoneScreen` 的「特别鸣谢 / 联系我们」入口保持原样。两端关于体系目前不一致，属于本次明确的范围外。
5. `docs/` 下历史文档（`docs/06-Analyze/`、`docs/09-Deploy/`、`docs/10-ClaudeCode/` 等）仍按当时的架构描述这 4 个页面，属于历史记录，未回改。

## 6. 明确没做的事

- 没有为这 4 条旧路径加 `Navigate` 重定向到 `/about/profile`（用户选的是「删干净」，且旧内容已无对应去处）。
- 没有顺带清理 `AboutProfile` 保留项的内容（算法说明 / 免责声明页面本身未改）。
- 没有碰 RN 端，也没有改后端（本次为纯前端信息架构收束，无接口变更）。
