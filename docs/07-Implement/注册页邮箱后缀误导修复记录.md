# 注册页邮箱后缀误导 修复记录

> 2026-09-27 · 反馈：「注册页面，用户可能会以为已经写好了邮箱后缀，导致无法收到验证码。」

## 一、问题

注册页的「学校邮箱」输入框**内部右侧**浮着一个灰色的 `@xmu.edu.my`：

```jsx
{!email.includes('@') && (
  <span className="pointer-events-none absolute inset-y-0 right-4 flex items-center text-[14px] font-medium text-slate-300">
    @xmu.edu.my
  </span>
)}
```

输入框还专门留了 `pr-[7.5rem]` 给这串文字让位，`placeholder` 写的是「输入邮箱前缀」——
等于在暗示「你只需要填前缀，后缀已经有了」。

但它**只是装饰**：真正被校验和提交的是 `email` 这个 state，前缀本身不构成邮箱。

### 为什么表现为「收不到验证码」

| 环节 | 实际行为 |
|---|---|
| 用户输入 | `CST2509054`，看到框内显示成 `CST2509054　@xmu.edu.my` |
| 点「发送」 | 按钮的 `disabled` 条件包含 `!email.trim().endsWith('@xmu.edu.my')` → **按钮是灰的，点了没有任何提示** |
| 点「注册」 | 才弹出一句「邮箱须以 @xmu.edu.my 结尾」，但用户不一定会把它和框里那串后缀联系起来 |

两种失效叠加：视觉上「后缀已经有了」，行为上「点了没反应」。`text-slate-300` 与 placeholder 的
`text-slate-400` 几乎同一色阶，人眼只会把它读成提示文字，而不是「这部分我还没填」。

同样的代码在 Web（`frontend/`）与 App（`frontend-app/`）各有一份；
`ResetPassword` 页只在 label 里写了域名，没有这个后缀，不受影响。

## 二、决定

**后缀从输入区彻底移除，改为输入框下方一行完整示例。**

选这个方案而不是「自动补全后缀」：自动补全会改变提交语义（用户填前缀就不再报错），
属于产品行为变更；本轮只解决「展示误导」，让输入区不再出现任何「已经填好」的假象。

## 三、改动

| 文件 | 改动 |
|---|---|
| `frontend/src/pages/Register.jsx` | 删掉输入框内的后缀 `span`；`pr-[7.5rem]` → 正常内边距；`placeholder` 由「输入邮箱前缀」改为「输入完整邮箱 / Enter your full email」；提示行由「请使用以 @xmu.edu.my 结尾的校园邮箱」改为 `例如 CST2509054@xmu.edu.my` / `e.g. CST2509054@xmu.edu.my` |
| `frontend-app/src/pages/Register.jsx` | 同上（App 端保持一致，示例文案 `e.g. CST2509054@xmu.edu.my`） |
| `__tests__/frontend/registerEmailField.test.js` | 新增 6 条守卫，钉住「后缀不得回到输入区」 |

## 四、验证

真机分支（`--mobile`，`(pointer: coarse)` 为真）实测注册页：

| 检查 | 改之前 | 改之后 |
|---|---|---|
| 输入区内的域名元素 | 1 个 `span`（`text-slate-300`） | **0 个** |
| 输入框 `padding-right` | `120px`（给后缀让位） | `16px` |
| 输入框包裹层可见文本 | `@xmu.edu.my` | **空字符串**（`domainInsideInputArea: false`） |
| `placeholder` | 输入邮箱前缀 | 输入完整邮箱 / Enter your full email |
| 下方提示 | 请使用以 @xmu.edu.my 结尾的校园邮箱 | 例如 CST2509054@xmu.edu.my |

- 360px 窄屏：输入框 `x=36 width=288 right=324`（左右对称），横向溢出 0
- 1440px 桌面：输入框宽 800，域名仍只出现在提示行，横向溢出 0
- 英文模式同样通过
- `npx jest` **41 suites / 589 tests 全绿**（新增 1 suite / 6 tests）
- `frontend` 与 `frontend-app` 两个 `vite build` 均通过

## 五、遗留（本轮未做，供后续判断）

「发送」按钮在不完整邮箱下是 `disabled` 且**没有任何提示**。后缀误导已消除，但一个只填了
`CST2509054` 的用户现在依然点不动按钮、也不知道为什么。若要进一步降低挫败感，可以把按钮改成
恒可点击 + 明确报错（例如「邮箱需要包含 @xmu.edu.my」），这是一处独立的行为改动，未包含在本轮。
