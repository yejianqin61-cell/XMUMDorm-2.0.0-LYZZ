`frontend/src`、`frontend-app/src`、`mobile/src`、`public`、`marketing/wechat` 与三份 README，
递归收集 `.js/.jsx/.ts/.tsx/.html/.css/.md/.json/.webmanifest`，然后：

1. 任何文件出现 `yejianqin61@gmail.com` / `01115078663` / `YEJIANQIN_git` / `mailto:` → 红；
2. 正则抓所有邮箱字面量，**只放行学校域名与测试占位域名**（`@xmu.edu.my`、`@example.com`、`@test.com`、`@company.com`、`@localhost`、`noreply@`）→ 其余一律红；
3. 7 个对外落点必须含 `xmumdorm666`；
4. 扫描文件数 > 100，防止路径写错导致测试空转。

## 5. 副作用与需要知悉的事

1. **隐私政策与服务条款现在唯一给出的联系方式是微信号**。这两页此前只有邮箱，改成微信后，不看微信的人就没有渠道了 —— 这是按用户裁定的预期结果，但确实降低了可达性。
2. **注册 / 登录 / 重置密码用的 `@xmu.edu.my` 邮箱不是联系方式**，是登录凭据与验证码送达地址，未做任何改动，扫描器也把它列入放行名单。`services/pushSend.js` 里的 `mailto:dorm-app@localhost` 是 Web Push 的 VAPID subject，不是对外联系方式，同样未动。服务条款第 7 条「重大变更会通过 App 内公告或邮件通知」描述的是**通知渠道**而非联系方式，保留。
3. **RN 端只收口了联系内容，没有删页面**：`MyZoneScreen` 里「联系我们」这个入口还在，因为本次裁定针对的是“出现哪些联系方式”，不是“保留哪些页面”。RN 的「特别鸣谢 / 关于」结构相较 Web / App 仍然不一致（上一轮已记录）。
4. **`marketing/wechat/dorm-wechat-template.html` 有另一个 agent 未提交的 6 行文案改动**。为了不把别人的在制品混进本次提交，这个文件用「只把 HEAD + 我的改动写进 Git 索引」的方式提交（`git hash-object -w` + `git update-index --cacheinfo`），因此：
   - 本 PR 里该文件的 diff 只有 **3 行删除**（邮箱那段）；
   - 工作区里那 6 行文案改动**仍然保持未提交状态**，归属不变。
5. `docs/` 下的历史文档（`docs/07-Implement/公众号推文模板与微信号统一.md`、`docs/05-Tasks/上线准备/Task03-隐私政策与品牌优化.md` 等）仍按当时情况记录着旧邮箱，属历史记录，未回改。
