## 二、公众号推文模板

```
marketing/wechat/
├── dorm-wechat-template.html   预览 + 一键复制
└── README.md                   工作流与限制说明
```

### 2.1 为什么正文全部写成内联 style

模板的正文区（`#articleBody`）里**一个 `class` 都没有**，全部是标签上的 `style="..."`。

这是刻意的保险：社区与工具源码的一致结论是微信编辑器**会剥离** `<style>` 标签、
`class` / `id` 选择器与外部 CSS，只有内联样式确定能活下来。即使它对某几类选择器其实是
放行的，写成内联也**不会损失任何东西**——所以这条路是无论限制多严都安全的选择。

> 需要说清楚的是：**「`<style>` / `class` / `id` 会被剥离」微信官方从未正式声明过**，
> 是多方独立实测 + 工具源码的一致结论。官方唯一发布过的是
> [编辑器插件开发规范](https://developers.weixin.qq.com/doc/subscription/guide/product/plugin_spec.html)，
> 内容方向是「什么不该做」，而不是「什么可以用」。两者的区分记在调研文档里。

另外几条**官方明说**的坑，模板也一并避开了：

| 官方规则 | 模板的做法 |
|---|---|
| 不建议设置任何字体族（`font-family`） | 全文未写 `font-family` |
| 不建议使用 `!important` | 一处未用 |
| 「固定宽度」属违规（居中不一致 / 内容溢出被截断 / 跨屏差异） | 容器 `max-width:677px;width:100%`，图片 `max-width:100%` |
| 同标签名、同样式、单子节点的嵌套超过 10 层会被**自动精简** | 最深处 4 层 |
| 建议给 `<img>` 加 `data-w`（原始像素宽） | 吉祥物写了 `data-w="503"` |
| Dark Mode 下不要用渐变做文字背景 | 渐变只在顶部品牌条，其上无正文文字 |

正文排版值取 **15px / 行高 1.75 / 字距 0.5px**，都在社区推荐区间内（字号 14–16、
行高 1.5–2、字距 0.5–1.5px）。

**圆点列表没用 `<ul>`**：微信经常把 `list-style` 吃掉，那样列表就退化成一堆没有圆点的缩进
文字。模板里每个要点是一行 `<section>` + 一个 `inline-block` 的圆点 `<span>` 画出来的。

### 2.2 配色从 App 图标里提取（不是拍脑袋定的）

用 System.Drawing 对 `frontend/public/icons/icon-512.png` 做像素统计得到实际色值：

| 变量 | 色值 | 用途 |
|---|---|---|
| 深蓝 | `#122D78` | 标题、强调字、小节竖条 |
| 天蓝 | `#ACD3F8` | 品牌主色、圆点、虚线框（图标里占比最高的饱和色） |
| 浅蓝 | `#EAF4FE` | 高亮块底色 |
| 奶油白 | `#F9F9F0` | 导语 / 引用块底色（吉祥物横幅的底色） |
| 深灰 | `#3F3F3F` | 正文（社区共识：正文不用纯黑） |

顶部吉祥物用的是 `frontend/public/icon-512-removebg-preview.png`——实测该 PNG
**四条边与四角 alpha 全为 0**（41% 全透明 / 55% 全不透明 / 4% 半透明抗锯齿），
所以能干净地压在浅蓝渐变上，不会出现一个白底方块。

### 2.3 两个必须手动处理的微信限制

| 限制 | 模板里的应对 |
|---|---|
| **不认站外图片链接** | 正文里是虚线框占位，到编辑器里用「图片」按钮从素材库重传；吉祥物同理 |
| **正文里的站外超链接点不动** | 正文不放 `https://` 当入口，改用编辑器右上角的「**阅读原文**」 |

### 2.4 模板内容

一套完整骨架，示例内容就是「加入我们」的招募推文，可直接改：
品牌条 → 主标题 → 导语块 → `01/02/03` 小节 → 圆点要点 → 高亮块 → 金句块 →
图片位 + 图注 → 圆点分隔 → CTA 联系卡片（微信 + 邮箱）→ 页脚。

测试改动：

  写的是 `xmumdorm666`、且不再出现 `YEJIANQIN_git`

  `readFileSync` 读真实源码
- `__tests__/marketing/wechatTemplate.test.js`（**新增 13 例**）—— 守护模板的微信兼容性

> 为什么模板也要测：**掉格式是「静默」的**。本地浏览器渲染永远正常，只有粘进公众号
> 才会发现 class/`<style>` 被剥离。所以「复制区必须全内联」这条线只能靠测试焊死，
> 而不是靠人记得。守卫覆盖：无 `class`、无 `<style>`/`<link>`、无脚本与嵌入标签、
> 无 `!important`、无 `font-family`、无 `@media`/伪元素、容器用 `max-width` 而非写死宽度、
> 图片带 `data-w`、CTA 是官方微信号、按钮仍写 `text/html` 且按钮本身不在复制范围内。

### 模板（Playwright 真实浏览器，HTTP 提供）

对 `#articleBody`（**即复制范围**）做程序化审计：

| 检查 | 结果 |
|---|---|
| `class` 属性数量 | **0** |
| 无内联 `style` 的元素 | 仅 5 个 `<br>`（换行标签本来不需要样式） |
| 禁用标签（`script`/`iframe`/`video`/`style`/`link`/`form`…） | **0** |
| `!important` / `font-family` / `@media` / 伪元素 | **均为 0 处** |
| 最大嵌套深度 | **4 层**（官方上限 10 层，超出会被自动精简） |
| 图片 | `data-w="503"`、`max-width:100%`、`naturalWidth = 503` 加载正常 |
| 正文排版实测值 | `15px` / `line-height 26.25px`(=1.75) / `letter-spacing 0.5px` / `rgb(63,63,63)` |
| 复制按钮 | 点击后按钮变「✓ 已复制，去粘贴」，状态栏显示已复制字符数 |
| **复制载荷是否等于被审计的 HTML** | 是——状态栏字符数 `10237` 与 `articleBody.outerHTML.length` **完全相等** |
| 正文是否含官方微信号 / 邮箱 | 均是 |
| 正文是否含 `YEJIANQIN` / `Jack` | 均无 |

> 复制载荷用「字符数恒等」来证明，而不是真去读剪贴板——无头 Chromium 拒绝
> `navigator.clipboard.read()`（`NotAllowedError`）。按钮走的是
> `navigator.clipboard.write([ClipboardItem])`，写入前先确认了
> `isSecureContext === true`、`window.ClipboardItem` 与 `navigator.clipboard.write` 均存在。

配色与排版另经**两轮截图目视确认**（900px 视口，375px 手机壳）：浅蓝渐变品牌条、
深蓝竖条小节标题、奶油底导语、圆点列表、金句块、虚线图片占位、CTA 卡片、页脚均正常。
