## 3. 匿名性专项（本模块最重要的安全不变量）

匿名是万能墙的核心承诺，因此设了专门的 `describe('匿名性（安全不变量）')` 区块，
核心是 `assertNoIdentityLeak(res)`：**递归遍历整个响应 JSON**，一旦出现
`user_id` / `username` / `nickname` / `avatar` / `from_user_id` 任一键即测试失败。

关键设计：测试数据 `RAW_CONFESSION` / `RAW_COMMENT` **故意包含** `user_id`、`username`、
`nickname`、`avatar` 等身份列，用以证明路由是**主动逐字段投影**（`projectConfession` /
`projectComment`）来保证匿名，而不是依赖 SQL「碰巧没选这些列」——后者一旦有人改动
SELECT 就会立刻泄漏。

| 用例 | 验证内容 |
|------|----------|
| `GET /window 不下发任何身份字段` | 列表窗口响应干净 |
| `GET /window 使用带身份字段的原始行时，仍被投影掉` | 即使 DB 行含身份列也不泄漏；并断言响应文本不含 `真实昵称` / `leaker_should_never_appear` |
| `GET /:id 不下发任何身份字段（即使 DB 行含身份列）` | 详情响应干净 |
| `GET /:id/comments 不下发任何身份字段（含 replies）` | 一级评论与**其 replies** 都干净 |
| `POST /comments 回读行含身份列时也不下发` | 写入后回读同样投影 |
| `POST / 投稿响应不下发身份字段` | 投稿响应干净 |

`viewer_is_mine` / `viewer_is_author` 为**布尔值**，只回答「是不是你自己发的」，
不含身份标识，因此不违反匿名性——它们不在禁止键列表中，且其语义已被评论面板正确消费。

## 5. 前端纯逻辑测试明细

### 5.1 `confessionKeyboard`（36 例）

表驱动覆盖全部键位映射；**三条硬规则的逐项验证**：

- **焦点让位**：`INPUT` / `TEXTAREA` / `SELECT`（含小写）/ `contenteditable` 下，
  方向键、Home/End、空格、Enter 全部返回 `null`（不拦截），仅 `Escape` 例外。
- **可激活元素让位（V1.1 新增）**：`BUTTON` / `A` / `SUMMARY`（含小写）上，
  `Enter` / ` ` / `Spacebar` 一律返回 `null`；而方向键与 `Home` / `End` **不受此限**，仍返回翻页动作。
- **修饰键**：`metaKey` / `ctrlKey` / `altKey` 任一按下即完全退出。
- **边界**：`key` 缺失、`ctx` 为 `null`、`defaultPrevented` 均安全返回而非抛错。

> 测试过程中发现并修复了一个真实缺陷：`ctx = {}` 的默认参数无法处理显式传入 `null`，
> 会抛 `TypeError: Cannot read properties of null`。已改为 `} = ctx || {};`。

> V1.1 补充：原实现只定义了「输入框内让位」，漏掉了按钮。结果是键盘用户把焦点移到
> 「下篇」按钮上按 `Enter` 时，事件被 `preventDefault()` 并解释为「展开评论区」，
> **按钮自身的点击被吃掉**。规则 3 即为修复，见设计文档 §17.3。

### 5.2 `confessionWindow`（30 例）

| 分组 | 关键断言 |
|------|----------|
| `applyWindowPage` | 顺序、index 归 0、空/非法输入安全降级 |
| `appendOlder` / `prependNewer` | 追加/前插正确；**前插后 index 同步后移，仍指向同一篇**；重复 id 不重插 |
| `move` | 窗口内移动；到边界时正确返回 `needsLoad: 'older'/'newer'`；**确实到头时返回 `moved:false, needsLoad:null`**（触发回弹而非请求）；空窗口/未知方向不抛错 |
| `jump` | Home/End 正确；空窗口安全 |
| `trimWindow` | 超上限裁剪后**当前下标仍指向同一篇**；`entries` 不残留已淘汰 id；自定义 max 生效 |
| `shouldPrefetch` | 近尾→`older`、近头→`newer`、中部→`null`、无更多内容→`null` |
| `patchEntry` / `removeEntry` | 只改目标；移除前置条目时 index 前移以保持指向；移除最后一篇后窗口归空、index 归 0 |

### 5.3 `confessionTemplatesParity`（9 例）

守护 `constants/confessionTemplates.js`（后端 CJS）与
`shared/constants/confessionTemplates.js`（前端 ESM）两份刻意双胞胎的一致性：
key 集合与顺序、`maxLength`、双语标签与描述、默认版式、
`normalizeTemplateKey` / `getTemplate` / `getTemplateMaxLength` 行为。
**任何人只改一边，这里立刻失败。**

### 5.4 `focusTrap`（16 例，V1.1 新增）

`shared/utils/focusTrap.js` 是评论弹窗 Tab 环绕的决策核心，纯函数、无 DOM 依赖。

| 分组 | 关键断言 |
|------|----------|
| 中间位置 | 正向不在末尾、反向不在开头 → 返回 `null`，交回浏览器原生 Tab |
| 首尾环绕 | 正向在末尾 → `0`；反向在开头 → `total - 1`；只有一个元素时正反向都停在它自己 |
| 焦点在容器外 | `currentIndex = -1` / 越界 / 非数字 → 正向给 `0`、反向给 `total - 1` |
| 无可聚焦元素 | `0` / 负数 / `undefined` / `null` / `NaN` → 一律 `null`，不抛错 |
| 选择器 | 排除 `[disabled]` 与 `tabindex="-1"`；覆盖 button / a[href] / input |

> 循环里最容易出错的两处——「单个元素时反复把焦点抢回自己」与「焦点还没进弹窗时按 Tab
> 直接跳出页面」——都被上表显式锁住。

### 5.5 `confessionCommentModal`（19 例，V1.1 新增）

`frontend/` 自带 `package.json`（`"type": "module"`），根 Jest 的 Babel 不作用于其下的文件，
因此无法渲染测试 JSX 组件（见 §8.2）。本文件沿用仓库既有做法：**读源码做结构断言**。

| 分组 | 断言的不可回归点 |
|------|------------------|
| 组件结构（9） | `createPortal` 到 `document.body`；`role="dialog"` + `aria-modal` + `aria-labelledby`；`body` 滚动锁与恢复；打开前焦点的捕获与归还（含 `document.contains` 守卫）；`window` 上的 `Esc`/`Tab` 监听与移除；`hasNestedOverlay` 的 `position: fixed` 判定；遮罩 mousedown+click 双判定；`getClientRects()` 可见性过滤；未登录时聚焦关闭按钮 |
| 样式几何（5） | 遮罩 `position: fixed` + 双轴居中 + `z-index: 2000`；强调色变量在遮罩上**重新声明**（portal 后不再继承 `.cf-wall`）；`min(84vh, 780px)` 限高 + `.cf-comments__body` 滚动 + 表单 `flex-shrink: 0`；`prefers-reduced-motion` 同时关掉遮罩与弹窗动画 |
| 一屏一篇高度（3） | CSS 为 `88vh`、窄屏 `82vh`；`ConfessionPager.PAGER_PANE_HEIGHT` 兜底值与 CSS 一致 |
| 入口无障碍状态（2） | 评论按钮带 `aria-haspopup="dialog"` / `aria-expanded`；只有当前展示的那一篇拿到展开状态 |

> 最后一项是有意为之的防回归：卡片被翻页轨道复制多份，若把 `commentsOpen` 直接透传，
> **所有**卡片都会向读屏软件播报「已展开」，而实际只有一个弹窗。

   本期范围为「仅 Web 端」（决策 Q6）。若后续要覆盖 App，需把
   `frontend/src/pages/ConfessionWall.*` 与 `components/confession/` 复制到 `frontend-app/`，
   两者此前是各自维护的（见 `__tests__/frontend/treeholeRecommendationCopy.test.js` 同时检查两个目录）。

4. **移动端 TabBar 未新增 Tab**
   `/confession` 在移动端通过路由可访问，但 `getTabIndex` 会使其归到第 0 个 Tab（广场）而高亮略偏。
   这是决策 Q6「不改 Layout 四格结构以免波及树洞」的已知取舍。

5. **（V1.1）举报浮层内部没有焦点陷阱**
   评论弹窗的 `Tab` 环绕收集的是整个弹窗内的可见可聚焦元素。当弹窗内的举报浮层打开时，
   焦点仍可在弹窗整体范围内移动，而不是被限制在举报浮层里。
   根因是 `components/ReportButton.jsx` 自身没有任何焦点管理（全仓库 20+ 处引用它）。
   改造它属于独立立项范围。

6. **（V1.1）背景滚动锁在移动端无效**
   弹窗只锁 `document.body` 的 `overflow`。桌面 / 平板外壳的滚动容器就是文档本身，因此有效；
   移动端外壳的滚动容器是 `.app-main`（`overflow: auto`），锁 `body` 拦不住它，
   在遮罩上滑动仍会滚动背景。本期移动端明确不保证（见设计文档 §2 补充事实）。
   通用解法是「从页面节点向上遍历可滚动祖先逐个上锁」，属独立小改动。

## 10. V1.1 增量变更（卡片加高 + 评论弹窗）

需求：**① 万能墙高度高 1.5 倍；② 评论区改为悬浮居中弹窗。**

| 项 | V1.0 | V1.1 |
|----|------|------|
| 一屏一篇高度 | `72vh`（窄屏 `68vh`） | **`88vh`**（窄屏 `82vh`） |
| 评论区形态 | 中间列内向下展开的面板 | **`position: fixed` 遮罩 + 居中弹窗**（portal 到 `body`） |
| 评论列表滚动 | 整页滚动 | 只有列表区滚动，标题与输入框常驻 |
| 弹窗关闭方式 | ✕ 按钮 | ✕ / `Esc` / 点击遮罩 |
| 焦点管理 | 打开时聚焦输入框 | ＋滚动锁、`Tab` 环绕、关闭时焦点归还 |
| 键盘规则 | 2 条 | 3 条（新增「可激活元素让位」） |

### 10.1 关于「高 1.5 倍」的结论

需求方先选择「加高但封顶在视口内」，**经实测该组合在本仓库布局下不成立**：
卡片之外的固定开销约 **377px**（站点顶栏 120 + 页面留白 64 + 墙内边距 48 + 页头 61 + gap 32 + 控制条 52），
因此「封顶在视口内」的上限是 `calc(100dvh - 377px)`——在 900px 高的视口上只有 523px（58vh），
**比 V1.0 的 72vh 还矮**。`min(88vh, calc(100dvh - 377px))` 只在视口高 ≥ 3142px 时才取到 88vh。

**裁定：以「加高」为准，取 88vh，接受页面滚动。** 完整推导见
[设计文档 §17.2](../../04-Module/M09-万能墙/Module09-万能墙模块设计.md)。
若需字面的 1.5 倍（108vh），只需改 `--cf-pager-height` 一处。

### 10.2 V1.1 顺带修掉的真实缺陷

**按钮上的 `Enter` / `Space` 被抢。** V1.0 的键盘规则只定义了「输入框内让位」，
漏掉了 `BUTTON` / `A`。键盘用户把焦点移到「下篇」按钮上按 `Enter` 时，事件被墙容器
`preventDefault()` 并解释为「展开评论区」，**按钮自身的点击被吃掉**。
V1.1 增加规则 3，并补 9 个用例锁住（设计文档 §17.3）。

## 11. V1.2 增量：翻页按钮移出折叠线

需求：「左右翻页的那个按钮被挡住了，可以各自将按钮左右平移」（1440×900 实测）。

### 11.1 两个叠加的缺陷

| 元素 | 修复前 | 问题 |
|------|--------|------|
| `.cf-pager__controls` | y=**1070** | 在 900px 折叠线以外，任何常见屏幕都看不到翻页按钮 |
| `.cf-pager__pane` | h=**412.5** | 漏写 `height`，高度退化为内容高度 |
| `.cf-card` | h=**404.5** | 792px 的视口里只占 412px，下方 380px 全是空白 |

- 命中测试（`document.elementsFromPoint`）证明按钮**没有被任何元素覆盖**，
  栈里只有 `svg / button / .cf-pager__controls / .cf-pager` —— 是几何位置问题，不是层叠遮挡。
- **「高度加了却看不出变化」的真正原因是第 2 条**：`88vh` 只把空白区域加高了，
  卡片本身因为 `min-height: 100%` 失去参照而只有 404px。

### 11.2 修复后实测（1440×900）

| 元素 | 修复后 |
|------|--------|
| 控制条 | y=**266**（折叠线以上） |
| 上篇按钮 | x=**329**（最左） |
| 序号 / 最新 / 最旧 | 居中分组 |
| 下篇按钮 | x=**1015**（最右） |
| `.cf-pager__pane` | h=**792** |
| `.cf-card` | h=**784**（真正撑满一屏） |

### 11.3 测试补充（+6 例）

`confessionCommentModal.test.js` 新增两个分组：

- **一屏一篇高度**：`.cf-pager__pane` 必须显式 `height: var(--cf-pager-height)`
  （防止再退化成 `auto`，这是本次真正的回归点）
- **翻页按钮可见性**：控制条的 DOM 顺序必须在视口之前、边界提示也必须在前、
  `justify-content: space-between` + `.cf-pager__center` 且两个按钮分别在中心分组两侧

### 11.4 ⚠️ 本次未解决：88vh 下卡片底部互动行仍在折叠线外

卡片既已撑满 792px，其底部的元信息行与 `♡ / 💬` 互动行就落到折叠线以下，点赞/评论需要滚动一点。
这是「加高」与「一屏看全」互斥的必然后果（§10.1）。要两者兼得实测可用 `--cf-pager-height: 62vh`
（1440×900 下卡片 ≈558px，仍是原先实际可见高度 404px 的 1.38 倍；推导见设计文档 §18.4）。
**当前保留 88vh，是否下调待产品负责人裁定。**
