# XMUMDorm 团队协作契约

## 1. 目标与原则

这份契约用于保证多人同时开发时，主分支可发布、改动可追溯、用户数据和密钥不被误提交。规则以降低协作成本为目的；不清楚时，先在 Issue 或 PR 中说明，再开始改动。

- `main` 永远保持可构建、可发布。
- 每项改动都有明确负责人、提交记录和验证方式。
- 不覆盖、不回退他人的未提交改动。
- 小而完整的改动优先于混合大提交。

## 2. 权限与分支

| 项目 | 约定 |
| --- | --- |
| 仓库管理员 | 负责成员访问、分支保护、生产发布与紧急回滚 |
| 开发成员 | 使用 GitHub Collaborator 权限；不直接推送 `main` |
| 个人分支 | `dev-名字缩写`，例如 `dev-yjq`、`dev-xyz` |
| 主分支 | `main`，只通过 PR 合并 |
| 开始任务 | 从最新 `origin/main` 同步到自己的开发分支 |

日常同步：

```bash
git fetch origin
git switch dev-名字缩写
git merge origin/main
```

发生冲突时，只解决与当前任务有关的冲突；无法判断归属或行为时，停止并在 PR/Issue 中说明，不凭猜测选择一方。

## 3. 提交规范

一个 commit 只做一件可描述的事。提交标题使用：

```text
type(scope): 简短说明
```

允许的 `type`：

| 类型 | 使用场景 |
| --- | --- |
| `feat` | 新功能 |
| `fix` | 缺陷修复 |
| `docs` | 文档、协作说明 |
| `refactor` | 不改变外部行为的代码整理 |
| `test` | 测试新增或修正 |
| `style` | 纯样式或格式调整 |
| `chore` | 构建、依赖、工具配置 |

示例：

```text
feat(canteen): add public dish contribution entry
fix(mailbox): render announcement content
docs(team): add collaboration contract
```

提交前必须检查：

```bash
git status
git diff --check
```

禁止习惯性使用 `git add .`。只暂存当前任务相关文件，例如：

```bash
git add frontend/src/pages/Settings.jsx frontend/src/pages/Settings.css
```

## 4. Pull Request

所有合并都创建 PR：

```text
base: main
compare: dev-名字缩写
```

PR 描述至少包含：

1. 做了什么。
2. 如何验证。
3. 是否涉及数据库迁移、环境变量、权限或生产数据。
4. UI 改动附截图或录屏。

合并前要求：

- 分支已同步近期 `main`，且无未解决冲突。
- 构建、测试或人工验证结果写入 PR。
- 至少一位有写入权限的成员审查并批准，除非仓库管理员临时调整保护规则。
- 作者不自行批准自己的 PR。

合并后删除已完成的个人分支仅在不再继续使用该分支时进行；长期个人分支保留，并继续从 `main` 同步。

## 5. 文档规则

- `docs/` 的层级目录只放 `README.md` 和主题文件夹，正文不裸露在层级根目录。
- 需求放 `docs/01-Requirement/`，澄清放 `docs/02-Clarify/`，架构放 `docs/03-Architecture/`，任务放 `docs/05-Tasks/`，分析放 `docs/06-Analyze/`，测试放 `docs/08-Test/`，发布与运维放 `docs/09-Deploy/`。
- 新建主题文件夹时，同时更新该层的 `README.md` 索引。
- 文件名使用中文且说明主题；任务文档以 `Task-模块-事项.md` 命名。避免 `新建文档.md`、`最终版2.md`、`test.md` 等无语义名称。
- 事实变化时更新原文档；新的阶段决策另建文档，不覆盖历史验收记录。

## 6. 数据库、接口与权限

- Schema 变更必须新增 migration，并在 PR 中写明迁移文件和回滚影响。
- 不直接手改生产数据库来替代 migration。
- 新增或放开接口必须说明认证、角色权限、输入校验与失败行为。
- API 契约变更要同步检查 Web、Capacitor App 和共享 API 层。

## 7. 密钥、数据与构建产物

以下内容不得提交：

- `.env`、账号密码、Token、私钥、Keystore 密码。
- Android keystore、华为签名导出包、生产数据库导出文件。
- `node_modules/`、构建目录、临时截图、个人 IDE 配置。

发现密钥已经进入 Git 历史时，立即通知仓库管理员，先轮换密钥；不要只删除当前文件就认为问题已经解决。

## 8. 上线与紧急修复

- 正常上线只从已合并的 `main` 构建。
- 线上故障先记录现象、影响范围、时间和日志，再修复。
- 紧急修复仍创建最小 PR；确需管理员直接处理时，事后补充 Issue/PR 记录和验证结果。

## 9. 生效与修订

本契约自合并到 `main` 后生效。规则需要调整时，通过 PR 修改本文件；团队讨论结论写入提交或 PR，避免只留在聊天记录中。
