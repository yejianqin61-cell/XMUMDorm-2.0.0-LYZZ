# 个人空间风险治理规格

**Status:** ready-for-agent

**范围：** App 与 Web 的 `/user/:id` 个人空间，以及共享的公开资料接口。

## Problem Statement

个人空间存在阻断访问的前端 Hook 调用顺序错误，资料加载完成后可能出现空白页面。公开资料接口还无条件返回校园邮箱及部分行为画像，用户无法控制这些信息是否对外可见。帖子总数、服务端分页上限和前端列表加载策略不一致，导致高活跃用户的历史内容被静默截断。页面另有路由参数宽松解析和语言模式遗漏，影响上线前的稳定性、隐私与一致性。

## Solution

将个人空间收束为稳定、最小公开的资料视图：任何资料加载、失败、重试和语言切换都不得导致 Hook 顺序变化或空白；公开访客只能获得展示个人资料和公开帖子所必需的字段；校园身份沿用既有可见性开关；行为画像默认不作为公开资料的一部分；用户可连续浏览与总数一致的帖子列表；非法资料 URL 必须被拒绝而非解析为其他用户。

## User Stories

1. 作为访问个人空间的学生，我希望资料加载完成后稳定显示内容，以便不会遇到空白页或需手动刷新。
2. 作为网络较慢的学生，我希望在资料加载、失败和重试之间切换时页面保持可用，以便知道当前状态并恢复访问。
3. 作为资料所有者，我希望校园邮箱不出现在公开资料响应中，以便陌生访客不能枚举我的联系方式。
4. 作为公开访客，我希望只看到资料所有者明确选择公开的学院、年级和专业，以便资料页遵守既有隐私设置。
5. 作为资料所有者，我希望收藏、社团关系、活动报名和最近参与记录不会默认暴露在公开资料页，以便我的使用行为不被无关访客画像化。
6. 作为访问者，我希望公开资料只展示该用户可公开的帖子和基础展示信息，以便页面的内容边界明确。
7. 作为高频发帖用户，我希望能够继续浏览全部公开帖子，以便资料页的帖子数与实际可见内容一致。
8. 作为访问者，我希望帖子统计不包含资料页不可见的广告帖，以便数字与列表一致。
9. 作为访问者，我希望错误的用户地址显示“用户不存在”或无效地址状态，以便不会意外打开其他用户资料。
10. 作为中文用户，我希望个人空间不出现英文硬编码或技术错误文案，以便与全局语言模式一致。
11. 作为英文用户，我希望个人空间所有可见标签、空状态和图片失败状态使用英文，以便不出现中英混杂。
12. 作为维护者，我希望公开资料接口有字段白名单和回归测试，以便后续添加用户字段时不会再次泄露隐私数据。
13. 作为维护者，我希望 App 与 Web 共用相同的资料页稳定性和隐私规则，以便双端不会出现行为分叉。

## Implementation Decisions

- 资料页的全部 Hook 必须在所有条件返回之前调用。加载、无效 ID 和请求失败仅决定渲染分支，不能改变同一次组件生命周期的 Hook 调用顺序。
- 公开资料接口使用显式公开字段白名单。邮箱、学号、账号状态、认证信息及其他联系信息不得出现在公开响应中；本人读取所需字段继续由现有的已认证“我的资料”接口提供。
- 继续复用学院、年级、专业的既有可见性开关。公开响应只能返回开关允许的字段，本人响应保留原始值以支持资料编辑。
- “活跃方向”和“最近参与”不再作为公开资料的默认响应和 UI 内容。它们不以新增公开开关的方式恢复；未来如需公开，必须单独定义明确的用户同意模型和数据范围。
- 帖子列表采用与服务端一致的分页契约。客户端请求页大小不得高于服务端上限；当服务端返回仍有下一页时，页面提供连续加载或明确分页入口，直至无更多内容。
- 资料统计与公开帖子列表采用同一可见性谓词：排除已删除、管理员隐藏及广告帖，避免数字和列表不一致。
- 用户 ID 仅接受完整的正整数；客户端不发送、服务端不解析带有额外字符的 ID。
- 个人空间全部可见文案纳入现有语言资源或当前页面的语言字典；图片加载失败使用面向用户的本地化回退文案，不显示技术字样。
- 保持现有“本人可查看点评与收藏”的鉴权边界，不将其开放给其他资料访客。
- 不引入新依赖、数据库表或通用隐私框架。本轮仅修复已暴露的公开资料边界与资料页稳定性。

## Testing Decisions

- 以公开资料接口为最高契约测试边界，验证未登录、他人登录和本人登录三种访问者获得的字段集合、校园身份可见性、统计数字及帖子分页结果。
- 在既有用户路由测试模式中新增公开字段白名单、非法 ID 拒绝、广告帖统计排除、分页上限和 `hasMore` 的断言。测试只断言 HTTP 可见行为，不断言 SQL 写法或组件内部状态。
- 为共享资料页增加渲染回归用例：初始加载、成功返回、失败返回、语言切换和从本人资料切换到他人资料均不得抛出 Hook 顺序错误，且应呈现对应状态。
- 对 App 与 Web 执行同一组资料页场景回归：公开资料、本人资料、超过单页上限的帖子、图片加载失败与中英文模式。
- 现有 `GET /api/users/:id/profile` 路由测试是后端断言的直接先例；现有加载、空状态和错误状态组件是页面状态回归的直接先例。

## Out of Scope

- 不重做个人空间的视觉信息架构、头像头图、卡片风格或底部 Tab。
- 不改变帖子、点评、收藏、社团或活动的业务权限模型。
- 不新增关注关系、用户搜索、私信、公开动态流或完整的隐私中心。
- 不修改已废弃的 `mobile/` React Native 前端。
- 不处理与资料页无关的通知系统治理工作。

## Further Notes

- 风险评估已确认公开生产资料响应包含邮箱字段，且服务端将请求的 50 条帖子限制为 30 条；两项都应作为上线前回归样例。
- 当前在审查环境没有可连接的本地浏览器实例。开发完成后需由验收者在 Web 与 Capacitor APK 进行实际资料页加载、返回、语言切换和长帖子列表验证。
