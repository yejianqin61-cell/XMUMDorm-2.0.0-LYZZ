## 一、背景与目标

### 1.1 背景

XMUM 学生之间的学习资料（课件、笔记、真题、往年试卷、参考书章节）目前散落在微信群、个人网盘、Google Drive 之间，存在三个问题：

1. **找不到** —— 没有统一下载入口，每届学生重复问「谁有 XX 课的资料」
2. **存不住** —— 个人网盘链接失效，资料随学长毕业一起消失
3. **占资源** —— 若走站内服务器存储，PDF 体积会迅速吃掉磁盘与带宽预算

### 1.2 目标

| # | 目标 | 衡量标准 |
|---|------|----------|
| G1 | 提供统一的学习资料浏览与下载入口 | 用户 3 次点击内拿到任意已收录资料 |
| G2 | 资料**读路径零服务器成本** | 文件字节全部由 GitHub/CDN 承担，本项目服务器不转发文件流；课程名/id 映射走轻量缓存 API（几 KB） |
| G3 | 资料库可被 Git 审计、可回滚、可协作 | 每次变更都是一次 commit/PR，有作者与时间 |
| G4 | 上传体验不需要用户拥有 GitHub 账号 | 站内登录用户直接上传，不感知 GitHub |
| G5 | 内容风险可控 | 有体积/类型/敏感词前置校验 + admin 下架能力 |

### 1.3 非目标（本期明确不做）

- ❌ 站内资料预览的**在线批注、划词、协同编辑**
- ❌ **移动端完整阅读体验**（RN 无原生 PDF/Markdown 渲染，一期仅提供「下载 / 浏览器打开」）
- ❌ 资料**全文搜索**（需索引服务，与「零服务器」目标冲突，见 P2）
- ❌ 资料**付费/积分下载**
- ❌ 把现有 `handbook`（一站通）文章迁入资料库
- ❌ 课程评价（`course_reviews`）本期**不**接入课程字典（保持现状）

## 二、核心设计原则（**约束性，不可协商**）

| # | 原则 | 理由 |
|---|------|------|
| **P1** | **资料库是 public 仓库** | 浏览器端要能直接读取内容；私有仓库必须带 token 请求，等于把 token 下发前端 |
| **P2** | **文件字节不经过本项目服务器** | 达成 G2；列表/正文/PDF/下载全部走 GitHub CDN；仅课程字典走轻量 API（见设计文档 §3） |
| **P3** | **写路径必须经过本项目服务器** | GitHub 写入凭据（PAT）绝不能进浏览器。违反则触犯 [`安全策略.md`](../../00-Constitution/policies/安全策略.md) 禁止事项第 3 条 |
| **P4** | **资料库内不存任何用户身份信息** | 资料库可能因版权被 DMCA 或封禁；不把用户数据放到会丢的地方。上传者信息只存本站自己的库 |
| **P5** | **PDF 必须由发送正确 `Content-Type` 的 CDN 分发** | `raw.githubusercontent.com` 对 PDF 返回 `application/octet-stream` + `nosniff`，iframe 无法预览（已实测） |
| **P6** | **无服务器状态** | 后端不缓存资料文件本体，不做对象存储写入；只做「代理 GitHub API」这一件无状态的事 |

## 四、功能需求

### 4.1 P0 —— 必须实现

#### FR-00 课程字典（前置基础设施）

- **实体**：新表 `courses`，身份 = **课程名 + 讲师**（联合唯一）；`course_code`（如 BSC103）**可选、不再唯一**；讲师未知用空串哨兵
- **维护**：从 `timetable_courses` 聚合种子 + 上传时自注册 + admin 合并（`course_aliases` 表）
- **查询**：`GET /api/materials/courses`（轻量缓存）+ `POST /api/materials/courses/resolve`（上传自动补全）
- **明确不做**：课程评价（`course_reviews`）本期**不**接入此字典

#### FR-01 资料浏览（课程为中心）

- **入口**：`/materials`（学习资料首页）
- **行为**：
  - 首页以**课程列表**为主轴：搜索课程（名字+讲师）→ 进入课程页
  - 课程页 `/materials/course/:id`：该课程下四 tab（笔记/课件/试题/答案）+ 考试节点/课时二次筛选
  - 文件清单来自 GitHub CDN `index.json`，课程名/id 映射来自轻量 `/api/materials/courses`
  - 支持关键词搜索（**仅匹配标题/描述/课程名/标签，不搜正文**）
  - 展示每项：标题、课程（名+讲师）、类型图标、考试节点/课时、体积、更新时间、下载次数
    > **2026-09-29 修订**：**不展示上传者昵称**（用户裁定）。资料库 `index.json` 位于公开仓库，
    > 上传者是用户数据，一律不写入；追责只在管理端读本站 DB。
- **空态/错误态**：GitHub 不可达时展示缓存快照 + 明确提示，不得白屏

#### FR-02 Markdown 在线渲染

- **支持**：`.md` / `.markdown`
- **实现**：浏览器 fetch 原文 → `ReactMarkdown` + `remark-gfm`（项目已有依赖）
- **要求**：
  - **禁止**渲染原始 HTML（`rehype-raw` 不得引入）——防 XSS，见设计文档 §7.1
  - 相对路径图片（如 `![](./img/diagram.png)`）必须能正确解析到同仓库 CDN 地址
  - 代码块样式与站内液态玻璃设计体系一致
  - 目录（TOC）按标题自动生成
- **移动端**：一期不实现渲染，仅提供「下载原文」按钮

#### FR-03 PDF 在线预览

- **支持**：`.pdf`
- **实现**：`<iframe>` 指向 jsDelivr CDN 地址，`Content-Type: application/pdf`（已实测可内联预览）
- **要求**：
  - **`raw.githubusercontent.com` 禁止用于 PDF 预览**（实测返回 `application/octet-stream`，iframe 会直接下载）
  - jsDelivr 单文件上限**已实测 = 恰好 20 MiB（20,971,520 B，含）**；21 MiB 返回 403 `File size exceeded the configured limit of 20 MB.`。**本站 20 MiB 上限与其零余量压线**（实测 20 MiB 仍返回 200，可用），超限时走降级链
  - **降级链**：jsDelivr → `mozilla.github.io/pdf.js` viewer → 仅提供下载按钮
  - 移动端：Safari/Chrome 内联 PDF 行为不一致，默认展示「打开 / 下载」而非 iframe

#### FR-04 资料下载

- **行为**：点击下载按钮触发浏览器保存
- **要求**：
  - 采用 CDN 地址 + 强制下载语义（`<a download>` / `?download=` 之类的 CDN 能力），**不得**让浏览器直接跳转裸 PDF（用户会丢失页面）
  - 下载文件名必须使用**原始文件名**，不得是哈希名
  - 下载计数：**按 `path` 计数**（`POST /api/materials/download`，而非按 DB id —— 管理员手工加入仓库的文件没有 DB 行），后端异步 `+1`，失败不阻塞下载（下载不经过后端）
  - **服务器不转发文件流**（FR-04 的关键验收点：实测下载时本项目后端无相关请求）

#### FR-05 资料上传

- **入口**：`/materials/upload`（需登录）
- **接口**：`POST /api/materials/upload`，`multipart/form-data`，**文件字段名为 `file`**（单文件）
- **表单字段（三层 details）**：

  | 层 | 字段 | 必填 | 取值/校验 |
  |----|------|------|-----------|
  | 文件 | 文件 | ✅ | 见下方白名单 |
  | L1 类型 | `type` | ✅ | 笔记 / 课件 / 试题 / 答案 / 其他（五选一） |
  | L2 课程 | `course` | ✅ | 名字+讲师 → 自动补全解析到 `courseId`；查不到则自注册；「通用/其他」伪课程承接非课程资料 |
  | L3a 课时 | `lesson` + `lessonTitle` | 选填 | 整数 + 可选短标题（≤ 64 字） |
  | L3b 考试节点 | `examNode` | 选填 | 期中 / 期末 / 平时测验 / 作业 / 月考；空 = 整门课 |
  | 附加 | `source` | 选填 | 官方 / 回忆版（**仅类型=试题时出现**） |
  | 标题 | `title` | ✅ | 2–100 字 |
  | 标签 | `tags` | 选填 | 最多 5 个，每个 ≤ 16 字 |
  | 简介 | `description` | 选填 | ≤ 300 字 |
  | 学期 | `semester` | 选填 | 如 `2025/09`（仅展示，不参与课程身份） |
  | 声明勾选 | — | ✅ | 「我确认该资料不侵犯他人版权，且不含个人隐私信息」 |

- **类型白名单**：`.md` `.markdown` `.pdf` `.txt` `.docx` `.pptx` `.xlsx` `.zip` `.png` `.jpg` `.jpeg` `.webp`
  > 例外：`.zip` 要求简介中说明内容构成
- **体积上限**：**单文件 ≤ 20MB**（已定；与 jsDelivr 上限持平，上线前须实测 20MB 边界，见设计文档 §3.4 T1）。超限时前端提前拦截并提示「请压缩后重试或联系管理员走 R2 通道」
- **提交后行为**：
  1. 前端展示「提交中 → 已提交，正在校验 → 已上线」的**真实状态机**（状态来自后端返回，不得假装成功）
  2. GitHub 侧 PR 校验未通过时，必须有明确失败原因（如「体积超限」「文件类型不在白名单」）
  3. 成功后在站内通知中心给上传者一条通知

#### FR-06 上传审计与记录

- **后端必须落库**（本站 MySQL，非 GitHub）：

  | 字段 | 说明 |
  |------|------|
  | `id` | 主键 |
  | `user_id` | 上传者 |
  | `course_id` | 课程字典外键（聚合单位） |
  | `type` / `lesson` / `lesson_title` / `exam_node` / `source` | 三层 details |
  | `material_path` | 资料库内相对路径 `c<id>/<type>/<file>` |
  | `title` | 标题 |
  | `file_sha256` | 内容哈希（软去重用） |
  | `file_size` | 字节 |
  | `pr_number` / `pr_url` | 对应 PR |
  | `commit_sha` | merge 后的 commit |
  | `status` | `pending` / `merged` / `rejected` / `removed` |
  | `reject_reason` | 失败原因 |
  | `created_at` / `updated_at` / `deleted_at` | 时间戳（遵守逻辑删除约定） |

- **理由（P4 的落地）**：资料库本身不存用户信息；「谁上传了什么」只能在本站可查，用于追责与下架

#### FR-07 内容安全前置校验

上传时**必须**按顺序执行，任一失败即拒绝：

1. **扩展名白名单**（服务端强制，不信任前端）
2. **体积上限**
3. **敏感词检查**：**只查元数据 —— 标题、简介、课时标题、标签**。
   命中时响应必须带上**命中的词与所在字段**（只说「包含违规词汇」用户无从下手）。
   > **2026-09-29 修订（原为「读 .md/.txt 正文 + 解压 .docx/.pptx 文本层」）**：
   > 实施后发现把本站词表（含 `fk` / `sb` 这类两字母缩写）套到最长 1MB 的课件正文上，
   > 误伤率极高 —— 实测 7 个正常场景 5 个被拒（`FK` 外键、`SB` 南桥、`USB`、`ISBN`、base64 串）。
   > 现改为**正文完全不扫**；内容风险由「每次上传都开 GitHub PR（diff 人工可见）」
   > + 「admin 下架」两条兜底。详见设计文档 §17.11。
4. **MIME 嗅探**：用文件魔数校验真实类型，**防止把 `.exe` 改名成 `.pdf`**
5. **软去重**：同 `file_sha256` 且同 (课程,类型,路径) → 拒绝并给出已有资料链接；同 sha 不同课 → 允许但前端提示「库中已有相同文件，仍要上传？」
6. **限流**：**默认不限流**（2026-09-29 修订，原为 5 次/小时）——
   有用户需要大批量上传。机制保留：设 `MATERIALS_UPLOAD_PER_HOUR` 为正整数即恢复上限。
   > 仍未解除的是全站按 IP 的 `express-rate-limit`（`/api`，生产 2500 次/15 分钟）；
   > 校园网共用出口 IP 下大批量上传可能触到那一层。

> 复用现有 [`middleware/sensitiveWordFilter.js`](../../../middleware/sensitiveWordFilter.js) 的敏感词表与缓存机制。
> 该中间件同时被树洞/广场等短贴场景使用，因此其 ASCII 词匹配已统一改为**词边界**（`\bsb\b`），
> 避免 `sb` 命中 `USB`/`ISBN`；中文词仍走子串（中文没有词边界概念）。

#### FR-08 管理员下架

- **入口**：`/admin/materials`
- **能力**：
  - 查看全部上传记录（含状态、PR 链接、**上传者**）
    > 上传者只在**管理端**可见，且数据来自本站 `materials.user_id`（不是公开的 `index.json`）。
  - 下架：GitHub 侧删除文件 + 更新 `index.json` + 站内标记 `removed`
  - **必须提示管理员**：「文件可能已被 jsDelivr/CDN 缓存，删除后仍可能短期内可访问」，并要求记录下架理由（进 `auditLog`）
- **应急**：提供一键「暂停受理新上传」开关（环境变量，无需部署）

## 五、非功能需求

| # | 类别 | 要求 |
|---|------|------|
| NFR-01 | **服务器带宽** | 浏览/预览/下载任意资料时，本项目后端请求数 = **0**（验收时用后端访问日志核对） |
| NFR-02 | **响应速度** | 列表页首屏 ≤ 1.5s（CDN 命中）；Markdown 正文 ≤ 2s |
| NFR-03 | **可用性** | GitHub/CDN 不可达时列表降级为缓存快照，不白屏 |
| NFR-04 | **安全** | PAT 仅存在服务端 `.env`；资料库内**无任何用户数据（含上传者昵称）**；前端不渲染 raw HTML |
| NFR-09 | **不暴露源仓库** | **任何界面、接口响应、脚本输出与公开文件都不得提供资料库地址，也不得跳转过去。** `.env.example` 只允许空值/占位符；资料库侧文件不得反向链接本站。守卫见 `__tests__/frontend/materialsRepoAddressGuard.test.js`。<br>⚠️ 已接受的残留：① `docs/**` 需记录真实拓扑；② 浏览器 DevTools 仍能从 CDN 地址看到 owner/repo（不反代就藏不住，方案 C 的既定代价）。 |
| NFR-05 | **可观测** | 每次上传写 `auditLog`；GitHub API 失败必须打日志（**不打印 token**） |
| NFR-06 | **可测试** | 新增路由必须有 `__tests__/` 用例，GitHub API 调用必须可 mock（遵守[测试铁律](../../00-Constitution/policies/测试铁律.md)） |
| NFR-07 | **可回滚** | 任意一次上传对应一个独立 commit，可 `git revert` 精确回滚 |
| NFR-08 | **仓库健康** | 资料库总体积 < 1GB（GitHub 官方建议，强烈建议 <5GB）；admin 看板需展示当前体积 |

## 六、验收标准（Definition of Done）

- [ ] 游客可浏览列表、预览 MD、预览 PDF、下载，全程后端零文件流量
- [ ] 登录学生可上传 ≤20MB 的白名单文件，并在 30s 内看到「已上线」
- [ ] 超限文件、非白名单文件、**元数据命中敏感词**、重复文件分别被正确拒绝并给出可读原因（敏感词拒绝须指明词与字段）
- [ ] 上传记录可在 `/admin/materials` 查询，含 PR 链接与上传者（上传者仅管理端可见，来自本站 DB）
- [ ] 任意界面 / 接口 / 公开文件都不提供资料库地址（NFR-09，守卫测试通过）
- [ ] admin 可下架，且下架操作进审计日志
- [ ] `PAT` 不出现在任何前端产物中（构建产物全文检索 `ghp_`/`github_pat_` 为空）
- [ ] 新增后端路由有单测，GitHub API 被 mock，`npm test` 全绿
- [ ] `init-db.sql` 与新增迁移保持最终状态一致
- [ ] 移动端资料页可打开、可下载（不要求渲染）
