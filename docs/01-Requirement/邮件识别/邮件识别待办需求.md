# 邮件识别待办（「自动读邮件」第一期）：需求

**版本**：V1.0（Web，第一期，待团队确认）　**日期**：2026-11-16　**提出人**：wx　**任务表**：任务管理表 #7「web:自动读邮件」

## 一、要解决的问题

学校的作业、讲座、缴费、报名通知都发在学校邮箱，英文、篇幅长、截止日期藏在正文里，容易漏。Dorm 已经有待办和学习日历，缺少一条「邮件 → 待办」的路。

## 二、为什么分两期

「自动读邮件」最完整的做法，是让 Dorm 连上学生的学校邮箱（Microsoft 365 / Outlook），定时读取新邮件。这需要：
- 在学校的 Microsoft 租户里注册应用、拿到 `Mail.Read` 权限（很可能要学校 IT 管理员同意）；
- 服务端保存每个用户的授权令牌（敏感数据，要加密和撤销机制）；
- 隐私说明和用户授权流程。

这些都要团队和学校先拍板，所以**第一期先做不需要任何邮箱授权的部分**：用户自己粘贴邮件，AI 识别，确认后加入待办。第二期（自动同步）放到第六节作为待定事项。

## 三、第一期范围

- 待办页（`/myzone/todos`）新增入口「从邮件识别待办」：
  1. 粘贴邮件正文（≤8000 字）
  2. AI 返回一句话摘要和最多 8 条待办（标题、截止日期、时间、优先级、分类、备注）
  3. 用户逐条勾选、修改标题和日期
  4. 点「加入待办」，走现有的 `POST /api/todos` 创建
- 截止日期按马来西亚日期（UTC+8）理解「本周五」这类说法；邮件里没写日期就留空，并提示「邮件里没写日期」。
- 服务端没配置 AI 服务时，入口不显示，待办页其它功能不受影响。

## 四、约束

- **邮件原文不落库、不写日志**；识别接口只返回结果，不写任何数据。
- 需要登录；每人每分钟最多识别 6 次。
- AI 服务可替换：任意 OpenAI 兼容接口。`MAIL_AI_*` 三项配齐才开启，没配时回退到翻译功能的 `TRANSLATE_API_*`。
- 模型输出逐字段校验：非法日期置空，没有日期就不带时间，优先级限制在 0–3，分类限定在白名单内，最多 8 条。

## 五、验收

| # | 标准 |
| --- | --- |
| 1 | 粘贴一封带截止日期的课程邮件，能识别出待办和正确的日期、时间 |
| 2 | 只有勾选的条目会被加入待办；加入后待办列表刷新 |
| 3 | 邮件里没写日期的条目，日期留空并有提示 |
| 4 | 未配置 AI 服务时看不到入口；未登录调用接口返回 401 |
| 5 | 服务端日志里没有邮件原文 |

## 六、第二期（自动读 Outlook）实测结论

2026-11-16 用 wx 的学校账号实测：
- 学校邮箱确实在 Microsoft 365 上（`xmu.edu.my` 的 MX 指向 `*.mail.eo.outlook.com`，租户 ID `9e6a47d3-2795-4b97-9e52-78b1060629f1`）。
- 学生**可以**在学校租户里注册应用。测试应用叫 `XMUM Dorm Mail Test`，没有密钥，只有一个本地开发回调地址。
- 申请**读邮件**（Graph `Mail.Read`）时，页面提示「**需要管理员批准**」：学校不允许学生自己授权。所以要自动读 Outlook，必须由学校 IT 管理员给这个应用做一次「管理员同意」。
- 只申请**登录 + 读基本资料**（`openid profile User.Read`）时，出现正常的同意页：学生自己就能授权。也就是说，「用学校账号登录 Dorm」不需要找学校就能做。
- Teams 消息权限比邮件更严，同样需要管理员同意，不建议。

待定：
1. 要不要去找学校 IT 申请 `Mail.Read` 的管理员同意（需要说明用途、数据怎么存、隐私说明）。
2. 拿不到授权的话，就继续用第一期的「粘贴邮件」方案。
3. 「用学校账号登录」可以单独立项，能替代现在的邮箱验证码注册。
