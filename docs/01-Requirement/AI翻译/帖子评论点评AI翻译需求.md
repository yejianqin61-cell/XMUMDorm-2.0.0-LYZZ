# 帖子 / 评论 / 点评 AI 翻译 — 需求

**版本**：V1.1（Web + App）　**日期**：2026-11-16　**提出人**：wx　**任务表**：任务管理表 #16「web:类推特自动帖子点评评论翻译」、#17「app:类推特自动帖子点评评论翻译」

## 一、要解决的问题

站内帖子、评论和食堂点评越来越多由非中文同学发布（英文、马来文），中文同学看不懂；反过来，英文界面的用户也看不懂中文内容。参考小红书 / B 站 / 推特：内容语言和读者界面语言不一致时，给一个「翻译」按钮，用 AI 译成读者的语言。

## 二、范围

**本期**：
- Web：帖子详情页的帖子正文、一级评论、二级回复（`posts`、`comments`）；食堂菜品详情页的点评与点评回复（`product_comments`）
- App：树洞帖子详情的正文与评论（`posts`、`comments`）；菜品详情的点评与回复（`product_comments`）
- 目标语言 = 读者当前界面语言（站点只有中文 / 英文两种界面）

**不在本期**：
- 广场校园资讯、热门帖、Web 树洞列表、万能墙（匿名，来源表不同）、社团等其它内容来源（要接只需在后端白名单加一条查询 + 前端挂组件）
- 自动整页翻译、翻译结果入库持久化

## 三、交互规则

1. 只有「内容语言 ≠ 界面语言」才出现按钮（判定见 `shared/utils/translation.js`）：中文界面下拉丁字母为主的内容（英文、马来文）显示；英文界面下汉字为主或中英夹杂的内容显示；少于 4 个有效字符的不显示。
2. 按钮默认不请求，**点了才翻译**（控制成本）；译文显示在原文下方，标注「由 AI 翻译」，再点收起。
3. 需要登录；服务端没配置翻译服务时，按钮整体不出现。

## 四、后端约束

- 接口只接受「内容类型 + ID + 目标语言」，后端自己从库里取原文；**不接受任意文本**，避免被当免费翻译代理。已删除 / 被管理员隐藏的内容取不到，也就翻不了。
- 每用户每分钟最多 30 次；原文超过 4000 字拒绝。
- 翻译服务商可换：任意 OpenAI 兼容 `chat/completions` 接口（智谱 GLM-4-Flash、火山方舟豆包、DeepSeek 等），只改环境变量。
- 服务商的报错不透给前端；密钥只在服务端，不能加 `VITE_` 前缀。

## 五、验收

| # | 标准 |
| --- | --- |
| 1 | 中文界面看英文帖 / 评论 / 点评出现「翻译」，点后显示中文译文；中文内容不出现按钮 |
| 2 | 英文界面看中文内容出现「Translate」，点后显示英文译文 |
| 3 | 未登录或未配置服务时不出现按钮，页面其它功能不受影响 |
| 4 | 同一条内容重复点击不重复请求（前端缓存 + 服务端缓存） |
| 5 | 已删除 / 隐藏内容返回 404；参数非法返回 400；未配置返回 503 |
