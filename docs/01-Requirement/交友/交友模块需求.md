# 交友模块：需求

**版本**：V1.0（Web，初版，待团队确认）　**日期**：2026-11-16　**提出人**：wx　**任务表**：任务管理表 #9「web:date交友模块」

## 一、要解决的问题

同学想找学习搭子、运动搭子，或者认识新朋友，现在只能在树洞里发帖。这样有两个问题：
- 联系方式一旦公开就收不回来；
- 发帖找人没有"双方都愿意"这一步。

任务表只有标题。这一版的方向是**校内、安全优先的「名片 + 互相打招呼」**，不做聊天、不做推荐算法。

## 二、范围

**本期（Web + 后端）**：新页面 `/about/date`，左侧导航「交友」，分三个 Tab：
1. **我的名片**：填写想找什么（交朋友、学习搭子、活动搭子、恋爱）、自我介绍（≤300 字）、兴趣标签（≤6 个）、联系方式（≤100 字），选择是否展示。可以删除名片。
2. **发现**：浏览别人的名片，可以按「想找」筛选；可以「打招呼」或「拉黑」。
3. **互相打招呼**：双方都打过招呼的人，显示对方的联系方式，可以一键复制。

**不在本期**：站内聊天、照片、推荐或匹配算法、App 端、管理后台的名片审核页（目前靠敏感词过滤 + 拉黑 + 现有举报入口）。

## 三、安全规则

| 规则 | 原因 |
| --- | --- |
| 自己挂出名片（展示中）才能浏览别人，也才会被看到 | 互相可见，防止只看不露的人 |
| 列表接口永不返回联系方式；双方互相打招呼后才可见 | 联系方式只给双方都愿意的人 |
| 单方面打招呼不通知对方 | 避免被骚扰；对方也打招呼时，双方各收到一条通知 |
| 拉黑后双向互不可见，并清掉双方之间的招呼 | 拉黑要立刻生效 |
| 只限学生账号、状态正常；封禁、注销的不出现 | 校内 |
| 写名片要过敏感词检查（自我介绍、标签）、需同意现行条款、被禁言者不能写 | 沿用全站规则 |
| 打招呼每人每小时最多 60 次 | 防刷 |
| 删除名片会连同我发出的招呼一起删 | 不留残余数据 |

## 四、数据

迁移 `082_date_profiles.sql` 新建三张表，不改已有表：`date_profiles`（名片）、`date_likes`（打招呼）、`date_blocks`（拉黑）。通知类型新增 `date_match`，归入「互动」。

## 五、验收

| # | 标准 |
| --- | --- |
| 1 | 没有名片时，「发现」提示先写名片 |
| 2 | 保存名片后能看到别人的名片，列表里没有任何联系方式 |
| 3 | 单方面打招呼：对方不收到通知；双方都打招呼：双方在「互相打招呼」里看到联系方式，信箱各收到一条通知 |
| 4 | 拉黑后对方从「发现」消失，对方也看不到我 |
| 5 | 关闭展示后，别人看不到我，我也看不到别人 |
| 6 | 自我介绍或标签含敏感词时不能保存 |

## 六、需要团队定

- 模块名称、要不要保留「恋爱」这个选项。
- 要不要加名片审核或举报入口（现有举报接口还不支持这种目标类型）。
- 是否限制年级或性别等筛选（本期不收集性别，避免敏感信息）。
