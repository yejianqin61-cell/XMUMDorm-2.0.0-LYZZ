# 食堂 App 首页 Instagram 风格改进规格

**Status:** ready-for-agent

**依据：** `docs/04-Module/M03-食堂/Instagram风格食堂首页UI调研.md`

## Problem Statement

学生打开食堂首页后，需要在同一页完成三个连续动作：找到食堂分区、比较值得吃的单品或店铺、浏览同学的真实食评。当前这三段均被圆角白底、阴影和胶囊式控件包裹，分区看起来像五个独立功能模块，排行榜不像可快速比较的榜单，吃货广场的图片又被压缩为缩略图。页面因此有明显的模块堆叠感，且出现了不需要向用户解释功能的提示文案。

## Solution

将 Capacitor App 的 `/eat` 首页中「食堂分区、排行榜、吃货广场」重构为连续、媒体与地点优先的信息流。视觉借鉴 Instagram 的内容层级，不复用其品牌资产、渐变或推荐算法：

- 食堂分区成为地点头像和名称构成的轻量入口；
- 排行榜成为文字 Tab 与紧凑排行行；
- 吃货广场成为以作者、正文、媒体、真实互动数据为顺序的连续内容流；
- 所有既有查询、路由、登录拦截、i18n、错误态与分页能力均保持不变。

## User Stories

1. 作为学生，我想一眼看到可进入的食堂分区，以便快速决定去哪里找吃的。
2. 作为学生，我想通过分区图片和名称识别地点，而不是在多个功能卡中猜测入口。
3. 作为学生，我想从食堂首页进入地图，以便在不熟悉地点时确认位置。
4. 作为学生，我想在单品、店铺和新上榜三个排行之间快速切换，以便按当前目的比较结果。
5. 作为学生，我想在榜单中看到清晰的名次、图片、名称和真实来源信息，以便快速判断是否值得点开。
6. 作为学生，我想只看到真实评分或热度数据，以便不被虚构的“爆款”或营销标签误导。
7. 作为学生，我想从单品排行直接进入菜品详情，从店铺排行直接进入商家详情，以便继续了解信息。
8. 作为学生，我想在吃货广场连续浏览同学的食评，而不是逐张阅读带阴影的摘要卡。
9. 作为学生，我想在有图片的食评中先感受图片内容，以便更快获得对菜品的直觉判断。
10. 作为学生，我想在无图片的食评中仍能紧凑阅读正文，以便文字分享不会被无意义的占位图干扰。
11. 作为未登录用户，我想点击发布时被带到登录页并在登录后继续发布食堂话题，以便不丢失既有访问路径。
12. 作为已登录用户，我想从吃货广场直接发布分享，以便参与校园食堂讨论。
13. 作为学生，我想从食评流进入帖子详情并看到真实点赞、评论和发布时间，以便决定是否进一步互动。
14. 作为使用中文或英文的学生，我想看到完整本地化的标签、空状态与错误提示，以便不因语言切换失去操作能力。
15. 作为窄屏手机用户，我想在不横向滚动页面的情况下使用三类排行和食堂入口，以便稳定完成浏览和跳转。
16. 作为使用辅助技术的用户，我想让分区、Tab、发布和加载更多操作拥有可理解的名称、焦点状态和足够的触控区域，以便独立使用页面。

## Implementation Decisions

- 本轮只调整 `/eat` 首页的三个区段及其必要的可访问性语义；搜索、运营轮播、随机选餐和地图入口不属于本次重构目标。
- 食堂分区继续使用现有分区查询、分区代码、图片资源与详情路由。每个入口仅展示圆形地点图片和单行名称，不使用白底卡、外层圆角、阴影或悬浮缩放动画。分区增多时，采用受容器宽度约束的横向入口列，不压缩文字，也不变回多层卡片。
- 排行榜继续使用现有的单品、店铺、新上榜三组查询、排序规则、前五条预览和“查看全部”入口。类别切换为等宽文字 Tab：未选中项无底板，选中项用正文色和底部强调线表达状态。Tab 保留按钮语义、选中状态、键盘焦点与关联内容区。
- 排行条目维持“名次、缩略图、名称、来源与真实评分”的信息密度。商品与商家继续跳转各自详情；新上榜没有评分时只展示可靠的店铺或分区信息，不以 `0.0` 补齐。名次不使用奖牌、火焰、渐变或营销性装饰。
- 吃货广场继续使用当前食堂话题查询、发布入口、登录拦截、帖子详情跳转、分页及中英文文案。移除面向用户的模块说明提示；标题右侧“发布”使用普通文字动作或等价写作图标，而不是药丸按钮。
- 每条食评按“作者与时间、正文、可选媒体、互动信息”顺序展示。内容之间只用细分隔线区分；有封面图时以接近内容全宽的媒体显示，媒体圆角最多 6px；无图内容保持紧凑文本行，不创建灰色占位卡。
- 点赞、评论、评分、时间及地点等只展示接口已有且可信的数据。若未来帖子提供可靠分区字段，可将其作为可点击地点标签；当前无数据时不展示虚构地点。
- 统一视觉基线为白色内容底、细分隔线、近黑正文、低对比元信息和单一既有品牌强调色。默认无阴影、无渐变、无玻璃效果；地点头像允许 50% 圆形，媒体仅允许轻微圆角。
- 所有主要操作的可点按面积至少为 44px；图片应提供恰当的替代文本，纯装饰图片使用空替代文本；不得以移除可见说明为由移除无障碍名称或错误反馈。
- 不新增后端接口、数据表、权限模型或个性化推荐逻辑，也不改变现有排行榜算法和食堂话题的内容治理规则。

## Testing Decisions

- 最高测试边界是既有 `/eat` 页面与其公开交互：测试外部可见的入口、切换、跳转、登录拦截、加载与错误状态，不测试内部 CSS 类名或实现细节。
- 验证分区查询成功、加载中、失败和空数据时，入口区域不会留下误导性的空白或失效点击区；每个可见分区仍能进入对应商家列表。
- 验证三个排行榜类别均可切换，选中状态可被辅助技术识别，且单品/店铺预览继续进入正确详情，“查看全部”仍可达。
- 验证食评流在有图、无图、无数据、加载失败和继续分页时均保持正确阅读顺序；未登录发布进入登录流程，已登录发布保留食堂话题上下文，帖子仍可进入详情。
- 在 375px、390px 与 430px 宽度进行视觉验收：地点名称不重叠，排行榜 Tab 不导致页面横向溢出，正文与互动信息不被截断，触控目标不小于 44px。
- 生产构建必须通过；在 Android Capacitor WebView 实机或等价环境中复验图片加载、滚动、Tab 焦点与登录跳转。

## Out of Scope

- 不修改废弃的 React Native `mobile` 前端、Web 端或其他食堂子页面。
- 不重做搜索栏、运营轮播、随机选餐、地图页、商家后台、菜品详情、点评发布页或排行榜详情页。
- 不增加收藏、下单、配送、距离、个性化推荐、热度计算、内容审核或新的帖子互动能力。
- 不引入 Instagram 的 Logo、品牌渐变、专有图标资产，亦不宣称页面使用 Instagram 的算法或设计系统。

## Further Notes

- 本规格的“Instagram 风格”仅指地点入口、紧凑分类导航与媒体优先内容流的层级原则；具体间距、字号与圆角为本项目实现建议，不是 Instagram 官方规范。
- 本仓库未配置可写入的外部问题追踪器；本规格以项目 `docs/01-Requirement` 的文档规范发布，并使用 `ready-for-agent` 状态供后续任务拆解与开发使用。
