# DormMap 校园 2D 与 3D 导览策划案

> 状态：已确认，待任务拆解  
> 适用端：Web；Capacitor App 不支持  
> 决策日期：2026-09-09

## Problem Statement

学生目前只能从文字、食堂分区或活动描述中理解校园地点，缺少一个可直观看到校园空间、重要地点和受运营控制活动的统一入口。现有食堂地图是静态背景图与局部贴纸配置，不具备统一地点模型、可持续维护的交互、2D/3D 切换或地点内容治理能力。

DormMap 将提供一个以厦门大学马来西亚分校核心学生动线为范围的 Web 校园导览。它不是开放地理地图、室内导航、数字孪生或用户自由标点社区；它的空间事实由官方地点库和管理员运营数据维护。

## Solution

在 Web 左侧全局导航新增 **DormMap**，路由为 `/dorm-map`。页面基于学校可授权使用的校园平面图呈现 2D 导览，并以同一份地点数据切换到自建低多边形 3D 校园视图。

- 默认进入 2D；用户显式切换到 3D 后才可旋转和倾斜视角。
- 2D 和 3D 共享同一地点 ID、活动锚点与地点详情抽屉，不维护两套标注数据。
- 首批由管理员维护约 15–25 个官方地点，覆盖入口、宿舍、教学楼、图书馆、食堂、学生服务、运动设施和景观等高频学生动线。
- 地点可配置一个或多个站内目标，优先支持食堂分区、商铺和站内页面；用户从地点详情直接跳转。
- 地图活动是独立于既有社团活动的管理员运营内容。仅管理员可发布、编辑、上下线并在 2D 地图上拖针锚定；普通用户仅查看。既有社团负责人发布活动能力不受影响，且首期不自动进入 DormMap。
- V2 再增加独立的地点评分点评；彩蛋不纳入当前范围。

## User Stories

1. 作为 Web 访客，我想从左侧导航进入 DormMap，以便快速了解校园空间和高频地点。
2. 作为 Web 访客，我想在不登录的情况下浏览校园地图和官方地点，以便在到校前完成基础导览。
3. 作为学生，我想在 2D 校园平面图上平移和缩放，以便从整体或局部寻找地点。
4. 作为学生，我想默认看到稳定、朝北的 2D 视图，以便不会因误旋转失去方向感。
5. 作为学生，我想明确切换至 3D 视图，以便以更直观的建筑关系理解校园布局。
6. 作为学生，我想在 3D 视图中缩放、平移、旋转和倾斜，以便从不同角度查看建筑外观级关系。
7. 作为学生，我想一键复位 3D 相机与朝向，以便在迷失视角后回到可理解的默认状态。
8. 作为学生，我想在 2D 和 3D 之间切换时看到同一批地点和活动标记，以便不需要重新学习两套地图。
9. 作为学生，我想点击地点标记打开详情抽屉，以便查看双语名称、分类、简介和可前往的站内入口。
10. 作为学生，我想从食堂地点直接进入对应食堂分区或商铺，以便从空间导览继续完成找饭任务。
11. 作为学生，我想看到管理员发布且当前有效的地图活动，以便发现近期校园安排。
12. 作为学生，我想点击地图活动标记查看活动详情和其站内行动入口，以便进一步了解或报名。
13. 作为学生，我不希望地图请求我的真实定位或跟踪我的浏览轨迹，以便安心浏览校园导览。
14. 作为登录用户，我想在 V2 为官方地点提交一条评分和文字点评，以便分享对校园地点的体验。
15. 作为登录用户，我想编辑或删除自己的地点点评，以便修正或撤回自己的内容。
16. 作为管理员，我想维护官方地点的双语名称、分类、说明、可见性、锚点和站内链接，以便地点事实准确、可控。
17. 作为管理员，我想在平面地图上拖针发布地图活动，以便活动位置准确而无需填写坐标。
18. 作为管理员，我想设置地图活动的起止时间、上下线状态和详情入口，以便过期内容自动从地图消失。
19. 作为管理员，我想删除违规地点点评并保留审计记录，以便维护内容质量。
20. 作为窄屏 Web 用户，我想至少使用 2D 导览和地点详情，以便地图在手机浏览器中仍有基础可用性。
21. 作为 Capacitor App 用户，我想看到明确的 Web-only 提示和返回入口，以便不会进入空白或失效页面。
22. 作为低性能设备用户，我想在 3D 不可用时自动使用 2D 导览，以便地图功能不会变成黑屏。

## Implementation Decisions

### 1. 端与页面边界

- DormMap 首期只在 `frontend` Web 工程实现；不向 `frontend-app` 增加地图入口、Three.js 依赖、地图资源或正式地图路由。
- Web 左侧一级导航新增 DormMap；`/dorm-map` 独立懒加载，避免将 3D 资源计入非地图页面首屏。
- Desktop/Wide 模式保留全局左侧导航，隐藏与当前地图任务无关的右侧辅助栏；地图使用左侧导航以外的主要可视空间。地点详情使用地图内可收起抽屉，而非额外的卡片列。
- 窄屏 Web 支持 2D 导览、地点详情和活动详情；3D 默认降级为 2D。Capacitor 若通过旧链接命中该地址，显示 Web-only 状态和返回广场入口。
- 浏览器 Fullscreen API 仅作为地图容器的可选增强；不可用、被拒绝或退出全屏均不影响正常浏览。

### 2. 渲染技术与降级

- 不以百度地图 JavaScript API GL、WebGLayer、Mapbox 或 Leaflet 作为首期主引擎；它们的经纬度底图坐标系与学校平面图/自建模型不匹配。
- 2D 使用 React + 原生 SVG。学校已确认可展示的校园平面图应优先以 SVG、原始 PDF 转 SVG 或高分辨率可裁切资产接入；地点和活动标记为 SVG 交互元素。
- 2D 的平移、滚轮/触控缩放和标记点击使用原生 Pointer Events 与 CSS/SVG 变换实现。地图外页面滚动不应被地图滚轮处理误拦截。
- 3D 仅新增 `three.js`。开发侧以简单几何体表达建筑外观、道路和绿地；不做室内、楼层、房间、室内导航、真实建筑模型采购或管理员建模器。
- 3D 场景配置受版本控制：建筑轮廓、基础高度、颜色和类型由开发侧根据校园平面图维护；管理员后台不编辑楼体几何。
- WebGL 初始化、资源加载或设备能力检查失败时，自动切回 2D 并给出非阻断提示。

### 3. 统一空间坐标与官方地点库

- 采用与图片/模型无关的归一化校园坐标：`x`、`y` 的范围为 0–1。2D 映射到 SVG viewBox，3D 由单一转换函数映射到世界坐标，确保同一地点不会在两视图漂移。
- 新增 `map_places` 作为唯一的官方地点锚点。字段包含稳定 ID/slug、中文名、英文名、分类、归一化 x/y、可选高度、双语简介、封面、排序、启用状态、创建与更新时间及操作者。
- 地点分类至少覆盖：教学、宿舍、食堂、服务、运动、景观、出入口、其他。
- 新增 `map_place_links`，以显式关联 `region`、`shop`、`internal_route` 等站内目标。禁止按地点名称模糊匹配现有食堂数据；外链不进入首期默认能力，如将来开放必须有独立白名单和安全策略。
- 现有食堂分区代码、商铺数据、社团活动自由文本地点都不能直接推导地图坐标。首次录入由管理员依据已确认的校园平面图人工校验。

### 4. 地图活动

- 地图活动是独立的管理员运营内容，不改变现有社团活动发布权限和现有活动路由。
- 仅管理员可以新建、编辑、上线、下线或删除地图活动；所有写接口必须经过现有 JWT 认证和后端 `requireAdmin` 强鉴权，前端隐藏入口不是权限边界。
- 地图活动至少包含：双语标题、双语简介、活动图片、2D 锚点 x/y、开始时间、结束时间、启用状态、可选站内详情/报名路由、创建与更新审计信息。
- 管理员在 2D 地图上拖针定位。发布前必须校验锚点在校园边界内且开始/结束时间合理；3D 坐标由统一映射生成，不单独录入。
- 公开列表只返回已启用且处于有效时间窗的活动；到期、下线或删除后不再显示。普通用户和社团负责人不可拖针或自行创建地图活动。

### 5. 地点评分点评（V2）

- V1/V1.1 地点详情只读。V2 新增独立 `place_reviews`，不得复用绑定 `product_id` 的菜品点评表。
- 一位登录用户对一个地点最多保留一条有效主点评；包含 1–5 星、文字、软删除字段与时间戳。图片、楼中楼回复不在首版地点点评范围。
- 用户仅能编辑/删除自己的点评；管理员可处理任意违规点评。敏感词过滤、举报、软删除和管理员审计沿用现有治理语义，并在后端强制执行。

### 6. 隐私、安全与资源

- DormMap 不请求浏览器地理位置权限，不采集、持久化或分析用户真实位置、地图平移、缩放、旋转或浏览轨迹。
- 不接入百度地图 API GL 或其 AK；未来若接入外部地图/到校导航，应单独立项，评估马来西亚可用性、服务条款、第三方数据处理、隐私政策与部署密钥边界。
- 校园平面图、地点封面和活动图片复用现有对象存储。校园图的展示授权、来源和不应公开的敏感地点清单必须在 V1 上线前由项目方确认。
- 所有管理员变更写入现有审计体系；数据库变更必须使用 migration，禁止手工修改生产库替代迁移。

### 7. 分期

| 阶段 | 交付内容 | 明确不做 |
| --- | --- | --- |
| V1 | Web DormMap 入口、2D SVG 导览、3D 简模、2D/3D 切换、地点库、地点详情、食堂站内跳转、全屏增强、2D 降级 | 公众点评、彩蛋、社团活动地图化、室内模型 |
| V1.1 | 管理员地图活动、2D 拖针、时间窗/上下线、活动详情与站内行动入口 | 用户/社团负责人拖针发布 |
| V2 | 地点评分点评、本人管理、管理员治理、举报/敏感词/软删除闭环 | 点评图片、楼中楼、地点排行榜 |
| 未规划 | 彩蛋 | 数据表、管理端、发现机制均不建设 |

## Testing Decisions

- 以地图对用户可见的外部行为为测试目标，不耦合 Three.js 内部对象或 React 实现细节。
- 对坐标转换、校园边界校验、地点链接白名单、活动有效时间窗和 2D/3D 同一地点映射建立纯函数测试。
- 对管理员 API 建立集成测试：未登录为 401、非管理员写入为 403、非法 x/y/时间窗为 400、管理员可完成地点与地图活动 CRUD、公开接口不会返回下线/过期内容。
- 对 V2 建立地点点评权限和治理测试：未登录不可写、同用户单地点唯一性、本人所有权、管理员处理、软删除与敏感词/举报接入。
- 对组件建立行为测试：SDK/3D 失败切回 2D、2D/3D 切换、重置视角、全屏失败不阻断、点击地点按显式 target 进入正确食堂/站内路径、Capacitor Web-only 状态可返回。
- 对 V1 进行人工 Web 回归：桌面 Chrome/Edge、窄屏 Web、禁用 WebGL、弱网/资源加载失败、鼠标/触控板操作、键盘焦点、全屏进入/退出和与页面滚动共存。
- 地图资产和首批 15–25 个官方地点必须在上线前逐点人工验收 2D/3D 锚定位置与站内跳转。

## Out of Scope

- Capacitor App 原生或 WebView 地图支持。
- 百度地图 JavaScript API GL、WebGLayer、真实经纬度底图、周边道路或校外导航。
- GPS 定位、附近地点、路线规划、用户位置追踪和地图行为分析。
- 室内/楼层/房间模型、室内导航、真实建筑扫描/高精模型与管理员 3D 建模编辑器。
- 用户自由新增地点、普通用户/社团负责人在地图发布活动、自由输入经纬度或拖针。
- 彩蛋功能及其数据模型。
- 地点评价的图片、楼中楼、排行榜和推荐算法。

## Further Notes

- 首期核心价值是“受控、可信、可理解的校园导览”，而不是地图功能数量。地点库质量和 2D/3D 坐标一致性优先于复杂特效。
- 项目方已确认：存在一份可用于展示的学校校园平面图；地点库由管理员维护；3D 仅建模建筑外观级简单几何；活动仅指独立的管理员地图活动；彩蛋暂缓。
- 实施前仍需补齐两个运营输入：可展示校园图的原始资产，以及首批官方地点清单及其人工验收坐标。
