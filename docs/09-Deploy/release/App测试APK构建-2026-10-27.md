## 2. 怎么再打一个

CI 里有手动工作流 `.github/workflows/app-apk.yml`：

```
gh workflow run app-apk.yml --ref main \
  -f api_base_url=https://xmumdorm-200-lyzz-production.up.railway.app \
  -f architectures=arm64-v8a,armeabi-v7a
gh run download <run-id> -n xmumdorm-test-apk -D dist-apk
```

产物是 `app-release.apk`（artifact 保留 14 天）。也可以只打一个 ABI 来省时间。

## 3. 为什么不在本地打（本机阻塞）

`assembleRelease` 在 Windows 上每次 6 分 44 秒必挂在：

```
ninja: error: manifest 'build.ninja' still dirty after 100 tries
```

失败任务是 `:expo-modules-core:buildCMakeRelWithDebInfo` 与 `:react-native-reanimated:buildCMakeRelWithDebInfo`。已排除的嫌疑：

| 试过的做法 | 结果 |
|---|---|
| 把项目放到短路径（junction `C:\rr`） | 同样失败 |
| 把 `node_modules`（9.2 GB）挪到短路径并做 junction | 同样失败 |
| 删除 `.cxx`、各原生模块 `android/build`、清理后重建 | 同样失败 |
| 只打 `arm64-v8a,armeabi-v7a` | 同样失败 |

路径长度因素已排除，判断为本机 CMake 3.22.1 / Ninja 1.10.2 组合的问题；Linux runner 上同一份代码构建正常。

**本机环境改动**：`app/node_modules` 现为 junction，指向 `C:\Users\USER\app\node_modules`（原 9.2 GB 目录移到了短路径）。单测已验证仍通过；若要还原，删掉 junction 并把该目录移回 `app/node_modules` 即可。

## 4. 已知限制

- Debug keystore 签名：任何拿到包的人都能装，⛔ 不能用于正式分发。
- 后端地址在构建时烘焙；换后端要重新触发一次工作流并传 `api_base_url`。
- 只含 `arm64-v8a` / `armeabi-v7a`；x86_64 模拟器装不上，需要时在 `architectures` 里加上。
