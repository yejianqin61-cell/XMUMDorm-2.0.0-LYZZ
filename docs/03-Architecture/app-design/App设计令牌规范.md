# App 设计令牌规范

**日期**：2026-10-01　**版本**：v1.0 草案 · **待批准**
**上游**：[App 设计宪法](../../00-Constitution/principles/App设计宪法.md) 第 1.4 条（全局组件化）／第 2 条（令牌是唯一来源）／第 16 条（图标体系）；[App 前端风格体系](App前端风格体系.md) §一／§二
**性质**：本文件是**令牌的规范**（有什么、什么角色、怎么验）。**机器产物**由 `tokens/design-tokens.css` + `node scripts/gen-tokens.js` 生成。
**所有者裁决依据**（2026-10-01）：「**亟待建立的有令牌（也就是 csstoken）**」「**品牌色先采用厦大蓝和美团黄**」「**全局组件化，一改全部改**」

> **数值来源标注**：`【实测官方资产】` ＝ 从官方品牌资产量得；`【算得】` ＝ 由实测锚点机械推导并逐条过了对比度门；`【提案】` ＝ 待真机/脚本复核，**不得当已验证规格使用**。

## 一、单一创作源 + 构建期生成（为什么不能只有一份 CSS）

| 产物 | 消费者 | 手写？ |
|---|---|---|
| `tokens/design-tokens.css` | Web 直接消费 | ✅ **唯一事实源** |
| `tokens/generated/native-tokens.ts` | App（RN） | ❌ 生成，含对比度元数据 |
| `tokens/generated/tokens.json` | 两把尺子 | ❌ 生成 |

**改一处、全局变**：改 `design-tokens.css` → `node scripts/gen-tokens.js` → App 与 Web 同时变。

> ⚠️ **React Native 运行期没有 CSS 自定义属性**（这是平台事实，不是选择）。所以"csstoken"在本项目的落地方式是：**CSS 是创作格式与 Web 的运行时格式；App 侧由构建期生成 TS**。
> ⛔ 禁止引入 `nativewind` / `restyle` / `unistyles` / `tamagui` 来"实现 CSS 变量"（宪法 9.11.2）——生成方案达到同一目的且不多一层构建期依赖。

## 二、命名与分层

```
Foundation   原始值，不含语义。业务代码不得直接消费。
  --color-brand-700        --color-accent-300        --color-xmu-…（不建）
Semantic     角色，按主题分套（dark / light）。业务代码只消费这一层。
  --color-bg-canvas  --color-text-primary  --color-action-primary  --color-border-subtle
Component    极少数。默认不建；出现时必须说明 Semantic 表达不了什么。
  --size-control-height-lg
```

**命名纪律**：语义名**两端一致**（iOS/Android 同一套名字）；**颜色取值共享**，**字阶取值分端生成**（宪法 2.5.4）。

## 三、颜色令牌（每个都必须带元数据）

元数据字段（宪法 2.3）：`usage`（surface|fill|text|icon|border）／`textSafe`／`contrastOn`／`contrastRatio`（**实测**）／`theme`。
⛔ **`textSafe` 不得按档位推断** —— 只能由该令牌对 `contrastOn` 的实测比值决定。

### 3.1 品牌主色 · 厦大蓝（色相 **H=261.2°**）

**锚点**：`#173874`【实测官方资产】`www.xmu.edu.cn/images/logo2.png`（占 11.2%，OKLCH L=0.353 / C=0.110）。色阶由该锚点所在色相按 OKLCH 逐档生成。

| 令牌 | 值 | 白字 on 它 | 它作文字 on 白 | 它 on 暗底 `#12141a` | 角色 |
|---|---|---|---|---|---|
| `--color-brand-50` | `#e9f1fd` | — | 1.14 ❌ | 16.19 | 品牌浅底（light 的 `bg.brandSoft`） |
| `--color-brand-100` | `#ccddfa` | — | 1.37 ❌ | 13.40 | 选中背景、装饰填充 |
| `--color-brand-200` | `#9fbff6` | — | 1.87 ❌ | 9.87 | 描边、图标（暗色） |
| `--color-brand-300` | `#7fa9f3` | 2.37 ❌ | 2.37 ❌ | **7.78 ✅** | **暗色主题的强调文字/图标** |
| `--color-brand-400` | `#5e90ea` | 3.16 ❌ | 3.16 ❌ | **5.83 ✅** | 暗色主题的次级强调 |
| `--color-brand-500` | `#3d6dc3` | **5.03 ✅** | **5.03 ✅** | 3.66 | 亮色主题的次级强调；CTA 填充（次选） |
| `--color-brand-600` | `#2452a6` | **7.41 ✅** | **7.41 ✅** | 2.48 | **CTA 填充（首选）** |
| **`--color-brand-700`** | **`#173874`** | **11.33 ✅** | **11.33 ✅** | 1.63 ❌ | **官方锚点**；亮色主题的主文字/主标题/顶栏 |

**由实测直接推出的两条硬约束**：
1. **`#173874` 在暗底只有 1.63:1 → 暗色主题必须用同色相的提亮档**（`brand-300` / `brand-400`），亮色主题才用 `#173874` 本体。两套主题各自完整成套（宪法 2.2）。
2. `brand-700` / `brand-600` / `brand-500` 的「它 on 暗底」全部 < 4.5 → **亮色主题的深蓝阶一律不得出现在暗色主题的文字位置**。

### 3.2 品牌辅色 · 美团黄（色相 **H=86.1°**）

**锚点**：`#ffc300`【实测官方资产】`www.meituan.com/favicon.ico`（占 60.2%，OKLCH L=0.848 / C=0.174）。

| 令牌 | 值 | 黑字 on 它 | 白字 on 它 | 它作文字 on 白 | 它 on 暗底 | 角色 |
|---|---|---|---|---|---|---|
| `--color-accent-100` | `#fdefd0` | 18.43 ✅ | 1.14 ❌ | 1.14 ❌ | 16.16 | 浅底、高亮行背景 |
| `--color-accent-200` | `#fad88d` | 15.27 ✅ | 1.38 ❌ | 1.38 ❌ | 13.39 | 描边、装饰 |
| **`--color-accent-300`** | **`#ffc300`** | **13.06 ✅** | 1.61 ❌ | 1.61 ❌ | **11.45 ✅** | **官方锚点**；**填充（必须配黑字）** 与 **暗色主题的强调** |
| `--color-accent-500` | `#b28c30` | 6.69 ✅ | 3.14 ❌ | 3.14 ❌ | 5.86 | 深色描边 |
| `--color-accent-700` | `#6a5319` | — | 7.33 ✅ | **7.33 ✅** | 2.51 | **亮色主题下唯一可作文字的黄色档** |

**由实测直接推出的硬约束**：
1. ⛔ **美团黄永远不能作亮色主题的文字**（作文字 on 白仅 1.61:1）。它只有两个合法角色：**填充（必须配黑字）** 与 **暗色主题下的强调**。
2. ✅ **暗色主题下美团黄特别好用**（on 暗底 11.45:1），因此暗色主题的强调色实际由 `accent-300` 与 `brand-300` 分担。
3. ✅ **`accent-300` + 黑字 + 2px 黑描边** 天然就是 Neo-Brutalism 的 CTA 配方（宪法 1.1 白名单第一类），是本项目最"划算"的品牌表达。

### 3.3 状态色（**警告色相已由 73.3° 移到 55°**）

| 状态 | 暗色主题用（on `#12141a`） | 亮色主题的文字档（on 白） | 色相 |
|---|---|---|---|
| 成功 | `#39c58d` — **8.37 ✅** | `#29845e` — **4.61 ✅** | 161.9° |
| 警告 | `#bb6a29` — **4.56 ✅** | `#af6226` — **4.57 ✅** | **55.0°**（原 73.3°） |
| 危险 | `#f36d6d` — **6.33 ✅** | `#c35253` — **4.51 ✅** | 22.3° |

**为什么移动警告色相**：美团黄 H=86.1° 与原警告 H=73.3° 只差 **12.7°**，违反宪法 2.3 的 25° 门。移到 **55°** 后：对美团黄 **31.1°** ✅、对危险 **32.7°** ✅、对厦大蓝 **153.8°** ✅、对成功 106.9° ✅。
→ **主色/辅色/三个状态色两两满足 25° 门，不需要任何例外。** 规则保持为硬规则。

**警告仍必须带图标**（所有者要求）：警告**不得**仅靠色块表达，必须同时出现图标与文案，因为 55° 琥珀与美团黄同处暖色区，在快速扫视下仍需第二重区分。

### 3.4 中性色与主题

**暗色表面阶梯【已定】**（暗色一等公民，宪法 2.2；**不用纯黑**）：

| 令牌 | 值 |
|---|---|
| `--color-bg-sunken` | `#0d0f13` |
| `--color-bg-canvas` | `#12141a` |
| `--color-bg-surface` | `#1b1e26` |
| `--color-bg-raised` | `#242833` |

**文字阶梯**：主/次/弱三档，**必须同时对 `canvas` 与 `surface` 都达 4.5:1**（宪法 2.3）。具体取值由 `scripts/gen-tokens.js` 生成并**逐条校验**，落在 `tokens/generated/tokens.json`；本文件不复述未校验的数字。

**亮色主题**：同样的语义名、另一套完整取值（`canvas #f7f8fa` / `surface #ffffff` 起步）。**暗色先定、亮色派生，但两者都必须是完整套装。**

**禁止**：纯黑大底、渐变（宪法 1.3.5）、用模糊表达层级（1.3.1）、运行期动态取色进入令牌层（9.12）。

## 四、非颜色令牌

| 组 | 规则 | 状态 |
|---|---|---|
| **字阶** | 角色名两端一致（`display/title/headline/body/label/caption`），**取值分端生成**：iOS 用系统文字样式（Dynamic Type），Android 用 M3 字阶角色。**只用系统字体**，⛔ 不打包字体文件，⛔ Android 不写 `fontFamily`。 | 结构【已定】，档位【提案】 |
| **间距** | 以 4 为基数的等比阶（4 / 8 / 12 / 16 / 24 / 32 / 48）；页面左右留白统一取一档 | 【提案】 |
| **圆角** | 分档 `sm / md / lg / full`；同一语义元素全局同档 | 【提案】 |
| **描边** | 常规 1px；**Neo-Brutalism 专用 2px**（仅 CTA / Badge / 分区标题三类，宪法 1.1） | 【已定】 |
| **阴影** | 亮色下极克制；**暗色下一律不用阴影，改表面色**；Neo-Brutalism 用**硬偏移阴影**（唯一允许的"重"阴影） | 【已定】 |
| **图标尺寸** | **从字阶派生**，不写魔法数字；stroke 全局统一（宪法 16.3） | 【提案】 |
| **动效** | 时长/曲线**自建**（M3 物理在 RN 无官方实现）；每条必须声明 reduced-motion 降级 | 【提案】待 P1 定稿 |
