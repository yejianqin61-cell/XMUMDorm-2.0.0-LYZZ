## 2. 五格底栏骨架

### 2.1 骨架图（`【已定】`：所有者 2026-10-02 第三轮）

```
┌───────────────────────────────────────────────────┐
│ 顶栏：页面标题        ＋信箱动作（未读角标常驻）      │  ← 任何一级 Tab 都一样
├───────────────────────────────────────────────────┤
│ 二级顶部 Tab 条（仅"有子栏目"的一级 Tab 显示）        │  ← 横向可滚，吸顶
│  食堂 │ 社团 │ 二手 │ 跑腿 │ 新生指南 ←── 指示器    │
├───────────────────────────────────────────────────┤
│                                                   │
│            当前二级 Tab 的内容（可滚动）             │  ← 滚动位置各自独立
│                                                   │
├───────────────────────────────────────────────────┤
│  广场   │   工具   │  校园里  │   我的   │   ＋     │  5 格
└───────────────────────────────────────────────────┘
         ↑ 一级 Tab（导航）                ↑ 动作型 Tab（发布）
```

**三个层次一次说清**：
- **顶栏**：标题 + **唯一动作**（信箱）。**永远只有这一个动作**，不得变成图标收纳区（宪法 4.2）。
- **二级顶栏 Tab 条**：一级 Tab **内部**的子栏目切换。**有子栏目才有它**，没有就不占位（不显示空条）。
- **五格底栏**：4 个导航目的地 + 1 个**动作型 Tab**（发布）。**第 5 格不是目的地**（见 §3）。

### 2.2 五格职责（`【已定】`）

| 格 | 内容 | 定位 | 二级 Tab |
|---|---|---|---|
| **广场** | 食堂 · 社团 · 二手 · 跑腿 · 新生指南 | **服务聚合** | ✅ 有（集合待确认） |
| **工具** | 课程表 · 待办 · 放假日 · **校方系统快速打开** | **本 App 最主要功能入口** | ✅ 有（集合待确认） |
| **校园里** | 树洞 · 万能墙（**仅导航层合并**） | 内容社区 | ✅ **就是这两项**（宪法 4.1.1） |
| **我的** | 个人身份、个人内容、私信、设置 | 个人 | ⏳ **待确认**（可能不用二级 Tab） |
| **＋ 发布** | 收束**全部发布动作** | **动作**，不是目的地 | —（打开发布中心，见 §3） |

> **一级 Tab 由四格回到五格**（所有者 2026-10-02 裁决）。宪法 4.7.8 记录的"五降四带来的标签弹性收益"**据此失效**，但**信箱仍留在顶栏**（所有者未改该决定）——即：本轮的净变化是**发布从 FAB 上提到第 5 格**，不是把信箱挪回 Tab。

### 2.3 图标归属：底栏永远是第 2 层（平台原生）

1. **底栏图标一律由系统容器绘制**（宪法 4.3 禁止自绘 Tab 栏）→ 图标必须是**平台图标名**传给原生 API：Android/Material Symbols · iOS/SF Symbols（宪法 16.1）。
2. ⛔ **底栏里不得出现 Lucide 组件** —— **第 5 格也一样**，它是底栏的一部分，用平台 `add` / `plus`，**不是** Lucide `plus`。这是最容易做错的一处（发布是"我们的功能"，很容易顺手用品牌位图标）。
3. **四个导航格的图标名**：Material Symbols 四名已逐个核实存在；**SF Symbol 名仍属【提案】**，须用 Apple SF Symbols app 核对（[TODO TD-34](../TODO.md)）。
4. 第 1 层（Lucide）负责的是**内容里的**图标：发布中心内的七类发布图标、列表与卡片内的语义图标、空态/错误态等。

### 2.4 标签与宽度

| 项 | 规则 | 依据 |
|---|---|---|
| 四个导航格 | **图标 + 常态短标签**（中文 ≤3 字） | 宪法 6.3 |
| **第 5 格** | **只有加号，无文字标签**（所有者原话："一个加号按钮"）→ **登记为 6.3 的显式例外** | 所有者 2026-10-02 |
| 宽度基准 | 一律按**英文**定尺寸（英文长度中位数是中文 **2.50×**）；中文不得填满容器 | 宪法 6.2 |
| ⛔ 禁止 | 用截断或省略号掩盖"标签放不下"——**放不下就改标签，不是加省略号** | 宪法 10.5-3 |

> **第 5 格无文字标签的代价必须知情**：纯图标格**可发现性最差**（用户不知道加号里有什么）。因此 **① 无障碍标签必须写全（"发布"，见 §3.4）② 发布中心的条目必须自解释 ③ 首次进入不得是空屏**。这三条不是可选优化。

### 2.5 ⛔ 第六格禁令（`【已定】`，含一条直接推论）

- **平台事实（已取官方原文）**：Material Components for Android 官方文档 —— *"Navigation bars can have three to five destinations."* 与 *"**Note:** `BottomNavigationView` does not support more than 5 `menu` items."*（2026-10-02 取回全文）；iOS HIG 同为 3–5（[调研-03 §4.1](../research/App设计调研-03-Dorm能力面与使用场景盘点.md)）。
- **因此**：五格**已经用满**。⛔ **不得新增第 6 格**；将来任何新一级能力**只能**归入既有四格、或做成既有一格里的二级 Tab。
- **直接推论（已由调研证实）**：**实时私聊不可能单独占一格**。调研结论是**不放 Tab** —— 会话列表归「我的」下的二级页，**未读角标挂在顶栏唯一动作「信箱」上**（单一未读真源 = 服务端聚合接口，客户端不本地递减）；「校园里」语义不符（公共内容域 vs 实名交易上下文）。见 [实时私聊调研](../research/App实时私聊调研-技术难度与服务器开销.md) §5 与 [TO-CONFIRM](../TO-CONFIRM.md) C-07。

## 3. 第 5 格：动作型 Tab（发布）

### 3.1 语义：它是动作，不是目的地

**"动作型 Tab"= 长得像 Tab、但语义是动作的格位。** 判据一句话：**它没有自己的内容区**。
因此它**不参与**"哪个 Tab 被选中"的状态，也**不得**在返回栈里出现。

### 3.2 行为规格（六条，逐条可验收）

| # | 规则 |
|---|---|
| 1 | 点击 → **弹出发布中心**（全屏目的地或模态 Sheet，形态开发期定），**底栏选中态不变** |
| 2 | 关闭发布中心 → **回到点击前的那个一级 Tab、那个二级 Tab、那个滚动位置**（不得重置到列表顶部） |
| 3 | 在发布中心内完成一次发布 → 关闭后**停留在原位置**；不强制跳转到新内容（避免"发完就被带走"） |
| 4 | 返回键 / 返回手势在发布中心内 → 关闭发布中心本身，**不得**把底栏切到别处 |
| 5 | **重复点击**（已在发布中心时）**不得叠加**第二个发布中心（宪法 4.4.4：不同时叠两个模态） |
| 6 | 冷启动 / 深链进入时，**底栏选中项永远落在四个导航格之一**，不可能"选中发布" |

### 3.3 ⚠️ 知情偏离：这一格与两条既有规范冲突

**必须如实记录，不得写成"零成本"：**

| 冲突对象 | 原文口径 | 本项目的处置 |
|---|---|---|
| **Apple HIG** | tab bar 支持**导航**，**不提供动作**（宪法 5.4.2 曾据此明令"'底栏中间放发布'零官方背书，**禁止采用**"） | **所有者 2026-10-02 裁决覆盖该条款**。宪法 5.4.2 相应改写为"**知情偏离**" |
| **宪法 4.1（v1.2）** | "发布走 FAB，两者都不占 Tab" | **被本轮裁决取代**：发布上提到第 5 格 |

**代价清单（记录下来，避免日后被当作"没想过"）**：
1. **不是平台正统**：审核侧存在"偏离 HIG"的非零风险（实践中有大量先例：Instagram / Reddit 等把加号放进底栏，**但这只说明"通常不被拒"，不构成官方背书**）。
2. **可发现性靠图标本身**：见 §2.4 的三条补偿要求。
3. **实现路径有风险**：原生 Tab 在 SDK 57 只有 `unstable-native-tabs`（宪法 4.3），"点了不切页"的动作型格位**需要首周真机验证**（[TODO TD-31](../TODO.md)）。**若原生容器做不到，正确的退路是改用"FAB + 底栏四格"回到宪法 v1.2 方案，并请所有者重新裁决 —— ⛔ 不得自绘 Tab 栏。**
4. **英文宽度压力回升**：底栏回到 5 格，每格可用宽度下降（宪法 6.3 的放松结论作废）。

### 3.4 无障碍（第 5 格的验收核心）

- **必须给可读标签**（宪法 7.2）：TalkBack / VoiceOver 读出**"发布"**（英文 "Publish"），而**不是**"加号"或"第 5 个标签页"。
- **必须给角色与提示**：明确它是**按钮**语义（若原生容器只能渲染成 Tab 角色，则**标签必须自带动作含义**，用 "发布" 而不是 "+"）。
- **命中区 ≥48×48dp（Android）/ ≥44×44pt（iOS）**，视觉可见的加号可以更小，**命中区不得更小**。
- **不得依赖颜色区分选中态**（它没有选中态，正好规避）。

### 3.5 发布中心 = **数据驱动的注册表**（否则"一改全部改"在这里就断了）

**这是本轮最重要的结构性要求**：发布类型会**持续增加**（所有者已预告 **拼车 / 问答**）。

1. 发布中心**不得**把七类发布动作硬编码成七个按钮。必须是**注册表**：每条 = `{ id, 标题词条, Lucide 图标名, 权限判据, 目标表单页 }`。
2. **新增一类发布 = 注册表加一条**，⛔ **不改导航壳、不改布局、不改底栏**。
3. **权限过滤由后端布尔字段驱动**（如社团帖需 `viewer.canManage`、校园帖需组织成员资格）→ ⛔ UI 不得自行推断权限（页面清单 §3-S 要点）。
4. **入口条目与目标表单必须一一对应**：注册表里没有的发布类型，**页面上不得出现**（含灰度/占位）。

### 3.6 FAB 的处置（⛔ 不得双入口）

| 位置 | 处置 | 理由 |
|---|---|---|
| S-01 广场首页的发布 FAB、S-17 社团主页的发布 FAB、C-01 校园里/万能墙的发布 FAB | **删除** | 发布已收束到第 5 格；**同一动作只留一个入口**（宪法 1.4） |
| S-07 食堂「今天吃什么」FAB | **保留** | 语义是**随机选餐**，不是发布 |
| 其他非发布语义的悬浮按钮 | 保留，但**同一屏不得同时出现两个悬浮按钮** | 悬浮按钮互相遮挡 |

### 3.7 合规门禁仍然在提交链路上

**A-05 合规门禁（发布 UGC 前必须已接受条款）必须挂在每一个发布表单的提交链路上**，与入口形态无关 —— 把发布上提到第 5 格**不改变**这条红线（宪法 12.2）。

## 4. 二级导航：**顶部 Tab 条**（本规范的核心）

### 4.1 形态与适用（`【已定】`：所有者 2026-10-02）

> 所有者原话：**"广场，校园里，工具这里面的子栏目，我们不做成模块化入口，而是做成顶部 tab 切换。"**

| 项 | 规则 |
|---|---|
| **形态** | 一级 Tab 内部的子栏目，用**顶部横向 Tab 条 + 指示器**切换，**内容随选中项替换** |
| **适用** | **广场 / 工具 / 校园里**（"我的"是否使用**待确认**） |
| ⛔ **禁止（本条的核心）** | **不得**用"**宫格入口页 + 点进去 push 一个子页面**"作为子栏目的主要导航形态。旧版 `QuickActionGrid` 式的仪表盘**不再承担子栏目导航** |
| ✅ 允许 | 一级 Tab 的**首屏**仍可有摘要/统计/内容条（这是"这一屏给我什么信息"），但**子栏目的切换必须由顶部 Tab 承担**，不得要求用户先看宫格再点进去 |

**为什么这条重要**（不是风格偏好）：宫格入口页会让每个子栏目**多一次转场、多一层返回栈**，并且**回来时丢掉子栏目的位置**；顶部 Tab 把"切换子栏目"变成**零转场**动作，且天然保住各自的滚动位置。

### 4.2 六条硬规则

| # | 规则 | 判据 |
|---|---|---|
| **R1** | 子栏目**一律**用顶部 Tab；**同一级 Tab 内不得混用两套子栏目导航** | review 时数入口形态 |
| **R2** | 每个二级 Tab **独立维护**滚动位置、分页状态、筛选条件；**切换不得重置** | 切走再切回，位置必须还在 |
| **R3** | 一级 Tab 切换**保留**各格自己的二级选中项（回到"工具"时还在"课程表"） | 来回切一级 Tab 验证 |
| **R4** | **导航 Tab ≠ 筛选 Chips**：导航用 Tab 条（有指示器、有位置播报），筛选用 Chips（可多选、可清除）。**⛔ 两者不得互相冒充** | 二手页同时有分类筛选时最易出错 |
| **R5** | **子栏目数量 > 5 时横向可滚动**，但 **⛔ 不得用"更多 ▾"下拉把子栏目藏起来** | 溢出时看实现 |
| **R6** | **内容区不做横向滑动切 Tab**（Android 左右边缘 / iOS 左边缘都是**系统返回手势区**，宪法 4.6） | 手势冲突实测 |

> **R4 的补充**：`SegmentedTabs` 与 `FilterChips` 是两个**不同**的组件，不得用一个顶两个。视觉上必须可区分（Tab 有指示器/下划线，Chip 是独立药丸）。

### 4.3 状态保持（`【已算得】`自宪法 4.1.1 与 4.4.3）

| 场景 | 要求 |
|---|---|
| 二级 Tab 之间来回切 | 各自的滚动位置、分页游标、已加载页数**全保留** |
| 一级 Tab 之间来回切 | 保留该一级 Tab 的二级选中项与内容状态 |
| 进详情页再返回 | 回到**进入前的二级 Tab 与滚动位置**（不得回到首个二级 Tab） |
| 进程被杀后返回 | 至少**输入不丢**；强制落盘项见页面清单 §5.3 |
| 「校园里」两个子视图 | **宪法 4.1.1 的既有要求不变**（各自返回栈与滚动位置独立） |

### 4.4 深链与返回栈

1. **二级 Tab 必须可深链**：路由 path 里带上子栏目段（复用 Web 既有路径优先），深链落到某个二级 Tab 时，**栈底按宪法 4.4.1 回退到该一级 Tab 首页**。
2. **返回是系统级行为**（宪法 4.4.2）：⛔ 不得劫持 `KEYCODE_BACK`。
3. ⚠️ **受 R1 前置**：Android target 36 返回键失效风险未解（宪法 4.5 / [TODO TD-30](../TODO.md)）→ 结论出来前**不锁定**实现方案。

### 4.5 无障碍与动效

| 项 | 规则 |
|---|---|
| 角色 | 顶部 Tab 条必须暴露 **tablist / tab 语义**，选中项暴露 `selected` 状态 |
| 播报 | 读屏时告知**位置**（"第 2 个，共 5 个"），**不得只念标签** |
| 命中区 | 每个 Tab ≥48dp / ≥44pt；**Tab 条本身不得低于 48dp 高** |
| 溢出 | 横向滚动后，**选中项必须能自动滚入可见区**（不得让选中项停在屏幕外） |
| 动效 | 切换用**淡入淡出 / 指示器位移**；⛔ 不用横向整页位移（同 R6）；**必须有 reduced-motion 降级**（宪法 7.3） |
| 字号 | 支持系统字号放大；放大后 **Tab 标签允许换行或缩短，⛔ 不得裁字**（宪法 6.2） |

### 4.6 视觉规格（**只定语义，取值未冻结**）

`【提案】` 以下取值**待风格体系阶段/真机定稿**，此处只声明"必须来自令牌、不得在屏内写魔法数字"（宪法 1.4 / 2.4）：

| 元素 | 语义 | 取值 |
|---|---|---|
| Tab 条高度 | 触控下限 + 上下留白 | 待定（≥48dp / ≥44pt） |
| 指示器 | 表达"当前在哪" | 待定（粗细 ≥2dp，颜色用品牌色令牌） |
| 未选中/选中文字 | 层级由**颜色与字重**表达，⛔ 不用透明度叠加当层级 | 待定 |
| 吸顶 | 顶部 Tab 条**默认吸顶常驻**（不随滚动隐藏） | 例外须登记 |

## 5. 顶栏与滚动行为

| 项 | 规则 |
|---|---|
| 顶栏内容 | **标题 + 一个动作（信箱）**。⛔ 不得放第二个动作 |
| 与二级 Tab 的关系 | 顶栏在上、Tab 条在其下方；**Tab 条吸顶、顶栏按风格体系决定是否随滚动收起**（取值未冻结） |
| 标题 | 一级 Tab 显示**格名**；进入二级 Tab 后**标题保持格名**，二级位置由 Tab 条表达（⛔ 不得让标题在 Tab 之间跳变） |
| 详情页 | 顶栏由**原生导航栏**提供（宪法 4.3），标题 = 内容标题；**信箱动作在详情页是否保留 = 待确认项**（页面清单 §9.1 未登记，登记为 [TO-CONFIRM C-06](../TO-CONFIRM.md)） |
| 滚动边缘效果 | 交原生容器（宪法 4.3），⛔ 不得自绘"贴玻璃" |

## 6. 安全区与屏幕适配（insets）—— 所有者 2026-10-02 指定为必办项

### 6.1 八条铁律

| # | 铁律 |
|---|---|
| **S1** | **每屏必须消费真实 insets**（`react-native-safe-area-context`），⛔ **禁止**写死 `paddingTop: 44` / 用 `StatusBar.currentHeight` 当布局依据 |
| **S2** | **只有一个安全区容器**：全 App 唯一的 `Screen`/布局壳负责注入 insets，页面**只声明意图**（"我要顶栏/我不要顶栏""列表底部要留白"）。⛔ 不得每屏各写一遍 —— 否则一次改动要改 N 处（宪法 1.4） |
| **S3** | ⛔ **不得用 RN 内置的 `SafeAreaView`** —— 它已废弃且**仅 iOS 生效**（Android 上静默无效，正好制造"测试机对、用户机错"） |
| **S4** | `SafeAreaProvider` **只挂一次**（根布局）；⛔ 不得在页面内再套 Provider |
| **S5** | **底部留白的归属必须唯一**：原生 Tab 栏**自带**安全区处理 → ⛔ 我们**不得**再叠加一层 bottom inset（会双倍空白）。内容区要留的是"最后一项不被 Tab 栏压住"的量，**不是** insets 的量 |
| **S6** | **键盘与 insets 叠加**：键盘弹出时输入条的避让 = **键盘高度与 bottom inset 的合并计算**，⛔ 不得各算各的（否则输入框被键盘顶出屏幕或悬空） |
| **S7** | **每个覆盖层都要自己处理 insets**：模态、BottomSheet、ActionSheet、全屏 WebView 页、启动页、Toast。**这是最常漏的一类**（页面处理了，浮层没处理） |
| **S8** | **iOS 与 Android 的默认行为不同，必须显式统一**：iOS `ScrollView` 默认自动调整内容内边距（`contentInsetAdjustmentBehavior`），Android 不会 → **统一走 S2 的容器**，⛔ 不得依赖两端各自的默认行为 |

### 6.2 四类 insets 必须全部处理（少一类就会在某种机型上出问题）

| # | 类别 | 典型机型/形态 | 处理要求 |
|---|---|---|---|
| 1 | **顶部：状态栏 + 挖孔/刘海/灵动岛** | 无挖孔安卓、中置挖孔、iOS 刘海、**灵动岛（顶部 inset 更高）** | 顶栏背景必须**铺满到屏幕顶边**，内容从 inset 之下开始；⛔ 不得出现"状态栏留白"或"内容被挖孔切掉" |
| 2 | **底部：手势条 vs 三键导航** | 手势导航（inset 小）/ 三键导航（inset 明显更大） | **必须读真实值**，⛔ 不得假设两者相同 |
| 3 | **左右：横屏与曲面屏** | 横屏（刘海在侧边）、曲面屏、折叠屏外屏 | 横屏下**左右 insets 必须生效**；⛔ 关键操作不得贴左右边缘（系统返回手势区） |
| 4 | **大屏/分屏/折叠屏展开** | `sw≥600dp`、分屏、iPad 多任务 | **大屏自适应是首发要求**（宪法 5.3）；不得把竖屏布局直接拉伸 |

### 6.3 逐类部件的具体口径

| 部件 | 口径 |
|---|---|
| **列表（`FlashList`/`LegendList`）** | 首项与末项的留白用 insets **注入 `contentContainerStyle`**；⛔ 不得用"末尾塞一个空白 item"糊 |
| **粘性底栏（如报名/输入条）** | 高度 = 内容高度 + bottom inset（**唯一叠加处**，且此时该屏不再有 Tab 栏） |
| **聊天/评论输入条** | 同 S6：键盘高度 + bottom inset 合并；键盘收起时输入条回到 Tab 栏之上 |
| **全屏 WebView（T-05）** | **必须把 insets 传给内嵌页**（顶部不让状态栏压住、底部不让手势条压住）；⛔ 内嵌页不得自绘状态栏背景（会出现双层条） |
| **启动页** | logo 必须在**安全区内居中**（挖孔机型不得遮挡） |
| **模态/Sheet** | 顶部 sheet 手柄与底部按钮区各自消费 insets |
| **Toast / 轻提示** | 距离底边 = bottom inset + 间距；⛔ 不得贴在屏幕物理底边 |

### 6.4 机型矩阵（**≥8 台/形态，逐项真机验证**；`【提案】`具体机型待脚手架期定）

| # | 形态 | 验证重点 |
|---|---|---|
| 1 | Android 无挖孔 + 手势导航 | 底部 inset 正确、无双倍留白 |
| 2 | Android 中置/左置挖孔 | 顶部内容不被切、顶栏铺满 |
| 3 | Android **三键导航** | bottom inset 变大后布局不破 |
| 4 | Android 曲面/窄边框 | 左右内容不贴边、边缘不误触 |
| 5 | Android **折叠屏展开 / 分屏**（`sw≥600dp`） | 大屏自适应 |
| 6 | Android **横屏** | 左右 insets 生效 |
| 7 | iOS **刘海** | 顶部/底部 insets |
| 8 | iOS **灵动岛** | 顶部 inset 更高时标题不被压 |
| 9 | iOS 带 Home Indicator + **键盘弹出** | S6 合并计算 |
| 10 | iPad 分屏 / Stage Manager | 大屏自适应与多任务 |

### 6.5 逐条验收清单（打不上勾不得结案）

- [ ] 顶栏背景铺满到屏幕顶边，内容从 inset 之下开始
- [ ] 底栏/手势条**没有**遮挡任何可点内容；且**没有**双倍空白
- [ ] 列表最后一项可完整滚动到可见区域（不被底栏压住）
- [ ] 键盘弹出时输入框与提交按钮**都可见**

- [ ] `sw≥600dp` 下布局不是简单拉伸
- [ ] 每个模态/Sheet/Toast/WebView 页**各自**处理了 insets（S7）
- [ ] 暗色与亮色两种主题下**状态栏图标颜色正确**（⛔ 不得出现"暗色主题 + 黑色状态栏字"）

## 7. 冻结边界：什么现在定、什么开发期定（所有者 2026-10-02 裁决）

> 所有者原话：**"当前由于页面太多，功能太多，不适合一次性全部规定好。具体页面布局，可以等到开发时再进一步确认和调整。"**

### 7.1 **冻结**（改动须走宪法修订或本文修订）

1. 五格底栏的构成与"第 5 格是动作"的语义；
2. 二级导航**必须是顶部 Tab 条**，且**不得**改回宫格入口页；
3. 二级 Tab 的六条硬规则（§4.2 R1–R6）；
4. 安全区八条铁律（§6.1）；⛔ 尤其 **S1/S3/S5/S6**（写死数值、用错 `SafeAreaView`、双倍留白、键盘与 inset 各自为政）；
5. 导航 Tab 与筛选 Chips 不得互相冒充；
6. 发布入口唯一（第 5 格），⛔ 不得保留第二个发布入口；
7. 顶栏只允许一个动作（信箱）。

### 7.2 **不冻结**（开发期逐页确认，**不需要回来请示**）

1. 每个页面的内部布局、信息顺序、卡片形态、栅格与留白；
2. 一级 Tab 首屏放什么内容（摘要卡 / 统计 / 内容条的取舍）；
3. 二级 Tab 的**视觉取值**（高度、指示器、字阶、动效参数）；
4. 页面总表的**重新切分**（合并/拆分/新增哪些页）；
5. 具体的机型清单（§6.4 的 `【提案】`部分）。

### 7.3 变更纪律（不冻结 ≠ 可以随便改）

1. **开发期的调整不得违反 §7.1 与宪法**；违反即视为"未完成"，不是"实现选择"（宪法 13.1）。
2. **改了就要回写文档**：页面结构变化写回 [页面清单](../product/App页面清单与结构盘点.md)，视觉取值写回 [前端风格体系](App前端风格体系.md)，组件变化写回 [组件类型定义](App组件类型定义.md)。**文档是 Agent 之间的通信协议**——不回写等于对下一个 Agent 说谎。
3. **不得用"开发期再定"当借口推迟本该现在定的骨架问题**：骨架（§7.1）就是现在定的。
