## 2. The approach, requirement by requirement

### R-1 重组五格导航与底部安全区

- **Approach**：把树洞和万能墙并入广场，释放原校园格给消息。发布保留动作语义，并移动到五格中央。
- **Touches**：设计宪法、页面结构、原生导航、深链栈底和底部安全区。
- **Test seam**：现有导航配置守卫、返回策略和设备安全区矩阵。
- **Acceptance**： [ ] 五格顺序为广场、工具、发布、消息、我的　[ ] 发布不改变选中格　[ ] 内容不被底栏遮挡
- **Hard part**：所有者已批准新五格。开工第一项必须先改宪法和页面结构真源，再改代码。

### R-2 统一页签、搜索和媒体入口

- **Approach**：复用现有顶部页签、搜索框和媒体选择器。只补缺失状态，不建立第二套组件。
- **Touches**：设计系统、内容列表、表单、无障碍和双语词条。
- **Test seam**：现有组件测试和逐屏 13.1 检查。
- **Acceptance**： [ ] 同类页签外观与交互一致　[ ] 搜索入口位置一致　[ ] 图片入口一致　[ ] 触控和读屏达标
- **Hard part**：视觉统一不能抹掉列表筛选、详情互动和表单上传的语义差别。

### R-3 把信箱升级为消息中心

- **Approach**：消息格承载互动、交易、系统和私信。批量动作降为次要按钮，消息行按目标类型跳到对应内容。
- **Touches**：消息列表、私信、通知目标、登录回跳和未读真源。
- **Test seam**：现有通知列表、未读汇总、会话列表和路由入口。
- **Acceptance**： [ ] 全部已读与清空不抢主导航视觉　[ ] 可用消息能直达目标　[ ] 失效目标给出可改正结果
- **Hard part**：通知中的目标可能已删除、无权限或缺少足够参数。

### R-4 把广场改成全站发现入口

- **Approach**：广场首页分为社区内容和校园服务。食堂、二手、跑腿、一站通和社团保持同级入口。
- **Touches**：广场聚合、服务入口、内容入口、路由清单和页面恢复。
- **Test seam**：广场聚合入口和每个目标页面的现有路由。
- **Acceptance**： [ ] 所有入口同级可见　[ ] 食堂不再包住其他服务　[ ] 树洞和万能墙从广场可达
- **Hard part**：马校一站通和新生指南是同一 Handbook 能力，不能重复建设第二个模块。

### R-5 重做工具首页、待办与放假日

- **Approach**：工具首页只展示高频摘要。待办只显示前三项并提供二级页；放假日放在课表摘要下方。
- **Touches**：工具仪表盘、待办、放假日数据和新建入口。
- **Test seam**：现有工具摘要、待办 CRUD 和放假日日期选择逻辑。
- **Acceptance**： [ ] 首页仅显示三项未完成待办　[ ] 可从首页新建待办　[ ] 放假日卡片可进入完整页面
- **Hard part**：新粗野视觉必须继续使用令牌、通过对比度门，并保留暗色主题。

### R-6 重做课表、导入引导与上课提醒

- **Approach**：周次只显示数字并支持横向滑动。课程颜色按稳定身份映射；导入前提示用户进入正确页面。
- **Touches**：课表网格、导入 WebView、今日课程、本地通知和权限引导。
- **Test seam**：现有周次纯函数、课程缓存、导入状态机和 notification permission 入口。
- **Acceptance**： [ ] 无左右箭头　[ ] 同课程颜色稳定　[ ] 周六周日隐藏　[ ] 已结束课程离开今日列表　[ ] 课前 30 分钟提醒
- **Hard part**：周六周日隐藏已经裁决；原生通知仍需要依赖准入、development build 和时区回归。

### R-7 把 Moodle 数据收进原生综合页

- **Approach**：首次登录使用内嵌页。登录后优先调用 Moodle AJAX，详情 DOM 只作补充，并把所选课程标准化到设备本地。
- **Touches**：Moodle 会话、课程选择、对象标准化、截止日期校验、设备本地缓存和同步状态。
- **Test seam**：现有 WebView 注入通道，以及去敏的 AJAX JSON、详情 HTML 和响应头夹具。
- **Acceptance**： [ ] 可选目标课程　[ ] 可查看章节、模块、公告、作业、资源和截止事件　[ ] 后续默认不展示 WebView
- **Hard part**：需在 development build 验证 WebView 内 AJAX、会话保持、详情 DOM 适配和异常远期截止日期。

#### Moodle 提取对象契约

以下对象已在用户授权的真实登录态中验证。样本覆盖账号当前 9 门课程、154 个章节和 275 个模块。

| 对象 | 本期字段边界 |
|---|---|
| `MoodleCourse` | ID、名称、链接、起止日期、可见性、收藏和进度 |
| `MoodleSection` | ID、序号、标题、链接、可见性、当前状态和模块顺序 |
| `MoodleModule` | ID、章节、类型、名称、链接、可见性、限制和完成状态 |
| `MoodleActionEvent` | 课程、模块、名称、时间、动作、链接和可操作状态 |
| `MoodleAnnouncement` | 讨论与帖子 ID、标题、正文、结构化作者、发布时间、附件和固定链接 |
| `MoodleAssignmentDetail` | 开放与截止、描述、要求、尝试次数、提交与评分状态、附件、成绩和评论数 |
| `MoodleResource` | 文件名、原链接、MIME、修改时间和重定向状态 |
| `MoodleFolderEntry` | 文件名、原链接和 MIME |

数据源按下列顺序使用。低优先级来源只补充高优先级来源没有的字段。

| 优先级 | 来源 | 用途 |
|---:|---|---|
| 1 | `core_course_get_enrolled_courses_by_timeline_classification` | 课程列表 |
| 1 | `core_courseformat_get_state` | 章节与模块 |
| 1 | `core_calendar_get_action_events_by_timesort` | 截止事件 |
| 2 | 模块详情 DOM | 公告、作业状态和文件夹 |
| 3 | 只读 HEAD | 单文件资源元数据 |
| 4 | 去敏 JSON、HTML 和响应头夹具 | 自动化回归 |

当前站点禁用 `core_course_get_contents`，实现不得依赖它。

模块处理以 Moodle 返回的底层类型为准。标题只提供语义标签，不改变类型。

| 模块类型 | 本期处理 |
|---|---|
| `forum` | 公告列表与详情 |
| `assign` | 详情、状态、截止和评分摘要 |
| `resource` | 文件元数据和原链接 |
| `folder` | 内部文件列表 |
| `url`、`page` | 名称、链接、可见性；页面可补摘要 |
| `quiz` | 名称、链接和截止事件 |
| `choice` | 名称、链接和状态摘要 |
| `mediasite` | 名称和链接，不深抓外部内容 |
| `chat` | 名称和链接，不同步聊天内容 |
| `label` | 保留为章节说明，不当作可打开资源 |

Tutorial 不是独立 Moodle 类型。它可能是 `resource` 或 `assign`，因此不建立独立抓取器。
公告作者只从结构化 DOM 提取，不把正文签名猜成作者。

隐私边界：

- `MoodleSession` 只留在 WebView Cookie Store，不读取、记录或上传密码。
- 课程、截止、成绩和提交状态只缓存在设备端，不上传项目生产数据库。
- 本地通知只根据设备端缓存生成；退出 Moodle 或清会话时同步清除缓存。
- 日志不得出现 sesskey、Cookie、成绩、提交文件名或公告正文。

数据质量规则：

- 只同步用户明确勾选的课程，以 `visible`、`uservisible` 和 `accessvisible` 判断可见性。
- 课程可能按日期、周次或主题组织，不假设固定章节结构。
- 作业没有截止日期属于合法状态，不为它生成截止提醒。
- 异常远期截止日期进入异常区，不自动通知。
- 课程起止日期可能与标题学期不一致，不能单独决定课程归属。
- 每日 03:00–04:30 马来西亚时间显示维护状态，不把失败写成空数据。
- 会话过期后返回内嵌登录，不尝试读取或恢复密码。

### R-8 完成食堂浏览、榜单、点评和菜品共建

- **Approach**：食堂首页前置搜索、榜单、区域、随机选餐和内容流。详情页复用已有收藏、点评与回复契约。
- **Touches**：食堂首页、排行榜、区域、商家菜单、菜品详情、点评表单和菜品共建。
- **Test seam**：现有食堂 API、缓存、详情、收藏和点评测试。
- **Acceptance**： [ ] 排行榜按单一类别切换　[ ] 缺图统一占位　[ ] 可添加菜品　[ ] 点评支持二级回复
- **Hard part**：商家详情的双栏布局必须在窄屏、横屏和大屏分别成立。

### R-9 完成二手、跑腿、指南和完整社团治理

- **Approach**：三类列表统一使用可滚动文字页签和下划线选中态。社团按现有完整域落地，不降级为入口页。
- **Touches**：二手、跑腿、一站通；社团发现、主页、活动、帖子、成员、管理和我的社团。
- **Test seam**：现有分页状态机、详情骨架、`clubs` 31 个后端路由、共享 API 和既有 Web 端测试。
- **Acceptance**： [ ] 二手搜索和价格筛选顺序正确　[ ] 跑腿卡片用满内容宽度　[ ] 指南有分类、点赞和评论　[ ] 社团用户与管理员闭环完整
- **Hard part**：社团后端能力较完整，但 App 端没有业务屏幕；分类筛选、成员移除等管理契约仍有缺口。

### R-10 重做树洞和万能墙的内容体验

- **Approach**：树洞使用单列内容流和可滑动多图。万能墙使用六种纯文本模板，并复用同一详情评论系统。登录用户新建话题后立即公开。
- **Touches**：树洞列表、帖子详情、搜索、万能墙模板、图片浏览和二级评论。
- **Test seam**：现有校园内容分页、搜索、点赞、评论和举报入口。
- **Acceptance**： [ ] 树洞列表支持多图切换　[ ] 详情先正文后图片　[ ] 两类内容都支持二级评论　[ ] 新话题提交成功后立即可见
- **Hard part**：多图手势不能与系统返回、列表滚动或顶部页签手势冲突。

### R-11 完成我的、设置和发布闭环

- **Approach**：我的首页聚焦身份和内容。编辑、设置放右上角；发布表单统一 safe area、标签选择和媒体入口；账号注销采用可审计的软删除。
- **Touches**：我的首页、内容归档、资料编辑、设置、账号注销、语言落盘和发布表单。
- **Test seam**：现有会话、资料、我的帖子、设置、表单宿主和发布描述符。
- **Acceptance**： [ ] 移除三块摘要　[ ] 四类内容可切换　[ ] 退出、软删除、语言可用　[ ] 三类发布页不贴边
- **Hard part**：后端已有软删除接口，但鉴权中间件尚未复查账号状态；必须保证注销后的旧 JWT 立即失效。

### R-12 让每个改动通过统一质量门

- **Approach**：每个模块同时交付行为测试、双语、四态、safe area 和设备记录。最后再进入上线收口计划。
- **Touches**：自动化出口、lint 债务、设备矩阵、可访问性和验收记录。
- **Test seam**：现有 verify、四把 rulers、lint 基线和 13.1 逐屏清单。
- **Acceptance**： [ ] 完整 verify 自然退出 0　[ ] 新代码不增加 lint warning　[ ] 关键页面有真机证据
- **Hard part**：Expo Go 不能证明原生 Tab、返回键、通知和 WebView 行为。

## 3. Ownership and phases

### 3.1 三个人如何分工

| 人 | 主责模块 | 独占写作用域 | 不直接修改 |
|---|---|---|---|
| 甲 | 导航、消息、我的、发布、共享 UI、集成 | App 路由、导航、信箱、个人域、发布、鉴权、UI 组件、i18n、CI | 乙丙的业务屏幕与域 API |
| 乙 | 工具、课表、待办、Moodle、通知提醒、食堂 | 对应客户端与域 API；Moodle WebView 提取、标准化和设备本地缓存 | 导航壳、共享 UI、公共词条 |
| 丙 | 广场内容、树洞、万能墙、二手、跑腿、指南、完整社团 | 对应客户端功能；对应业务路由、共享域 API 和新增迁移 | 导航壳、共享 UI、公共词条 |

甲是集成人，不替乙丙重写业务模块。乙丙需要新路由时，交付屏幕导出和路由清单，由甲接线。

甲独占公共词条文件。乙丙在各自 task brief 中提交词条键、中文、英文和参数清单，由甲批量接入。

甲独占公共组件。乙丙先复用现有顶部页签、搜索框、媒体选择器和评论线程。确有第二个消费者时，再向甲提交抽取请求。

后端入口和共享请求底座由甲接线。乙丙只修改自己的业务路由、服务和域 API，不改公共请求与鉴权底座。

### 3.2 Phase 3-0 — 新骨架可运行，最高风险可证伪

**Covers**：R-1 重组五格导航与底部安全区、R-2 统一页签、搜索和媒体入口、R-7 把 Moodle 数据收进原生综合页、R-9 完成完整社团治理、R-12 让每个改动通过统一质量门。

**Goal**：五格新骨架可以导航；三个负责人各有一个真实纵向切片；Moodle 和通知路径得到“可做”或“不可做”的证据。

**Tasks**

- 甲冻结“广场 / 工具 / 发布 / 消息 / 我的”导航契约并迁移路由守卫
- 甲用现有页签、搜索和媒体组件改造三个代表页面
- 甲修正底栏内容净空并覆盖安全区回归
- 乙把已验证的 Moodle 契约固化为解析器与去敏夹具，并验证 WebView 注入和会话保持
- 乙用 development build 验证通知权限和本地定时提醒
- 丙提交广场入口清单，把现有 `clubs` 31 个路由映射为 App 能力矩阵，并标出分类筛选与成员管理缺口
- 三人跑各自纵向切片并记录失败边界

**Proof**：development build 中五格正确且页面不被遮挡；三个 AJAX 方法可用；会话过期可回登录；日志无 Moodle 私密数据；通知有结论。

**Not here**：不铺完整页面，不做商店发布，不把 Moodle 私有数据上传项目后端。

### 3.3 Phase 3-1 — 高频入口可以完成一次任务

**Covers**：R-3 把信箱升级为消息中心、R-4 把广场改成全站发现入口、R-5 重做工具首页、待办与放假日。

**Goal**：用户从三个高频 Tab 进入后，可以读消息、找到服务、查看今天并新建待办。

**Tasks**

- 甲把互动、交易、系统和私信收进消息 Tab
- 甲让全部已读与清空使用次要动作，并补危险操作确认
- 甲按通知目标表接通内容、交易和失效目标
- 甲组装广场社区区与校园服务区，并接入乙丙入口
- 乙把工具首页待办摘要限制为三项并接通完整列表
- 乙补新建待办入口和最近放假日二级页
- 丙验证广场每个入口可达且返回后保持原位置

**Proof**：从消息可直达一条互动和一条交易；从广场可进入所有已承诺模块；从工具可新建待办并在前三项摘要中看到它。

**Not here**：不在此阶段重做各业务详情，不实现 Moodle 全量综合页。

### 3.4 Phase 3-2 — 课程与 Moodle 成为原生工作台

**Covers**：R-6 重做课表、导入引导与上课提醒、R-7 把 Moodle 数据收进原生综合页。

## 5. Decisions and validation boundaries

### 已批准的产品决定

- **D-1 新五格**：广场 / 工具 / 发布 / 消息 / 我的。树洞与万能墙不再占一级格。所有者已批准消息 Tab 和信箱改造。
- **D-2 一站通同一真源**：马校一站通、新生指南和 Campus Handbook 是同一个模块。
- **D-3 课程颜色**：用课程稳定身份映射批准色板，不从接口随机取色。
- **D-4 上课提醒**：先用设备本地通知，课表变化后重排；不把远程推送设为前置。
- **D-5 万能墙六模板**：便签、公告、档案、对话、清单、海报。六类共用内容与无障碍契约。
- **D-6 外部产品只作交互参考**：不复制 Twitter、Instagram、小红书或美团的品牌视觉。
- **D-7 课表周末**：隐藏周六和周日，不隐藏周五。
- **D-8 话题公开**：登录用户新建话题后立即公开，不设置发布前审核队列。
- **D-9 完整社团**：本期交付发现、主页、活动、帖子、成员、我的社团和管理员能力，不降级为入口或最小主页。
- **D-10 账号注销**：采用软删除。后端已有 `DELETE /api/users/me`，本期补齐旧 JWT 失效、客户端清会话、公开身份处理和审计记录。
- **D-11 Moodle 登录态契约**：App 持有平台会话，优先调用三种已验证 AJAX 方法。标准化数据只缓存在设备端。

### 已闭合问题与施工验证边界

- **C-1 课表隐藏星期**：已闭合。隐藏周六和周日。
- **C-2 Moodle 公开边界**：官方站点使用 Campus ID，支持 Edge，发放 `MoodleSession`，每日 03:00–04:30（马来西亚时间）维护。
- **C-6 Moodle 对象契约**：已通过 OpenCLI 在授权登录态完成只读验证。课程、章节、模块、事件、公告、作业和资源对象均已定界。
- **C-3 新建话题权限**：已闭合。登录用户提交成功后立即公开。
- **C-4 社团本期深度**：已闭合。完整社团单列 Phase 3-5，覆盖普通用户和管理员闭环。
- **C-5 注销语义**：已闭合。现有接口已将用户状态改为 `deactivated`；施工必须补齐鉴权状态复查，并定义身份脱敏、数据保留和恢复政策。

## 6. Rollback

- **Phase 3-0**：新五格真机失败时，保留现有四导航格加发布动作格，不继续迁移页面。
- **Phase 3-1**：消息目标不完整时，保留可读列表；关闭有歧义的跳转，不猜路由。
- **Phase 3-2**：WebView 调用或详情适配不稳定时，保留登录与课程选择，不发布不完整的原生综合页。
- **Phase 3-3**：食堂大改回归时，按首页、列表、详情、写入四段独立回退，不回退共享组件。
- **Phase 3-4**：新互动缺后端契约时，隐藏对应动作并保留只读详情，不做客户端假成功。
- **Phase 3-5**：社团角色或写入契约未通过时，不发布该阶段；保留旧 Web 能力，不把残缺 App 页面暴露给用户。
- **Phase 3-6**：软删除、法务或设备门失败时，不进入商店提交，继续使用内部候选包。

## 7. Not doing

- 不在本计划中加入拼车、问答、学习资料或新的全站运营管理后台。
- 不为视觉统一重写已经存在且可复用的组件。
- 不把所有业务塞进食堂，也不再创建第二个一站通模块。
- 不把学生社团 `clubs` 与运营组织 `organizations` 合并；两者继续按角色分开呈现。
- 不保存、上传或自行解析用户的校方密码。
- 不把 Moodle 私有课程、成绩、提交状态或公告正文写入项目生产数据库。
- 不用关闭 lint 规则、强制退出测试或伪造设备记录制造绿灯。
- 不把本期“治理完成”写成“已经可上架”；上架仍走后置收口计划。
