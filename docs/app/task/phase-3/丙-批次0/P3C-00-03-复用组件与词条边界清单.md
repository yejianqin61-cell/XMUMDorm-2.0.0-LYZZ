## 1. Where this task sits

- **Phase 3-0 新骨架可运行**：防止丙域重复建设公共组件。
- 本任务为二手、跑腿、指南、树洞和万能墙确定复用边界。
- **开始前**：无。**后续依赖**：Phase 3-4 的内容与服务实现。

## 2. What the developer needs to know

**Read first**

- `docs/app/task/Phase3全面治理工程计划.md` — 确认公共组件与词条的归属。
- `app/src/components/ui/TopTabStrip.tsx` — 确认现有页签接口。
- `app/src/components/ui/SearchField.tsx` — 确认搜索入口接口。
- `app/src/components/ui/MediaGrid.tsx` — 确认媒体展示能力。
- `app/src/components/ui/CommentThread.tsx` — 确认评论线程能力。

**Settled**

- 甲独占公共组件和公共 i18n 文件。
- 丙先复用，再申请抽取或扩展。
- 同类页签使用文字、横滑和下划线选择态。

**Edges and seam**

- 触及丙域的组件调用方式和交接文档。
- 验证缝隙是四个既有公共组件的公开 props。
- 不编辑公共组件及 i18n 文件。

**Run**

- `cd app && npm test -- --runInBand p0-06-secondary-tabs p1-05-controls`
- `cd app && npm run typecheck`

**Unknowns**

- 若公共组件无法表达批准的交互，形成甲的抽取请求。
- 不新增第二套组件作为临时替代。

## 3. The workflow

1. 阅读上述文件并重述：所有丙域首先使用现有公共组件。
2. 记录页签、搜索、媒体、评论的现有能力。
3. 为每个丙域标注应复用的组件。
4. 标注缺失能力、第二消费者和甲需处理的范围。
5. 起草中英文词条 key、文本与参数，不写公共词条文件。
6. 运行组件测试和类型检查。
7. 提交复用与词条边界表。
