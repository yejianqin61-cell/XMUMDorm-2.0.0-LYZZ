## 1. Where this task sits

- **Phase 3-0 新骨架可运行**：在改动前固定可比较的验证基线。
- 本任务记录丙域 App、Web、后端的测试入口与启动安全门。
- **开始前**：无。**后续依赖**：全部丙域实现与最终交接。

## 2. What the developer needs to know

**Read first**

- `docs/experience/2026-10-09-cjs-esm-route-startup-incident.md` — 确认 CJS／ESM 启动检查。
- `app/package.json` — 确认 App 的 typecheck、test、lint、verify 命令。
- `__tests__/frontend/clubDirectory.test.js` — 确认社团 Web 测试入口。
- `__tests__/routes/confessions.test.js` — 确认校园内容后端测试入口。
- `server.js` — 确认实际后端启动入口。

**Settled**

- 自动化通过不能替代实际启动、真机与真实后端验证。
- 触及 `routes/**` 或 `shared/**` 必须通过 CJS 语法和启动健康检查。
- 不能用 `--forceExit` 制造绿灯。

**Edges and seam**

- 触及测试记录和验证命令，不改业务实现。
- 验证缝隙是 App 域测试、后端路由测试与 `server.js` 启动。
- 不连接生产数据库或发布 Railway。

**Run**

- `cd app && npm run typecheck && npm test -- --runInBand p2x-bing-campus p2x-bing-market-errand`
- `npm test -- __tests__/routes/confessions.test.js __tests__/frontend/clubDirectory.test.js --runInBand`

**Unknowns**

- 本地数据库和真机条件不齐时，只记录环境阻塞。
- 启动检查需隔离临时端口与数据环境，不能误连生产。

## 3. The workflow

1. 阅读上述文件并重述：所有丙域改动必须有可重复验证。
2. 运行 App 类型检查与相关域测试。
3. 运行校园内容和社团的现有后端／Web 测试。
4. 记录通过、失败、跳过与环境原因。
5. 写入未来触及 `routes/**`／`shared/**` 时的 CJS 解析和启动门。
6. 不执行生产连接或部署。
7. 提交测试基线记录。

## 4. The test cases

| Case | Input | Expected | Seam |
|---|---|---|---|
| 1 | App typecheck | 退出码为 0 | TypeScript |
| 2 | 内容域测试 | 已有测试通过或有明确失败 | App 域测试 |
| 3 | 社团目录测试 | 已有目录行为不回归 | Web 测试 |
| 4 | 树洞后端测试 | 路由行为不回归 | `routes/confessions.js` |
| 5 | 路由改动后 | CJS 解析、启动与健康检查通过 | `server.js` |
