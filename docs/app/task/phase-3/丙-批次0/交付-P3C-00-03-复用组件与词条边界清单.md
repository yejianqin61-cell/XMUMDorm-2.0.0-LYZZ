# P3C-00-03 复用组件与词条边界清单

> 状态：已盘点（2026-10-10）  
> 原则：丙复用公共组件；公共组件与 `app/src/i18n/**` 由甲独占。需要新增共性能力时，先给甲提交抽取申请，不在业务页复制组件。

## 已有组件与丙的复用规则

| 公共组件 | 已确认能力 | 丙允许的使用方式 | 禁止事项 / 需要甲处理的情形 |
|---|---|---|---|
| `TopTabStrip` | 二级导航；横向溢出滚动；选中项自动滚入可见区；无障碍 tablist；本身无状态 | 二手、跑腿、树洞、万能墙等同级子栏目统一使用，页面自身保存选中键 | 不做宫格替代二级导航；不复制另一份 Tab 条；新增通用 Tab 行为先提给甲。 |
| `SearchField` | `inline`/`full` 两种检索形态；提交、清空、读屏标签 | 二手、新生指南、树洞、话题搜索直接传入业务状态和词条 | 不把它当表单字段或筛选器；不在组件内塞业务校验/错误。 |
| `MediaGrid` | `grid`/`hero`；图片张数决定布局；可传替代文本与点击回调 | 树洞、万能墙、二手、跑腿、社团详情展示媒体时复用 | 不复制图片九宫格；媒体选择/上传能力不在本组件内，若缺少通用上传入口由甲处理。 |
| `CommentThread` | 两层评论；组内展开；可传点赞、删除、回复与页脚；标签由调用方提供 | 树洞、万能墙、指南、社团详情将业务评论转换为 `CommentNode` 后复用 | 不做三级回复；不在组件内另起分页状态机；新评论模型先在丙域适配，不改公共组件。 |

## 现有复用证据

- 校园域当前已使用 `TopTabStrip`、`MediaGrid`、`CommentThread`；`CampusSearchScreen` 已使用 `SearchField`。
- 二手详情当前已使用 `MediaGrid` 的 `hero` 形态。
- 上述组件已有对应单元测试文件：`p0-06-secondary-tabs`、`p1-05-controls`、`p1-08-domain-components` 等；丙的业务测试应验证适配与行为，不复制这些组件本身的实现测试。

## 词条交接格式（丙 → 甲）

丙不直接修改公共词条文件。每个批次如出现新文案，在对应任务交付中以如下表提交给甲：

| 键名建议 | 中文 | 英文 | 参数 | 使用页面 | 触发批次 |
|---|---|---|---|---|---|
| `market.search.placeholder` | 搜索二手商品 | Search marketplace items | 无 | 二手列表 | 2 |
| `errand.empty` | 暂无跑腿任务 | No errands yet | 无 | 跑腿列表 | 2 |
| `guide.category.all` | 全部分类 | All categories | 无 | 新生指南 | 2 |
| `club.manage` | 管理社团 | Manage club | 无 | 社团主页 | 4 |
| `club.registration.full` | 报名人数已满 | Registration is full | 无 | 活动详情 | 4 |

上表只有键名申请示例，不代表这些键已经写入 `zh.ts`/`en.ts`。实际交付必须补齐页面、参数和无障碍标签，甲再集中接入双语文件。

## 新共性能力的准入规则

仅在同时满足下列条件时，丙向甲申请抽取公共组件或扩展：

1. 至少有两个独立业务域需要完全相同的交互与无障碍语义；
2. 现有四个组件无法通过 props 合理承载；
3. 丙提交两个消费页面、目标 props、状态模型、中文/英文/读屏文案和测试场景；
4. 甲确认组件归属后，丙再改业务页接入。

未满足以上条件的内容保持在丙域内实现，避免为了“未来复用”提前扩张公共层。

## 本批次禁止修改范围

- `app/src/components/ui/**`
- `app/src/i18n/**`
- 一级导航壳、底栏、公共请求/鉴权底座

本任务仅建立边界与交接格式，未改动上述范围。
