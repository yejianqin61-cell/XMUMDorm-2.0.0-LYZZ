# P3C-00-02 社团能力矩阵与缺口表

> 状态：已盘点（2026-10-10）  
> 范围：只记录现有代码事实与 App 实现缺口；不把 Web 已有页面等同于 App 已交付。

## 结论

服务端和 Web 端已具备较完整的社团业务基础；App 端没有任何社团路由或页面。因此批次 4 的工作以**复用现有 `/api/clubs` 业务接口、补齐 App 屏幕和角色边界**为主，不能新造另一套社团数据模型或权限判定。

## 现有能力矩阵

| 能力 | 普通用户 | 社团管理员 | 站点管理员 | 服务端 / Web 现状 | App 现状与丙的工作 |
|---|---|---|---|---|---|
| 浏览社团、活动、帖子 | 可读 | 可读 | 可读 | `GET /api/clubs/feed`、`/list`、`/activities`、`/posts`，Web 路由已存在 | App 缺失；补列表、详情及空/错/加载状态。 |

| 关注社团 | 登录后可切换 | 可切换 | 可切换 | `POST /api/clubs/:id/follow` | App 缺失；补登录态提示、切换反馈。 |
| 活动报名/取消 | 登录后可报名或取消 | 管理员不可报名本社团活动 | 可管理 | 注册、取消、报名状态接口已存在 | App 缺失；补报名状态、容量/截止/重复操作反馈。 |

## 已确认的 Web 参考面

- Web 路由：`frontend/src/routes/layoutRoutes.jsx` 已覆盖社团广场、社团列表、目录、我的社团、创建、成员、主页、活动详情、帖子详情及两个发布页面。
- Web 屏幕：`frontend/src/pages/Clubs/` 已有相应参考实现。
- 服务端：`routes/clubs.js` 已实现列表、详情、关注、点赞、评论、报名、成员管理、发布、删除等接口；实际权限必须继续由服务端鉴权，App 仅据 `canManage` 等响应控制可见入口。

## App 缺口与实施边界

1. 当前 `app/src/app/` 中未发现 `clubs` 目录、社团屏幕或社团特性模块；这是明确缺口。
2. 丙在批次 4 新建 App 社团屏幕、领域 API 适配与角色显示，复用现有 `/api/clubs`；不得改写甲的导航壳、公共鉴权和请求基座。
3. 社团路由完成后，丙向甲交付：屏幕导出、目标路径、必填路由参数、登录前后行为；甲负责挂入广场与一级导航。
4. 媒体上传、报名表导出和真实设备下载/分享属于高风险验收项，必须以真机或受控测试环境实际验证，不能用页面渲染代替。

## 批次 4 验收门槛

- 普通用户不能看到或调用社团管理动作。
- 社团管理员只能管理所属社团；站点管理员保留跨社团管理权限。
- 报名、点赞、评论、关注在成功与失败后均有可见反馈，刷新后状态与服务端一致。
- 发布成功返回对应详情或社团主页，不滞留在已提交表单。
- 任何 App 端隐藏按钮都不能替代服务端权限校验。
