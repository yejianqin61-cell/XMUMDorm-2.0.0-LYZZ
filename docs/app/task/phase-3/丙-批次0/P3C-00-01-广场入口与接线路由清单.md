## 1. Where this task sits

- **Phase 3-0 新骨架可运行**：先证明丙的业务入口可被甲安全接入。
- 本任务落实广场入口清单，不改导航壳或公共路由。
- **开始前**：甲冻结导航契约。**后续依赖**：Phase 3-1 的广场入口回归。

## 2. What the developer needs to know

**Read first**

- `docs/app/task/Phase3全面治理工程计划.md` — 确认广场与三人边界。
- `app/src/app/(tabs)/campus.tsx` — 确认现有广场入口数据。
- `app/src/app/campus/index.tsx` — 确认树洞／万能墙入口参数。
- `app/src/app/market/index.tsx` — 确认二手屏幕的路由出口。
- `app/src/app/errand/index.tsx` — 确认跑腿屏幕的路由出口。

**Settled**

- 广场入口同级；食堂不承载其他服务。
- 树洞和万能墙不再是一级 Tab。
- 甲接路由、深链和导航；丙只交付清单。

**Edges and seam**

- 触及丙域的屏幕出口和路线资料。
- 验证缝隙是广场入口到目标屏幕的现有路由。
- 不触及 `app/src/app/(tabs)` 的导航结构。

**Run**

- `cd app && npm test -- --runInBand p2x-bing-campus p2x-bing-market-errand`
- `cd app && npm run typecheck`

**Unknowns**

- 若目标页没有现有 App 路由，记录为甲的接线项。
- 若返回状态需要导航壳修改，停止并提交给甲。

## 3. The workflow

1. 阅读上述文件并重述：为甲交付丙域入口、参数和返回需求。
2. 列出六个广场入口及其用户可见名称。
3. 定位每个入口当前可用的 App 屏幕与参数。
4. 写入登录要求、失败表现和返回目标。
5. 标注甲的路由／深链接线项。
6. 运行入口相关测试和类型检查。
7. 提交入口清单。
