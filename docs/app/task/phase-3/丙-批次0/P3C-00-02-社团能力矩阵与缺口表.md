## 1. Where this task sits

- **Phase 3-0 新骨架可运行**：先验证完整社团能否做成闭环。
- 本任务把已有 Web 和后端能力映射到 App 所需能力。
- **开始前**：无。**后续依赖**：Phase 3-5 的社团实现。

## 2. What the developer needs to know

**Read first**

- `docs/app/task/Phase3全面治理工程计划.md` — 确认完整社团的范围和验收。
- `routes/clubs.js` — 确认现有后端端点与权限边界。
- `frontend/src/pages/Clubs/ClubsHome.jsx` — 确认现有用户端能力。
- `frontend/src/pages/Clubs/ClubMembersPage.jsx` — 确认成员管理能力。
- `__tests__/frontend/clubDirectory.test.js` — 确认已有行为证据。

**Settled**

- 社团本期必须完整，不降级为入口或最小主页。
- `clubs` 与 `organizations` 保持两套数据。
- 客户端权限只读取服务端布尔字段。

**Edges and seam**

- 触及社团业务路由、服务、Web 参考和 App 屏幕规划。
- 验证缝隙是 `routes/clubs.js` 的端点与既有 Web 测试。
- 不修改共享鉴权、甲的发布注册表和导航。

**Run**

- `npm test -- __tests__/frontend/clubDirectory.test.js --runInBand`
- `node --input-type=commonjs --check < routes/clubs.js`

**Unknowns**

- 分类筛选、成员移除和导出能力可能不全。
- 任一能力无真实端点时，写入缺口表，不用 App 假实现。

## 3. The workflow

1. 阅读上述文件并重述：把完整社团分成可验证的 App 能力。
2. 按发现、主页、活动、帖子、成员、我的社团、管理七类建矩阵。
3. 为每类定位现有路由、权限、Web 页面和测试证据。
4. 标注 App 缺失屏幕与后端缺口。
5. 定义普通用户和管理员的验收路径。
6. 运行 Web 测试与 CJS 语法检查。
7. 提交能力矩阵与缺口表。

## 4. The test cases

| Case | Input | Expected | Seam |
|---|---|---|---|
| 1 | 发现社团 | 有分类、搜索或列表端点 | `routes/clubs.js` |

| 3 | 活动报名 | 有报名和取消语义 | 社团活动端点 |
| 4 | 管理成员 | 有成员和角色能力 | 成员端点 |
