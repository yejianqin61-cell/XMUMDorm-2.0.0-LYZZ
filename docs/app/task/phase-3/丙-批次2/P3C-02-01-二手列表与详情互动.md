## 1. Where this task sits

- **批次 2 服务列表完成**：二手要形成“列表 → 筛选／搜索 → 详情 → 互动”的可验证闭环。
- 本任务实现 FR-02：两行文字页签、搜索、价格筛选，以及详情点赞／评论／举报。
- **开始前**：批次 0 完成。**后续依赖**：甲接入公共词条和广场入口。

## 2. What the developer needs to know

**Read first**

- `app/src/features/marketplace/MarketScreens.tsx` — 当前筛选、列表缓存和详情交互的真实边界。
- `shared/api/marketplace.js` — 二手列表、详情及已有写入契约。
- `routes/marketplace.js` — 是否存在真实评论、举报与收藏相关端点。
- `app/src/components/ui/TopTabStrip.tsx` — 二级导航不能被另一套胶囊控件替代。

**Settled**

- 分类为两行、可横向滚动的文字页签，选中态是红色粗下划线。
- 搜索在分类上方；价格筛选位于状态页签之下；不保留产品收藏入口。
- 公共组件、i18n、公共请求/鉴权底座不由丙修改。

**Edges and seam**

- 触及 `features/marketplace` 与其业务 API 适配；不改导航壳或公共 UI。
- Seam：`MarketListScreen`、`MarketDetailScreen` 与 marketplace 域契约。

**Run**

- `cd app && npm test -- --runInBand p2x-bing-market-errand`
- `cd app && npm run typecheck`

**Unknowns**

- 评论或举报没有真实服务端端点时，停止写假成功 UI，登记阻塞并保留只读/已有能力。

## 3. The workflow

1. 读取四个入口，重述现有契约与缺口。
2. 为两行页签、搜索/价格组合写失败测试。
3. 用已有公共组件完成列表层级，保持筛选、滚动和分页状态。
4. 为详情互动逐项确认真实端点、权限和错误语义；缺口写入阻塞册。
5. 补空、加载、错误、权限/无网状态及无障碍标签。
6. 运行目标测试和 typecheck，提交。

## 4. The test cases

| Case | Input | Expected | Seam |
|---|---|---|---|
| 1 | 分类、状态、搜索和价格组合 | 请求条件与列表结果一致 | `MarketListScreen` |
| 2 | 切换分类后返回 | 各列表位置和分页状态不丢失 | 查询快照 |
| 3 | 价格非法或 min 大于 max | 不发出错误业务请求，给出可理解错误 | 价格校验 |
| 4 | 未登录/无权限互动 | 不显示假成功，给出登录或拒绝处理 | `MarketDetailScreen` |
| 5 | 无评论或举报后端契约 | 对应入口不出现或明确登记阻塞 | marketplace API |
