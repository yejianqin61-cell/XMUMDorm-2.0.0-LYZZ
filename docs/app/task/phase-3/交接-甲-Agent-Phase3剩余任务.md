## A1 · 广场、业务路由、深链和返回栈

### A1-01 广场发现入口

- **修改范围**：一级导航/广场注册表、业务路由注册、深链配置、返回栈策略。
- **接入模块**：二手、跑腿、指南、树洞、万能墙、社团。
- **现状**：`/(tabs)/index.tsx` 尚未把这些模块作为广场可达入口；丙已交付各领域能力与推荐路径。
- **实现要求**：
  1. 从广场可进入每个承诺模块；不得只展示静态卡片。
  2. 详情页返回应回到原列表和原筛选/滚动语义，不能跳到已提交表单或空白页。
  3. 处理冷启动深链到详情页的参数校验、未找到、未登录与会话失效。
- **验收**：每个模块完成一次“广场 → 列表 → 详情 → 返回”；对二手、跑腿、树洞至少各写一条路由/返回测试。
- **来源**：P3C-01-01，`丙-批次0/交付-P3C-00-01-广场入口与路由接线清单.md`。

### A1-02 社团页面路由

- **建议路径**：`/clubs`、`/clubs/[id]`、`/clubs/activity/[id]`、`/clubs/post/[id]`、`/clubs/me`、`/clubs/[id]/manage`。
- **使用丙交付**：`listClubs`、`readClubPage`、`readClubProfile`、`readClubActivityDetail`、`readClubPostDetail`、`useClubFollow`、`useClubLike`、`useClubActivityRegistration`。
- **权限要求**：只根据后端 `viewer.following`、`viewer.isMember`、`viewer.canManage` 显示动作；不得客户端猜测管理员身份。
- **验收**：普通用户完成“发现 → 关注 → 活动 → 报名 → 取消”；管理员入口只向 `canManage` 用户出现。
- **来源**：P3C-04-10A，`丙-批次4/交付-P3C-04-社团契约与接线清单.md`。

## A2 · 公共组件与表单宿主扩展

### A2-01 两行横滚下划线筛选组件

- **解决**：P3C-02-01A（二手）、P3C-02-02A（跑腿）。
- **现状**：`FilterChips` 是多选胶囊；`TopTabStrip` 是单行二级导航，均不符合需求。
- **实现要求**：抽取公共组件或扩展现有组件，支持两行文字、横向滚动、单选、激活态红色粗下划线、读屏语义和小屏可达性。
- **接入**：二手分类/价格，跑腿类型/状态；业务状态仍保留在各领域。
- **验收**：两个独立消费者都可切换且请求参数正确；键盘/读屏可识别当前选项；不得复制两套组件。

### A2-02 动态分类二级页签

- **解决**：P3C-02-03A（Handbook）。
- **现状**：`getHandbookTabs()` 返回真实分类，但 `TopTabStrip` 只能接受预置 i18n 的静态定义。
- **实现要求**：公共二级导航支持 API 分类数据；为动态标签定义安全的展示/无障碍文案策略；“全部”仍是稳定的本地词条。
- **验收**：分类来自接口时可切换、空分类和长分类名不截断到不可使用；不把后端文本硬塞进静态 i18n 类型。

### A2-03 树洞多图浏览

- **解决**：P3C-03-02A。
- **现状**：`MediaGrid` 只有网格和单图 hero。
- **实现要求**：在公共媒体能力中提供横滑、多图页码/当前项、手势冲突处理、最大字号与读屏替代文本；树洞列表消费该能力。
- **验收**：1、2、3、4+ 图片场景可浏览；横滑不会触发列表误滚；亮暗主题可见。

### A2-04 发布表单远程可搜索/可创建选项

- **解决**：P3C-03-04A（新建话题）。
- **现状**：后端已有 `POST /api/posts/tags`，公共 `multiselect` 只能选择预加载选项。
- **实现要求**：在发布宿主提供防抖搜索、加载/失败/空态、创建远程选项、重复提交锁和服务端失败提示。
- **验收**：搜索已有话题；创建成功后立即被选中且进入公开列表；网络失败不显示假成功。

- **解决**：P3C-02-01B。
- **现状**：`routes/marketplace.js` 与 `shared/api/marketplace.js` 缺商品评论/举报契约。

### A3-02 跑腿举报路由对齐

## A7 · Web 质量门 CI（工程缺口）

- **现状**：`.github/workflows/app-rulers-and-tests.yml` 仅安装 App/根共享依赖，不安装 `frontend`，也不跑 `frontend` 的 `lint`、`build`。本地已验证两项均通过，但 PR 不会自动守住。
- **实现要求**：新增 Web job 或扩展现有 workflow：
  1. `frontend` 目录执行 `npm ci`，缓存键使用 `frontend/package-lock.json`；
  2. 执行 `npm run lint` 和 `npm run build`；
  3. root Jest 中的 `__tests__/frontend/frontendSourceLint.test.js` 在 Web 依赖存在时执行真实 `no-undef` 扫描；
  4. 将 `frontend/**` 与对应 workflow 文件加入触发路径。
- **验收**：干净 GitHub runner 上 Web lint/build/no-undef 均通过；故意引入未定义变量时 job 失败。
