# Phase 3 Task 02 · 设备矩阵验收

## 1. Where this task sits

- Phase 3 设备证据与发布材料收口：把 development build 变成可复核的页面观察证据。
- This task moves R-4 完成 13.1 development build 设备验收 across the existing page matrix.
- Starts after：Task 01 development build 记录. Waits on：Task 03 大屏复测 and Task 04 缺陷收口。

## 2. What the developer needs to know

**Read first**

- `docs/app/test/甲-逐屏13.1验收记录.md` — 甲批次 pages and checks.
- `docs/app/test/乙-逐屏13.1验收记录.md` — 乙批次 pages and checks.
- `docs/app/task/phase-0/P0-10-安全区与机型矩阵验收.md` — device and orientation matrix.
- Task 01 build record — build identity to write beside each result.

**Settled**

- Static tests do not count as device evidence.
- Record touch target, back behavior, orientation, font scale, screen reader, and reduced motion separately.
- A failed or unobserved check remains open.

**Edges and seam**

- Touches the existing 13.1 records and device evidence. Leaves shared layout code for Task 03.
- Seam: current page-by-page acceptance tables.

**Run**

- Run the development build on the available matrix devices.
- Run the relevant App regression tests after any code fix.

**Unknowns**

- If a required device or build is unavailable, mark the row unverified and name the missing evidence; do not mark pass.

## 3. The workflow

1. Read this brief and restate the task as: verify every required 13.1 observation against one build.
2. Copy the build identity into the acceptance records.
3. Execute the matrix checks for the available pages.
4. Record pass, fail, or unverified with observation and evidence location.
5. Link every fail to the unique defect ledger.
6. Commit only the evidence changes for this task.

## 4. The test cases

| Case | Input | Expected | Seam |
|---|---|---|---|
| 1 | page and device | each required check has a result | 13.1 record |
| 2 | failed check | defect id and repro condition exist | defect ledger |
| 3 | unavailable device | row stays unverified | matrix record |
| 4 | maximum font size | content remains usable or defect is recorded | device observation |
| 5 | reduced motion | behavior is observed or explicitly absent | device observation |
