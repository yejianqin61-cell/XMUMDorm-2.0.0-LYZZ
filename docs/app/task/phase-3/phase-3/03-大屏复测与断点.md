# Phase 3 Task 03 · 大屏复测与断点

## 1. Where this task sits

- Phase 3 设备证据与发布材料收口：确认大屏观察结果是否需要公共断点调整。
- This task moves R-4 完成 13.1 development build 设备验收 for large-screen behavior.
- Starts after：Task 01 build record. Waits on：Task 04 defect closure.

## 2. What the developer needs to know

**Read first**

- `docs/app/task/phase-2/P2Y-C03-逐屏验收与审计.md` — prior large-screen findings.
- `app/src/design-system` — existing spacing and layout seams.
- `app/src/components/ui/Screen.tsx` — shared safe-area and container behavior.
- Task 02 device records — observed pages and open failures.

**Settled**

- Reuse the shared layout seam before adding a page-specific workaround.
- A device observation decides whether a breakpoint is needed.
- No visual redesign or new product behavior belongs here.

**Edges and seam**

- Touches shared layout only when a recorded observation proves it necessary. Leaves page domain modules alone.
- Seam: existing `Screen` and design-system layout primitives.

**Run**

- Run the large-screen device observation first.
- If code changes, run `npm.cmd run typecheck` and the affected App tests.

**Unknowns**

- If no large-screen device is available, record the missing observation and do not change layout speculatively.

## 3. The workflow

1. Read this brief and restate the task as: decide the large-screen change from device evidence.
2. Review prior findings and current shared layout behavior.
3. Reproduce the affected pages on the target large-screen size.
4. Record whether the current breakpoint is sufficient.
5. If insufficient, patch the smallest shared seam and run its tests.
6. Link the result to the device record and commit.

## 4. The test cases

| Case | Input | Expected | Seam |
|---|---|---|---|
| 1 | large-screen page | no clipped or stranded content | shared layout |
| 2 | wide content | readable width and alignment | shared layout |
| 3 | no device evidence | no speculative code change | evidence record |
