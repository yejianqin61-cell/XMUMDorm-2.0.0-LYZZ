# Phase 3 Task 05 · 法务正文接入

## 1. Where this task sits

- Phase 3 设备证据与发布材料收口：把批准的法律文本接入静态页。
- This task moves R-5 替换隐私政策和服务条款占位正文 into the app without inventing legal language.
- Starts after：正式中英文文本和版本日期可用。 Waits on：Task 06 静态页回归。

## 2. What the developer needs to know

**Read first**

- `app/src/features/me/legal.ts` — current legal page model and placeholder boundaries.
- `app/src/i18n/zh.ts` — Chinese legal copy source.
- `app/src/i18n/en.ts` — English legal copy source.
- `docs/app/TODO.md` — TD-61 and release wording constraints.

**Settled**

- Legal text comes from the owner; the developer must not author or infer it.
- Chinese and English must identify the same approved version and date.
- Remove placeholder wording only when replacement text is supplied.

**Edges and seam**

- Touches legal static-page content and its version metadata. Leaves navigation and unrelated copy alone.
- Seam: existing legal page data structure and static-page renderer.

**Run**

- Run the existing legal-page and i18n checks.
- Run `npm.cmd run typecheck` after content/type changes.

**Unknowns**

- If approved text is absent, stop and record the external input blocker; do not fabricate a substitute.

## 3. The workflow

1. Read this brief and restate the task as: insert the owner-approved bilingual legal version.
2. Verify the supplied text has a version, date, and matching language scope.
3. Replace only the placeholder payload and related metadata.
4. Search for remaining placeholder phrases in the legal surface.
5. Run legal-page, i18n, and typecheck checks.
6. Commit the content change and evidence.

## 4. The test cases

| Case | Input | Expected | Seam |
|---|---|---|---|
| 1 | approved Chinese text | page has no placeholder | legal page |
| 2 | approved English text | page has no placeholder | legal page |
| 3 | version and date | both languages match | legal metadata |
| 4 | missing approval | no content is invented | external-input gate |
