## 1. 目标

把**本 App 头号功能**的形态立起来：**内嵌 WebView 打开三个校方系统 · 记住会话 · 注入 JS 读课表 `<table>`**，并把结果**降级安全**地交给下一个环节（`POST /schedule/import/preview`，Phase 1）。同时把 R3 的**可行性结论**落成书面材料。

## 2. 依据

- 宪法 **4.1.2**（形态＝内嵌 WebView；AC＝学号登录；Moodle/签到 若走 Google SSO → 单独降级为系统浏览器；⛔ **工具 Tab 里只有这三个是网页**，其余全部原生）
- 宪法 **4.1.2-2/3**（凭据两套：**我们自己的 JWT 走 `expo-secure-store`**；**校方凭据由平台 WebView 的 cookie 存储持有**，⛔ App 代码不读、不落盘、不上传）
- 宪法 **4.1.2-4**（⛔ 不得自动化签到或代替用户完成校方动作）
- 宪法 **4.3.4-5**（App Store 4.2 Minimum Functionality 风险必须主动化解）
- 宪法 **4.1.2-6 / C-04 残余 / D-08**（六项待实测：双解析域名只写域名 · 内嵌可行性 · 会话保持 · 课表页渲染时机与列语义 · Moodle/签到登录方式 · 使用条款）
- 宪法 **17.3**（全屏 WebView **必须把 insets 传给内嵌页**；⛔ 内嵌页不得自绘状态栏背景）

## 4. 实现要点

### 4.1 三个系统的配置（**只写域名**）

| id | 域名 | 登录方式 | 内嵌 |
|---|---|---|---|
| `ac` | `ac.xmu.edu.my` | **学号登录**（已确认） | ✅ webview |
| `moodle` | `l.xmu.edu.my` | **待实测**（若 Google SSO → 降级） | ⏳ 待实测 |
| `checkin` | `acad.xmu.edu.my/mobile` | **待实测** | ⏳ 待实测 |

- ⛔ **绝不写 `10.68.x.x` / `203.106.6.x`**（内外双解析；写 IP 会在另一种网络下直接失败）。
- 三个系统**只在校内使用**（所有者裁决）→ **不把校外可达性当需求**，但要注意"校外打不开"必须给**可理解的错误**（不是"网络错误"）。

### 4.2 会话与凭据（两套，不得混）

- 我们自己的 JWT：`expo-secure-store`（⛔ 不进 AsyncStorage 明文）。
- 校方凭据：**由平台 cookie 存储持有**（iOS `WKWebsiteDataStore.default()` / Android `CookieManager`）→ ⛔ **App 代码不读取、不落盘、不上传**；⛔ 后端不得接收校方凭据（安全红线）。
- `incognito={false}`、`cacheEnabled`、`sharedCookiesEnabled`（iOS）、`thirdPartyCookiesEnabled`（Android）按 R3 证据逐项设。

### 4.3 注入读表

- 注入时机三重：`injectedJavaScriptBeforeContentLoaded`（设 UA/insets CSS）+ `injectedJavaScript`（DOM 就绪后第一次采集）+ `ref.injectJavaScript`（**页面异步渲染时轮询重试**，因为课表可能是 SPA 异步出表）。
- 回传：`window.ReactNativeWebView.postMessage(JSON.stringify({ type, payload }))` → `onMessage` 解析 → `extractSchedule`。
- ⛔ **不注入任何"点击/提交/签到"脚本**（宪法 4.1.2-4：只做"打开 + 保持会话"）。

### 4.4 insets 传递（宪法 17.3）

- **外层容器**负责顶部/底部安全区（WebView 视图本身不铺到物理边缘）；
- 同时用 `injectedJavaScriptBeforeContentLoaded` 给内嵌页注入
  `document.documentElement.style.setProperty('--dorm-inset-top', '<n>px')` 等，供内嵌页自行避让；
- ⛔ **内嵌页不得自绘状态栏背景**（会出现双层条）；
- 该 WebView 页是**覆盖层**→ 按 S7 自己处理 insets，⛔ 不复用页面结果。

### 4.5 App Store 4.2 风险化解（知情）

① 工具 Tab 在感知上**不等同于浏览器**；② 该能力必须与**原生**课表/待办**同屏同层**呈现；③ 上架前做一次专项自评（登记 [TODO](../../TODO.md)）。

## 5. 验收标准

| # | 判据 |
|---|---|
| H1 | 配置里 **0 个 IP**（源码扫描 `\d+\.\d+\.\d+\.\d+`） |
| H2 | 三个系统的 URL 均为 **HTTPS** 且路径正确 |
| H3 | 注入脚本**不含**任何 `click(` / `submit(` / `dispatchEvent` / 自动签到语义词 |
| H4 | `extractSchedule` 对三种输入（正常表 / 空表 / 异步未出现）都有确定输出，**不抛异常** |
| H5 | 制表符文本格式与 `POST /schedule/import/preview` 的入参口径一致（列数一致、无空行） |
| H6 | 容器把 insets 同时传给**外层**与**内嵌页 CSS 变量**；⛔ 无内嵌页自绘状态栏 |
| H7 | 凭据：**0 处**读取/存储/上传校方 cookie 的代码；JWT 只走 `expo-secure-store` |
| H8 | `embed: 'external'` 分支存在（Moodle/签到 走 Google SSO 时的降级路径可用） |

## 7. 风险与降级

| 触发 | 降级动作（**写在前面**） |
|---|---|
| AC 拒绝内嵌 / 注入读不到表 | **降级路径 A**：课表改**手工粘贴文本**（`extractSchedule` 的文本通道升为主路径）+ 校方系统改**系统浏览器外链**；⛔ `react-native-webview` 不引入 |
| Moodle/签到 走 Google SSO | 该格 `embed: 'external'`（Google 官方明令禁止嵌入 webview 做 OAuth）；**不影响 AC 主链路** |
| 校方系统使用条款不允许内嵌 | 三个系统全部降级为外链，**头号功能降级为"打开 + 粘贴"**，并把结论写进 C-04/D-08 |
