## 4. 实现要点

### 4.1 `resolveInsets` 的输入输出（唯一计算点）

```ts
type Input = {
  insets: { top: number; bottom: number; left: number; right: number };
  topMode: 'topbar' | 'overlay' | 'none';      // 页面意图
  bottomMode: 'tabbar' | 'own' | 'none';       // 底部留白归属（S5）
  keyboardHeight: number;                      // 0 = 键盘收起
  tabBarHeight: number;                        // 原生 Tab 栏高度（不含 inset）
};
type Output = {
  headerPaddingTop: number; contentBottomPadding: number;
  contentPaddingLeft: number; contentPaddingRight: number;
  keyboardPadding: number;
};
```

**规则（逐条对应铁律）**：
1. `topMode='topbar'` → `headerPaddingTop = insets.top`（顶栏背景向内延展到屏幕顶边；⛔ 不用 `StatusBar.currentHeight`）。
2. `bottomMode='tabbar'` → **`contentBottomPadding = tabBarHeight`，不含 `insets.bottom`**（S5：原生 Tab 栏**自带**安全区处理 → 我们再叠一层就是双倍空白）。
3. `bottomMode='own'`（粘性输入条/底栏）→ `contentBottomPadding = insets.bottom`（**唯一叠加处**）。
4. `keyboardHeight > 0` → `keyboardPadding = keyboardHeight`（**键盘高度与 bottom inset 合并**：键盘已经盖住手势条区域，⛔ 不得 `keyboardHeight + insets.bottom`，那正是 S6 要防的悬空/顶出）。
5. 左右一律 `insets.left/right`（横屏、曲面屏、折叠屏外屏；S1：读真实值）。
6. **大屏**：`sw ≥ 600dp` 时内容最大宽度收敛（`maxContentWidth`），⛔ 不做竖屏拉伸（宪法 5.3）。

### 4.2 容器纪律

- `SafeAreaProvider` **只挂一次**（根 `_layout.tsx`，S4）；⛔ 页面里再套 Provider 视为未完成。
- ⛔ **不许出现 `SafeAreaView`**（S3）；全仓 0 处导入。
- **覆盖层各自处理**（S7）：本任务的 `Screen` 提供 `overlay` 形态（模态/Sheet/Toast/全屏 WebView 用），**不允许**覆盖层复用页面的 insets 结果。
- **S8**：iOS `ScrollView` 默认自动调整内容内边距 → 容器里统一显式设置 `contentInsetAdjustmentBehavior="never"`，两端行为一致。

## 7. 风险与降级

| 风险 | 降级 |
|---|---|
| 原生 Tab 栏自身高度不可得 | `tabBarHeight` 由导航壳传入常量 + 真机校准；**仍不叠加 `insets.bottom`**（S5 优先） |
| 键盘高度事件在 Android 上抖动 | 用 `Keyboard` 事件 + 200ms 去抖；**去抖期间不改变 `contentBottomPadding`** |
| `contentInsetAdjustmentBehavior` 与原生 Tab 冲突 | 记 ADR；⛔ 不退回"两端各靠默认行为"（S8） |

### 8.1 与本文档原口径的差异（**如实记录**）

| 项 | 文档原口径 | 实际做法 | 原因 |
|---|---|---|---|
| 键盘高度去抖 | §7 风险表写"用 `Keyboard` 事件 + 200ms 去抖" | **未做去抖**（直接取事件值） | Phase 0 骨架还没有输入条；去抖属 Phase 1 输入条落地时的实现细节，登记在此避免"以为做了" |
