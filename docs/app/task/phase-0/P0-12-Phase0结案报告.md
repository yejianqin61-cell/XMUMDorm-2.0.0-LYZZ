# P0-12 · Phase 0 结案报告

| 项 | 值 |
|---|---|
| 负责人 | 甲 |
| 依赖 | P0-01 … P0-11 |
| 写作用域 | 本文件 · `docs/app/task/phase-0/README.md`（状态回填） |
| 状态 | ⏳ |

## 1. 目标

按 [README §1](README.md) 的 **G1–G6** 逐条给出**证据**，并明确**哪些成立、哪些部分成立、哪些必须真机**。⛔ 不允许"整体完成 ✓"这种无法核对的结论。

## 2. 结案报告必填内容

| 段 | 必填 |
|---|---|
| **G1–G6 逐条判定** | 每条：成立 / 部分成立 / 未成立 + **可复现的命令或文件路径** |
| **提交清单** | 每个子任务的 **commit hash + 一句话**（conventional commit） |
| **测试证据** | 测试套件数 / 用例数 / 通过率 + 执行命令 |
| **四把尺子输出** | 四条命令的 exit code 与关键数字（`#hex` / `fontSize` / `ownedUiRefs` / `t(k)` / `textSafe` 达标数） |
| **四项 spike 结论** | R1 / R2 / R3 / R7 各一句话结论 + 去向（哪个文档、哪个 TODO 编号） |
| **未闭合项** | 逐条写"卡在哪 + 谁来做 + 阻塞什么"（真机项、账号类型 C-02、二级 Tab 集合 C-03/C-04…） |
| **对 Phase 1 的移交** | 乙/丙从哪个目录、哪个分支、哪些约定开始；目录定稿表（README §4） |
| **偏差登记** | 与生产计划的口径差异（README §5 的三条 + 本轮实际发生的） |
| **回滚点** | 若 Phase 1 出问题的降级路径（生产计划 §6.3 四条）在本轮的落地状态 |

## 3. 验收标准

| # | 判据 |
|---|---|
| L1 | G1–G6 每条都有**命令级证据**（⛔ 不含"应该没问题"） |
| L2 | 未闭合项**逐条**有归属与阻塞说明 |
| L3 | 移交段落能让一个**没见过本项目**的 Agent 直接开工（含目录定稿、命令、门） |
| L4 | 所有"待真机"的项在报告里**集中成一张表**，可一次跑完 |
