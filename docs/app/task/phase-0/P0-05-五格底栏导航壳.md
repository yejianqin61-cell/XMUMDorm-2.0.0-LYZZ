## 1. 目标

把 **五格底栏**（广场 / 工具 / 校园里 / 我的 / ＋发布）跑起来，其中第 5 格是**动作型格位**：点击**打开发布中心**、**底栏选中态不变**、**不进返回栈**、**重复点击不叠加**；顶栏**只有信箱一个动作**。

## 4. 实现要点

1. **第 5 格无文字标签**（§2.4）→ 平台图标名：Android `add` / iOS `plus`（⛔ **不是 Lucide `plus`**，宪法 4.9.6）。
2. **可发现性三条补偿**（§2.4）：① 无障碍标签必须读"发布"/"Publish"（⛔ 不是"加号"）② 发布中心条目自解释 ③ 首次进入不是空屏。
3. **命中区**：≥48dp / ≥44pt（视觉加号可更小，命中区不得更小）。
4. **动作型格位行为**（§3.2 六条）：点击 → push `/publish`，**底栏选中态不变**；关闭 → 回到点击前的**一级 Tab + 二级 Tab + 滚动位置**；返回键在发布中心内 → 关闭发布中心本身；**重复点击不叠加**（用路由去重，见 4.4.4）。
5. **降级开关**：若 R2 结论是"原生容器做不到动作格位" → `publishSlot='fab'`（四格 + 发布 FAB），**改动局限在导航壳**，并请所有者重新裁决（宪法 4.9.9）。⛔ **任何情况下不得自绘 Tab 栏**。
6. **信箱**：四个一级 Tab 的顶栏右上角**四屏一致**（同一组件，不是四份实现）；角标口径来自**单一未读真源**（Phase 0 用占位 0，接口 Phase 1 接）。
7. **返回栈**：每个 Tab 独立（宪法 4.4.1）；R1 结论未出前**不锁定**返回栈实现（见 P0-09）。

## 4.8 R2 结论与实现形状（**已核实 @2026-10-02**）

> 完整证据：实解包 `npm pack expo-router@57.0.24` + `react-native-bottom-tabs@1.4.0` 读 `.d.ts` 与源码。

| 事实 | 内容 |
|---|---|
| **选 (a) `expo-router/unstable-native-tabs`** | 57 线**存在**且已具备动作型格位所需的全部机制；(c) `expo-router/native-tabs` 稳定入口是 **58.0.1** 才加的 → 选 (c) 等于弃用 SDK 57 |
| **动作型格位的官方开关 = `disabled`** | `NativeTabTrigger` 的 `disabled?: boolean` 官方描述：*"If `true`, the tab is shown but cannot be selected by tapping it in the tab bar"*；实现里 `preventNativeSelection: options.disabled`（iOS/Android 同源）；`disabled` 加入于 **56.2.0**，`isPrevented` 语义于 **56.2.10** 补齐 → SDK 57 已完整 |
| ⛔ **不要指望 `e.preventDefault()`** | `NativeTabNavigationEventMap.tabPress` 的 **`canPreventDefault: false`** → `listeners.tabPress` 里 `preventDefault()` **无效**；`href={null}` 是 JS Tabs 的能力，原生 Tabs 不适用；也没有 `role="button"` |
| **正确的接线** | 被 `disabled` 挡下时，导航器**仍会 `emit` 一个 `tabPress` 事件并带 `data.isPrevented = true`**，随后**不** dispatch `JUMP_TO` → 选中态与返回栈都不变。因此：`listeners={{ tabPress: e => { if (e.data.isPrevented) openPublishCenter(); } }}` |
| **⚠️ `disabled` 挡不住深链** | 官方注明：JS 侧 `router.push()` / `<Link />` 仍能进该路由。因为 `Trigger` 必须有 `name`，**必须**配一个 `app/(tabs)/publish.tsx` 写死 `<Redirect href="/(tabs)/square" />` 兜底，防止死路由/污染返回栈 |
| **图标** | iOS `sf="plus"`；Android `md="add"`（**需 `expo-symbols`**，缺失会静默无图标）；每个 prop 支持 `{ default, selected }` 双态 |
| **第 5 格无文字标签** | `<NativeTabs.Trigger.Label hidden />`（iOS 路径已确认会把 `options.title` 置空）；Android 的 per-Trigger `labelVisibilityMode='unlabeled'` **待真机确认**（Material 的 `labelVisibilityMode` 本是整条 `BottomNavigationView` 的属性） |
| ⚠️ **`hidden` 动态切换会重挂载导航器并重置 state** | 因此第 5 格的 label 隐藏**必须静态**，不得做成运行期切换 |
| **Plan B 记录在案** | `react-native-bottom-tabs@1.4.0` 也支持动作格位（路由级 `options.preventsDefault: true`），但它**不在主包**（在 `@bottom-tabs/react-navigation@1.4.0`，要换掉 expo-router 的 tab 容器），且 **无 per-tab label 隐藏**、Android 无 Material 图标名。**仅当 (a) 的真机第 3/4 条失败时才启用** |

**真机验证 6 条（Android 首验 / iOS 复验；⚠️ 必须用 development build，⛔ Expo Go 的返回键与 Tab 行为不可信）**：

| # | 验什么 | 通过 | 失败 |
|---|---|---|---|
| 1 | 点第 5 格后当前页内容与选中态 | 完全不变 | 整屏切换或选中态跳到第 5 格 |
| 2 | 弹出后按系统返回/侧滑 | 关掉发布中心，落回原 Tab | 停在第 5 格 |
| 3 | `tabPress` 是否触发且带 `isPrevented` | 触发；不触发则改试 `screenListeners` | 仍不触发 → 放弃 (a)，切 Plan B |
| 4 | 只有加号无文字（另四格文字必须仍在） | 其余四格文字正常 | 一起被隐藏 → 改用空标题方案 |
| 5 | `sf="plus"` / `md="add"` 图标真身 | 两端都渲染出加号 | Android 空白 = 缺 `expo-symbols` |
| 6 | `router.push('/(tabs)/publish')` 深链 | 重定向到广场、不闪屏、不污染返回栈 | 进死路由 |

### 8.1 与本文档原口径的差异（**如实记录**）

| 项 | 文档原口径 | 实际做法 | 原因 |
|---|---|---|---|
| 第 5 格的路由 | 未提 | 必须有 `(tabs)/publish.tsx` **占位路由**（只重定向到 `/`） | `NativeTabs.Trigger` 的 `name` **必须**指向存在的路由（R2 核实）；而 `disabled` **挡不住深链**（官方注明 `router.push` 仍能进）→ 不重定向就会进死路由 |
| 发布中心的顶栏 | §4 未提 | 覆盖层自有顶栏（标题 + 关闭），insets 仍由 `Screen` 注入（新增 `headerOverlay` 能力） | 4.2 的"顶栏只允许一个动作"约束的是**一级 Tab 顶栏**；模态需要自己的关闭手段（S7），但 insets 不能因此多一个调用点（S2） |
| 原生 Tabs 的单测 | 文档 §6 写了 8 条自动化用例 | **不渲染原生 Tabs**（Jest 里没有原生模块），改为验"配置 + 语义"层 | "点了不切页"本就是纯逻辑（`resolveTabPress`）；渲染层留给 §4.8 的真机 6 条清单 |
| `reanimated` 警告 | 未预料 | 测试日志里每个内联样式一条 `shared value's .value` **误报**（它把令牌的 `.value` 当 SharedValue）。试过官方 `mock.js` 关掉 → RN/screens 需要 `getUseOfValueInStyleWarning`，mock 未实现 → **保留真实 reanimated 与噪音** | 记录在此，避免后人再试一遍 |
