# 生产开发计划 — 从 0 到可内测（3 周 / 3 人）

**日期**：2026-10-02　**版本**：v1.0
**性质**：**task 层执行计划**。上游：[App 设计宪法](../constitution/App设计宪法.md)（**已批准**）· [页面清单](../product/App页面清单与结构盘点.md) · [骨架与布局规范](../design/App页面骨架与布局规范.md) · [组件类型定义](../design/App组件类型定义.md)
**协作规则**：[团队协作契约](../../team/团队协作契约.md) · [Git 协作手册](../../team/Git协作手册.md) · [协助者 Agent 守则](../../team/协助者Agent守则.md)

> **一句话结论**：**3 周做到"可内测"可行，但前提是三件事同时成立** —— ① 内测范围**砍到 40 页**（不是 88 页）；② 第 1 周必须把 `R1/R2/R3/R7` 四个 spike 打完并让**设计系统 + 四个屏幕骨架**在第 8 天前可用；③ 三个人**按轨道分工、写作用域不重叠**，每日一次合并窗口。
> **做不到 ② 就直接顺延一周**——因为乙、丙的所有页面都建在甲的基座与骨架上。

## 0. 「可内测」的验收标准（DoIT = Definition of Internal-Test Ready）

全部打勾才算内测就绪。**这是本计划的最终门，其他阶段的出口门都是为它服务。**

| # | 标准 | 判据 |
|---|---|---|
| 1 | **能装进别人的手机** | 一份 EAS 构建（AAB/APK）分发成功，**陌生设备**装得上、能冷启动 |
| 2 | **主链路可用** | 登录 → 工具（课表）→ 校园里（看帖/发帖）→ 广场（看食堂/发二手）→ 我的（看资料）**五个动作全部走通** |
| 3 | **头号功能成立** | **校方系统内嵌 → 学号登录 → 读取课表 → 导入 → 课表出现**（R3 结论） |
| 4 | **四态齐全** | 每个内测页面都有 加载/空/错误/无网；错误文案满足宪法 10.4（可感知/可理解/可改正） |
| 5 | **安全区与双主题** | 过[骨架规范 §6.5 的 10 条清单](../design/App页面骨架与布局规范.md)；暗/亮两套主题都不破版 |
| 6 | **四把尺子绿** | `design-debt-report` / `contrast-check` / `brand-ramp` / `gen-tokens` 全部 exit 0，且**已接入 CI** |
| 7 | **双语完整** | 内测页面 `t('key')` 无缺词条，无内联三元（尺子会拦） |
| 8 | **测试者能自救** | 有反馈入口（应用内"联系我们"或群），有构建号与版本号可报 |
| 9 | **声明可回滚** | 任何阶段失败都有降级路径（见 §5） |

> ⛔ **明确不属于"可内测"**：商店上架、隐私政策 URL、Data safety、ToS 门禁、屏蔽/注销、原生推送、拼车/问答、社团全套、榜单/课评/日记/放假日/地图/推荐。
> ⚠️ **其中三条是商店红线（ToS 门禁 / 屏蔽用户 / 账号注销），内测可以先不做（内部人员自用），但**上架前必须补齐** —— 别把"内测没做"当成"不用做"（宪法 12.2）。
> **内测 ≠ 上架**：内测走 **Internal / Closed testing 轨**（无需商店审核）。若要跑个人账号的 **12 人 × 14 天**计时，**第 1 个可安装构建就直接放进封闭测试轨**（见 §6 排期说明）。

## 1. 三个人 = 三条轨道（贯穿三周，不来回换人）

**分工原则**：按**业务域**切，不按"前端/后端"切；**一个人的写作用域 = 一个目录子树**，不交叉（[守则 §三](../../team/协助者Agent守则.md)）。

| 人 | 轨道 | 拥有（写作用域） | 为什么这样切 |
|---|---|---|---|
| **甲** | **基座 + 个人域** | `tokens/**`（只读消费）· `app/src/design-system/**` · **`app/src/components/ui/**`（自有 UI 组件）** · `app/src/app/**`（路由与导航壳）· `app/src/shared/**` · `app/src/i18n/**`（**共同拥有，只加 key 不删**）· `app/src/features/{navigation,auth,me,mailbox,publish}/**` · `.github/workflows/**` | 基座是所有页面的前置；个人域（登录/我的/信箱/发布）**多为 P2/P4/P15/P16 原型复用**，与基座同一个人做不会串行阻塞 |
| **乙** | **工具域（本 App 头号功能）** | `app/src/features/tools/**`（校方系统 · WebView · 课表抓取 · 课程表 · 待办） | 技术最新、风险最高，且与后端 `schedule/todos` 一对一对齐；一个人从头跟到底 |
| **丙** | **内容与社区域** | `app/src/features/{square,campus}/**`（食堂链路 · 二手 · 跑腿 · 指南 · 树洞 · 万能墙） | 全是 P1/P2/P3 列表详情复用，同一套骨架，一个人做能保持手感与一致性 |

> ✅ **目录已于 2026-10-02 定稿**（甲=所有者），最终版本见 [phase-0/README §4](phase-0/README.md)。与本文档原 `【建议】` 的两处差异：
> ① **自有 UI 组件落 `app/src/components/ui/**`** —— 因为 `design-debt-report.js` 的 `ownUiComponentRefs` 指标**硬编码统计 `components/ui/` 这个字符串**，放别处尺子永远红；
> ② 仓库根的 `shared/{api,constants,utils,config,query}` **不动**（宪法 9.6/9.7：它是 App 与 Web 共用的那五个子目录）。

**共同拥有（都要碰，必须约定顺序）**：`app/src/i18n/**`（词条）——按功能加 key，**不删别人的 key**；`docs/**`（各自的实施记录各写各的文件）。

## 2. Phase 0 · 地基与风险清除（Day 1–3）

**目标**：把"能不能做"变成"已经证明能做"。
**出口门**：① 真机上跑起**空壳 App**（五格底栏 + 二级顶部 Tab + 令牌已生效）② `R1/R2/R3/R7` 四个 spike **都有书面结论**（含"不行"这种结论）③ EAS 能出一个可安装构建 ④ 四把尺子进 CI。

| 人 | 交付 | 关键动作 |
|---|---|---|
| **甲** | 脚手架 + 导航壳 + 构建通道 | `npx expo create`（SDK 57 线）· `npx expo install` 装依赖 · expo-router 五格底栏（**第 5 格＝动作型格位**）· **唯一安全区容器**（宪法 17 条）· 接入 `tokens/generated/native-tokens.ts` · EAS 项目与首个 preview 构建 · CI 跑四把尺子 |
| **乙** | **R3 spike**（最关键） | WebView 打开 `https://ac.xmu.edu.my/` → 学号登录 → 会话是否跨重启保持 → 注入 JS 读课表 `<table>` → 产出**可行性结论 + 可复用原型代码**；顺带测 **R1 返回键**（Android target 36 是否直接退出 App） |
| **丙** | **R2 spike + 契约盘点** | 原生 Tab 在 SDK 57 的三条路（`unstable-native-tabs` / `react-native-bottom-tabs` / 等 58）**逐个真机试**，重点验证**"点了不切页"能不能做到**；同时产出**内测端点清单**（从 `shared/api/` 23 个模块里挑出 40 页用到的，标注缺参数的接口） |

**Day 3 决策会（30 分钟，三人必须到）**：
- R2 选哪条路 → 若**做不到动作型格位**：立刻改成"四格 + 发布 FAB"（宪法 4.9.9 的唯一退路），**按此调整后续所有排期**，并记 ADR。
- R1 有风险 → 按宪法 4.5 保留逃生舱，**不锁定返回栈实现**。
- R3 **不再有"成立与否"的决策点**（所有者 2026-10-02 裁决：**内嵌是硬需求，不做真机验证**）。若某个站读不到表 → 按站降级（§6.3），**形态与 `react-native-webview` 都不动**。

## 3. Phase 1 · 设计系统与四个骨架（Day 4–8）

**目标**：让"写页面"变成"拼骨架"，并把**两个纵向切片**跑通。
**出口门**：① 组件库**被真消费**（宪法 9.5：首个纵向切片必须真用组件与令牌，否则不许铺开）② 两个切片在真机可用 ③ `design-debt-report` 的 `#hex=0`、`fontSize 字面量=0`、**自有组件引用 ≥1** 全部达标。

| 人 | 交付 | 关键动作 |
|---|---|---|
| **甲** | **设计系统内测子集 + 四个屏幕骨架** | 从 82 个组件里取内测必需子集（**目标 ≈30 个**：`A01 Surface`/`A02 Text`/`A06 Icon`/`C01 Button`/`C02 IconButton`/`C06 SearchField`/`C07 Select`/`C14 SegmentedControl`/`K06 ListItem`/`K08 Card`/`K17 EntityCard`/`T01–T04 四态`/`O01 Toast`/`O08 InputSheet`…）· **`ListScreen` / `FormScreen` / `DetailScreen` / `StaticPage` 四个骨架** · i18n 词条层 + 双语 · 错误文案渲染器（宪法 10.4） |
| **乙** | **工具纵向切片（T-04 → T-05 → T-03 → T-02）** | 校方系统列表（单项配置：AC / Moodle / 签到）· 内嵌 WebView + 工具栏 · **注入读表 → 制表符文本 → `POST /schedule/import/preview` → 确认 → `/import`** · 课表周视图（`GET /schedule/week`）· 兜底"粘贴文本"入口 |
| **丙** | **食堂纵向切片（S-07 → S-08 → S-09 → S-10）** | 区域网格 → 店铺列表 → 菜品列表（分类侧栏）· 菜品详情 + 点评列表 + 图片 · 分页四态（`refresh/append × Loading/Error`）· 缓存 TTL 按后端口径（banners 5min / regions 10min / rankings 30s） |

**依赖纪律（这一周最关键）**：
- **甲的第 8 天是硬日期**：骨架没出来，乙丙不许开始铺页面（否则会各写各的样式 → 违反 1.4 全局组件化，后面返工更贵）。
- 乙丙这几天**先写页面骨架之外的确定性工作**：乙＝WebView 与抓取逻辑（Python/JS 注入脚本可先独立调），丙＝接口字段核对与列表数据层（`shared/api` 直连，不依赖 UI 组件）。

## 4. Phase 2 · 模块铺开（Day 9–15）

**目标**：把 40 页填满，进入"逐屏验收"状态。
**出口门**：① 40 页全部可进入、四态齐全 ② 每页过宪法 13.1 的逐屏清单 ③ 无 P0 级崩溃（连续使用 30 分钟不白屏）。

| 人 | 交付（按优先级） | 关键动作 |
|---|---|---|
| **甲** | **我的 9 页 + 发布中心 + 信箱 + 鉴权收尾** | M-01/02/04/13/18/19/20 · **F-01 信箱（四屏一致 + 角标口径统一）** · **P-01 发布中心（注册表驱动：万能墙/树洞/社团活动/二手/跑腿 五条 + 权限过滤）** · 私信 M-11/M-12（**4s 轮询 + 分页**，不做实时通道）· A-03/A-04 验证码链路（**开发期用 `NODE_ENV=development` 回传的验证码**） |
| **乙** | **待办 + 食堂剩余 2 页 + 工具收尾** | T-06 待办（含优先级分段、日期时间选择）· S-11 发点评（`RatingScale` 5 档，**不是星级**）· S-14 搜索（`q` 超长/为空是**业务无结果**，不是网络错误）· 工具首页 T-01（课表摘要 + 今日待办 + 校方系统卡）· 课表本地优先缓存 |
| **丙** | **校园里 4 页 + 二手/跑腿/指南 6 页** | C-01（**两个互斥子视图 + 各自滚动位置**）· C-02 详情（评论、点赞、举报入口）· C-03 搜索 · C-05 万能墙投稿（三版式 60/1000/300 上限实时切换）· S-22/23 二手（含"想要"）· S-24/25 跑腿（联系方式**详情可见、列表不返回**）· S-26/27 指南 + Markdown 阅读器 · P-02/P-05/P-06 三个发布表单（**走同一 `FormScreen`**） |

**并发纪律（三人同时改同一个 App 工程）**：
1. **每天 10:00 一个 15 分钟合并窗口**：各自把前一天的分支合进 `main`（或约定的集成分支），**只在这个窗口合**，避免整天冲突。
2. **谁先合谁先改公共文件**：`app/src/app/**`（路由）、`i18n/**`、`shared/**` 只由**甲**改；乙丙需要新增路由/词条时，**提 issue 或直接在群里说**，由甲当天加。
3. **PR 规则**（契约 §4）：乙丙的 PR 至少 1 人批准；**甲的基础设施 PR 由乙丙交叉 review**（互相看得见对方在用什么）。
4. **不通过就降级**：任何一页卡住超过 1 天，**先按"可用但简"的版本合入**（例如二手详情先不做图片查看器），不要让一个人拖住整条线。

### 6.3 回滚与降级（**写在前面，不是出事才想**）

| 触发条件 | 降级动作 | 代价 |
|---|---|---|
| **某个校方站拒绝内嵌 / 注入读不到表**（**不再是"R3 成立与否"** —— 所有者 2026-10-02 裁决：**内嵌是硬需求，⛔ 不整体放弃**） | **按站降级**：该站改系统浏览器外链；若它是 AC，则该次课表导入走**手工粘贴文本**（T-03 既有兜底）。**其余站与形态不变** | 头号功能对**那一个站**降级为"打开 + 粘贴"，**内测仍可发**；`react-native-webview` **仍然保留** |
| **R2 不成立**：原生容器做不到"点了不切页" | **降级 B**：改"**四格 + 发布 FAB**"（宪法 4.9.9 的唯一退路），并请所有者重新裁决；**代价是发布入口回到 FAB** | 底栏回到四格；骨架不变，改动局限在导航壳 |
| **甲第 8 天没交出骨架** | **进入救火模式**：甲停个人域页面，乙丙暂停铺页转做数据层与逻辑；**内测范围再砍 8 页**（先砍 S-26/27、C-03、M-18/19/20、P-06） | 内测页数 39 → 31，头号功能与社区主链路保住 |
| **某域连续两天卡住** | 按"可用但简"合入，把问题登记为内测已知缺陷（**写进内测说明**，不假装没有） | 测试者看到已知缺陷是正常的；**看不到问题才是事故** |
