## 2. The approach, requirement by requirement

### R-1 参数化发布表单骨架 `FormScreen` + 承载页接线

- **Approach**: 把 `K01` 的字段描述符 DSL 抬到**屏幕层**：一个 `FormScreen` 吃"字段描述符 + 提交函数 + 成功去向"，自己管四态、草稿、校验、错误定位与离开确认；`/publish/[type]` 只按 `PublishId` 取描述符喂给它。
- **Touches**: 组件层（新屏幕骨架）+ `features/publish`（描述符注册点）+ 发布承载路由。
- **Test seam**: 组件层已有的 `useForm` 测试接缝 + 承载页的渲染用例。**不新增接缝**。
- **Acceptance**: [ ] 三类表单只靠描述符差异生成　[ ] 四个发布入口共用同一 `FormScreen`　[ ] 草稿在进程被杀后恢复　[ ] 未知 `type` 重定向回发布中心
- **Hard part**: **字段描述符归谁写** —— 若归 `FormScreen`，三个域就都要改同一个文件（写作用域交叉）。本计划定为：**描述符按域归位**（`FormScreen` 只消费），见 §4 写作用域。

### R-2 发布中心接真实 viewer

- **Approach**: 用真实会话与后端 viewer 布尔字段替换 `PHASE0_VIEWER`；可见性仍只由 `visibleEntries()` 决定。
- **Touches**: `features/publish` + 会话层。
- **Test seam**: 注册表现有的纯函数用例（`visibleEntries`）。**不新增接缝**。
- **Acceptance**: [ ] 未登录时看不到任何发布条目　[ ] `canManageClub === false` 时看不到"社团活动"　[ ] 前端**没有**任何"本地推断权限"的代码
- **Hard part**: viewer 字段从哪个接口来 —— 若后端暂无聚合接口，先由"我的"页已有的资料接口拼出来，并**登记为待后端补齐**。

### R-3 我的域 9 页可进入

- **Approach**: 9 页多数是 `P2` 列表与 `P16` 静态页的实例化，靠骨架拼装；资料编辑走 `P4`。
- **Touches**: `features/me`（新建）+ 我的 Tab 路由。
- **Test seam**: `K05 ListScreen` 与 `P16 StaticPage` 的既有骨架接缝。**不新增接缝**。
- **Acceptance**: [ ] 9 页都能从"我的"进入　[ ] 资料编辑保存后返回可见新值　[ ] 3 个静态页（关于/隐私/条款）走同一 `StaticPage`
- **Hard part**: `M-01` 是仪表盘（`P7`），**Phase 1 没有把 `P7` 落成模块** → 这页是本域唯一"没有骨架可套"的页。

### R-4 私信 4s 轮询 + 分页

- **Approach**: 会话列表与消息流都用"轮询 + 游标分页"，进入会话开始轮询、离开即停；不做实时通道。
- **Touches**: `features/me` + `shared/api` 的私信模块。
- **Test seam**: 纯函数（轮询开关/去重/游标推进）。**不新增接缝**。
- **Acceptance**: [ ] 4s 一次且**离开页面立即停止**　[ ] 新消息不重复、不丢　[ ] 后台时不停打接口
- **Hard part**: 轮询与"下拉刷新/上拉加载"同时发生时的**去重与顺序**（`created_at` 同秒会很常见）。

### R-5 信箱 `F-01` + 角标口径统一

- **Approach**: 四个入口（顶栏、我的、校园里、广场）都指向同一个信箱页；未读数只有一个来源。
- **Touches**: `features/me` + 导航壳（顶栏角标）。
- **Test seam**: 角标计算的纯函数 + 顶栏渲染用例。**不新增接缝**。
- **Acceptance**: [ ] 四处入口都进同一页　[ ] 未读数一处为真、四处显示一致　[ ] 已读后角标立即减少
- **Hard part**: 角标是"全局状态"，而导航壳归甲、页面归甲 —— 虽然同人，但它与 `R-4` 的轮询同频，容易重复请求。

### R-6 鉴权收尾 `A-01`/`A-03`/`A-04`

- **Approach**: 启动页做会话水合与品牌位；注册与找回密码复用 `P15` 的表单卡；开发期验证码走后端回传。
- **Touches**: `features/auth` + 路由。
- **Test seam**: `features/auth` 已有的登录接缝 + 验证码链路的纯函数。**不新增接缝**。
- **Acceptance**: [ ] 冷启动能判断"已登录/未登录/会话过期"而不闪屏　[ ] 验证码倒计时与重发规则正确　[ ] 注册成功后直接进入已登录态
- **Hard part**: `A-01` 启动页与 `_layout` 的水合时序 —— 处理不好会先闪一下登录页。

### R-7 工具收尾 `T-01` + `T-06`

- **Approach**: `T-01` 是 `P7` 仪表盘（课表摘要 + 今日待办 + 校方系统卡）；`T-06` 是 `P2` 列表 + 优先级分段 + 日期时间选择。
- **Touches**: `features/tools` + `features/todos`（新建）。
- **Test seam**: `K05` 骨架 + 待办的优先级/日期纯函数。**不新增接缝**。
- **Acceptance**: [ ] `T-01` 三块内容都来自真实接口　[ ] 待办增删改与勾选生效　[ ] 优先级分段切换不改路由
- **Hard part**: `T-01` 与 `T-02` 的课表摘要若各自取数，会出现同一接口两次请求 → 用同一份缓存（R-15 的课表缓存是它的前置）。

### R-8 食堂剩余 `S-11` + `S-14`

- **Approach**: `S-11` 用 `C13 RatingScale` 的**五档**（⛔ 不是星级，见任务包 README §7-13）+ 图片 + 正文；`S-14` 是检索骨架（`P14`）的实例化。
- **Touches**: `features/square` + 路由。
- **Test seam**: `C13` 组件接缝 + 搜索的"空/超长 = 业务无结果"纯函数。**不新增接缝**。
- **Acceptance**: [ ] 发点评后详情页能立刻看到　[ ] 五档与后端 `RATING_ENUM` 完全一致　[ ] 搜索无结果是**业务空态**而不是网络错误
- **Hard part**: `S-11` 提交后要刷新 `S-10` 的评论与综合分（跨页失效），而 Phase 1 用的是自研取数外壳、不是 query 缓存。

### R-9 校园里四页

- **Approach**: `C-01` 两个**互斥子视图**（万能墙 / 树洞）各保持自己的滚动位置与分页；`C-02` 详情走 `P3`；`C-03` 搜索走 `P14`；`C-05` 投稿是三版式上限切换。
- **Touches**: `features/campus`（新建）+ 路由。
- **Test seam**: `P3 DetailScreen` 与 `P3`/`P14` 既有骨架 + `SecondaryTabStore`（Phase 1 已有的滚动位置保持机制）。**不新增接缝**。
- **Acceptance**: [ ] 两个子视图互斥且各自恢复滚动位置　[ ] 详情能点赞/评论/举报　[ ] 投稿三档上限实时切换
- **Hard part**: **`C-03/C-04` 未拍板**（二级 Tab 集合）→ 见 R-12，先用临时口径，切换点只留一处。

### R-10 二手 / 跑腿 / 指南六页

- **Approach**: 全部是 `P2`/`P3` 的实例化；跑腿的**联系方式只在详情返回**；指南用 `P10` 阅读器（Phase 1 已有 Markdown 渲染）。
- **Touches**: `features/marketplace`、`features/errand`、`features/guides`（新建）+ 路由。
- **Test seam**: `P3 DetailScreen` + `ListScreen` 既有骨架。**不新增接缝**。
- **Acceptance**: [ ] 列表接口**不出现**联系方式字段，详情才有　[ ] "想要"标记生效　[ ] 指南正文渲染 Markdown 且长文可滚动
- **Hard part**: 列"联系方式可见性"是**后端契约**问题 —— 前端只能验证"列表里没有"，不能靠前端遮掩。

### R-11 三个发布表单 `P-02`/`P-05`/`P-06`

- **Approach**: 三张表单只提供各自的**字段描述符**，其余全交给 `FormScreen`。
- **Touches**: 三个域的 feature 目录各一个描述符文件。
- **Test seam**: `FormScreen` 的接缝（R-1 建的那个）+ 各自描述符的纯函数断言。**不新增接缝**。
- **Acceptance**: [ ] 三张表单零重复布局代码　[ ] 提交成功后回到各自域并能看到新内容　[ ] 未知 `type` 不出现技术性文案
- **Hard part**: 三个域同时改"发布"这件事 → **描述符必须按域分文件**，否则三人在 `features/publish/` 上打架。

### R-12 二级 Tab 集合的临时口径

- **Approach**: 不动"二级 Tab 是顶部 Tab 条"这条宪法口径（4.8），只把集合内容做成**一处配置**；`C-03/C-04` 拍板后只改那一处。
- **Touches**: 导航配置（甲）。
- **Test seam**: 配置的纯函数断言（集合与页面一一对应）。**不新增接缝**。
- **Acceptance**: [ ] 集合只在一处定义　[ ] 改集合不需要动任何页面　[ ] 未拍板期间不出现"更多 ▾"
- **Hard part**: 一旦有人把集合硬编码进页面，后来改就要全量返工 —— 这是 Wave A 最贵的一处。

### R-13 每页四态 + 错误三要素 + 双语

- **Approach**: 每页交付时**自带**四态与词条，⛔ 不留到最后统一补；错误一律走 `toErrorCopy` 三要素。
- **Touches**: 全部页面（各自域）。
- **Test seam**: 各页组件用例 + `T0x` 四态组件的既有断言。**不新增接缝**。
- **Acceptance**: [ ] 每个新页有加载/空/错误/无网　[ ] 错误文案可感知/可理解/可改正　[ ] 双语词条零缺失
- **Hard part**: 四态很容易被"先做 happy path，回头补"拖到最后 —— 所以本计划把它放进**每页的验收项**而不是独立阶段。

### R-14 逐屏验收 13.1

- **Approach**: 每页一条验收记录（令牌无字面量 / 对比度 / 双语 / 四态 / 触控尺寸 / reduced-motion / 深链 / 返回栈 / 大屏 / 信箱入口 / 错误三要素）。
- **Touches**: `docs/app/task/phase-2/` 的验收记录文件（每人一份）。
- **Test seam**: 四把尺子是**可执行的**那一半；其余靠人逐条打勾。**不新增接缝**。
- **Acceptance**: [ ] 40 页各有验收记录　[ ] 四把尺子 exit 0　[ ] 缺项以"已知缺陷"记账而不是空缺
- **Hard part**: "逐屏验收"最容易被跳过 —— 所以它是 Wave C 的**出口门**，不是建议。

### R-15 Phase 1 遗留清偿

- **Approach**: 按价值排序清偿：课表本地优先缓存（`T-01` 依赖它）→ `S-10` 发评论与收藏 → 食堂缓存 → `S-07` 广告位/榜单 → `TodayCard`；`TD-45/46` 随页处理。
- **Touches**: 各自域。
- **Test seam**: Phase 1 已建的既有接缝（`useTimetableWeek`、`useCanteenResource`）。**不新增接缝**。
- **Acceptance**: [ ] 飞行模式下课表可见且标注"不是最新"　[ ] `S-10` 能发评论并立刻可见　[ ] 食堂读接口接上缓存（不改页面契约）
- **Hard part**: 广告位要先有 6 种 `link_type` 的目标解析（属广告模块）→ **本 Wave 不做**，只登记。

## 3. Phases

### Wave A — 跨域机制先打通（Day 9–10）

**Covers**: R-1 参数化发布表单骨架 `FormScreen` + 承载页接线 · R-2 发布中心接真实 viewer · R-12 二级 Tab 集合的临时口径 · R-15 Phase 1 遗留清偿（**只做课表缓存那一项**，它是 `T-01` 的前置）。

**Goal**: 从发布中心点一条"树洞"，能填、能提交、能在 `C-01` 看到它 —— **一条细线穿过所有层**；并且二级 Tab 集合只存在于一处配置里。

**甲（基座 + 个人域）**

- 建 `FormScreen`：吃字段描述符、管四态与草稿、接离开确认
- 把 `/publish/[type]` 的空壳 body 换成 `FormScreen`，按 `PublishId` 取描述符

## 5. 并发纪律（每天照做）

1. **每天 10:00 一个 15 分钟合并窗口**：各自把前一天的分支合进集成分支，**只在这个窗口合**。
2. **写作用域冲突 = 立刻停手**：发现要改别人目录里的文件，**先说再做**（守则 §三）。
3. **PR 规则**：乙丙的 PR 至少 1 人批准；甲的基座 PR 由乙丙**交叉 review**。
4. **一页一提交**，符合 conventional commit；**测试没过时的修复单独提交**（Phase 1 的 8 个独立修复就是这么来的）。
5. **卡住超过 1 天**：先按"可用但简"合入，把问题登记为**内测已知缺陷**（⛔ 不假装没有）。
