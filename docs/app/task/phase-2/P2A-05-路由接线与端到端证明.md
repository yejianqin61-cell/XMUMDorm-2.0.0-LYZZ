# P2A-05 · 路由接线、端到端证明与描述符交接单

**Phase A 跨域机制与发布一条线**，其目标是"点一条发布 → 填 → 提交 → 在列表看到"这条细线真的通。
**本任务推进 JR-1 的承载页接线**，并交出后续三条描述符的**交接单**（乙丙各写自己域的文件）。
**Starts after**：`P2A-04 发布表单宿主 hook 与提交门控`。**Waits on it**：乙 / 丙的描述符交付。

## 1. 本任务需要知道什么

**Read first**

- `app/src/app/publish/[type].tsx` — 现在的空壳与"未知 type 重定向"的既有断言。
- `app/src/features/publish/PublishFormHost.tsx`（本任务新建）与 `descriptor.ts` — 宿主与契约。
- `app/src/__tests__/p1-15-schedule-import.test.tsx` — **mock 路由与共享 api 的模板**（`__state` 写法照抄）。
- `docs/app/task/phase-2/开发设计文档-甲.md` §5.3 — ⛔ 甲不许写丙的 `features/campus/**`。
- `docs/app/task/phase-2/开发设计文档-甲.md` §6-G4 — 门禁源缺失的登记口径。

**Settled**

- 未知 `type` ⇒ **重定向回发布中心**（既有断言仍要绿）。
- 已注册但**描述符还没交** ⇒ 一个业务空态（"暂未开放" + 返回），⛔ 不是技术文案、⛔ 不是白屏。
- 描述符由乙丙交；甲只交**交接单**，⛔ 不代写别人的域。
- 端到端证明用**用例内的描述符**（`jest.mock` 注入），⛔ 不为测试在生产代码里开后门。

**Edges and seam**

- 碰 `app/src/features/publish/**` 与 `app/src/app/publish/[type].tsx`；⛔ 不写 `features/{campus,square,...}`。
- Seam：**S-1 页面**（路由 → 表单 → 提交 → 去向）+ **S-4**（未知 type 与缺口分支）。

**Run**

- `cd app && npx jest src/__tests__/p2a-05 --ci`
- `cd app && npx jest src/__tests__/p0-07 --ci`（既有发布用例必须仍绿）
- `cd app && npx tsc --noEmit`

**Unknowns**

- `[type].tsx` 被 `p0-07` 用源码扫描断言含 `<Redirect` 与 `PUBLISH_CENTER_ROUTE` → 改写时必须保留。
- 交接单要写清限额来源：⛔ 限额不许写进控件，必须由页面/描述符注入。

## 2. 工作流

1. 读上面五处，用一句话复述本任务。
2. 写 1 号用例（未知 type ⇒ 重定向）—— 先红。
3. 建 `PublishFormHost` 与"暂未开放"分支，让 1–2 号用例绿。
4. 加 3 号用例（缺口分支渲染空态且不发请求）。
5. 用 `jest.mock` 注入一个描述符，加 4–5 号用例（分节渲染、提交成功走向、提交失败三要素）。
6. 写交接单（三条描述符放哪、导什么、限额从哪来）。
7. 跑三个命令，提交。
