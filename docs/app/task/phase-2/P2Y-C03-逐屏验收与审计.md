# P2Y-C03 · 逐屏验收与审计

## 1. Where this task sits

- Wave C 缓存与验收收尾；推进 R-Y7 错误与逐页验收。
- Starts after：缓存和边界回归；Waits on it：冲突项最后裁决。
- 固定main基线到交付HEAD，保留用户的既有未跟踪文件。

## 2. What the developer needs to know

**Read first**
- `docs/app/constitution/App设计宪法.md` — 13.1逐页清单有哪些门？
- `docs/team/协助者Agent守则.md` — 汇报与验证的最小证据是什么？
- `docs/app/TODO.md` — 未测项应进入哪个唯一登记册？
- `docs/app/TO-CONFIRM.md` — 哪些裁决已经存在，不能重复建项？

**Settled**：自动检查不是双平台真机通过；不提交他人的未跟踪文件；固定差异审计。
**Edges and seam**：现有verify、根测试、四把尺子；乙文档与登记册增量。
**Run**：`cd app; npm.cmd run verify -- --silent`（测试阶段改用jest --silent）；根 `npm.cmd test`；`git diff --check`。
**Unknowns**：Lint缺配置、公共UI/入口归属和真机能力不足时如实登记；审计只读并平行检查Standards与Spec。

## 3. The workflow

1. 阅读第2部分并复述：每页有证据，未测项不打勾。
2. 跑全量检查并记录真实退出码。
3. 逐页写13.1记录，回写任务索引和唯一登记册。
4. 提交后在干净审计检出中固定差异做两轴复核。
5. 逐缺陷给改进方案，能独立修复的先修复。
6. 写批次小结、提交并按授权推送dev-yps。

## 4. The test cases

| Case | Input | Expected | Seam |
|---|---|---|---|
| 全量 | App源码 | 类型/测试/尺子有退出码 | verify |
| 共享JS | 根仓库 | 根测试结果明确 | npm test |
| 文档 | 新增乙文档链接 | 无新增失效链接 | 链接检查 |
| 差异 | main基线..HEAD | Standards/Spec各有证据 | 审计 |
| 分支 | origin/dev-yps已更新 | 先fetch再普通push，不force | Git |
