# P2B-04 · F-01 信箱页

**Phase B 未读真源一条线**。信箱是**推入式全屏目的地**（不是模态、不是 Tab、不进收纳处）。
**本任务推进 JR-7 信箱 F-01** 的另半边：把 `P2B-01` 的角标接到一页真的能读、能标已读、能清空的列表。
**Starts after**：`P2B-01 未读真源与顶栏角标`。**Waits on it**：`P2B-03 Q4/K22 裁决`（分类切换用哪个控件）。

## 1. 本任务需要知道什么

**Read first**

- `routes/notifications.js:156-267` — 列表载荷（`list/hasMore/page/pageSize/unreadSummary`）与**筛选优先级** `category > module > type`
- `routes/notifications.js:291-332` — 清空：**公告永不清**、三口径（`category`/`module`/`scope`）
- `app/src/components/ui/ListScreen.tsx` — `K05` 的 `labels` / `tabs` / `filterChips` 三个槽位**各司其职**（R4）
- `app/src/components/ui/ListItem.tsx` — 未读/禁止点击的呈现能力
- `docs/app/product/App页面清单与结构盘点.md` §3-F 的十条「防 Web 缺陷复发」要点

**Settled**

- 三分类（互动/交易/系统）用 **`C14 SegmentedControl` 的 `withCount`**（Q4 的默认裁决，见 `P2B-05`）；⛔ 它不是导航 Tab，故不进 `tabs` 槽位。
- `read-batch` **前端按 100 分批循环**（后端硬上限 `MAX_READ_BATCH_SIZE = 100`）。
- `target.available === false` 的通知**置灰不可点**。
- 公告（`announcement`/`system_announcement`）**不可清空**，清空确认文案要写明。
- 已读后**重新拉汇总**（不本地递减），角标随之变化。

**Edges and seam**

- 碰 `app/src/features/mailbox/**` + 改 `app/src/app/mailbox.tsx`（现在只有 13 行的空壳）。
- Seam：**S-4 纯规则**（分批、可点性、可清空性）+ **S-1 页面**（四态与筛选）。

**Run**

- `cd app && npx jest src/__tests__/p2b-04 --ci`
- `cd app && npx jest src/__tests__/p0-07 --ci`（发布入口唯一性等既有断言）
- `cd app && npx tsc --noEmit`

**Unknowns**

- `is_read` 后端**只认 `'1'`**（传 `true` 会静默返回未读）—— 参数必须用字符串。
- 信箱页自己的顶栏要不要信箱动作（它在信箱里）—— 本任务按"不显示"处理，并在页面注释写明理由。
