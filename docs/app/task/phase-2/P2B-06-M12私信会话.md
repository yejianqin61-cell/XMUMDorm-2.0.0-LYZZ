# P2B-06 · M-12 私信会话（D05/D06 + 4s 轮询）

**Phase B 未读真源一条线**的最后一环，也是**数据层风险最高**的一处。
**本任务推进 JR-6 私信 M-12**：气泡 + 输入条 + 4s 轮询 + 离开即停 + 1200 字上限。
**Starts after**：`P2B-03 M-11 会话列表页`（从它点进来）。**Waits on it**：Phase C 的「我的」入口行。

## 1. 本任务需要知道什么

**Read first**

- `routes/marketplace.js:838-898` — 读消息：`ORDER BY created_at ASC, id ASC` **`LIMIT 500`、无任何参数**（"增量"只能客户端过滤）
- `routes/marketplace.js:32,67-72,901-941` — 写消息：`MARKETPLACE_CHAT_MAX_LEN = 1200`，而且是**静默截断**不是拒绝
- `routes/marketplace.js:944-964` — 已读回执按角色写 `seller_last_read_at` / `buyer_last_read_at`
- `app/src/components/ui/Form.tsx` 的 `useForm` 与 `app/src/features/square/useCanteenResource.ts` — 本仓"手工取数外壳"的既有写法（⛔ 没有 `useQuery` 可用）
- `app/src/components/ui/InputSheet.tsx` — 输入条与键盘/inset 合并计算的既有实现（复用它的交互，不复制）

**Settled**

- 不引任何实时通道（C-07 建议 A）；**4s 轮询**，进入开始、**离开立即停**、后台停。
- 消息上限 **1200 字由客户端拦**（服务端会静默截断，用户会以为发全了）。
- 顺序按 `id` 断胜负（同秒 `created_at` 很常见）；去重按 `id`。
- `D05 ChatBubble` / `D06 ChatComposer` 必须**真的存在**（宪法 9.3：`P5` 是必须独立存在的原型，即使 1 页也不许塞进通用件）。
- 读会话时**同时**把那批 `marketplace_chat` 通知标已读（否则角标读完了还在）。

**Edges and seam**

- 碰 `app/src/components/ui/**`（两个已登记组件）+ `app/src/features/mailbox/**` + 新增一个路由文件。
- Seam：**S-1 组件契约**（两个新组件）+ **S-4 纯规则**（轮询开关 / 去重 / 顺序 / 游标推进）。

**Run**

- `cd app && npx jest src/__tests__/p2b-06 --ci`
- `cd app && npx jest src/__tests__/p0-11 src/__tests__/p1-05 --ci`（尺子用例与 C 层契约）
- `cd app && npm run rulers`

**Unknowns**

- >500 条的会话**永远丢最旧**（服务端写死 500）→ 必须在页面/文档里如实标注，⛔ 不假装有历史分页。
- 轮询与"发送后立刻可见"的竞态：发送成功后**不要**等下一次轮询才显示自己那条。

## 2. 工作流

1. 读上面五处，用一句话复述本任务。
2. 写 1–2 号用例（去重、顺序、1200 字上限）—— 先红。

6. 加 5 号用例（离开/后台不乱打接口），跑三个命令，提交。
