# P2A-01 · 描述符契约与缺口账本

**Phase A 跨域机制与发布一条线**，其目标是：从底栏第 5 格点「万能墙」，能填、能提交、能在 `C-01` 看到它 —— 一条细线穿过所有层。
**本任务推进 JR-1 P4 发布表单的宿主装配与描述符注册表**：把"发布 id → 字段描述符"的契约与"哪些还没交"的账本定下来。
**Starts after**：无。**Waits on it**：`P2A-04 发布表单宿主 hook 与提交门控`（它按本契约写 hook）。

## 1. 本任务需要知道什么

**Read first**

- `app/src/features/publish/registry.ts` — 发布注册表有哪些条目、`status` 与 `permission` 怎么表达（描述符必须与之对齐）。
- `app/src/components/ui/FormField.tsx` — 字段描述符 DSL 的 `kind`、`source`、`validate`、`neverDraft` 契约。
- `app/src/components/ui/Form.tsx` — `useForm` / `FormProps` / `SubmitSemantic` / `FormSectionDescriptor` 的既有签名。
- `app/src/__tests__/p0-07-publish.test.ts` — 既有的注册表断言（新断言不得与之冲突）。
- `docs/app/task/phase-2/开发设计文档-甲.md` §3-JR-1 — 本任务的验收项与硬骨头。

**Settled**

- `P4` 骨架**就是**组件层 `K01 Form`；⛔ 不新建 `FormScreen` 组件（组件定义 §2.7）。
- 描述符**按域分文件**，注册点由甲独占；乙丙不改注册点文件。
- 当前 5 条 `ready` 条目**都没有**描述符 → 用**缺口账本**表达；⛔ 不许把断言放宽成"允许缺失"。
- 媒体字段只能用 `kind:'custom'` + `neverDraft:true`（DSL 没有媒体 kind）。

**Edges and seam**

- 只碰 `app/src/features/publish/**`；⛔ 本任务不碰 `components/ui/**`。
- Seam：**S-4 纯规则**（本任务不渲染任何东西）。

**Run**

- `cd app && npx jest src/__tests__/p2a-01 --ci`
- `cd app && npx tsc --noEmit`

**Unknowns**

- 账本必须从注册表 `status:'ready'` **派生**后再比对：将来加一个 ready 条目而忘记录账，断言要红。
- 若发现"不新建组件就表达不了媒体字段" → 停下问，⛔ 不顺手改骨架。

## 2. 工作流

1. 读上面五处，用一句话复述本任务。
2. 写 1 号用例（缺口账本 == "ready 但无描述符"的集合）—— 先红。
3. 建描述符的类型与纯函数，让它变绿。
4. 逐条加 2–5 号用例（红→绿）：id 合法、字段名唯一、`labelKey` 在词条表里、媒体字段 `neverDraft`、`create` 必须给落地路由。
5. 跑 jest 与 tsc。
6. 提交。

## 3. 测试用例

| Case | Input | Expected | Seam |
|---|---|---|---|
| 1 | 空描述符表 + 5 条 ready 条目 | 缺口账本恰为这 5 个 id（多一个少一个都红） | S-4 纯规则 |
| 2 | 一个 `id` 不在注册表里的描述符 | 不变量断言抛错（描述符不许指向未注册的发布类型） | S-4 |
| 3 | 同一分节里两个同名字段 | 不变量断言抛错 | S-4 |
| 4 | `labelKey` 不在 `zh` 词条表里的字段 | 不变量断言抛错 | S-4 |
| 5 | 描述符声明了媒体字段却漏写 `neverDraft:true` | 不变量断言抛错；`semantic:'create'` 缺落地路由同样抛错 | S-4 |
