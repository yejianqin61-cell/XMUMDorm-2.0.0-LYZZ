# P2Y-A02 · 课表共享与导入失效

## 1. Where this task sits

- Wave A 打通共享数据；推进 R-Y1 共用课表缓存。
- Starts after：缓存往返修复；Waits on it：T01 课表摘要。
- 导入成功刷新读者；失败保留旧缓存。

## 2. What the developer needs to know

**Read first**
- `app/src/features/tools/timetable.ts` — hook 如何避免重复请求与旧响应回写？
- `app/src/app/tools/schedule-import.tsx` — commit 成功的唯一落点在哪里？
- `app/src/features/auth/tokenStore.ts` — 请求生命周期如何识别会话变化？
- `shared/config/semesters.js` — 学期与当前周的唯一真源是什么？

**Settled**：保留既有hook签名；缓存只存课程数据和非凭据身份；不改甲域会话。
**Edges and seam**：`useTimetableWeek` 与导入页渲染；课表域自有失效通知。
**Run**：`cd app; npm.cmd test -- --runInBand p2y-a02 p1-15 p1-16 p2c-03`；`npm.cmd run typecheck`。
**Unknowns**：冷启动身份不可确定时不复用其他账号缓存；无法识别身份则不持久化私有数据。

## 3. The workflow

1. 阅读第2部分并复述：同周读者共享请求，成功导入使旧版本失效。
2. 写两个读者一次请求的失败用例。
3. 实现请求合并与账号/学期隔离。
4. 加入导入失效和旧响应竞争用例。
5. 接成功导入落点并验证失败不失效。
6. 运行回归与类型检查，提交。

## 4. The test cases

| Case | Input | Expected | Seam |
|---|---|---|---|
| 同周双读者 | 同时读取week3 | 一次远端请求，两处相同课程 | hook |
