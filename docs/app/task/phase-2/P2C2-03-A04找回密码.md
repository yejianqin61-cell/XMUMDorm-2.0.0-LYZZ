# P2C2-03 · `A-04` 找回密码

**Phase C2 鉴权收尾**的最后一环。
**本任务推进 JR-8** 的第三件：找回密码（**复用** `A-03` 建立的那条验证码链路，⛔ 不另起一套）。
**Starts after**：`P2C2-02`。**Waits on it**：无。

## 1. 本任务需要知道什么

**Read first**

- `routes/auth.js:128-183` — `send-reset-code`：**要求邮箱已注册**（与发码不同）、60s 冷却、10/日、10 分钟
- `routes/auth.js:190-240` — `reset-password`：取**最新一条**未用且未过期的码、校验后置 `used_at`
- `shared/api/auth.js` — `sendResetCode` / `resetPassword`（同一处「只增字段」的改动要覆盖它们）
- `app/src/features/auth/**` 与 `P2C2-02` 的注册页 — 表单与倒计时按钮**复用**，⛔ 不复制一份
- `docs/app/product/App页面清单与结构盘点.md` §3-A 的 `A-04` 行（关键组件 `Form` `Input` `OtpInput`）

**Settled**

- 与注册**共用** `D25 CountdownButton` 与邮箱域名判定（⛔ 不建第二套）。
- `send-reset-code` 对**未注册邮箱**返回 400 → 文案不能泄露"这个邮箱存在/不存在"以外的信息？**不**：后端已经明确返回，前端**如实转达**（⛔ 不自己发明隐私策略）。
- 重置成功后**回到登录页**并给回执（⛔ 不直接进已登录态：新密码要用户自己用一次）。
- 新密码规则与服务端一致（**≥6 位**），客户端只为"少一次失败往返"。

**Edges and seam**

- 碰 `features/auth/**` + 新增路由；⛔ 不改 `shared/**` 之外的东西。
- Seam：**S-4 纯规则**（新密码校验、步骤机）+ **S-1 页面**。

**Run**

- `cd app && npx jest src/__tests__/p2c2-03 --ci`
- `cd app && npx tsc --noEmit`

**Unknowns**

- 三步（邮箱 → 验证码 + 新密码 → 完成）在**一页**里还是两页？本任务按**一页三步**（`P15` 是单页表单卡），状态用纯函数步骤机表达。

## 2. 工作流

1. 读上面五处，用一句话复述本任务。
2. 写 1–2 号用例（步骤机：没发码不能提交；新密码 <6 位拦下）—— 先红。
3. 写纯函数，让它绿。
4. 铺页面（复用注册页的字段与 `D25`），加 3–4 号用例。
5. 加 5 号用例（重置成功 → 回登录页 + 回执）。
6. 跑两条命令，提交。
