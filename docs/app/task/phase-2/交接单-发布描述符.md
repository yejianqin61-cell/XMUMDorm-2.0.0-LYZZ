## 2. 交什么（一个对象，导出一份或多份）

```ts
// 形状（类型从 @/features/publish/descriptor 引）
export type PublishFormDescriptor = {
  id: PublishId;                                   // 必须与发布注册表里的 id 完全一致
  sections: readonly FormSectionDescriptor[];       // 分节 + 字段（K01 Form 的 DSL）
  semantic: 'create' | 'update' | 'action';
  submit: (values: FormValues) => Promise<{ id?: number | string; route?: string | null } | void>;
  routeAfterSubmit?: (result) => string | null;     // ⚠️ create 语义**必填**
  mediaFields?: readonly string[];                  // 声明的媒体字段必须 neverDraft:true
  formId?: string;                                  // 默认 publish:<id>
  submitLabelKey?: MessageKey;                      // 默认 publish.submit
  successKey?: MessageKey;                          // 默认 publish.submitted
};
```

三条**会拦你**的硬规则（机器断言，不是 review 意见）：

1. **字段名在同一个描述符里唯一**；
2. 每个字段的 `labelKey` **必须在 `app/src/i18n/zh.ts`（以及 en）里存在** —— 只加 key，⛔ 不删别人的；
3. **图片/媒体字段**：DSL 没有媒体 kind，只能 `kind:'custom'` + 自己 `render` 一个 `C20 MediaPicker`，
   并把字段名写进 `mediaFields`，同时置 **`neverDraft: true`**
   （本地 URI 重启后失效，落草稿等于给用户一张坏图）。

## 3. 三条你不许做的事

1. ⛔ **不许改 `app/src/features/publish/**`**（注册点、宿主、门禁都是甲的写作用域）；
   要加一行注册，**在群里说一句**，甲当天加。
2. ⛔ **不许改 `/publish/[type]` 路由、发布中心、`K01 Form`** —— 那是骨架。
3. ⛔ **不许把限额写进控件**：`title ≤ 120` / `images ≤ 4` / 二手**不接受 gif** 这类差异
   **由你的描述符注入**（`maxLength` / `max` / `allowGif`），不是改 `MediaPicker`。

## 4. 交付后会发生什么（就是你的验收）

1. 甲在 `descriptors.ts` 的 `PUBLISH_DESCRIPTORS` 加一行，并**从 `KNOWN_MISSING_DESCRIPTORS` 删掉你的 id**；
2. `npx jest src/__tests__/p2a-01` —— 漏删或假删都会**红**（"实际缺的"必须等于"账本写的"）；
3. `/publish/<你的 id>` 从"暂未开放"变成可填可提交的真表单（`P2A-05` 的端到端用例已经证明这条路通）。
