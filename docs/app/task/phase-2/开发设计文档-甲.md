## 结论（先看这段）

1. **甲的 Phase 2 = 15 个内测页 + 发布表单宿主 + 3 处跨轨机制**（viewer / 二级 Tab 配置 / 未读真源）。15 页 = `A-01`–`A-04` + `M-01/02/04/11/12/13/18/19/20` + `F-01` + `P-01`（[生产开发计划 §1.1](../生产开发计划-三周到内测.md)）。
2. **上游计划漏算了最大的一块**：甲的页面需要 **9 个 Phase 1 没交付的组件**（`K09 K10 K15 K16 K22 C20 D05 D06 D25`）。没有它们，`M-01`/`M-02`/`M-12`/`A-03`/`A-04`/`F-01` 一页都铺不了。本文把它立为 **JR-4**，并按"随消费页交付"排进阶段。
3. **`FormScreen` 不能建。** 组件定义 §2.7 明写：`P2`/`P4` 的骨架**就是组件层的 `K05`/`K01`**，再包一层 `src/proto/P4` 就是**套壳**（9.14-②）`【已核实：App组件类型定义.md:340】`。R-1 因此重定义为「**描述符注册表 + 宿主 hook + 路由页组合 `K01 Form`**」——三件都**不是 UI 组件**。
4. **最贵的是私信链路，不是页面数量。** 后端**没有跨商品会话列表**（唯一的线程列表接口是 per-item 且**仅卖家**），消息接口**没有任何游标**（固定 `LIMIT 500` 升序）`【已核实：routes/marketplace.js:786、:862】`。这决定了 `M-11` 的形态要么动后端、要么降级并登记缺陷。
5. **最险的是权限与合规门禁没有真源。** `viewer` 要的三个布尔里，`canManageClub`/`isOrgMember` 只能从别的接口拼，**`acceptedTerms` 后端零实现**（全仓 grep 0 命中）`【已核实】`。所以本文把"**源缺失**"做成显式分支，并要求所有者签字。
6. **三件事不能假装能做完**：`M-11` 的买家侧（无接口）、A-05 门禁（无真源）、`S-10` 发评论的归属（计划内部冲突）。三件都在 §0 与 §7 写明，⛔ 不作为"默认值"。

## 3. 逐条方案

> 每条五段：**Approach**（形状）· **Touches**（模块，不是文件；精确路径在 §5）· **Test seam**（优先复用既有接缝）· **Acceptance**（可勾选）· **Hard part**（最可能出错的或还没定的）。

### JR-1 P4 发布表单的宿主装配与描述符注册表

- **Approach**: `P4` 骨架**不重写**。甲交三件**非 UI** 的东西：① **描述符注册表** —— 发布 id → 字段描述符，静态映射，甲独占这一个文件；② **宿主 hook** —— 吃描述符，管提交语义、合规门禁、成功去向、草稿 id、`neverDraft` 规则；③ **路由页组合** —— `/publish/[type]` 取描述符后直接渲染 `K01 Form`。域描述符由乙丙各写自己的文件，甲只加一行注册。
- **Touches**: 发布 feature（注册表 / hook / 提交）+ 发布承载路由 + 组件层（**只读消费**）
- **Test seam**: 复用 **S-2 骨架契约**（`Form` 的 props → 状态）+ **S-4 纯规则**（注册表不变量、描述符完整性、提交语义映射）。**不新增接缝。**
- **Acceptance**:
  - [ ] 注册表里每个 `status:'ready'` 的条目**都有**描述符；反向也成立（机器断言，先红后绿）
  - [ ] 三张发布表单（发树洞 / 发二手 / 发跑腿）**零重复布局代码**，只差描述符
  - [ ] 未知 `type` **重定向回发布中心**，⛔ 不出现"未知类型"这类技术性文案（10.4）
  - [ ] 媒体字段**不落草稿**；密码类字段永不落草稿
  - [ ] 提交成功后按 `postSubmitPlan(semantic)` 走，⛔ **不弹成功对话框**（`Form.tsx` 的类型里就没有这个选项）
  - [ ] A-05 门禁在**每个**发布表单的提交链路上生效（口径见 JR-2）
- **Hard part**: 字段 DSL **没有媒体 kind**（`FormFieldKind` 只有 `text…custom`）`【已核实：FormField.tsx:49-62】` → 图片走 `kind:'custom'` + `C20 MediaPicker` 渲染。⚠️ 但 `custom` 字段若落草稿，会把一个**重启后失效的本地 URI** 写进 AsyncStorage → 必须 `neverDraft:true`，并在草稿恢复后保证不出现"幽灵图"。

### JR-2 发布中心接真实 viewer

- **Approach**: 建一个 `useViewer()`（发布 feature）：`signedIn` 取会话；`canManageClub` / `isOrgMember` 取**后端已有的列表字段**；**拿不到就当 `false`（fail-closed）** —— 宁可不显示条目，也不显示一个点不动的入口。可见性**仍只由 `visibleEntries()` 决定**，⛔ 页面上不许再有一处权限判断。
- **Touches**: 发布 feature + 会话层（只读）
- **Test seam**: 注册表既有纯函数用例（`visibleEntries`）+ `useViewer` 的**纯映射函数**（输入后端字段 → 输出 viewer）。**不新增接缝。**
- **Acceptance**:
  - [ ] 未登录时**一条发布条目都看不到**
  - [ ] `canManageClub` **未知或 false** 时"社团活动"不显示（⛔ 不显示为禁用占位）
  - [ ] `PHASE0_VIEWER` 硬编码被删除，且**没有**任何"本地推断权限"的代码（源码扫描断言：推断只允许出现在 `useViewer` 一处）
  - [ ] viewer 的两个来源请求失败时，页面**降级为"仅通用三条"**而不是报错整屏
- **Hard part**: `/api/users/me` **不返回任何能力布尔**（`users.js:146-164`）→ 必须**多打两个请求**（`GET /api/clubs/me/clubs`、`GET /api/organizations/me`）；而 `acceptedTerms` **连来源都没有**（见 JR-12 与 Q2）。另：`/api/users/me` 有 **15s 服务端缓存**（`users.js:134`）→ 刚改的资料在本页可能延迟可见，⛔ 不要用"没变"当 bug 修。

### JR-3 二级 Tab 集合收成一处配置

- **Approach**: 集合**只存在**于 `secondaryTabs.ts` 的 `SECONDARY_TABS`。未拍板期间 `square` / `tools` / `me` 保持**空数组**（空集合 ⇒ 不渲染 Tab 条，⛔ 不显示空条）；「校园里」已定（树洞 / 万能墙）。甲只加**机制与断言**，⛔ 不预占所有者的决定。
- **Touches**: 导航 feature（配置）+ 一级 Tab 页（渲染点）
- **Test seam**: 配置的纯函数断言（集合与子视图一一对应；空集合不渲染条；溢出不得用"更多 ▾"）。**不新增接缝。**
- **Acceptance**:
  - [ ] 集合只在一处定义；改集合**不需要动任何页面**
  - [ ] 未拍板期间不出现"更多 ▾"，也不出现空 Tab 条
  - [ ] `C-03`/`C-04`/`C-05` 拍板后，落地改动 **≤ 3 个数组 + 3 行断言**
- **Hard part**: `C-05`（"我的"是否用二级 Tab）未定。本文按建议 **B（不用）** 设计 —— `M-01` = 资料卡 + 入口列表；但入口列表必须**能被 Tab 条替换而不改页面结构**，否则一旦选 A 就要重排首屏。

### JR-5 我的域 9 页可进入

- **Approach**: 9 页里 8 页是**既有骨架的实例化**（`P2` 列表 ×3、`P16` 静态 ×3、`P4` 表单 ×1 …）；只有 `M-01` 是 `P7 仪表盘`，而 `P7` **没有独立模块** —— 组件定义明写它是"页面级组合"`【已核实：App组件类型定义.md:337】`。所以 `M-01` **落页面级组合，⛔ 不为它新建 `src/proto/P7`**（那会与列表/表单骨架同罪）。
- **Touches**: 我的 feature（**新建**）+ 我的 Tab 路由
