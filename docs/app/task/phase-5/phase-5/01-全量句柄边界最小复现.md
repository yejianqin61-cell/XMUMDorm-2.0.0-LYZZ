# Phase 5 Task 01 · 全量句柄边界最小复现

## 1. Where this task sits

- Phase 5 出口根因清偿：关闭 R-8 的全量 Jest 生命周期阻断。
- 本 task 将“测试完成后挂起”缩小到可复现的 suite 边界。
- Starts after：Phase 4 Task 05。Waits on：Task 02 根因修复。

## 2. What the developer needs to know

**Read first**

- `app/jest.config.js` — Jest worker、超时和 preset 边界。
- `app/jest.setup.js` — 全局 mock 是否创建长生命周期资源。
- `app/src/shared/queryClient.ts` — QueryClient 的缓存与连接配置。
- `app/src/features/*/*Screens.tsx` — 页面级订阅和定时器清理。

**Settled**

- 不使用 `--forceExit`，句柄必须被真实清理；见 Phase 4 Task 03。
- 测试断言和产品行为不因诊断而放宽；见 R-8。

**Edges and seam**

- Seam 是 Jest suite 的进程退出边界；保留业务入口和既有测试。
- 本 task 只增加诊断证据，不修改生产代码。

**Run**

- `npm.cmd test -- --runInBand --detectOpenHandles --silent <suite>`。
- `npm.cmd run typecheck`。

**Unknowns**

- 句柄可能来自订阅、QueryClient GC 定时器或测试 mock；无法归属时停止并记录。

## 3. The workflow

1. 读取配置和候选生命周期，写出一个句子的问题边界。
2. 按候选 suite 分组运行 detectOpenHandles。
3. 对可退出组与挂起组做二分比较。
4. 记录首次引入挂起的 suite、资源类型和退出状态。
5. 运行 typecheck，确认诊断没有改变类型边界。
6. 提交诊断记录。

## 4. The test cases

| Case | Input | Expected | Seam |
|---|---|---|---|
| 1 | 已自然退出的 suite 组 | 进程自然退出 | Jest process |
| 2 | 候选 suite 组 | 复现或排除挂起 | Jest process |
| 3 | 首次引入挂起的最小组 | 资源归属可解释 | Jest process |
| 4 | typecheck | exit 0 | TypeScript |
