# Phase 5 Task 03 · 出口回归与剩余告警记录

## 1. Where this task sits

- Phase 5 出口根因清偿：验证 R-8，并更新 R-7 的可追踪状态。
- 本 task 用 fresh process 验证句柄修复，再记录 lint 未完成项。
- Starts after：Task 02。Waits on：Phase 5 summary。

## 2. What the developer needs to know

**Read first**

- `app/package.json` — verify 和 verify:serial 的真实命令。
- `docs/app/evaluation/Phase4-Task05-完整verify双次回归.md` — 两次失败边界。
- `docs/app/TODO.md` — TD-70 的当前 warning 基线。
- `docs/app/evaluation/Phase4收口小结.md` — 上期开放项。

**Settled**

- R-8 必须连续两次退出 0，不能以手动中止作为成功。
- R-7 必须继续报告 rule/file，不关闭 lint 规则。

**Edges and seam**

- Seam 是 `verify`、`verify:serial` 和 lint 输出；不新增包装器。
- 若句柄仍挂起，本 task 记录失败边界并保留开放状态。

**Run**

- `npm.cmd run verify` 两次 fresh process。
- `npm.cmd run lint`、`npm.cmd run typecheck`、`npm.cmd run rulers`。

**Unknowns**

- 若两次结果不一致，保留第一次分歧阶段，不宣称稳定出口。

## 3. The workflow

1. 读取上期失败记录，写出本期成功判据。
2. 运行第一次完整 verify 并保存阶段结果。
3. 从新进程运行第二次完整 verify。
4. 对比退出码、测试计数、句柄提示和 rulers 阶段。
5. 运行 lint、typecheck、rulers 的独立验证。
6. 写收口记录和下一步，提交本 task。

| 3 | lint | warning 可按规则追踪 | lint |
