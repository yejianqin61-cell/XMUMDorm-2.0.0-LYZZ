# Phase 2 Task 03 · 长会话夹具回归

## 1. Where this task sits

- Phase 2 私信消息完整性与合规门禁：证明超过 500 条消息不会丢失。
- This task moves R-2：用夹具覆盖首屏、历史页、空页、末页和并发轮询。
- Starts after：Task 01–02。Waits on：Phase 2 私信完整性证明。

## 2. What the developer needs to know

**Read first**

- `app/src/__tests__/p2b-06-chat.test.tsx` — 消息页现有夹具。
- `app/src/features/mailbox/chat.ts` — 纯函数边界。
- `__tests__/routes/marketplaceChatMessages.test.js` — 后端消息路由测试。
- `docs/app/evaluation/Phase2审计报告.md` — D-2 与 TD-15/TD-56。

**Settled**

- 夹具必须超过 500 条，不能用 2 条样例替代。
- 测试排序和数据完整性，不改变产品上限之外的 UI 文案。
- 不向生产数据库写测试消息。

**Edges and seam**

- 触及后端路由夹具、ChatScreen 测试和分页规则；不改推送。
- Seam：现有路由测试与 ChatScreen 测试。

**Run**

- `npm test -- --runInBand __tests__/routes/marketplaceChatMessages.test.js`
- `cd app && npm.cmd test -- --runInBand --silent src/__tests__/p2b-06-chat.test.tsx`

**Unknowns**

- 若现有测试数据库夹具无法表达 500 条以上消息，停止并说明夹具接缝缺口。

## 3. The workflow

1. 阅读本 brief，并重述：用超过 500 条的离线夹具证明消息完整性。
2. 盘点后端和 App 各自可注入的夹具位置。
3. 先写首屏、分页、空页和并发的失败用例。
4. 实现或调整夹具及断言。
5. 运行后端与 App 目标测试。
6. 提交本任务。

## 4. The test cases

| Case | Input | Expected | Seam |
|---|---|---|---|
| 1 | 501 条消息首屏 | 不超过接口页大小且游标存在 | message GET |
| 2 | 第一页后翻页 | 所有消息最终各出现一次 | message GET |
| 3 | 空历史页 | 不删除已有消息 | ChatScreen |
| 4 | 并发轮询和翻页 | 无重复、无倒序 | ChatScreen |
| 5 | 末页后继续请求 | 稳定返回空页 | message GET |
