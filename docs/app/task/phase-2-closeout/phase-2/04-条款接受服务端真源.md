# Phase 2 Task 04 · 条款接受服务端真源

## 1. Where this task sits

- Phase 2 私信消息完整性与合规门禁：用户接受当前条款版本有服务端记录。
- This task moves R-3：建立条款版本与用户接受记录的读写路径。
- Starts after：无。Waits on：发布门禁切换。

## 2. What the developer needs to know

**Read first**

- `docs/app/evaluation/Phase2审计报告.md` — D-3 与 TD-59。
- `app/src/features/me/legal.ts` — 当前条款页面和占位状态。
- `shared/api/marketplace.js` 或用户 API — 现有 API 适配风格。
- `routes/users.js` 与数据库迁移 — 用户状态和迁移惯例。

**Settled**

- 服务端当前版本是最终判断，不信任客户端缓存。
- 接受记录按用户和条款版本保存。
- 不在本任务决定法律正文。

**Edges and seam**

- 触及用户/条款后端路径、迁移和共享 API；不改发布门禁本身。
- Seam：后端集成测试和真实写入契约。

**Run**

- `npm test -- --runInBand __tests__/routes`
- `cd app && npm.cmd run typecheck`

**Unknowns**

- 若数据库没有稳定的迁移入口或现有用户表不能承载版本记录，停止并报告，不用客户端字段替代。

## 3. The workflow

1. 阅读本 brief，并重述：服务端记录并返回用户当前条款接受版本。
2. 找到用户 API、迁移和认证用户 id 的现有接缝。
3. 为读取、首次接受、重复接受和版本变化写失败测试。
4. 添加最小持久化路径和响应契约。
5. 运行后端测试、类型检查和迁移静态检查。
6. 提交本任务。

## 4. The test cases

| Case | Input | Expected | Seam |
|---|---|---|---|
| 1 | 用户读取条款状态 | 返回当前版本和接受状态 | terms API |
| 2 | 接受当前版本 | 写入用户版本记录 | terms API |
| 3 | 重复接受当前版本 | 幂等成功 | terms API |
| 4 | 接受新版本 | 保留可审计版本记录 | terms API |
| 5 | 未认证请求 | 明确鉴权错误 | terms API |
