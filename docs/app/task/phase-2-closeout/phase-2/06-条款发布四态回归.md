# Phase 2 Task 06 · 条款发布四态回归

## 1. Where this task sits

- Phase 2 私信消息完整性与合规门禁：把条款状态和发布结果固定成出口证据。
- This task moves R-3：覆盖未接受、已接受、过期和状态缺失四种结果。
- Starts after：Task 04–05。Waits on：Phase 2 收口记录。

## 2. What the developer needs to know

**Read first**

- `docs/app/task/Phase2收口改进工程计划.md` — R-3 proof。
- `app/src/__tests__/p2a-05-publish-route.test.tsx` — 发布页面门控。
- 条款服务端集成测试 — 状态和拒绝信封。
- `app/src/i18n/errors.ts` — 双语错误映射。

**Settled**

- mock 证明页面映射，真实测试账号证明服务端写入和拒绝。
- 不把缺失状态当作放行。
- 不在本任务补写法律文本。

**Edges and seam**

- 触及发布门禁回归、真实契约记录和 Phase 2 验收证据；不新增业务能力。
- Seam：现有发布测试、后端测试和 live contract。

**Run**

- 运行后端路由测试、App 发布测试和 `npm.cmd run typecheck`。
- 运行真实条款/发布契约（若无测试账号，记录未验证）。

**Unknowns**

- 若没有安全的真实测试账号或条款写入环境，停止并记录外部证据缺口。

## 3. The workflow

1. 阅读本 brief，并重述：用四态证据关闭服务端条款发布门禁。
2. 汇总 Task 04–05 的响应和错误口径。
3. 补齐四种状态的失败回归用例。
4. 运行离线、后端和真实契约测试。
5. 新建 Phase 2 验收记录，区分代码与真实环境证据。
6. 提交本任务。
