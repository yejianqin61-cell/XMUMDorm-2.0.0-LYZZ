# Phase 2 Task 01 · 消息历史游标契约

## 1. Where this task sits

- Phase 2 私信消息完整性与合规门禁：长会话可向前翻页且不丢消息。
- This task moves R-2：定义消息历史接口的游标、空页和末页响应。
- Starts after：Phase 1 私信链路。Waits on：历史分页合并实现。

## 2. What the developer needs to know

**Read first**

- `routes/marketplace.js` — 当前消息接口固定 `LIMIT 500` 的响应。
- `shared/api/marketplace.js` — App 请求入口和参数形状。
- `app/src/features/mailbox/chat.ts` — 消息归一化与排序规则。
- `docs/app/task/phase-2/P2B-06-M12私信会话.md` — 现有轮询边界。

**Settled**

- 继续使用 HTTP 分页，不引入 WebSocket。
- 游标必须由服务端定义，客户端不猜时间戳。
- 保留现有 `list` 字段，新增字段向后兼容。

**Edges and seam**

- 触及消息 GET 路由、共享 API 和契约测试；不改发送接口。
- Seam：现有后端路由测试与 live contract。

**Run**

- `npm test -- --runInBand __tests__/routes/marketplaceChatMessages.test.js`
- `cd app && npm.cmd run typecheck`

**Unknowns**

- 若数据库排序字段不足以形成稳定游标，停止并说明需要的索引或字段。

## 3. The workflow

1. 阅读本 brief，并重述：让消息接口能稳定返回向前翻页的游标。
2. 盘点当前 SQL、响应和客户端请求。
3. 为首屏、带游标、空页和末页写失败契约。
4. 实现最小游标参数与响应字段。
5. 运行路由测试、类型检查和 live contract。
6. 提交本任务。

## 4. The test cases

| Case | Input | Expected | Seam |
|---|---|---|---|
| 1 | 首次请求 | 返回最新一页和可用游标 | message GET |
| 2 | 使用游标请求 | 返回更早消息且无重复 | message GET |
| 3 | 游标越过最早消息 | 空列表且明确末页 | message GET |
| 4 | 非法游标 | 明确 400，不执行模糊查询 | message GET |
| 5 | 同一时间戳消息 | 顺序稳定 | message GET |
