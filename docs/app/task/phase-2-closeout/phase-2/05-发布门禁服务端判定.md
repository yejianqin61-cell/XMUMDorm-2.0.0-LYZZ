# Phase 2 Task 05 · 发布门禁服务端判定

## 1. Where this task sits

- Phase 2 私信消息完整性与合规门禁：UGC 发布必须服从当前条款版本。
- This task moves R-3：将发布提交门改为服务端当前版本判定。
- Starts after：Task 04。Waits on：四种发布结果回归。

## 2. What the developer needs to know

**Read first**

- `routes/posts.js`、`routes/marketplace.js` — UGC 发布入口和认证方式。
- `app/src/features/publish/descriptor.ts` — App 发布提交接缝。
- `app/src/__tests__/p2a-05-publish-route.test.tsx` — 当前发布门测试。
- `docs/app/TO-CONFIRM.md` C-22 — 暂放行决策及其边界。

**Settled**

- 服务端拒绝优先于客户端 `acceptedTerms` 字段。
- 拒绝必须保留可修正的中英文错误语义。
- 不把条款正文嵌进发布模块。

**Edges and seam**

- 触及发布后端入口、App 提交错误映射和测试；不改发布表单描述符。
- Seam：现有发布提交门控。

**Run**

- `npm test -- --runInBand __tests__/routes`
- `cd app && npm.cmd test -- --runInBand --silent src/__tests__/p2a-05-publish-route.test.tsx`

**Unknowns**

- 若存在多个 UGC 发布入口而计划未列出统一入口，停止并先汇总入口。

## 3. The workflow

1. 阅读本 brief，并重述：发布请求由服务端当前条款版本最终放行或拒绝。
2. 追踪所有发布入口和现有客户端门禁。
3. 为未接受、已接受、过期和缺失状态写失败测试。
4. 接入服务端判定与双语错误映射。
5. 运行后端、App 目标测试和类型检查。
6. 提交本任务。

## 4. The test cases

| Case | Input | Expected | Seam |
|---|---|---|---|
| 1 | 未接受当前版本发布 | 服务端拒绝并可修正 | publish API |
| 2 | 已接受当前版本发布 | 发布成功 | publish API |
| 3 | 接受旧版本发布 | 服务端拒绝 | publish API |
| 4 | 状态缺失发布 | 服务端拒绝 | publish API |
| 5 | App 收到拒绝 | 显示中英文可理解提示 | publish screen |
