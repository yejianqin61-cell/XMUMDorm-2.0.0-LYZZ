# Phase 1 Task 05 · 私信非法线程回归收口

## 1. Where this task sits

- Phase 1 真实私信链路恢复：目标是把真实链路和线程安全边界固定成可复跑出口。
- This task moves R-1 恢复真实私信会话列表链路和 R-6 增加私信线程归属校验：完成阶段回归证据。
- Starts after：Task 01–04。Waits on：Phase 2 私信历史游标。

## 2. What the developer needs to know

**Read first**

- `docs/app/task/Phase2收口改进工程计划.md` — Phase 1 目标和证明口径。
- `docs/app/task/phase-2-closeout/phase-1/03-线程进入归属预检.md` — 预检行为和测试边界。
- `docs/app/task/phase-2-closeout/phase-1/04-读写共享线程归属判断.md` — 读写动作覆盖范围。
- `docs/app/test/甲-真实后端契约验证.md` — 真实后端证据格式。

**Settled**

- 自动化测试和真实契约证据分开记录。
- 未能连接真实环境时，阶段不能写成完整交付。
- 不在本任务处理历史分页、推送或设备验收。

**Edges and seam**

- 触及 Phase 1 已改代码的回归测试和验收记录；不增加新业务能力。
- Seam：现有 live contract、ChatScreen 测试和 App 出口命令。

**Run**

- 运行目标测试、`npm.cmd run typecheck`、`npm.cmd run rulers`。
- 运行资源允许的完整串行测试，并记录跳过项和外部依赖。

**Unknowns**

- 若真实后端仍未部署，阶段只能以“仓库内完成、外部未验证”收口，不能继续 Phase 2。

## 3. The workflow

1. 阅读本 brief，并重述：用一组证据关闭 Phase 1 的真实链路和安全边界。
2. 汇总 Task 01–04 的测试、提交和外部验证状态。
3. 运行会话列表和聊天页目标测试。
4. 运行类型检查、rulers 和串行全量测试。
5. 新建 Phase 1 验收记录，区分代码、真实后端和未验证项。
6. 只有所有验收点有证据时才标记阶段完成。
7. 提交本任务的单一变更。
