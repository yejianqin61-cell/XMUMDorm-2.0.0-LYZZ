# Phase 1 Task 04 · 读写共享线程归属判断

## 1. Where this task sits

- Phase 1 真实私信链路恢复：目标是读取和发送都遵守同一线程归属边界。
- This task moves R-6 增加私信线程归属校验：避免只保护读取而放过发送。
- Starts after：Task 03 线程进入归属预检。Waits on：非法线程回归测试。

## 2. What the developer needs to know

**Read first**

- `app/src/features/mailbox/ChatScreen.tsx` — 读取、已读和发送动作的生命周期。
- `app/src/features/mailbox/chat.ts` — 消息 API 归一化和请求函数。
- `docs/app/task/phase-2/P2B-06-M12私信会话.md` — 4 秒轮询和发送验收。
- `app/src/__tests__/p2b-06-chat.test.tsx` — 当前消息页测试接缝。

**Settled**

- 归属判断必须覆盖读取、标已读和发送。
- 不新增 mailbox 基础抽象或第二套错误分类器。
- 真实后端拒绝仍必须安全处理。

**Edges and seam**

- 触及消息页动作和已有 API 适配；保留 ChatScreen 业务接缝。
- 不修改会话列表的数据契约。

**Run**

- 运行 `npm.cmd test -- --runInBand --silent src/__tests__/p2b-06-chat.test.tsx`。
- 运行 `npm.cmd run typecheck`。

**Unknowns**

- 标已读请求可能与首次读取并发。若归属判断无法覆盖该请求，停止并报告副作用边界。

## 3. The workflow

1. 阅读本 brief，并重述：读取、标已读和发送使用同一归属边界。
2. 标出 ChatScreen 的三类请求入口和当前竞态。
3. 为非归属线程补发送和标已读的红测试。
4. 复用 Task 03 的归属结果，阻止所有不安全动作。
5. 验证合法线程的轮询、标已读和发送不受影响。
6. 运行目标测试和类型检查。
7. 提交本任务的单一变更。

## 4. The test cases

| Case | Input | Expected | Seam |
|---|---|---|---|
| 1 | 非归属线程进入页面 | 不启动轮询 | ChatScreen |
| 2 | 非归属线程点击发送 | 不发出写请求 | ChatScreen |
| 3 | 非归属线程进入后标已读 | 不发出已读请求 | ChatScreen |
| 4 | 合法线程进入并轮询 | 4 秒轮询仍正常 | ChatScreen |
