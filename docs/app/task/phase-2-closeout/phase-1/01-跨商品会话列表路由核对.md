# Phase 1 Task 01 · 跨商品会话列表路由核对

## 1. Where this task sits

- Phase 1 真实私信链路恢复：目标是让真实用户打开 M-11 时不再遇到 404。
- This task moves R-1 恢复真实私信会话列表链路：确认本地实现、部署入口和运行版本一致。
- Starts after：无。Waits on：真实契约矩阵和 M-11 联调。

## 2. What the developer needs to know

**Read first**

- `docs/app/test/甲-真实后端契约验证.md` — 404 的真实环境证据和请求口径。
- `docs/app/TODO.md` — TD-55 的责任边界与当前状态。
- 后端 marketplace 路由 — 本地路由是否存在、响应字段和鉴权分支。
- 现有 live backend contract 测试 — 真实请求如何配置和跳过。

**Settled**

- R-1 要求真实环境路由可用；mock 通过不能关闭该缺陷。
- M-11 使用跨商品会话列表，不回退到买家只能从详情页进入。
- 不在本任务重做会话列表 UI。

**Edges and seam**

- 触及后端路由、部署入口和真实契约测试；保留现有页面接缝。
- Seam：现有 live backend contract 入口，不新增底层测试接缝。

**Run**

- 在后端目录运行对应 live contract 命令；再运行 `npm.cmd run typecheck`。
- 若真实环境仍 404，保留可复现证据，不把本地 mock 写成完成。

**Unknowns**

- 运行环境可能没有同步本地路由。若需要凭据、部署权限或外部平台操作，停止并报告阻塞。

## 3. The workflow

1. 阅读本 brief，并用一句话重述：让真实会话列表路由和本地实现一致。
2. 找到本地路由、部署入口和 live contract 的实际命令。
3. 对比路由响应、鉴权和错误分支与客户端消费契约。
4. 修正仓库内可修正的部署配置或契约测试，不改页面 UI。
5. 运行真实可用的契约检查和类型检查，记录外部环境边界。
6. 提交本任务的单一变更。
