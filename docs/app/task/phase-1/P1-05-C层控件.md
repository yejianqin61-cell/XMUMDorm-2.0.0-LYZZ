## 3. 实现要点

### 3-1 §3.1 的选型阶梯落进了代码，不只写在文档里
- `C14` 的项数区间**是一个可测的常量与纯函数**（`isSegmentedCountValid`），超限在 dev 下 `console.warn` 并**指路**（"6–7 项请用 C10 group，>7 项请用 C07"）；
- `C09` 的上限判定 `isOptionEnabled` 在**点击前**生效（未选项不可点），而不是事后报错；
- `C04` **没有** `errorText` 之外的浮层能力，`C06` **没有** `errorText` —— 职责边界用**类型**表达。

### 3-2 `C19 OtpInput` 为什么是"一个输入框 + 一排展示格"
§2.2 要求支持**粘贴**。而"每格一个输入框"要手写焦点搬运，且**系统短信验证码自动填充只认单个 `textContentType="oneTimeCode"` 的输入框**。
→ 真值只由一个输入框承载（`number-pad` + `normalizeOtp` 过滤非数字并截断），展示格是**装饰**（隐藏出无障碍树）。
a11y 因此只需要读**一个** textbox："验证码，6 位，已输入 2 位"。

### 3-3 ⚠️ 组件定义 §7.3 的两处 a11y 措辞在 RN 上落不了地（**已如实改口径**）
| §7.3 写的 | RN 的实际 API | 处置 |
|---|---|---|
| `C10` 暴露 `checked` **与 `checkedState`** | **`checkedState` 是 `react-native-web` 的字段**（对应 `aria-checked="mixed"`）；RN 本体是 **`checked: boolean \| 'mixed'`** | 按 RN 实现；⛔ 若照抄 `checkedState`，该字段会被丢掉 —— **等于没暴露**，正是 §7.3 想避免的 |
| `C04`/`C05`/`O08` 暴露 `invalid` **与 `required`** | RN 的 `AccessibilityState` **没有这两个字段** | 两者并入**可播报标签**（`inputAccessibilityLabel`），这也符合 §7.3 同段的要求"**错误文本是 label 的一部分**" |

> 这不是"实现偷工"，而是**文档用 web 术语写了 RN 契约**。已在这两个组件里写明差异与理由。

### 3-4 顺手修掉一个真实设计问题：用文本字符冒充图标
初版用了 `▾` `▴` `✓` `×` `⚠` 这些**文本字符**当图标。三处都不对：
1. 宪法第 16 条的**两层图标体系**里没有"文本字符"这一层；
2. `⚠` 擦边 **⛔ Emoji 图标**红线；
3. `▾` 撞上了 `P0-06` 的 R5 源码扫描（"下拉式溢出"）。
→ 全部换成 **A06 Icon + 逐图标子路径导入**：`chevron-down/up` · `check` · `minus` · `triangle-alert` · `x`。
⚠️ 顺带验到调研里写的那个坑：**`alert-triangle` 已改名 `triangle-alert`**（`alert-triangle.js` 在包里不存在）—— 名字写错的表现是**不透明的模块解析失败**。

### 3-5 `C07`/`C09` 的 `O07 PickerSheet` 缺口（**如实登记**）
§3.1 规定 `C07` 的平台形态是 **`O07 PickerSheet`（底部列表/滚轮）**，而 `O07` **尚未落地**（不在 P1-07 的 O 层批次里）。
本版实现的是**就地展开的选项列表**：
- ⛔ **不是**自绘浮层（§3.1 明令禁止浮层形态）；
- `Select` 因此做成**受控/非受控两用**（`open`/`onOpenChange`），`O07` 落地后**只换内部呈现，调用点形状不变**。
