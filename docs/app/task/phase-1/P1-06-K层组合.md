## 3. 实现要点

### 3-1 `ListItem`：语义放在**行**上，视觉控件不抢点击
`toggle` / `select` 两态下，**整行就是那个控件**（行带 `switch` / `checkbox` 角色与状态），
内部的视觉开关/勾选框 `pointerEvents="none"` + 隐藏出无障碍树。

为什么必须这样：
- 读屏否则会看到**两个开关**（行一个、视觉控件一个）；
- 真机上点视觉开关与点行尾会**各触发一次** —— 双重切换，是这类行最经典的 bug。

### 3-2 `SectionHeader`：NB 白名单是**允许**，不是**必须**
§5.2 的白名单三件套是"2px 硬描边 + 硬偏移 + 高对比色块"。本组件**只取 2px 硬描边**：
- "高对比色块"会在**每个分区**上盖一块色 → 直接违反 2.4-3（暗色层级由表面色表达）；
- "硬偏移"是给**小块**（角标）设计的，拉成整行后噪音远大于收益。

⛔ 这不是"忽略白名单"，是**在白名单内部做取舍** —— 差异写在组件注释与本表里，不靠人猜。

### 3-3 `RankingRow`：名次**不是**颜色
`medal` 变体只给前 3 名的名次方块**加一块底色**，**数字始终渲染**。
容易被做错的是"前三名只显示奖牌图标/只显示金色"→ 直接违反 2.1.1。
另外：`rank` 由**后端**给出（`rank = index + 1`），⛔ 客户端不重算（同分时的稳定性由后端排序决定）。

### 3-4 `EntityCard`：null 是常态，且**只有一个 null 处理点**
接口调研（G17）明确：`price` / `comprehensive_score` / `review_count` **后端都可能返回 `null`**。
→ `formatNullablePrice` / `formatNullableScore` / `entityMetrics` 三个**纯函数**把 null 语义收在一处：
- `null` → **"暂无价格" / "暂无评分"**，⛔ **不得当成 0**（把"没有评分"显示成"0.0"是数据事故）；
- `0` 是**真实值**（免费菜品 `¥0`），与 `null` 区分开 —— 两条都有用例。

`entityMetrics` 逐域给出该域该显示的指标串，页面**不允许**自己在卡外拼指标。

### 3-5 顺带登记一处令牌缺口
`EntityCard` 的媒体区高度：令牌源里**没有**"卡片媒体高度"档位。
处置：用**比例** `aspectRatio: 16/9` —— 比例是无量纲的，不会变成"屏内魔法数字"（2.4 管的是尺寸/间距）。
若设计日后定了专用档位，只改这一个文件。
