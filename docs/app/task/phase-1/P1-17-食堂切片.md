## 2. 实现要点

### 2-1 ⚠️ README §7-13：**评分是五档枚举，不是星星**
页面清单 `S-10` 写 `StarRating`（1–5 星），但 `RATING_ENUM = ['夯爆了','顶级','人上人','NPC','拉完了']`
（`routes/canteen.js:37`），权重 `10/7/4/1/−1` 由服务端 `CASE` 算综合分（`:313`），
**没有任何星级字段**。
→ 评分画**档位标签**（`C12 Chip` + 已有词条），⛔ 不用 `StarRating`：
画星星等于**编一个不存在的数据**。用例断言这三页的代码里不出现 `StarRating`。

### 2-2 三条路径更正（§7-2/3/4）落到代码
| 文档 | 实际 |
|---|---|
| `/regions/:id/ranking` | `/regions/:regionId/top-products?limit=` |
| `/shops/:id/hot` | `/shops/:shopId/hot-products` |
| `/products/:id/reviews` | `/products/:productId/comments` —— **而且详情接口本身就带第一页评论** |

→ 所以进 `S-10` **只打一次请求**（用例断言 `getProductCommentsRaw` 未被调用），
翻页才打第二个。页面**不拼路径**（全走 `shared/api/canteen`）。

### 2-3 ⛔ `null` 是常态（登记项 `G17`）：⛔ 不用 0 冒充"没有"
`price` / `comprehensive_score` / `review_count` **都可能是 `null`**，而且
`/shops/:shopId/products` 在缺列时会**换一条不含这三列的 SQL**（`routes/canteen.js:1009`）
→ 它们**可能整个不存在**。所以：
- 规范化器保留 `null`（⛔ 不 `Number(x) || 0`）；
- 界面显示"暂无 / 暂无评分"，用例断言**不出现 0 分 / RM 0**。

### 2-4 ⚠️ 为 `K05` 加 `listHeader` 槽位（**不是**把它与 `tabs` 合并）
`S-08`/`S-09` 在列表上方有**榜单/店头信息**，而 `K05` 只有 `tabs`（导航）与
`filterChips`（筛选）两个槽位 —— 把"内容"塞进任一个都是**把语义说错**。
→ 新增第三个槽位 `listHeader`（`ListHeaderComponent`，随列表滚动；空态也保留）。

⚠️ **为什么叫 `listHeader` 而不是 `header`**：P1-09 的用例**明确禁止** `header` 这个名字
（`expect(code).not.toMatch(/header\??:/)`），它当时就是用来防止"把 `tabs`/`filterChips`
合成一个 header"的。该口径**继续有效** —— 所以新槽位换一个不会与它混淆的名字，
⛔ 没有去改 P1-09 的断言。P1-09 新增的用例同时守住"三个槽位并存、`header` 仍被禁止"。

### 2-5 分类是**筛选**，不是导航（§4.8.1-R4）
`S-09` 的分类**不改路由**，只把 `category_id` 传给同一个 `/products` 接口
（服务端支持 `?category_id=`，`:988`）→ 走 `filterChips` 槽位 + `C12 Chip(selectable)`，
⛔ 不用 `K22 SegmentedTabs`（那会让"切分类"看起来像"换页面"）。
用例断言：切分类后接口参数变了、**路由一条都没跳**。

### 2-6 匿名投影（宪法 4.1.1）
服务端只对**商家回复**回填 `author.nickname`/`avatar`，普通评论两者恒为 `null`
（`routes/canteen.js:1209-1211`）→ 界面：
- 普通评论显示**"匿名"**，⛔ 不编昵称、不显示灰头像；
- 商家回复显示昵称 + **引用块**（⛔ 不只靠缩进或颜色区分）。
`isMerchantReply` 由"有没有昵称/头像"反推，⛔ 不新加协议字段。

### 2-7 翻页要**按 id 去重**
`created_at ASC` 的评论列表在有新评论时会整体后移 → 第 2 页会重复第 1 页的尾部
（服务端 `LIMIT pageSize+1` 就是为 `hasMore` 服务的）。`mergeCommentPages` 按 id 去重。

## 6. 风险与降级

| 风险 | 触发 | 处置 |
|---|---|---|
| 四页**没有**本地优先缓存 | 离线看不了 | ⚠️ 已知差异：`TTL` 与 `canteenCacheKey` 已备好但**本页未接**（`T-02` 已示范怎么做）。理由：食堂读接口服务端本身有缓存、且页面是"逛"不是"查"，先保正确性；接缓存时**不改页面契约**（只改 `useCanteenResource` 内部） |
| 榜单/广告位缺失让 `S-07` 显得单薄 | 使用者感受 | 已如实登记（§3）；`S-07` 的核心"按区域进店"已通 |
| 评论只有首页 + 手动「加载更多」 | 没有自动翻页 | 与 `K05` 的自动追加不同——评论是**详情页的一段**而不是列表主体，手动更可控；若真机觉得烦，改用 `K05` 的 `append` 状态机（不改协议） |
| 分类很多时横向滚动无提示 | 分类 > 4 个 | 用横向 `ScrollView`（§4.8：溢出**横向滚动**而不是"更多 ▾"）✅ 已按宪法做 |
| `S-10` 无收藏入口 | 用户想收藏 | 已登记（写路径专项）；⛔ 宁可没有，也不放一个点了没反应的星标 |
