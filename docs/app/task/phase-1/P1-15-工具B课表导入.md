## 2. 实现要点

### 2-1 两条**来自服务端代码**的硬事实（不是猜的）
1. 文本 < **10** 字直接被拒（`routes/schedule.js:35/57`）→ 客户端**镜像**这条规则。
   ⚠️ 镜像的含义（§3.2.2-②）：客户端校验只为**减少一次失败往返**，**服务端始终是权威**。
   所以界面上的"太短"提示**不阻止**用户改完再点（也绝不代替服务端判断）。
2. **`commit` 是整表覆盖**（`:77` 起删旧写新）→ 必须 `O03 AlertDialog(danger)` 二次确认。
   ⛔ 不能"点了就覆盖"。用例断言：**确认之前不会调 commit 接口**。

### 2-2 ⚠️ README §7-1 的路径更正落实到了代码
文档写 `POST /api/schedule/import`，**实际是 `/import/commit`**。
本页**不拼路径**，走 `shared/api/schedule.js` 的 `previewScheduleImport` / `commitScheduleImport`
（用例用源码断言守住"页面里没有 `/api/schedule/import` 字面量"）。

### 2-3 预览必须**规范化**（服务端返回是未类型化 JSON）
`normalizeImportPreview` 把 `{courses, meetings, stats, errors}` 收成强类型：
字段改名（`course_code` → `courseCode`）、空串归 `null`、类型护栏、缺字段给空数组、
非法输入返回 `null`（⛔ 不在渲染路径上抛）。
为什么必须做：渲染层直接读未类型化 JSON 会得到 `undefined` 并**画出空行**。

### 2-4 状态机的三条不变量（都写成了断言）
- **改文本即作废预览**：否则用户改完内容、还能按"确认导入"把**旧文本**覆盖上去
  —— 这是最危险的一类脏状态；
- **没有预览就不许提交**，**解析出 0 门课程也不许提交**（会把现有课表清空）；
- `previewing`/`committing` 期间不重复进入（防重复请求，返回**同一引用**）。

### 2-5 复用而不是重造
- **`K01 useForm`**：粘贴的长文本**草稿落盘**（宪法 4.4.3），进程被杀不丢；
- `K02`/`K03` + `C05 TextArea`（计数器）；`K04 ErrorSummary`（三要素）；
- `O03 AlertDialog(danger)`；`O01 Toast`（成功后是**回执**，⛔ 不是对话框）；
- **鉴权失败交给 P1-13 的 `useSession().handleAuthFailure`**（⛔ 页面不自己判 401/403）。

### 2-6 服务端错误串是**中文**的（如实登记）
`errors[]` 由服务端解析器生成（如"课程号解析失败：…"），是**服务端数据**而不是我们的文案。
本页**原样显示**（⛔ 不吞掉，否则用户不知道少了哪几行）；⚠️ 英文界面下这几行仍是中文 —— 
这与 Web 侧行为一致，登记为本轮遗留（要彻底解决需后端返回结构化错误码）。

## 3. 本轮**独立 bug 修复**（`371c237`）
`useForm` 的草稿恢复是**异步**的，而 `initialValues`（外部初始值）是同步生效的 →
**只要草稿存在，它总是最后写入、总是赢**。
触发场景正是本任务：`T-05` 抓来的长文本进 `T-03`，却被磁盘上昨天的旧草稿覆盖，
而且旧草稿短到连"预览"按钮都变灰 —— 用户看到的是"我刚读到的表不见了"。

为什么算 K01 的缺陷：**任何"外部初始值 + 草稿"的组合都会中招**
（例如"编辑已有内容"：初始值来自服务端 + 本地草稿），P1-10 时还没有这类页面所以没暴露。

修法：新增 **`skipDraftRestore`**（跳过恢复、**但仍保存**）。
⛔ 没有改成"按时间戳比新旧"：那样调用方就无法表达"这次的外部值必须优先"，
而这种意图只有调用方知道。补的用例在 K01 层。

## 6. 风险与降级

| 风险 | 触发 | 处置 |
|---|---|---|
| 服务端 `errors[]` 是中文串 | 英文界面 | 本轮**原样显示**并登记；彻底解决要后端返回结构化错误码（不是 App 能单方面改的） |
| 路由参数带**长文本**（几千字） | 极大课表 | 参数走的是 JS 内存，不落 URL；若真机发现卡顿，改为"写 pending 草稿 + 只传标记"，⛔ 不传 base64 |
| 预览与提交是**两次解析** | 服务端两次解析同一文本 | 服务端 `commit` 自己会再解析一遍（它才是权威）；⛔ 不把预览结果回传给 commit（那会引入"预览与服务端不一致"的新风险） |
| 覆盖前**没有**"当前有多少课"的提示 | 用户不知道会丢什么 | 对话框已写明"现有课表会被替换，无法撤销"；若需要数量，`T-02` 建好后从课表查询带过来 |
| 20 000 字上限 | 超大粘贴 | 是**页面注入**的限额（§3.2.2-③），⛔ 不写在控件里 |
