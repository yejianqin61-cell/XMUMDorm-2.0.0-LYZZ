## 2. 实现要点

### 2-1 会话三态**不猜 URL**，用页面自己报的事实
`D27` 要显示 `signedOut` / `signedIn` / `expired`。判断依据是**注入脚本读到的**
"当前这页有没有密码输入框"：
- **有密码框** = 这是登录页；**没有** = 已经进到系统内部了。

⛔ **为什么不去猜登录 URL**：三个校方系统的登录路径我们**没有实测过**，
按"路径里含 `/login`"之类的猜测写规则就是**凭记忆写**（宪法 15.2-1 明令禁止），
而且对方随时会改。用 DOM 事实判断既可靠又不需要知道对方的 URL 结构。

三态的区分是**证据**而不是感觉：

| 上一次 | 这次看到 | 结果 | 为什么 |
|---|---|---|---|
| 任何 | 无密码框 | `signedIn` | 进到系统内部了 |
| `signedIn` | **有**密码框 | **`expired`** | 之前进得去、现在被弹回登录页 → 会话丢了 |
| `signedOut` | 有密码框 | `signedOut` | 从没登录过，⛔ **不谎报"过期"** |
| `expired` | 有密码框 | `expired` | 保持 |

### 2-2 探测**每次加载与每次导航结束都要补一枪**
`injectedJavaScript` 只在文档结束时跑一次；而"登录成功 → 进首页"在单页应用里
**不触发文档加载**。所以 `onLoadEnd` 与 `onNavigationStateChange(loading=false)` 都再注入一次
—— 否则状态会永远停在"这是登录页"。

### 2-3 注入脚本**只观察，不动手**（宪法 4.1.2-4）
会话探测脚本只做 `document.querySelector('input[type=password]')` + `postMessage`，
⛔ 不填表、不点击、不读任何凭据。用例把 `.click(` / `.submit(` / `.value =` / `dispatchEvent`
四条写成**禁止性断言**。

### 2-4 消息分流只做信封，⛔ 不重复解析课表
`parseWebViewMessage` 只判断 `kind`：`session` → 结构化；**`schedule` → 原样交回**，
由既有的 `extractSchedule.parseInjectedMessage`（P0 已有用例守着）做严格解析。
写成第二份课表解析就是"同语义两层"（9.14-①），两边迟早不一致。

### 2-5 ⚠️ 页面清单说要用 `SessionBadge`，但**没有这个组件**（登记为 README §7-11）
页面清单 `T-04` 的组件列写着 `ListItem` `SessionBadge` `Button`（清除会话）`InlineNotice`，
但组件定义 §2.6 里**没有 `SessionBadge`** —— 它其实是 **`D27 SchoolSystemCard` 内部的状态徽标**。
按 9.14-③「1 处使用 = 就地写」，本页用 `D27`（它 own 三态徽标 + 清除会话），
⛔ **不为一个徽标新建组件**。用例断言 tools 目录下没有 `sessionbadge` 文件。

### 2-6 如实说明"我们能知道什么"
页面顶部一条 `InlineNotice`：**会话状态由本机观察得出；清除会话只删除本机记录，
校方站点可能仍记得登录**。这不是免责声明，是**事实**：真正的会话在平台 cookie 存储里，
我们清不到（清 cookie 需要一个原生的 cookie 模块，未准入 → 见 §6 风险）。

### 2-7 「读取本页课表」为什么要做成工具栏按钮
用户的真实路径是"**先进到课表页、再点读表**"，而注入只在文档结束时跑一次 → 靠不住。
所以 `SchoolSystemWebView` 暴露**命令式句柄**（`readSchedule()` / `probeSession()`），
由工具栏按钮触发；⛔ 不让宿主页自己拿 `webRef`（那会绕过本组件的注入纪律）。
读表结果**如实回显**（读到几行 / 这一页没有表），⛔ 不弹对话框。

## 6. 风险与降级

| 风险 | 触发 | 处置 |
|---|---|---|
| **"清除会话"清不掉校方 cookie** | 用户以为点了就登出 | 清 cookie 需要原生的 cookie 模块（`@react-native-cookies/cookies`，**未准入**）→ 当前只清本机记录 + `WebView` 的 cache/history 由平台管；页面 `InlineNotice` **如实说明**。若真机验证发现"清了还认得"，再走准入流程加模块 |
| 三态是"本机观察值"，不是校方权威状态 | 用户在别处登录/登出 | 页面已写明；下次进 `T-05` 会自动重探并更新 |
| 密码框判断在"改密码"页也会为真 | 系统内有改密码页 | 会把状态报成 `signedIn → expired`（假过期）。低概率且可自愈（再进首页即回到 `signedIn`）；若真机常见，改为"密码框 **且** 无其他已登录痕迹"的双条件，⛔ 不引入猜测路径 |
| `T-01` 只做了入口 | 该页完整内容（待办/课表摘要） | 属切片后续任务；本任务只保证"路由可进入"（E2），并已在页面注释写明 |
| `localStorage`/SPA 内部路由不触发 `onLoadEnd` | 单页应用 | 已在 `onNavigationStateChange(loading=false)` 补探 |
