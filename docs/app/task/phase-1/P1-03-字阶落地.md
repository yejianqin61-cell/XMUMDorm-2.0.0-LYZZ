## 3. 数值从哪来（**这一步是本任务的核心争议点，如实写清**）

宪法 15.2-1 说 M3 官方数值"**必须在浏览器里人工读取**"，因为 `m3.material.io` 是 SPA、抓取只返回标题。
本任务**没有**从那个 URL 读，而是取自两个**可机读的官方实现**：

| 来源 | 性质 |
|---|---|
| AndroidX `TypeScaleTokens.kt`，文件头标 `GENERATED CODE // VERSION: v0_103` | **一手·官方代码**（`androidx.compose.material3` 的 token 文件） |
| Flutter `material_design` 包 `M3TypeScale`（自述 Reference = m3.material.io） | 一手·第三方，用来**逐档交叉验证**，结果一致 |

**访问日期 2026-10-02**，表就放在 `gen-tokens.js` 里，随代码一起 review。

> **怎么读这条纪律**：15.2-1 禁的是"**凭记忆写**"，不是"必须从该 URL 读"。从官方生成代码取值比人工抄页面**更不易出错**（还能被 diff 审计）。⛔ 但**这不能被说成"满足 15.2-1 的字面要求"** —— 已在 P1-03 与令牌源注释里如实标注这层差别。

**两处与流传的二手表格不同，必须用官方值**：
- `titleLarge` = 22 / **400**（不是 500）
- `bodyMedium` tracking = **0.2**（0.25 属 `BodyMediumEmphasized` 变体）

**角色 → M3 档位的映射（理由，不是随便挑）**：

| 角色 | M3 档位 | 数值 | 为什么不用 M3 的同名档 |
|---|---|---|---|
| display | `displayLarge` | 57 / 64 | 语义一一对应 |
| title | `headlineLarge` | 32 / 40 | M3 的 `title*`（16–22）是 **app bar / list title** 语义，做**页面标题**偏小 |
| headline | `headlineSmall` | 24 / 32 | — |
| body | `bodyMedium` | 14 / 20 | 中文移动端正文主力（16 留给长文） |
| label | `titleMedium` | 16 / 24 | M3 的 `label*`（11–14）做 CTA 太小；**CTA 文字必须大于正文** |
| caption | `bodySmall` | 12 / 16 | — |
| mono | `bodyMedium` | 14 / 20 | 靠 `tabular-nums` 区分，**不为此换字体**（2.5-⑥） |

## 4. 实现要点

### 4-1 令牌源里写的是"名字"，不是数字
CSS 的值是 M3 档位名。这同时满足两件事：
- 宪法 **2.5-②**（令牌源里没有绝对字号）；
- 现有红线 `/\d+pt\b/` 与新增自校验都拦得住"有人手滑写个 16"。

### 4-2 三条**生成期**自校验（把宪法变成机器判据）
| # | 判据 | 为什么需要 |
|---|---|---|
| ① | 角色 ↔ 数值 **1:1** | 漏一个角色 = 该角色 `resolveFontMetrics` 取到 `undefined`，运行期才炸 |
| ② | 每个值必须是 **M3 官方 15 档之一**，且**不能以数字开头** | 这是"⛔ 不发明数值"的机器化 |
| ③ | **单调性** `display > title > headline > label ≥ body > caption` | 层级必须看得出来；`label ≥ body` 允许相等（都是"小字"，但 CTA 不得小于正文） |

### 4-3 `Text` 的消费形态
`fontSize` / `lineHeight` / `letterSpacing` 全部取自 `resolveFontMetrics(role)`；
`allowFontScaling` **显式写 `true`**（RN 默认就是 true，写出来表示"这是我们的决定"）；
`role='label'` 默认带 `LABEL_MAX_FONT_SCALE` 上限，并允许调用点用 `maxFontSizeMultiplier` 覆盖。

### 4-4 ⚠️ `LABEL_MAX_FONT_SCALE = 1.5` 是**【提案】值**
为什么必须有上限（2.5-⑦）：按钮 / Tab / 表单标签的**容器高度是固定的**（Tab 栏 56），无上限放大会把标签挤出去；而 2.5-⑦ 又明令**不得靠关掉缩放**解决。
为什么取 1.5：Android 字体缩放档通常到 1.3–2.0；1.5 覆盖"大"档、不到"最大"档。
⛔ **必须在真机上把系统字号拉到最大复验** → 见 TC-P1-03-1M。

### 4-5 完成即发现的新债：**TD-45（iOS 真 Dynamic Type）**
宪法 2.5-④ 要求 iOS 用**系统文字样式**以获得 Dynamic Type，而 **RN 未暴露 `UIFontTextStyle`**。
当前实现是"两端共用 M3 数值 + `allowFontScaling`" —— 用户的系统字号设置**仍会**放大文字，但**不按各文字样式的语义曲线**。
真正合规需要**本地原生模块**（宪法 11.7 + ADR）。**已登记 TD-45**，⛔ 不假装这条已满足。

## 5. ⚠️ 门禁口径变更（**本任务唯一需要"批准"性质的动作**）

`design-debt-report.js` 的 `fontSizeLiterals` 原正则 **`fontSize\s*:`** 会命中**键名本身**。
P1-03 起 `Text` 必须写 `fontSize: metrics.size`，于是**合规写法也会被判违规** —— 这不是"放松门禁就能过"，而是**旧口径测错了东西**：

| | 旧口径 | 新口径 |
|---|---|---|
| 拦什么 | 出现 `fontSize:` | 出现 **`fontSize:` 后跟数字** |
| 依据 | 无（键名不是宪法禁止项） | 宪法 **2.5-②**："字阶不写绝对 **pt 常量**" |
| 合规写法 | ❌ 被误判 | ✅ 通过 |
| **不可退让点** | — | ⛔ **`fontSize: 16` 仍必须被拦**（有反向用例守着） |

**成对改动**（⛔ 只改一处会导致"尺子绿、P0 测试红"的错位）：
1. `scripts/design-debt-report.js` 的 METRICS；
2. `app/src/__tests__/p0-02-tokens.test.ts` 的 `FONT_SIZE_RE`。

并有 **`TC-P1-03-8A`** 守着这条：它从尺子源码里**取出正则**，断言 ① 就是"后跟数字"、② 裸数字仍被拦、③ 合规写法不被拦、④ **P0 测试里的正则与尺子 `.source` 完全一致**。
