## 3. 实现要点

### 3-1 **三级取内容**：`remote → cache → bundled`
⚠️ 顺序里唯一"反直觉但正确"的一条：**`cache` 优先于 `bundled`**。
cached 是"**上次真正拿到过的版本**"，比随包发的内置副本新；
反过来的话，服务端更新过的手册**永远读不到新版**（用户会一直看到装机那天的内容）。
另外空串/纯空白**不算内容**（否则会渲染出一张白屏）。

### 3-2 离线优先的**全部意义**：失败不清空已有内容
`useStaticDoc` 的三步：
1. **先把能立刻显示的显示出来**（缓存 → 内置），此时 `loading` 仍为真（远端还在打）；
2. 远端成功 → 覆盖并**落缓存**；
3. 远端失败 → **保留已有内容**，只把 `error` 记下来（页面据此显示 `T04(stale)`）。

`resolveStaticState` 的 `hasContent` 优先，于是 **"有缓存时渲染 stale 而不是错误屏"**
（宪法 10.6 / 验收索引）不是靠页面自觉，而是**状态判定的结果**。用例给了正反两向断言。

### 3-3 §2.7 的"**无交互**"是硬约束，不是描述
P16 的交互契约只有**滚动与链接**。用例用源码断言守住：
⛔ 没有 `TextInput`、没有 Button/Input/TextArea/Checkbox/Switch/Pressable、没有 `AlertDialog`、
没有 `Modal`、没有 `useReducer`、没有 `FlashList`。
连**空态**也用 `T01` 而不是"假装是错误"——⛔ 不给静态页发明交互。

### 3-4 与 `K01` 草稿同款的**凭据护栏**预检
缓存 key 是 `static:<docId>`，若 docId 形如 `reset-password`，落盘层会**拒绝**
（切分后出现 `password` 段）。处置与表单草稿一致：`canCacheStatic()` 预检，
**不通过就干脆不缓存**（读写都变 no-op），⛔ 不崩、也不静默写。

### 3-5 只做骨架该做的事
- **链接交页面**（`onLinkPress`）：站内路由 / 系统浏览器不是骨架的知识；
- **TOC 由 `D18` own**，骨架只按 `showToc` 决定要不要算；
- **顶栏仍是插槽**（`topBar`/`topMode`），与 `P3` 同规 —— C-06 未定，骨架不预占。

## 6. 风险与降级

| 风险 | 触发 | 处置 |
|---|---|---|
| 内置副本与远端版本的**内容差异**没有校验 | 服务端大改手册 | 现阶段不引入内容版本号（`version` 字段后端未提供）；若将来需要，加 `if-none-match` 式比对，⛔ 不发明前端版本号 |
| `useStaticDoc` 每次挂载都打远端 | 打开静态页频繁 | `@tanstack/react-query` 的 `staleTime` 才是正解（P1-02 已定 60s）——页面用 query 取远端、把结果喂给本骨架即可，⛔ 骨架不自己造缓存策略 |
| `showToc` 的目录跳转需要滚动定位 | 长协议文档 | TOC 的**生成**已由 `D18` own；跳转属阅读器（`P10`）的交互，等 `M-19`–`M-21` 落地时接 |
| `EmptyState` 用了 `kind="broken"` | 语义上更像 `firstRun` | 静态页不该"从没有过内容"；真出现说明文档配置错了 → 给"重试"比给"去发布"合理。已在此记录判断 |
