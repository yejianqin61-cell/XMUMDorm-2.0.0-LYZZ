## 3. 实现要点

### 3-1 分页状态机的三条不变量（都写成了断言）
1. **同一方向不重复进入 `loading`** —— 防重复请求；`paginationReducer` 对这种动作**返回同一个引用**
   （用例直接用 `toBe` 断言"真的什么都没变"，而不是只比较字段）。
2. **`hasMore === false` 时不再 append** —— 到底了就不要再问。
3. **新请求开始即清掉上一次错误** —— 否则"正在重试"与"上次的错误"会同时显示。

### 3-2 `canAutoAppend` 与"手动重试"是**两件事**（这轮踩到的语义坑）
最初把两者合成了一个 `canAppend`，结果自相矛盾：reducer 允许从 `'error'` 再 `start`
（这就是 retry），而滚动判定却说不允许。**其实两边都对，只是问的不是同一个问题**：
- **自动追加**（滚动触发）在 `append: 'error'` 时**必须**为假 —— 否则用户一滚就反复打一个正在失败的接口；
- **手动重试**必须允许 —— 否则失败后再也回不来。

→ 改名 `canAutoAppend`，并**补一条用例**专门断言"自动不允许、手动允许"同时成立。
名字里带 `Auto` 就是为了让后来人别再把它当"能不能追加"。

### 3-3 四态判定：有内容时**不许**让错误接管整屏
```ts
itemCount > 0 → 'data'
```
这一条先于其它判断。否则"刷新失败"会把用户正在看的内容整屏换掉 ——
已有数据时的失败应该表现为页脚/顶部提示，而不是错误页。
另外**加载优先于空态**，否则首屏会先闪一下"还没有内容"。

### 3-4 状态保持：复用 `SecondaryTabStore`，并且补了两个细节
- `P0-06` 的 `SecondaryTabStore` **已有** `scrollOffset` / `cursor` / `filters` 三个字段，
  正好是 `P2` 要的 → ⛔ 不新建第二套（纪律 4）。它在仓库里原本**只有类、没有实例**，
  于是补了应用级单例 `secondaryTabStore`：
  **R2（切走再切回位置还在）只有在所有页面共享同一个实例时才成立**。
- ⚠️ **`filters`/`cursor` 必须有本地态**：`store` 是普通对象，改它不会触发重渲染。
  最初写成"只读一次"，本会话内改筛选对页面**不可见**（切 Tab 回来才生效）—— 那是持久化只做了一半。
  用例专门断言"写进仓库 **且** 本会话立刻可见"。
- **改筛选会 `dispatch({type:'reset'})`**：旧游标指向旧筛选结果，继续追加会**串数据**。

### 3-5 滚动位置恢复：为什么不用 `initialScrollIndex`
`initialScrollIndex` 只在列表**首次挂载**时生效，而这里列表要**等第一页数据回来才挂载**，
时机对不上 → 会静默失效。改为拿到数据后调一次 `scrollToOffset({animated:false})`，
并用 `restoredRef` 保证**只做一次**（否则每次重渲染都会把用户拽回去）。

### 3-6 `FlashList` 在 Jest 里可用（已实测）
`@shopify/flash-list@2.0.2` 是 0 原生文件（可 OTA），**在测试渲染器里会真的渲染出行**
（探针实测 `row-a` 可查）。副作用：挂载后会自行触发一次 `onEndReached`
并在 `act()` 外更新状态（控制台警告，不影响断言）—— 这条正好被用来**反向验证**：
`hasMore=false` 时那次自动触底**必须不回调**。

## 6. 风险与降级

| 风险 | 触发 | 处置 |
|---|---|---|
| `scrollToOffset` 在数据刚回来时列表可能还没量好 | 真机（恢复位置偏一点） | 已用"拿到数据后一次"的时机；若仍偏，改在 `onContentSizeChange` 后触发。⛔ 不引入延时魔法数 |
| `onEndReachedThreshold={0.5}` 是**比例**不是尺寸 | 长/短列表预取过早或过晚 | 比例属无量纲；若真机表现为"还没滑到底就转圈"，按列表类型（列表/网格）分档，而不是全局调大 |
| `FlashList` 的 `numColumns` >1 时 `ListFooterComponent` 布局 | 二手网格（`S-22`） | 页脚自带 `paddingVertical`；若错位，改为 `ListFooterComponentStyle` 全宽，不改骨架契约 |
| `P2` 还有"可选 tab 头" | 二级 Tab 集合待所有者拍板（C-03/C-04/C-05） | `header` 是**透传插槽**，骨架不预占该决定（README §5-1） |
