# evaluation —— 对已定方案的评估判定

**本目录放什么**：**判定**类文档。对象是**已经存在的东西**（已定的方案、已跑的脚本、已上架的版本、已完成的实现），产出是**准入 / 不准入、达标 / 不达标、可发布 / 不可发布**的结论。
**本目录不放什么**：做决定**之前**的取证与方案对比（→ [`../research/`](../research/)）、我们自己的验收结果（→ [`../test/`](../test/)）。

> **判据（一句话）**：**为了决定**而查事实 → `research/`；**为了判定**已存在的东西 → `evaluation/`；**为了记录我们跑出来的结果** → `test/`。

## 三、写法纪律

1. **必须先有被判定对象**（文档 / 代码 / 构建 / 版本），且**指得出它的位置与版本**。
2. **结论要可反驳**：写清判据、阈值、样本、复现命令；**不得只写"经过评估，没有问题"**。
3. **不达标就写不达标**，并给出**唯一主行动**；不得用"后续优化"结案（宪法 13.2）。
4. 数值一律带 `【已定】/【算得】/【提案】` 标注（与 `research/` 同一口径）。
