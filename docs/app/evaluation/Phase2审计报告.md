### D-1 线上私信列表路由未部署

- **症状**：代码已调用跨商品会话列表，但真实后端带令牌仍返回 404。
- **证据**：`docs/app/test/甲-真实后端契约验证.md:40`、`:60`、`docs/app/TODO.md:178`。
- **影响**：M-11 在真实环境无法加载会话列表；自动化 mock 通过不能替代线上契约。
- **判据**：R-4 要求私信链路可用，TD-55 明确把未部署路由列为阻塞项。

### D-2 私信历史没有游标

- **症状**：消息接口固定读取最新 500 条，客户端只能对这一个窗口做 `id > lastSeen` 过滤。
- **证据**：`app/src/features/mailbox/chat.ts:5`；`app/src/features/mailbox/ChatScreen.tsx:14`。
- **影响**：长会话看不到更早消息；轮询每次读取整页，流量也随会话长度增长。
- **判据**：R-4 明确要求分页和“不丢”；项目自身已把该问题登记为 TD-15、TD-56。

### D-3 `acceptedTerms` 没有后端真源

- **症状**：viewer 发现后端没有 `acceptedTerms` 时不写该字段，合规门按“源缺失=放行+标记”处理。
- **证据**：`app/src/features/publish/viewer.ts:10`、`:73`；`app/src/features/publish/complianceGate.ts:71`。
- **影响**：发帖前同意条款的状态无法由服务端证明，存在上架合规风险。
- **判据**：Phase 2 设计文档 JR-12 和 TD-59 都把它标为后端能力缺口及上架红线。

### D-4 13.1 真机证据未完成

- **症状**：业务路径有自动化测试，但触控尺寸、横屏、大屏、最大字号、系统动效和平台返回仍未由设备确认。
- **证据**：甲记录明确写出 15 页中 0 页全部通过；乙记录写出 12 页中 0 页完成全部设备验收。
- **影响**：不能证明 App 在目标机型上满足 13.1；当前可作为代码内测候选，不能作为发布候选。
- **判据**：R-14 要求逐屏记录和缺项记账，现有记录只完成了机器与静态部分。

### D-5 法务正文仍是占位

- **症状**：隐私政策和服务条款开头仍写明“占位正文”和“待替换”。
- **证据**：`app/src/features/me/legal.ts:8`、`:35`。
- **影响**：不能直接用于商店提交或正式用户发布。
- **判据**：TD-61 明确要求上架前替换正式文本。

### D-6 会话线程没有客户端归属校验

- **症状**：`ChatScreen` 将路由参数转为正整数后直接读取和发送；客户端没有证明该线程属于当前用户。
- **证据**：`app/src/features/mailbox/ChatScreen.tsx:55`、`:92`、`:157`。
- **影响**：错误或恶意深链会先进入不属于当前用户的会话路径，最终安全边界依赖后端拒绝。
- **判据**：Phase 2 缺陷总账将 D-3 列为待修，并要求补归属校验与用例。

### D-7 lint warning 尚未清偿

- **症状**：lint 为 0 error，但仍保留约 220–310 个 warning，数量因运行时配置和批次不同而变化。
- **证据**：`docs/app/TODO.md:204`、`docs/app/task/phase-2/丙实施记录/最终收口与交接.md:12`。
- **影响**：新代码问题可能被既有迁移告警淹没，维护成本继续累积。
- **判据**：这是 smell baseline 下的 possible tooling debt，不把 0 error 误写成 warning 清零。

### D-8 默认 verify 的资源稳定性

- **症状**：依赖安装后 `typecheck` 通过；串行 Jest 为 87 suites、1328 tests 通过，2 suites、16 tests 跳过；`rulers` 单独通过。但默认并行 `npm run verify` 的 Jest 进程发生 Node OOM，未到 rulers 阶段。
- **证据**：本审计在干净工作树运行的命令输出；测试结束还报告有异步操作未停止。
- **影响**：CI 或低内存开发机可能无法得到完整出口结果。
- **判据**：这是验证器可重复性备注，不据此断言业务代码失败；仍需修复或明确资源边界。
