# R3 结论 · 校方系统内嵌可行性（工具 Tab 头号功能）

**日期**：2026-10-02　**版本**：v1.0
**性质**：**evaluation 层**（判定记录）。对应 [P0-08 子任务](../task/phase-0/P0-08-校方系统内嵌容器.md)。
**判定对象**：三个校方系统（AC / Moodle / 签到）能否用**内嵌 WebView + 会话保持 + 注入读表**的方式支撑"打开 → 学号登录 → 读课表 → 导入"这条主链路。

---

## 0. 一句话结论

**内嵌方案成立（有条件）**：`react-native-webview@13.16.1` 由 Expo SDK 57 官方钉版；**iOS / Android 的 cookie 默认就是持久化的**；`X-Frame-Options` 不约束原生 WebView 的顶层导航（宪法记录正确）。**真正会静默摧毁会话的只有两个开关**（无痕模式、iOS 上"关缓存 + 共享 cookie"），**主风险不在内嵌本身，而在 Moodle / 签到 是否走 Google SSO**（若是 → 那两个系统单独降级为系统浏览器，**不影响 AC 主链路**）。

> ⛔ **仍有三项必须真机才能定**：三个系统是否反 WebView / 会话能否跨重启保持 / 课表页是否异步渲染且列语义稳定。见 §4。

## 1. 已取到的一手证据

| # | 事实 | 来源 |
|---|---|---|
| 1 | **SDK 57 钉版 `react-native-webview@13.16.1`**（实测解包 `expo@57.0.26` 的 `bundledNativeModules.json`；同表 `react-native 0.86.3`、`screens ~4.26.0`、`safe-area-context ~5.7.0`） | `app/node_modules/react-native-webview/package.json` = **13.16.1**（本仓库实测） |
| 2 | **iOS 默认持久**：`if (_incognito) { nonPersistentDataStore } else { defaultDataStore }` | RNW 13.16.1 `apple/RNCWebViewImpl.m:462-465` |
| 3 | ⚠️ **iOS 陷阱**：**仅当 `sharedCookiesEnabled` 为真**时才走上面那条；`if (!_incognito && !_cacheEnabled) { nonPersistentDataStore }` → **关缓存会连带把会话变成不落盘** | 同上 `:1872-1874` |
| 4 | **Android 默认持久**：cookie store 是**进程级单例**，写 App 私有目录、跨重启保留；库在 `createViewInstance` 已设 `domStorageEnabled = true`，并在 `onPageFinished` 调 `CookieManager.flush()` | AndroidX `CookieManager` 官方文档 + RNW 13.16.1 `RNCWebViewClient.java:58` |
| 5 | ⚠️ **Android 无痕模式是破坏性的**：`if (!enabled) return;` 然后 `removeAllCookies(null)` + `clearCache(true)` + `clearFormData()` → **不可逆** | RNW 13.16.1 `RNCWebViewManagerImpl.kt:469-485` |
| 6 | **`injectedJavaScript` 只在文档加载完成时跑一次**；官方原文：**"Be sure to set an `onMessage` handler, even if it's a no-op, or the code will not be run."** | RNW `docs/Reference.md` |
| 7 | **`injectedJavaScriptBeforeContentLoaded` 在 Android 上不可靠**（官方 Warning："may work, but it is not 100% reliable"，issue #1609 / #1099） | 同上 |
| 8 | **`X-Frame-Options` 的语义是"是否允许被 `<frame>/<iframe>/<embed>/<object>` 渲染"** → **不含顶层导航**；原生 WebView 的 `source={{uri}}` 是顶层文档 → **不约束**（宪法 4.1.2-6② 记录正确） | MDN + RFC 7034 |
| 9 | UA：`userAgent` 是**整体覆盖**，`applicationNameForUserAgent` 是**追加**（且被 `userAgent` 覆盖）→ 只应追加 | RNW `docs/Reference.md` |
| 10 | 内嵌第三方页拿不到 `viewport-fit=cover` → 它页面里的 `env(safe-area-inset-*)` **恒为 0** → 必须由我们注入 | RNW 文档 + 宪法 17.3 |
| 11 | 审核 4.2 **逐字**："Your app should include features, content, and UI that elevate it beyond a repackaged website."；**4.2.2 逐字**点名 **"web clippings"** | Apple App Review Guidelines（本次抓取） |

## 2. 因此的工程处置（已落到代码）

| 处置 | 位置 | 理由 |
|---|---|---|
| ⛔ **不出现无痕模式** | `features/tools/SchoolSystemWebView.tsx` | 证据 5：Android 上不可逆地清 cookie |
| ✅ `cacheEnabled` / `sharedCookiesEnabled` / `thirdPartyCookiesEnabled` 显式开启 | 同上 | 证据 2/3/4；且 Android 侧默认 `true` 也要写出来作为**意图声明** |
| UA **只追加** `XMUMDorm/1.0` | 同上 | 证据 9（⛔ 不整串覆盖，否则会丢 `Mobile` 标记） |
| `injectedJavaScript`（文档结束跑一次）**＋** `onLoadEnd` 里用 ref 再补一枪 | 同上 | 证据 6/7 + 课表页可能异步渲染 |
| **必须**给 `onMessage` | 同上 | 证据 6（否则注入代码根本不执行） |
| insets 走 **CSS 变量注入**（`--dorm-inset-top/bottom/left/right`） | `features/tools/injectedScripts.ts` → `buildEmbeddedInsetCss` | 证据 10；同时外层容器也消费 insets（S7） |
| 宿主页 `app/system/[id].tsx`：`googleSso` → **系统浏览器** | 代码 + 本判定 | Google 官方明令不得在嵌入浏览环境做 OAuth |
| ⛔ 注入脚本**不含** `click(` / `submit(` / `dispatchEvent` | `injectedScripts.ts` + 测试断言 | 宪法 4.1.2-4：只做"打开 + 保持会话" |

## 3. 合规自评（App Store 4.2 / 4.2.2）

- 4.2 的判据是"**是否超越 repackaged website**"，4.2.2 点名 **web clippings**。
- 本项目 88 页里校方系统只占工具 Tab 的**三项**，其余全部原生（课程表 / 待办 / 放假日 / 社区 / 二手 / 跑腿…）→ **不构成纯封装**。
- ⚠️ 但审核备注（App Review Notes）**必须主动写清**：校方系统**只在校内网可用**，并附可复现的演示方式（截图 / 录屏 / 演示账号）。否则审核员会按"无法访问的后端"直接拒。
- 三条化解要求（宪法 4.1.2-5）：① 工具 Tab 在感知上不等同于浏览器 ② 该能力与原生课表/待办**同屏同层** ③ 上架前专项自评 → 登记为 **上架前必办**。

## 4. ⛔ 必须真机才能定的六项（**当前一律不得当已成立**）

| # | 待实测 | 通过判据 | 失败判据 → 处置 |
|---|---|---|---|
| 1 | AC 学号登录页能否在 `WKWebView` / Android WebView 内完成登录并落 cookie | **杀进程冷启后仍免登录** | 若被拒 → **降级路径 A**（外链 + 粘课表文本） |
| 2 | Moodle / 签到 的登录方式 | 不跳 `accounts.google.com` 即内嵌 | 若跳 → 该系统 `embed: 'external'`（**不影响 AC**） |
| 3 | `sharedCookiesEnabled` 是否必需 | AC 会话只靠 `WKWebsiteDataStore` 即可保持 | 若需共享 `NSHTTPCookieStorage` 才有会话 → 保持开启（注意证据 3 的组合陷阱） |
| 4 | 课表页 `<table>` 的**列语义稳定性**：列序 / `rowspan` 合并 / 有无 `th` / 是否多表 / 是否分页 | 抓到的行能唯一映射到"课程 / 教师 / 教室 / 周次" | 若列不稳定 → 抓取选择器要按表头定位，或转服务端兜底解析 |
| 5 | 课表页**渲染时机** | `onLoadEnd` 后 10s 内能拿到 >=2 行 | 若更慢 → 提高轮询上限（`maxTries`） |
| 6 | 三个系统的**使用条款**是否允许第三方 App 内嵌访问 | 条款允许 | 若不允许 → 三个系统全部改外链，头号功能降级为"打开 + 粘贴" |
