# R3 结论 · 校方系统内嵌可行性（工具 Tab 头号功能）

**日期**：2026-10-02　**版本**：v1.1（v1.1 ＝ 所有者裁决：**不做 6 项真机验证，内嵌形态是硬需求**）
**性质**：**evaluation 层**（判定记录）。对应 [P0-08 子任务](../task/phase-0/P0-08-校方系统内嵌容器.md)。
**判定对象**：三个校方系统（AC / Moodle / 签到）能否用**内嵌 WebView + 会话保持 + 注入读表**的方式支撑"打开 → 学号登录 → 读课表 → 导入"这条主链路。

---

## 0. 一句话结论

**内嵌方案成立，且已由所有者裁决为「产品硬需求」**：`react-native-webview@13.16.1` 由 Expo SDK 57 官方钉版；**iOS / Android 的 cookie 默认就是持久化的**；`X-Frame-Options` 不约束原生 WebView 的顶层导航（宪法记录正确）。**真正会静默摧毁会话的只有两个开关**（无痕模式、iOS 上"关缓存 + 共享 cookie"）—— 两者在本仓库**都没有启用**。

> ✅ **所有者裁决（2026-10-02）**：**"我不会测试 R3 那六项，但是我知道，我们一定要做 WebView 内嵌调用学校网站系统。LUMO 也是这么干的，他们能上我们也行。"**
> **因此 §4 的六项从"必须真机才能定"降级为「实现期观察项」**：它们**不再阻塞任何事，也不再需要真机** —— 六项在本仓库**都已预先取了安全默认值**（§4.1），真撞上时**只改该站的适配，不改形态**。
> **唯一不能靠决心解决的一条**是 Moodle / 签到 若走 Google SSO（**Google 的政策强制**：其官方政策逐字禁止把 OAuth 授权请求交给"开发者掌控的 embedded user-agent"，而**它点名的能力里有两种本容器明确具备** —— 注入任意脚本、访问会话 cookie）→ 那两个系统按 `resolveEmbedMode` 走系统浏览器，**AC 主链路不受影响**（§4.1-2，已取到官方逐字原文）。

## 3. 合规自评（App Store 4.2 / 4.2.2）

- 4.2 的判据是"**是否超越 repackaged website**"，4.2.2 点名 **web clippings**。
- 本项目 88 页里校方系统只占工具 Tab 的**三项**，其余全部原生（课程表 / 待办 / 放假日 / 社区 / 二手 / 跑腿…）→ **不构成纯封装**。
- ⚠️ 但审核备注（App Review Notes）**必须主动写清**：校方系统**只在校内网可用**，并附可复现的演示方式（截图 / 录屏 / 演示账号）。否则审核员会按"无法访问的后端"直接拒。
- 三条化解要求（宪法 4.1.2-5）：① 工具 Tab 在感知上不等同于浏览器 ② 该能力与原生课表/待办**同屏同层** ③ 上架前专项自评 → 登记为 **上架前必办**。

## 5. 未取到逐字原文的条目（**如实标注**；第 2 条已补抓关闭）

1. Apple `WKWebsiteDataStore` 文档页是 JS 渲染，本次抓取只返回标题 → **"跨 App 持久化"的官方逐字表述未取得**（但 `defaultDataStore` 的源码分支已直接读到，结论不受影响）。
2. ✅ **已补抓并取得逐字原文（2026-10-02 第二次）**：Google [OAuth 2.0 Policies](https://developers.google.com/identity/protocols/oauth2/policies)「Use secure browsers」段 —— *"A developer must not direct a Google OAuth 2.0 authorization request to an embedded user-agent under the developer's control. Embedded user-agents include, but are not limited to, software libraries that allow a developer to insert arbitrary scripts, alter the default routing of a request to the Google OAuth server, or access session cookies."*（页面标注 **Last modified: August 5, 2026**）。**关键读法**：该列表**非穷举**（原文 "include, but are not limited to"），而其中**两种能力本容器明确具备** —— **注入任意脚本**与**访问会话 cookie**；再叠加同一段的后半句要求"**浏览环境必须让用户能核验当前连接（含请求 URI 与连接安全信息）**"，而原生 WebView 恰恰不提供浏览器式的地址栏/证书核验 → **走到 Google 登录那一步必然会失败**。所以这不是"我们做不做得到"，而是**政策强制**；依据已充分，`resolveEmbedMode` 的降级是唯一正确处置。
