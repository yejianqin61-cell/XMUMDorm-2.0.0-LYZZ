# App 测试与验收

**状态**：**空目录（除本 README）** —— App 尚未开工，因此**还没有任何验收记录**。本文件定义"什么进这里、怎么记、按什么门判"，以免开工后验收结果散落到别处。

**与 [`research/`](../research/) 和 [`evaluation/`](../evaluation/) 的分工**：`research/` 放**做决定之前**的调研取证，`evaluation/` 放对已存在方案的**评估判定**；**本目录放我们自己的验收结果**（逐屏打勾、真机矩阵、脚本运行快照）。三者判据见 [`../README.md`](../README.md) §二。

## 一、放什么

| 类别 | 文件命名（建议） | 内容 |
|---|---|---|
| **逐屏验收** | `逐屏验收-<模块或Tab>.md` | 按[宪法第 13 条](../constitution/App设计宪法.md)逐屏打勾：13.1 本宪法条款 + 13.2 调研-01 的 74 条判据 + 13.3 的 18 条反向症状 |
| **真机矩阵** | `真机矩阵-<日期>.md` | 暗/亮双主题 × iOS/Android × 小屏/大屏/折叠屏；记录机型、系统版本、构建号 |
| **安全区矩阵**（宪法第 17 条） | `安全区矩阵-<日期>.md` | 按[骨架规范 §6.4](../design/App页面骨架与布局规范.md) 的 **≥8 台/形态**逐台打勾（挖孔 / 三键导航 / 横屏 / 折叠屏 / 刘海 / 灵动岛 / 键盘弹出 / iPad 分屏），并逐条过 §6.5 的 10 条清单 |
| **可执行尺子的运行快照** | `尺子快照-<日期>.md` | 四把脚本的原始输出（见 §三），含退出码 |
| **无障碍核对** | `无障碍-<日期>.md` | TalkBack / VoiceOver 逐控件核对；字号放最大后的布局；触控目标实测 |
| **风险 spike 结论** | `spike-<风险名>.md` | R1 返回键 / **R2 原生 Tab 与动作型格位（第 5 格"点了不切页"）** / R3 校方系统**内嵌**与会话（含 Moodle/签到 登录方式）—— **结论可能形成 ADR** |
| **依赖准入登记** | `依赖登记.md` | 每个第三方包五项：许可证 / 是否含原生 / OTA 影响 / **最后发布时间（读版本自身时间戳，不得用 `time.modified`）** / 是否强加视觉身份 |

## 二、怎么记（三条纪律）

1. **只记可复核的事实**：命令、原始输出、机型、构建号、日期。**不写"看起来没问题"**。
2. **未打勾的条目不得以"后面再优化"结案**（宪法 13.2 原话）。要么打勾，要么**开一个具名缺陷**。
3. **验收记录不覆盖历史**：新一轮验收**新建文件**，不修改上一轮（项目既有约定：新的阶段决策另建文档，不覆盖历史验收记录）。

## 三、四把可执行尺子（每轮验收都必须贴原始输出）

| 尺子 | 命令 | 门 |
|---|---|---|
| 设计债 | `node scripts/design-debt-report.js --path <app>/src --fail-on-zero` | `#hex` = 0、`fontSize` 字面量 = 0、**自有 UI 组件引用 ≥1**、内联双语三元 = 0、`t('key')` ≥1 |
| 对比度 | `node scripts/contrast-check.js --fail` | 每个 `textSafe` 令牌达标 |
| 品牌色阶准入 | `node scripts/brand-ramp.js --hue <选定色相> --fail` | 6 条对比度门 + 3 条色相间距门。⚠️ `--compare` 是探索用法，**不得当门**（候选清单故意含未过门项，脚本会对 `--compare --fail` 直接拒绝，退出码 2） |
| 令牌生成自校验 | `node scripts/gen-tokens.js` | 每个 `textSafe: true` 的令牌实测达标，否则退出码非 0；**连跑两次产物字节一致** |

**四把都必须接入 CI，作为合并门**（宪法 14.1）。
