## 1. 测试分层（为什么这样分）

| 层 | 目录 / 形式 | 跑在哪 | 覆盖什么 | 为什么不用别的层 |
|---|---|---|---|---|
| **① 纯函数单测** | `app/src/**/__tests__/*.test.ts` | Jest（`jest-expo` preset） | insets 解析、注册表、二级 Tab 状态保持、令牌主题、词条对称、课表抽取、返回策略 | 这些是**规则**，不是渲染；纯函数让"机型矩阵"可以在 CI 里跑 |
| **② 组件渲染测** | 同上（RNTL） | Jest | 五格底栏配置渲染、顶部 Tab 条 a11y 属性、发布中心条目渲染 | 需要断言 a11y 角色/状态与条目数 |
| **③ 源码扫描测** | 同上（读文件 + 正则） | Jest | **宪法可直接判的项**：S1/S3/S4/S5、无自绘 Tab、无 `BackHandler` 劫持、无 IP、无 barrel → 这些是"结构约束"，渲染测测不出来 | 与 `design-debt-report.js` 同一思路；⛔ 不是替代尺子，而是**把宪法条款变成会失败的测试** |
| **④ 尺子（外部脚本）** | 仓库根 `scripts/*` | CI + 本地 | 设计债 / 对比度 / 品牌色阶 / 令牌生成 | 宪法 14.1 要求；**不得在测试里重实现** |
| **⑤ 真机人工** | 记录表（`安全区机型矩阵记录.md`、R1 结论文档） | 真机 | 机型矩阵 10 项、返回键 5 项（**R3 的"会话保持 / 课表页渲染"已由所有者 2026-10-02 裁决取消，不再列入人工层**，见 [R3 结论 §4.1](../evaluation/R3-校方系统内嵌可行性结论.md)） | 无真机不可替代；⛔ 不得用模拟器结果冒充机型矩阵 |

> **⛔ 一条纪律**：层 ③ 的扫描断言**只能**用来防止"已经写好的规则被改回去"，**不得**用来把不合规的写法"扫过去"。判据是"渲染出来对不对"（宪法 9.11-3），不是"脚本是否变绿"。

## 5. 运行方式（本地 = CI 同一套命令）

```bash
# App 单测（层 ①②③）
cd app && npx jest --ci

# 类型检查
cd app && npx tsc --noEmit

# 四把尺子（层 ④，等价于 CI 的 job）
cd app && npm run rulers
```

⛔ **CI 与本地必须跑同一套参数**（否则"本地绿、CI 红"会变成日常）。
