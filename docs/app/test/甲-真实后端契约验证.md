# 甲域真实后端契约验证（不用 mock）

**线上后端**：`https://xmumdorm-200-lyzz-production.up.railway.app`（`shared/api/config.js` 的 `nativeApiBaseUrl`）
**怎么来的**：所有者指出"仓库里有后端、服务器在线，**一律不要 mock**"。此前甲域全部用例都 `jest.mock` 掉了 `shared/api/*` ——
**mock 是我自己按源码推断写的，它当然符合我的推断**，所以"后端到底返回什么"从未被检验过。本文件记录**打真服务**的结果。

**可重复入口**：
```powershell
cd app
$env:LIVE_API_BASE='https://xmumdorm-200-lyzz-production.up.railway.app'
npx jest src/__tests__/live-backend-contract --ci     # → 5 passed
```
不设 `LIVE_API_BASE` 时整组跳过（CI 无网络/无凭据也不会红）。⚠️ 用 `node:https` 而**不是** `fetch`：
jest-expo 下 `fetch` 被替身接管（实测 `res.status === undefined`）——**那等于又一次"看似打真服务、其实假打"**。

## 5. 🐛 真数据逼出来的缺陷（已修）

| ID | 缺陷 | 真数据证据 | 修法 | 状态 |
|---|---|---|---|---|
| D-11 | **今日课程时段显示带秒**：`M-01` 直接渲染 `start_time` → 界面会出现 `14:00:00 离散数学…` | `GET /api/schedule/week?week=1` → `"start_time":"14:00:00"` | `features/me/dashboard.ts` 新增纯函数 `formatClockTime()`（截到 `HH:MM`，⛔ 不解析成 Date）；`courseLineParams` 改用之 | `CLOSED` |

**为什么 mock 抓不到**：我 mock 的 `WEEK_PAYLOAD` 里写的是 `'08:00'`/`'14:00'` —— **是我猜的**；真服务给的是带秒的字符串。
新增两条用例：`p2c-03`（离线回归，钉死 `formatClockTime`）+ `live-backend-contract`（打真服务验 `start_time` 格式与去秒结果）。

## 6. ⛔ 仍未用真数据覆盖的（如实）

| 项 | 原因 |
|---|---|
| `topItems` 的**条目**形状 | 测试账号今日 0 条待办 |
| `GET /api/users/:id/profile` 在**有 viewer 令牌**下的 `user_liked` / `hidden_by_admin` 过滤 | 已验的是公开视图 |
| 聊天消息列表（`GET /api/marketplace/chat/messages`） | 该路由**线上不存在**（同 §2-1） |
| 注册链路（`/api/auth/register`） | 线上 `NODE_ENV=production` 不回传验证码 → 无法自助注册；⛔ 不去污染生产数据 |
| 发帖/点赞/评论等写操作 | ⛔ 刻意不做：不给线上生产库造脏数据 |

## 7. 口径变更（我按此执行）

- **契约假设必须打真服务验**：凡是我对"后端返回什么"的判断，都必须有 §1 那样的真实响应做证据。
- **mock 只用于"不依赖后端的逻辑"**（渲染、状态机、纯函数、UI 结构）；**不得**再用 mock 证明"后端会返回 X"。
- 线上网关（Railway）与本地 backend 的**差异**要显式记录（§2-1 就是第一例）。
