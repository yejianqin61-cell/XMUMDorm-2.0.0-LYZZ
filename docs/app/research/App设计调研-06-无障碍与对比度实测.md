# 无障碍与对比度实测

**日期**：2026-09-30
**性质**：新 App 设计的前置事实输入（Lead 亲自实测）
**为什么是宪法级**：无障碍不是"加分项"——它是应用商店的合规内容、是每屏验收项、也是"像成品 App"的一部分。更关键的是：**App 要继承品牌调色板，而实测显示这套色板整体不达标**。若不在令牌层解决，App 会把不合规的对比度一起继承过去。

---

## 一、结论先行

| 结论 | 证据 |
|---|---|
| 品牌调色板的 **400/500 档位是装饰色，不能作文字，也不能承载白字** | 白字放品牌蓝仅 **2.53:1**；放警告杏仅 **1.76:1**（AA 要求 4.5:1） |
| `slate-500`（弱化文字）**不满足正文 AA** | 对白底 **4.03:1**（要求 4.5），仅够大字 |
| `slate-400`（占位/禁用）**连大字 AA 都不满足** | 对白底 **2.41:1**（要求 3.0） |
| 真正合格的是**深色文字层** | `text-primary` 13.27:1、`text-secondary` 7.92:1 ✅ |
| 要达标，品牌色需压暗到原亮度的 **60%～78%** | 见第三节量化表 |
| 双端口径一致：`#hex` 直用是问题根源 | 与 [`App设计调研-00`](./App设计调研-00-旧App设计债实测基线.md) 的 1437 处硬编码同源 |

## 二、WCAG 对比度实测（Web 品牌调色板）

测量方式：WCAG 2.x 相对亮度公式（sRGB 线性化后加权），对比度 = (L₁+0.05)/(L₂+0.05)。

| 配对 | 对比度 | AA 正文 (4.5) | AA 大字 (3.0) |
|---|---|---|---|
| `text-primary` `#20304a` on 白 | **13.27** | ✅ | ✅ |
| `text-primary` on `page` `#f7fafc` | 12.66 | ✅ | ✅ |
| `text-secondary` `#42526b` on 白 | **7.92** | ✅ | ✅ |
| `text-secondary` on `page` | 7.56 | ✅ | ✅ |
| `slate-500` `#6f8097` on 白（弱化文字） | **4.03** | ❌ | ✅ |
| `slate-400` `#9aa8bc` on 白（占位/禁用） | **2.41** | ❌ | ❌ |
| 品牌蓝 `#4da7ff` **作为文字** on 白 | **2.53** | ❌ | ❌ |
| **白字 on 品牌蓝** | **2.53** | ❌ | ❌ |
| **白字 on 成功绿** `#39c58d` | **2.20** | ❌ | ❌ |
| **白字 on 警告杏** `#ffb547` | **1.76** | ❌ | ❌ |
| **白字 on 危险红** `#f36d6d` | **2.91** | ❌ | ❌ |
| `slate-900` on 品牌蓝浅底 `#e8f4ff` | **11.89** | ✅ | ✅ |
| 品牌蓝 on 品牌蓝浅底 | 2.27 | ❌ | ❌ |

### 判定

- **能用的**：深色文字层（`slate-900` / `slate-700`）。这是唯一在浅底上安全的层。
- **不能用作文字**：`blue/mint/apricot/pink` 的 400 档、`success/warning/danger` 的 500 档。
- **不能承载白字**：所有品牌色块。也就是说，**"品牌色按钮 + 白色文字"这种最常见写法，在这套色板下全部不合规**（2.53 / 2.20 / 1.76 / 2.91 都低于 4.5）。
- `slate-500`（4.03）只能用于大字或非关键信息；`slate-400`（2.41）**只能用于纯装饰**（分隔线、禁用图标），不能用于任何需要读的文字。

> 从色彩体系的角度这不意外：400/500 是中间调，本来就不该承载文字。**问题在于 Web 直接把中间调当强调色和按钮底色用**。App 若继承同一套调色板而不补全色阶，会继承同一个问题。

## 三、要达标，品牌色需要暗到什么程度

以「对白底达到 4.5:1」为目标，按比例压暗求第一个达标值（**机械压暗的下限参考，不是品牌色建议**——正式色阶应由设计给出，且需要保持色相与饱和度的合理关系）：

| 品牌色 | 原值 | 原对比度 | 压暗后（下限参考） | 达标注对比度 | 保留亮度 |
|---|---|---|---|---|---|
| 品牌蓝 blue-400 | `#4da7ff` | 2.53 | `#387aba` | 4.51 | 73% |
| 薄荷 mint-400 | `#73d9b3` | 1.71 | `#45826b` | 4.51 | 60% |
| 杏 apricot-400 | `#ffb86c` | 1.70 | `#996e41` | 4.51 | 60% |
| 粉 pink-400 | `#ff8fb1` | 2.14 | `#a85e75` | 4.64 | 66% |
| 成功 success-500 | `#39c58d` | 2.20 | `#278660` | 4.50 | 68% |
| 警告 warning-500 | `#ffb547` | 1.76 | `#996d2b` | 4.59 | 60% |
| 危险 danger-500 | `#f36d6d` | 2.91 | `#be5555` | 4.55 | 78% |

**结论**：**每个品牌色都必须有一个"文字安全"的深色兄弟档**。设计令牌至少要分三层语义：
`装饰/填充`（原 400/500） → `浅底`（100） → **`文字安全`（约 600/700）**。
白字只能用在后两者中的深色档上。

## 四、Web 无障碍实现现状（对照基线）

| 项 | 实测 | 说明 |
|---|---|---|
| `prefers-reduced-motion` | **8 处** | 有处理，但仅 8 处——动效降级未覆盖率全局 |
| `focus-visible` 样式 | 15 处 | 键盘焦点有处理 |
| `aria-label` | 221 处 | 有实际投入 |
| `img alt` | 127 处 | 有实际投入 |
| `role` | 83 处 | 有实际投入 |
| `tabIndex` | 8 处 | 很少 |
| 骨架屏/空态/加载组件 | 4 个 | 状态覆盖存在 |

**判定**：Web 的无障碍**不是空白**，属于"有意识但不系统"：ARIA 与 alt 有投入，但 **reduced-motion 只覆盖 8 处**，意味着大部分动效没有降级路径。

## 五、对 App 设计的硬含义

1. **令牌必须声明"可否承载文字"，而不只是给颜色。**
   每个颜色令牌要么是 `surface/fill`（装饰），要么是 `text-safe`（已通过 4.5:1 验证）。**不允许出现"品牌色 + 白字"这种未经校验的组合。**
   验收方式：令牌表里每个 text 用途的令牌都要附对比度实测值；可用脚本复算。

2. **"品牌色按钮"必须有合规解法。**
   既然品牌色块不能承载白字，可选路径只有三条：① 用深色文字放在浅品牌底上；② 用加深后的品牌色承载白字；③ 按钮改用中性深色 + 品牌色仅作强调描边。**这必须由设计哲学先定调**，不能每屏自行选择。

3. **触控目标尺寸要写进宪法并逐屏验收。**
   Android 与 iOS 的最小触控目标不同（两者都要求约 44–48 dp/pt 量级，具体值以官方规范为准，见平台规范调研）。移动端 Tab、图标按钮、列表行内操作是重灾区。

4. **动态字体/字号缩放必须支持。**
   系统字号放大后布局不能崩——这恰恰与第 4 节的双语长度问题叠加（[`App设计调研-05`](./App设计调研-05-双语与文本弹性实测.md)）：**英文更长 + 字号更大**是移动端布局的最坏组合，设计余量必须按这个组合留。

5. **动效必须有 reduced-motion 降级路径。**
   Web 只有 8 处降级，App 不能重演。宪法应要求：每个动效都声明其降级行为。

6. **读屏可用性（TalkBack / VoiceOver）是每屏验收项。**
   纯图标按钮必须有可读标签；图片必须有替代文本；自绘控件必须暴露正确的角色与状态。

7. **状态必须齐全：加载 / 空 / 错误 / 无网 / 无权限。**
   旧 App 与 Web 的差距不在"有没有骨架屏"，而在是否**每屏**都定义。宪法应把"五个状态"列为屏级交付物。

## 六、需要所有者拍板

1. **合规目标等级**：只要求 WCAG **AA**，还是对关键路径要求 **AAA**（7:1）？
2. **品牌色的"文字安全"档**：接受"加深品牌色"（视觉上更沉），还是"品牌色只做装饰、文字一律用中性深色"（更克制、更接近原生 App）？
3. **是否把无障碍列入上架前必须通过的硬门**（而非"尽量做"）。

## 七、复测方法

```bash
# 对比度（WCAG 2.x 相对亮度）
node -e "
const hex=h=>{h=h.replace('#','');if(h.length===3)h=h.split('').map(c=>c+c).join('');return [0,2,4].map(i=>parseInt(h.substr(i,2),16)/255)};
const lin=c=>c<=0.03928?c/12.92:Math.pow((c+0.055)/1.055,2.4);
const L=h=>{const[r,g,b]=hex(h).map(lin);return 0.2126*r+0.7152*g+0.0722*b};
const CR=(a,b)=>{const l1=L(a),l2=L(b);return (Math.max(l1,l2)+0.05)/(Math.min(l1,l2)+0.05)};
console.log(CR('#4da7ff','#ffffff').toFixed(2));  // 2.53
"

# 无障碍实现覆盖
grep -rc 'prefers-reduced-motion' frontend/src --include=*.css | ...
```

> 本文的对比度数据来自 **Web 的品牌调色板**。App 定稿自己的令牌后，**必须对每个 text 用途的令牌重跑同一计算**，并把结果写进令牌表。
