# 广场四个功能入口完整展示 UI 调研

> 调研对象：Capacitor App 广场页的“社团广场 / 马校一站通 / 帮帮我 / 出物”四个入口  
> 调研日期：2026-08-13  
> 调研范围：只研究入口的排布与视觉层级，不改 API、权限和四个目标路由。

## 结论

当前四个入口不应继续使用横向滚动的卡片带。它们都是广场的一级功能入口，应该在首屏同时可见、可识别、可点击；但不需要四张大卡片，也不需要解释性副文案、渐变、阴影或箭头。

建议采用“无卡片外壳的 2×2 入口矩阵”：

- 四个入口在手机窄屏一次性完整展示，不发生横向滚动。
- 每个单元格只保留线性图标、短标题和明确的点击区域。
- 用一条外部底部分隔线及单元格之间的细分隔线组织关系，不给每个入口单独画一张浮层卡片。
- App 在 375/390/430px 宽度下统一使用 2×2；较宽的 Web 内容区可以切换为一行四列，但仍保留同一套视觉规则。
- 中英文标题允许自然换行，不为了“塞进一行”而缩小到不可读；单元格高度固定，避免语言切换时页面跳动。

这套形式同时满足“保留功能入口”“完整展示”“避免堆叠感”和“减少 AI 卡片味”。

## 当前实现盘点

### App

入口组件：`frontend-app/src/components/square/TodayCampusQuickActions.jsx`  
页面调用：`frontend-app/src/pages/SquareHome.jsx`  
主要样式：`frontend-app/src/pages/SquareHome.css`

当前 `.square-home-page--timeline .today-campus-quick-actions` 使用：

```css

```

每项又设置了 `flex: 0 0 auto` 和最小宽度，因此四个入口在窄屏无法同时容纳，用户必须左右滑动。现有组件虽然已降级为图标加标题，但容器仍然是横向滚动带。

### 既有文档中的冲突

`docs/10-ClaudeCode/App前端治理前置设计资料/广场页面仿X风格UI调研与改进方案.md` 第 8 条原先建议“超出屏幕宽度时支持水平滚动”。这条建议与当前目标“**四个入口全部完整展示，不左右滑动**”冲突，应以本次目标为准并在后续开发任务中修订。

## 一手来源观察

### X：连续信息流优先，入口承担真实筛选或导航

X 官方帮助文档把主界面描述为连续的帖子时间线，并用 `For you` / `Following` 切换信息来源；帖子文字区域直接进入详情，操作项放在内容行内或菜单中。由此可复用的不是 X 的品牌外观，而是“内容优先、导航轻量、减少包装层”的信息架构。

对本项目的启发：四个入口应是内容流上方的一小段导航，不应占据四张大型营销卡片的视觉权重；入口文字应直接表达目的，不再追加“探索校园”“了解更多”等解释性文案。

来源：[X Help — About your For you timeline](https://help.x.com/en/using-x/x-timeline)

### Apple HIG：分组、留白、对齐和渐进披露

Apple HIG 建议：

- 用留白、背景形状、颜色或分隔线分组相关内容；
- 给重要信息足够空间，不要被非必要细节挤压；
- 通过一致的对齐建立可扫描的层级；
- 当内容集合无法全部展示时再使用渐进披露，但不应把本来只有四项的集合藏在横向滚动中；
- 布局应适配不同屏幕宽度，并测试最小和最大布局。

对本项目的启发：四项数量固定且很少，最合适的是一次性可见的规则网格；细分隔线比四个独立阴影卡片更能表达“同一组入口”；中文和英文换行应由布局容纳，而不是通过横向滚动解决。

来源：[Apple Human Interface Guidelines — Layout](https://developer.apple.com/design/human-interface-guidelines/layout)

### Material 3：卡片是内容容器，不是所有入口的默认外壳

Material 3 官方说明卡片用于容纳相关元素，并提供 elevated、filled、outlined 三种容器变体；卡片布局应根据内容灵活变化。这个定义意味着卡片适合承载有内容层级的对象，而不是把四个简单导航入口都包装成独立浮层。

对本项目的启发：这四项只有图标、标题和点击行为，不需要卡片的 elevation、渐变背景或大圆角。保留统一的点击区域即可，视觉上采用列表/网格分组更合适。

来源：[Material Design 3 — Cards](https://m3.material.io/components/cards/overview)

## 方案比较

| 方案 | 完整展示 | 视觉堆叠 | 中英文适配 | 结论 |
| --- | --- | --- | --- | --- |
| 当前横向滚动小卡片 | 否 | 中 | 好 | 淘汰 |
| 四列图标入口 | 是（中文） | 低 | 英文标题可能拥挤 | 仅适合宽屏 Web |
| **无卡片 2×2 入口矩阵** | **是** | **低** | **好** | **App 首选** |
| 四行列表 | 是 | 低 | 最好 | 纵向占用较多，作为无障碍或宽字重 fallback |
| 四张大卡片 2×2 | 是 | 高 | 好 | 不符合当前视觉目标 |

## 推荐规格

### 结构

```text
社团广场              马校一站通
帮帮我                出物
```

实际 DOM 仍可复用当前 `actions.map(...)`，只改变容器和单元格样式，不新增 API 或数据模型。

### App 尺寸建议

- 外层：全宽、白底，与信息流共用同一内容平面。
- 列数：固定两列；不使用 `overflow-x`。
- 单元格：`min-height: 64px`，左右内边距约 `12px`，图标 18–20px，标题 13–14px。
- 单元格间距：使用 `1px` 分隔线或背景色切换，不使用阴影。
- 圆角：入口组不设圆角；若需要触摸反馈，只在按下态使用浅色背景。
- 标题：最多两行，使用 `line-height: 1.35`；英文 `XMUM Guide` 等较长标题自然换行。
- 点击区域：整个单元格可点击，触摸命中区至少约 44px 高。
- 图标：继续复用 Lucide 线性图标；不要叠加 emoji、装饰图案或箭头。
- 图标视觉：统一使用黑色或接近黑色的线描镂空图标，保持透明内部、单一描边和一致的线宽；不使用彩色底框、渐变填充或实心插画。建议沿用 Lucide 图标体系，通过 `color: #111`、`stroke-width: 1.8–2` 控制视觉重量。
- 动效：只保留短暂的背景色/opacity 反馈；不做入口横向滑入、浮动或缩放动画。

### Web 适配

Web 如果内容区宽度足够，可以在 `min-width` 达标后使用四列；断点切换不应改变入口内容和语义。App 与 Web 共享“图标 + 标题 + 分隔线”的视觉语言，避免两端再次出现一端是大卡片、另一端是小按钮的分裂。

### 排布位置

入口组应继续位于广场主 Tab 下方、轮播图附近的既有功能入口位置。建议顺序保持：

1. 广场标题与主 Tab
2. 四入口矩阵
3. 校园轮播图
4. 校园通知子 Tab 与信息流

如果产品最终确定轮播图必须紧贴页面顶部，则入口矩阵可放在轮播图下方，但不应复制一份入口到其他区域。

## 验收清单

- 375px、390px、430px App 宽度下，四个入口均完整可见，不出现横向滚动。
- 页面和入口组均不存在 `overflow-x: auto`、`flex: 0 0 auto` 这类横向滚动依赖。
- 中英文切换后，标题不被裁切，不改变单元格高度，不出现布局跳动。
- 每个入口的图标和短标题清晰，整个单元格可点击，四个路由保持不变：
  - `/about/club`
  - `/about/freshman-guide`
  - `/about/errands`
  - `/about/second-hand`
- 入口组没有渐变、阴影、大圆角、箭头或解释性副文案。
- 入口组与信息流之间只有必要的留白/分隔线，不再形成“卡片套卡片”。
- `prefers-reduced-motion` 下不出现额外动效。

## 开发边界

本调研不改代码、不变更后端接口、不改变四个入口的业务权限和目标路由。开发时优先修改：

1. `frontend-app/src/pages/SquareHome.css`
2. `frontend-app/src/components/square/TodayCampusQuickActions.jsx`（仅当需要补充语义属性或样式钩子）
3. 对应的 App 视觉回归；Web 端是否同步应作为单独开发决策确认。
