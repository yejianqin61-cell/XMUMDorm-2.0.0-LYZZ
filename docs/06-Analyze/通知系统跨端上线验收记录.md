## 2. Railway 只读契约检查

检查直接挂载当前通知路由到内存 Express 实例，通过 `supertest` 连接 Railway 数据库。测试令牌临时生成且未记录，未执行清理、已读或其他数据写入。

匿名固定样本共有 57 条通知：互动 52 条、事务 0 条、系统 5 条。结果如下：

| 场景 | 结果 |
|---|---|
| 互动第一页 | 返回 20 条，`hasMore=true`，页大小 20 |
| 事务第一页 | 返回 0 条，`hasMore=false`；当前样本没有事务数据 |
| 系统第一页 | 返回 5 条，`hasMore=false` |
| 响应内未读汇总 | 三类列表均包含 `interaction`、`transaction`、`system` |
| 独立未读汇总兼容端点 | 保持可用并返回三个类别 |
| 单帖互动展开 | 返回同一帖子 6 条互动，`hasMore=false` |
| 公告边界数据 | 5 条公告中有 4 条空标题、2 条空正文，可覆盖 Task 05 的主要数据边界 |

现有样本不具备事务通知和超过 20 条的单帖互动，因此不能用这次 Railway 实数检查证明事务卡片视觉或展开明细第二页。对应接口行为已由通知路由自动化测试覆盖，最终 UI 仍应使用验收数据补测。

## 3. 功能回归覆盖

以下行为已有自动化或构建证据：

- 默认类别、三分类过滤、稳定分页、`hasMore` 和分页参数校验。
- 列表响应内未读汇总与独立汇总端点兼容。
- 公告弹窗查询能识别有效帖子目标并生成可用的详情路径。
- 普通帖子目标过滤、用户隔离、删除目标不可导航。
- 同帖点赞评论聚合、异帖隔离和公告隔离。
- 批量已读的去重、上限、用户约束、数据库失败和客户端乐观回滚。
- 无标题公告不生成标题，无正文公告使用当前语言的空正文文案。
- Web 与 Capacitor App 均可使用共享后端契约完成生产构建。

以下行为必须由产品验收，不标记为自动通过：

- Android 真机首次进入信箱时的加载体感、返回、滚动、展开和 Tab 切换。
- 弱网下首次进入、切换类别、返回缓存类别、增量加载失败和恢复。
- 使用具备事务通知及单帖超过 20 条互动的账号检查两级分页。
- 展开互动组、批量已读、独立“查看帖子”和不可访问帖子提示的完整点击链路。
- 清空当前类别不影响其他类别，系统公告保留。
- 中文与英文模式下所有 Tab、动作、空状态、错误状态和公告文案无混搭、溢出或遮挡。
- 公告从信箱进入详情页，以及与全局公告弹窗之间的已读状态一致性。

## 4. 浏览器与实机限制

测试时本地 `5173` App 开发服务与 `4040` API 均在运行，但当前执行环境没有可连接的 in-app browser 实例，因此没有使用其他浏览器工具冒充页面验收。Chrome DevTools 网络面板、移动端视口截图和交互录屏均留给产品验收。

本轮没有连接 Android 设备或模拟器。APK 构建成功只能证明原生工程可编译，不能替代真机触控、系统返回、网络切换和视觉验收。
