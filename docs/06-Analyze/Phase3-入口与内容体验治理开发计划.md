# Phase 3 - 入口与内容体验治理开发计划

## 目标

Phase3 聚焦三个明确范围：轮播图广告系统、树洞推荐话术清理、底部 Tab 体验优化。目标是建立可控的管理员广告投放闭环，移除未实现的算法暗示，并让 App 的主要导航更接近稳定、克制的原生体验。

详细业务规格见 `docs/01-Requirement/Phase3-底部Tab轮播广告与树洞话术治理规格.md`。

废弃的 `mobile/` RN 前端不在范围内。第 16 项 unspecified 暂不处理。

## 治理范围

### P3-10 轮播图广告系统

- 复用现有帖子编辑器、图片上传和详情容器，新增广告帖元数据模型。
- 只有管理员可以代为创建、编辑、预览、投放、下线和归档广告帖。
- 现有轮播管理入口下分为“广告内容库”和“轮播投放位”，App/Web 共用后端权限与数据。
- 广告帖与轮播图是一对多关系：一篇广告帖可被多处轮播复用，每张轮播独立维护展示素材和投放时间。
- 广告轮播只允许“不跳转”或“跳转广告帖”；后端拒绝指向普通帖的广告配置。
- 广告帖从全部普通信息流、搜索、热搜、推荐和个人帖子列表中排除。
- 普通用户只有在有效广告轮播关联存在时才能访问广告详情；失效后显示明确不可用状态。
- 广告详情隐藏点赞、评论、分享和作者主页，展示广告标识、投放方名称、正文图片和一个可选 CTA。
- 站内 CTA 使用应用内路由；HTTPS 外链在 App 使用 Capacitor Browser；特殊协议暂不支持。
- 第一版记录最小点击数据，不包含复杂计费、曝光归因或广告主自助投放。

### P3-14 移除树洞算法推荐话术

- 删除树洞瀑布流中“继续沿着你的兴趣看”“和你的校园身份更相关”等未实现推荐能力的文案。
- 不改变现有帖子排序、分页、筛选和接口行为。
- 同步检查中英文文案、空状态、加载状态和结束状态，避免继续暗示个性化推荐。
- 不新增推荐算法，也不引入新的推荐解释文案。

### P3-15 底部 Tab 栏体验优化

- 优化 App 底部 Tab 的选中态、图标/文字层级、触控反馈和切换动效。
- 目标是连续、克制、接近 iOS 原生体验；不使用渐变、堆叠卡片或过度装饰。
- 保持现有路由、登录态、返回键、深链接和安全区域计算不变。
- Web 端只在共享逻辑或视觉契约确有必要时同步，不强行复制 App 专属交互。

## 实施顺序

1. 建立广告元数据、生命周期、管理员权限和普通信息流过滤，先保证数据边界。
2. 完成广告内容库、广告模式编辑/预览、轮播投放位关联和失效页。
3. 完成广告详情模式、CTA 跳转和最小点击记录，再执行 App/Web 广告链路回归。
4. 清理树洞推荐话术，并进行中英文模式全文检索。
5. 按 Apple 风格调研优化底部 Tab，最后做 App 真机切换、返回键、减少动效和安全区域回归。

## 验收标准

- [ ] 管理员可在 App/Web 的轮播管理工作区创建广告内容并配置一处或多处投放；普通用户不可执行管理操作。
- [ ] 广告帖不出现在任何普通发现入口，仅在有效广告轮播关联存在时可访问。
- [ ] 广告详情明确标注投放方，不显示普通互动，并正确执行站内或 HTTPS CTA。
- [ ] 广告下线、过期、取消关联和逻辑归档后，普通用户看到稳定的不可用状态。
- [ ] 管理员可预览草稿/失效广告并查看最小点击数据。
- [ ] 树洞页面不再出现未实现算法推荐的引导文案，排序和数据请求无变化。
- [ ] 底部 Tab 选中态清晰，切换反馈顺滑，点击区域满足移动端触控要求。
- [ ] Android 返回键、深链接、登录态切换和安全区域不回归。
- [ ] App 构建通过；Web 构建通过或确认无需同步修改。
- [ ] 中英文模式和无障碍焦点/标签回归通过。

## 不在范围内

- 个人空间整体重构（备忘录第 4 项）。
- 通知系统全链路测试和 UI 治理（第 11、12 项）。
- 公告弹窗正文真实链路确认（第 13 项，单独安排）。
- 广告计费、竞价、曝光/转化归因、广告主自助后台和特殊协议跳转。
- 原始清单第 16 项。
