# 万能墙阶段 1：统一信息流骨架

2026-11-02｜丙（App 校园内容）
授权：所有者当日指令 —— 本轮**只做阶段 1**，用示例内容完成 APK 实机视觉验收，
不提前开发发帖、自动排版、评论、投票、招募私聊与推荐算法。

产品口径（覆盖此前的旧六卡/公告卡批次）：

- 万能墙只有**两种帖子**：自由帖、招募帖，在**同一个单列纵向信息流**里混排；
- 公开内容默认**匿名**：只显示「匿名 · 时间」，不显示头像/昵称，也不生成随机头像；
- 两种帖子共用外层卡片、匿名标识、时间、类型标签与公共操作区；
- 旧海报卡/档案卡/便签卡/公告卡/对话卡/清单卡**并入自由帖呈现**，不再作为独立类型；
- 本阶段为**临时骨架**：示例内容必须显式标注，未实现的入口不得伪装成可用。

## 示例内容的边界（硬约束）

- 示例帖是**前端常量**，不发请求、不写数据库、不出现在任何接口里；
- 信息流顶部有说明条「示例内容 · 仅用于阶段 1 视觉验收，不代表真实投稿」，每张示例卡带「示例」标签；
- 示例帖**不可点击**（没有 `campus-row-*` 入口），不会进入并不存在的详情；
- 交互区（点赞/评论/收藏）只展示计数与图标，**没有点击行为**，不是未实现的按钮；
- 真实投稿为空时，空态文案是「还没有真实投稿」，不是「还没有帖子」——避免与示例内容混淆。

## 明确未做（不在本阶段范围）

- 自由帖真实发布、文字海报自动排版与预览（阶段 2）；
- 评论/回复/点赞/收藏/投票（阶段 3、4）；
- 招募发布、编辑、人数与状态维护、轻量留言（阶段 5）；招募专属私聊（阶段 6）；
- 个性化推荐、热度排序（本轮按要求只保留可靠的时间排序与分页）；
- 后端路由、数据库、管理端：**零改动**；未执行任何 push / fetch / 远端同步。

## 实机验收建议（对应所有者列出的 5 条）

1. 自由帖与招募帖在同一列表里交替出现，视觉上属于同一个社区；
2. 卡片左右 16、卡间 8、卡内 16 的间距在真机上是否自然，是否还有过大留白；
3. 「匿名 · x 分钟前」与右侧「招募 / 示例」标签是否清楚，操作区是否像"只是计数"；
4. 长文（打印店那条）、中英混排（A3 自习室那条）、短招募与长招募是否有布局问题；
5. 万能墙仍挂在广场「今日 / 树洞 / 万能墙 / 食堂 / 跑腿」的顶部 Tab 里，没有新增全局标题栏或底部导航。

## APK 构建（由所有者执行）

仓库已有手动工作流 `.github/workflows/app-apk.yml`，不依赖 EAS / EXPO_TOKEN：

1. 先由你确认并推送本分支（本 Agent 未推送、未与远端交互）；
2. GitHub → Actions → `app-apk` → Run workflow，参数保持默认即可
   （`api_base_url` 默认生产地址；`architectures` 默认 `arm64-v8a,armeabi-v7a`）；
3. 构建完成后在该次 run 的 Artifacts 下载 `xmumdorm-test-apk`，内含 `app-release.apk`；
4. 机器上现装的 `com.xmumdorm.app` 与 CI 的 debug 签名可能不一致，若提示签名冲突，先卸载旧版再安装。
