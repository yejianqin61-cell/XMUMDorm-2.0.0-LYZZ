## 三种实体及真实接口

下表路径以仓库根为基准；行号对应上述基线。

证据：[树洞 API](../../../../shared/api/posts.js)、[匿名墙 API](../../../../shared/api/confessions.js)、[校园此刻 API](../../../../shared/api/square.js)。

### 图片保存与权限说明

已声明 Expo 57、expo-file-system、expo-image、expo-sharing、expo-image-picker，未声明 expo-media-library。
证据：[package.json](../../../../app/package.json) 第 32–45 行与 [app.json](../../../../app/app.json) 插件清单。
图片选择与系统分享不能据此证明完成相册保存；本地原生依赖也尚未装齐。

【提案】采用 Expo 57 对应的 MediaLibrary 与 FileSystem，先下载当前预览 URL，再写入相册，清理临时文件。
[Expo 57 MediaLibrary 文档](https://docs.expo.dev/versions/v57.0.0/sdk/media-library/)已核对，存在图库写入与 writeOnly 权限选项。
实现前再次核对该版本文档、平台权限与插件配置；本轮未固定 API 调用，不声称已支持某个系统版本。
FileSystem 版本页本轮工具读取失败，留待实现前重查；不能依训练记忆写 Expo API。
新增依赖、lock 与原生配置属于跨负责人接线，提交具体变更清单给甲指定单写者后再动。

保存契约沿用 `saved | permission-denied | failed`；仅系统写入成功后显示 saved。
详情与全屏预览捕获同一张当前图片 URL；保存期间禁重复提交，切图/退出后旧请求不覆盖新状态。
拒绝时保留预览并提供设置或重试；下载失败、URL 失效与写入失败分别保留重试入口。
权限仅按平台需要触发；不为保存预先索取全图库读取权。Android 13/14/15 与 iOS 的实际请求范围逐机记录。

待甲接收词条建议：保存到设备 / Save to device；保存中 / Saving；已保存 / Saved。
以及：未获权限 / Permission needed；前往设置 / Open settings；保存失败，请重试 / Couldn't save. Try again。
另交评论不可查看、无权限、删除中、删除失败等现有词条复用表；丙不写 i18n 字典。
