### 4.4 匿名编号算法（阶段 3 的关键）

对每个帖子：

1. 查该帖**全部评论（包括已逻辑删除）**的 `user_id → MIN(id)`；
2. 楼主固定编号 `1`（即使还没评论过）；
3. 其他参与者按 `MIN(id)` 升序依次 `2,3,4…`；
4. 同一个人在同帖的评论/回复始终同一个编号；跨帖重新计算；
5. 不新增表、不写回数据库，纯读时计算。

注意：

- **不要硬删除/清空旧评论**。编号依赖历史行的 `MIN(id)`；硬删除会让编号重排。
- 删除评论只做 `deleted_at` 逻辑删除；编号计算仍然包含它。
- 编号不接受客户端传入，也不能由客户端计算（客户端没有 `user_id`）。

### 4.5 评论树、排序、精选、级联

- DB 的 `parent_id` 保留真实父子关系（可任意深度）；
- `nestComments` 把任意深度后代**扁平挂到根评论的 `replies`**，保留 `parent_id`，附 `root_id`、`reply_to_id`、`reply_to_excerpt`；
- 一级评论排序：
  - 缺省：`created_at ASC, id ASC`（Web 旧口径，不要改）；
  - `latest`：`created_at DESC, id DESC`；
  - `hot`：`like_count*2 + 后代回复数` 降序，同分按时间升序；
  - 精选（`featured_at` 非空）永远置顶，按精选时间升序；
- 二级及更深回复始终按时间升序，不参与热度重排；
- 精选：仅帖子作者、仅一级评论、每帖最多 3 条；取消精选把 `featured_at` 置 NULL；
- 删除评论：先取该帖存活评论在内存求后代集合，再一次性 `UPDATE ... SET deleted_at`；本条与全部下级都不可见。

### 4.6 App/Web/管理端兼容

- Web 的 `ConfessionWall.jsx` 不传 `sort`，默认顺序不变；`root.replies` 结构不变；新增字段忽略即可。
- Web 的旧六卡仍按 `template_key` 展示；App 新帖默认 `template_key='letter'` + `poster_style`，Web 会按旧“档案卡”显示，不报错。
- 管理端沿用 `confession_comments` 表；新增 `featured_at` 列不影响列表/删除；管理员删除评论仍走原接口，注意现在会级联隐藏下级。
- 评论仍然**不发送站内通知**（阶段 2/3 既定口径），不要“顺手”加通知。
