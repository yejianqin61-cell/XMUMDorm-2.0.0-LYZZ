## 丙已提供什么

- `treeholeImageSave.ts`：createTreeholeImageSaver图库端口，真实HTTP(S)下载、必要权限、真实写入后saved、拒绝和失败分开。
- `TreeholeImageSaveControls.tsx`：详情和预览共用忙态、三结果和失败重试；文本由调用方提供，不改公共字典。
- `TreeholeMedia.tsx`：详情与预览都读同一个current，保存捕获点击时URL，切图/往返/换帖后不串回执。
- `CampusDetailScreen.imageSave`→`TreeholePostDetail.imageSave`→`TreeholeMedia.imageSave`：已提供真实模块接缝。

无配置时保持现有阅读，保存入口不启用。配置须同时提供真实save函数及统一词条文本；不提供假的默认成功器。
事务只在writer.writeImage完成后返回saved；系统分享、临时文件下载和权限授予均不算保存成功。
默认不携带账号token下载公开媒体。真实URL需服务器可读；401/404或下载失败会返回failed，不能拿旧缓存冒充本次成功。

## 真实媒体URL依据

`routes/posts.js`第135/186行把post_images.file_path交给`utils/assets.js`的assetUrl。
配置PUBLIC_ASSET_BASE_URL时返回对象存储地址，已有HTTP(S)路径原样保留，未配置时可能返回`/uploads/...`。
模块仅对`/uploads/`复用现有`shared/api/config.getUploadUrl`及注入的后端地址，显示/预览/保存共用解析后的URL。
没有另建下载端点、拼接生产密钥、改服务端字段或把任意字符串猜成相册图片。
下载文件必须存在、非空、是file:///且有图片扩展名；不猜测未知格式，不转换图片，原生不支持格式时按failed处理。

## J-8：由配置单写者安装与重建

当前app/package、lock和实际node_modules没有expo-media-library；已安装Expo ~57.0.26、file-system ~57.0.7。
SDK57官方推荐MediaLibrary ~57.0.5；甲使用兼容安装命令，由实际生成的lock记录最终补丁版本，本轮没有安装。

```powershell
# 在app目录，由配置单写者执行
npx expo install expo-media-library
```

需要修改的现有公共文件：`app/package.json`、`app/package-lock.json`、`app/app.json`；原生构建按甲安排。
使用SDK57支持的`expo-media-library/legacy`入口提供如下三个函数，避免主入口弃用同名函数运行时报错。
已有image-picker权限只用于菜品点评选图，不替代新增的相册写入用途说明。

```ts
import * as Photos from 'expo-media-library/legacy';
import { createTreeholeImageSaver } from '@/features/campus/treeholeImageSave';

// 在已确认原生模块可用的接线层创建一次；保持save函数身份稳定。
const saveCurrentImage = createTreeholeImageSaver({
  getWritePermission: () => Photos.getPermissionsAsync(true, []),
  requestWritePermission: () => Photos.requestPermissionsAsync(true, []),
  writeImage: localUri => Photos.saveToLibraryAsync(localUri),
});
```

接口含义：get先读写入权限；未授权且canAskAgain才request，永久拒绝不再次弹系统授权；设置恢复后下次保存重新读取。
writeOnly=true和空granularPermissions用于仅保存场景，不请求图片/视频/音频读取；需在Android13/14/15与iOS实际确认。
若写入期间权限变化而write抛错，本次返回failed，留页可重试；不会报告saved。
`saveToLibraryAsync`成功是Promise<void>，不要求伪造asset id；适配器不得提前resolve或把异常吞为成功。

给app.json的插件增量（合并到现有plugins，不覆盖原插件）：

```json
["expo-media-library", {
  "photosPermission": "Allow photo access when required by the system",
  "savePhotosPermission": "Allow saving the current treehole image to Photos",
  "isAccessMediaLocationEnabled": false,
  "granularPermissions": []
}]
```

用途说明的最终中英文及平台本地化由甲统一；iOS生成NSPhotoLibraryAddUsageDescription，权限声明须经新构建生效。
当前没有图库原生模块和新构建，不得只更新JS就宣布支持相册；安装/权限/相册结果需要设备证据。
接线前确认Photos.isAvailableAsync可用；不可用时不注入imageSave，不能用Sharing.shareAsync替代上述writeImage。

## J-9：词条与真实详情入口

需甲统一增加下列键，文本为候选，可按统一口径定稿；模块只接收字符串，不直接消费未合入的键。

| 建议键 | 中文 | 英文 |
| --- | --- | --- |
| screen.campus.mediaSave | 保存图片 | Save image |
| screen.campus.mediaSaving | 保存中 | Saving |
| screen.campus.mediaSaved | 已保存到相册 | Saved to Photos |
| screen.campus.mediaPermissionDenied | 未获相册权限，请在设置中允许后重试 | Allow Photos access in Settings, then retry |
| screen.campus.mediaSaveFailed | 保存失败，请重试 | Couldn't save. Try again. |

失败动作直接复用现有action.retry；拒绝后保存按钮仍可操作，页面和预览不自动关闭，不强制导航设置页。
当前真实路由是 `app/src/app/campus/[id].tsx`，甲在该路由或既有接线层将下列配置传给CampusDetailScreen。
保留该路由现有postId/published参数逻辑，不创建第二条详情路由。

```tsx
const imageSave = {
  save: saveCurrentImage,
  messages: {
    save: t('screen.campus.mediaSave'), saving: t('screen.campus.mediaSaving'),
    saved: t('screen.campus.mediaSaved'), permissionDenied: t('screen.campus.mediaPermissionDenied'),
    failed: t('screen.campus.mediaSaveFailed'),
  },
};
// 在现有路由组件中消费；saveCurrentImage复用同一个事务实例。
return <CampusDetailScreen postId={postId} published={published} imageSave={imageSave} />;
```

同URL正在保存时，事务实例会共享同一Promise，避免从详情和预览重复下载/写入；完成后用户可再次明确发起保存。
缓存目录每事务独立，权限拒绝不创建下载；下载/写入后均尝试清理。已写入后缓存清理失败不误报保存失败。
