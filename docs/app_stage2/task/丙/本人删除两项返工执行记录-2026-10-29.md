## D-2 HTTP 删除失败缺少正确恢复语义

复现：4 例新行为测试在修改前全部失败，旧实现对所有错误只显示网络重试提示。
取证：shared/api/request.js:93 将 HTTP 状态保存在 Error.status，并保留 apiStatus/body；测试按这一真实结构构造错误。
服务端 routes/confessions.js 的 DELETE 403 也表示非作者，因此不将所有 403 交给会清会话的通用鉴权分类。

| 输入 | 本地行为 | 恢复动作 |
| --- | --- | --- |
| 401 | auth.expired，复用 handleAuthFailure | 现有 /login；不再提供删除重试 |
| 403 | 当前账号无权限，不错误清会话 | 返回列表；不提供网络重试 |
| 404 | 详情切为内容不存在/已删除 | 返回列表；列表由实际刷新收敛 |
| 断网、500、无效成功回执 | 保留内容与失败说明 | 重试重新打开确认框，确认前不请求 |

404 不记录成功删除、不乐观剔除缓存、不自动返回。401 的标准会话失效流程会清公共查询缓存，属于认证恢复，不是删除成功。
测试用例验证该流程的调用与登录按钮接线；实际凭据存储清理、SessionGate 导航仍需设备/真实会话联调。
异步回执只有 generation 仍匹配才更新详情；成功删除即使已离页仍同步列表，不再次导航；失败离页不写成功标记。
证据：CampusScreens.tsx:221、374、479；测试:940–998；严格布尔标记及服务端最终鉴权均未改动。
复用已有公共 UI、双语词条和登录路由；本轮无新增交甲接线需求。
状态：D-2 已修复并有自动证据，等待复审。
