# 阶段C-03 · 课表定位参数与高亮（R-2）

## 1. 本任务的位置

- **阶段 C 提醒与通知归口**。本任务让课表页接收 `week`/`course` 参数，直接落到对应周并高亮目标那天。
- **前置**：无（C-02 依赖本卡的参数语义）。**后置**：无。

## 2. 开发者需要知道的

**先读**

- `app/src/app/tools/timetable.tsx` — 路由现状：只渲染 `TimetableScreen`，不收任何参数。
- `app/src/features/tools/TimetableScreen.tsx:101-104,190-240` — 组件的周次状态与 `highlightWeekday` 出参。
- `app/src/features/tools/timetableView.ts` — `visibleTimetableWeekdays` / 高亮语义。
- `docs/app_stage2/task/乙负责需求/交甲-A2-09c课程提醒点击接入.md` — 参数名与期望。

**已定**

- 参数名：`week`（正整数）与 `course`（课程码）；非法值一律回落到当前周，不报错。
- 高亮沿用现有 `highlightWeekday`（渲染器只认"星期几"），⛔ 不给渲染器加新语义。
- 只在**首次进入/参数变化**时应用，⛔ 不覆盖用户手动翻周。

**边界与接缝**

- 改路由文件 + `TimetableScreen` 新增两个可选 prop；不动渲染器与 `proto/P11`。
- 接缝：路由传参 → 组件周次/高亮出参（渲染 props 断言）。

**运行**

- `cd app && npx jest src/__tests__/s2-29-timetable-deeplink --ci`
- `cd app && npm run typecheck`

**未知**

- 课程码到"星期几"的解析需要当前周数据；若数据未加载完就解析，要等数据到位再高亮（用例要覆盖）。

## 3. 工作流

1. 读四个入口并一句话复述。
2. 写用例 1（带 week=5 → 组件显示第 5 周），红。
3. 加 `initialWeek` prop 并在路由读取参数，绿。
4. 写用例 2（带 course → 渲染器收到目标星期高亮），绿。
5. 补用例 3（非法/缺失参数 → 当前周、不高亮、不报错）。
6. 跑用例 + typecheck，提交。
