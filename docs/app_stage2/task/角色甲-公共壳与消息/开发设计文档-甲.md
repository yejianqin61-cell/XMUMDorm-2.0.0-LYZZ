## 结论（先看这段）

1. **甲本轮 = 5 组已裁决需求 + 1 组公共接线**：A2-11 发布安全区（P0）、A2-13 我的加载与资料（P0/P1）、A2-12a/b 消息来源与跳转（P0）、A2-12c 的分类常量部分（P0，甲的服务端文件）、A2-02 广场吸顶（P1）、A2-01 启动链路（P1，白屏部分）、外加路由注册 / 词条汇总 / 文档回写。
2. **最贵的不是页面，是 A2-02 的接缝**：广场五个内容 Tab 中，**只有 3 个（树洞 / 万能墙 / 跑腿）走甲拥有的列表骨架**，今日（`TodayPane.tsx:74` 自持 `ScrollView`）与食堂（`CanteenHome` 走 `FeatureScreen`）不经过甲 —— 所以"滚动上报"只能在甲拥有的骨架里自动成立，剩下两个必须由乙接一行，登记为搁置。
3. **A2-12 有真实服务端缺口，必须先补投影再改 UI**：`GET /api/notifications` 现在只给 `target.{type,id,key,title,path,available}`【已核实 `routes/notifications.js:113-147`】，**没有来源正文摘要**，也没有 `target.comment_id`；`post_title` 只对 5 个帖子类 type 返回【已核实 `:34-41, :93`】。摘要必须由甲先在服务端加投影，App 才有东西可显示。
4. **两处已确认的代码与裁决不一致**（本轮修）：`CATEGORY_TYPES` 把 `marketplace_want` 与 `activity_*` 都归 `transaction`【已核实 `services/notificationService.js:52-66`】，与 D2-12 / 契约 §交易列表 L79 冲突；`app.json` **没有 splash 配置**、`expo-splash-screen` **不在依赖里**【已核实：`app/node_modules` 与 `package-lock.json` 均无】，冷启动白屏没有兜底。
5. **A2-11 的改动点在公共表单容器**，`Form` 被 **7 个生产文件**直接消费（发布宿主、注册、找回密码、资料编辑、待办、食堂点评、菜品点评），另有排课导入消费同一套 `useForm` 与离开保护【已核实：源码 `import { Form }` 共 7 个生产文件】→ 必须做成**可选模式**，否则一次改动波及注册与点评。这需要团队领导定口径（§0-Q2）。
6. **三件事本轮不做也不假装能做**：丁的接线 A-1…A-7 与交易 Tab 会话化（押后）、课程测评屏幕（等戊）、真机证据（本机无设备，只能记"未验证"）。

## 3. 逐条方案

> 每条五段：**Approach**（形状）· **Touches**（模块，不是文件；精确路径在 §5）· **Test seam**（优先复用既有）· **Acceptance**（可勾选）· **Hard part**（最可能出错的或还没定的）。另加 **联动**：跨轨说明。

### J2-1 发布表单的安全区与提交位统一

- **Approach**：把"提交位"从滚动内容里拆出来，落进唯一安全区容器的粘性底栏槽（该槽已存在且已实现"键盘高度 / bottom inset 二选一"的合并计算【已核实 `Screen.tsx:109-114,218-231`】）。表单骨架新增一个**可选提交模式**：默认保持"提交在滚动内容内"（8 个既有消费页零变化），发布宿主显式启用"底栏提交"。媒体选择与预览弹层沿用"由容器注入 insets、覆盖层不自己读"的既有规则【S7】。
- **Touches**：组件层（表单骨架、安全区容器、媒体选择与预览弹层、Sheet/Toast）、发布 feature（宿主装配）。
- **Test seam**：复用 **S-2 骨架契约**（同一份 props → 状态，多的只是位置）+ **S-6/S-7 安全区**（`p2d-02` 类用例已存在）。**不新增接缝。**
- **Acceptance**：
  - [ ] 6 个已就绪发布表单（万能墙 / 树洞 / 社团活动 / 社团帖子 / 二手 / 跑腿）**全部**用同一提交位实现，页面零重复布局
  - [ ] 键盘弹出时**最后一项输入与提交同时可点**；键盘收起后提交位回到 Tab 栏/手势条之上，**无双倍留白**
  - [ ] 媒体选择、图片预览、动作面板、Toast 各自有明确 insets 来源，⛔ 无 `SafeAreaView`、无写死数值
  - [ ] 非发布表单（注册 / 找回密码 / 资料编辑 / 待办 / 食堂点评 / 菜品点评 / 排课导入）**行为不变**（回归零差异）
  - [ ] 逐页截图覆盖 Android 手势 / 三键 / 带顶部安全区三种形态（无设备则记「未验证」，⛔ 不写「通过」）
- **Hard part**：`Form` 是本仓最大的公共组件之一（24KB），提交位搬家会同时牵动"离开确认 / 草稿 / 校验错误聚焦"三处状态；另有 8 个消费页必须证明零回归。媒体字段的弹层由各域描述符以渲染函数注入（`mediaRender`），**层级归属**容易在"域弹层"里漏掉 insets。
- **联动**：媒体选择/预览弹层的**入口**在各域发布描述符里（二手=丁、跑腿=乙、社团=戊、树洞/万能墙=丙），甲只改容器与甲拥有的发布媒体组件；若某域的弹层自己绕开容器读 insets，需要对方改一行 → 登记 §6-L6。

### J2-2 「我的」加载策略与资料一致性

- **Approach**：把「我的」的资料取数从"挂载即打、失败即整卡降级"改成"**会话就绪后再取、单一取数点、可失效**"：① 用会话状态门控首次取数（冷启动/后台恢复都先等水合）；② 资料取数收成一处（一个 hook + 一份缓存），保存资料成功后**显式失效**，返回「我的」立即可见；③ 退出登录或换账号按会话标识清缓存；④ 各区块保持现有的分区降级，⛔ 不整屏报错。
- **Touches**：我的 feature（仪表盘取数、资料编辑、内容 Tab 的取数门）+ 会话层（只读消费状态）+ 词条。
- **Test seam**：复用 **S-4 纯规则**（资料归一化 + 失败分类）+ 既有会话门用例；新增用例只断言"取数时机"与"保存后失效"，不新增接缝。
- **Acceptance**：
  - [ ] 冷启动登录后**首次进入「我的」无需手动刷新**；后台恢复、退出重登三条路径同样成立
  - [ ] 资料保存成功后返回「我的」，昵称/头像/学院等**立即显示新值**
  - [ ] 保存失败**保留表单输入**并可重试；某区块失败只降级该区块，已成功载入的资料不被清空
  - [ ] 换账号后不出现上一个账号的昵称/头像/等级（缓存按账号隔离）
  - [ ] 弱网/断网时保留当前内容并给重试，⛔ 不显示"数据为空"冒充成功
- **Hard part**：现状是"每次挂载都取一次、无缓存、无焦点刷新"【已核实 `MeScreen.tsx:69-83`】，而「我的」的四个内容 Tab 各有自己的取数门（`ContentPanes` 内 `active` 门）—— 修资料层不能顺手改内容 Tab 的缓存语义。另：仪表盘的今日课程**只读依赖**乙的课表取数，它抖一下不得让资料区一起挂。
- **联动**：课表取数属乙（只读，不改）；「我的」内容 Tab（帖子/点评/收藏等）的后端属丙/戊，但屏幕文件在甲目录内 —— 本轮只动取数时机，不改列表业务。

### J2-3 通知来源摘要的服务端投影

- **Approach**：在甲主责的通知查询里加一层**目标解析器注册表**：按 `target.type` 解析出"来源摘要 + 被回复摘要 + 评论定位 id"，一次性批量回源、按**查看者权限**决定是否可看，长度截断；解析器未注册的类型返回空摘要，由 App 用类型 + 标题兜底。**⛔ 不把 Web 路径当数据传给客户端**（`path` 仅作兜底）。匿名域一律不返回真实作者身份。
- **Touches**：服务端通知通用模块（查询投影 + 解析器注册表 + 分类常量之外的部分）+ 通知路由的响应组装。
- **Test seam**：既有服务端通知路由测试文件（537 行）扩用例；匿名与失效两条分支必须各有一条真实结构用例。**不新增接缝。**
- **Acceptance**：
  - [ ] 帖子/墙帖/社团动态三类通知返回 `source_excerpt`；评论类额外返回 `reply_to_excerpt` 与 `target.comment_id`
  - [ ] 目标删除 / 隐藏 / 无权限时 `target.available=false` 且**两段原文均为空**，只保留类型与"不可查看"占位所需的最小字段
  - [ ] 匿名域通知**不返回** `from_user` 真实身份（现状对所有类型都返回【已核实 `notifications.js:101-108`】）
  - [ ] 摘要长度有上限（服务端截断），客户端只按可见行数截断展示，⛔ 不落盘敏感原文
  - [ ] `GET /api/notifications` 与 `/unread-summary` 的既有字段含义不变（`id/type/is_read/created_at` 等）
- **Hard part**：来源正文分散在 posts / 校园 / 社团 / 攻略 / 二手 五个域，**甲只拥有其中"帖子类"的解析器**；其余域的解析器由对应负责人补（§6-L2）。若一次性把所有表的 SQL 写进通知模块，等于甲擅自接管别人的数据契约。另：匿名判定与"管理员可见"是两套逻辑，不能用一个布尔混用。
- **联动**：**丙**（树洞/万能墙来源）、**戊**（社团动态、攻略、课程测评来源）、**丁**（二手商品/会话来源）各交一份"目标类型 + 失效样例 + 摘要来源"清单；甲提供注册表接口与帖子类解析器。**本轮只做帖子/校园/匿名三类**，其余【搁置·待团队领导统一】。

### J2-4 通知分类与未读口径常量

- **Approach**：按 D2-12 把分类常量改成裁决口径：`marketplace_want → interaction`、`marketplace_chat → transaction`、`activity_register_success / activity_start_reminder / activity_deadline_reminder → system`；泛型 `marketplace` 保留在模块筛选、从交易分类移除（按 §0-Q3 提案）；`CATEGORY_TYPES` 与 `MODULE_TYPES` 保持"模块筛选 ≠ 分类"的两层语义。改完**同时**回归 Web 端（Web 与 App 共用同一套服务端分类）。
- **Touches**：服务端通知通用模块（常量）+ Web 通知/信箱展示回归 + App 端分类筛选用例。
- **Test seam**：既有信封/分类断言（`unread-summary` 的 `byCategory` 自洽性）+ Web 端分类展示用例。**不新增接缝。**
- **Acceptance**：

### J2-5 App 侧统一目标路由与失效态

- **Approach**：建**唯一**的目标映射函数：输入 `target.{type,id,comment_id,available}`，输出 App 路由或"不可跳转"。现状只有 3 个社团目标被映射，其余 Web 路径一律不猜【已核实 `MailboxScreen.tsx:56-67`】。映射分三档：**可跳**（路由已存在）、**不可跳但有说明**（类型未知/目标失效/落点待对方确认）、**待补**（类型已知、App 无落点 → 登记缺口，⛔ 不猜 Web 路由）。列表行在重新聚焦时刷新，避免展示旧摘要。
- **Touches**：消息 feature（映射函数、行渲染、聚焦刷新）+ 词条（失效态文案）。
- **Test seam**：复用 **S-4 纯规则**（映射函数输入→路由/失效的纯函数表）+ 既有信箱四态用例。**不新增接缝。**
- **Acceptance**：
  - [ ] 映射函数是**唯一**入口；页面里不再有第二处 `target.type` 判断（源码断言）
  - [ ] `post`、`club`、`club_activity`、`club_post` 可跳；`campus_post` 在丙核对前**标"不可跳"并给出说明**（契约明说当前墙页不可直接套用）
  - [ ] 目标失效（`available=false`）时行可点但不发生错误跳转，进入可理解说明态；⛔ 不把 Web `path` 传进 Expo Router
  - [ ] 评论类通知携带 `comment_id` 时，路由带上定位参数（落地滚动定位由内容页负责，本轮不接）
  - [ ] 重新聚焦刷新后不出现旧摘要（列表数据以最近一次响应为准）
- **Hard part**：`campus_post` 与匿名墙是**不同实体**（契约 §路由映射明确要求丙先核对）；`marketplace_thread` 与会话页的落地依赖丁的接线（押后）。映射函数要能容纳"待补"状态而不抛错。
- **联动**：**丙**核对 `campus_post` 落点；**戊**给社团/课评目标（课评页未建）；**丁**给二手商品/会话目标。**本轮只落地已存在路由的映射**，其余登记 §6-L3，【搁置·待团队领导统一】。

### J2-6 广场上部收起与五 Tab 吸顶

- **Approach**：广场壳变成"**三段式**"：可收起的上部（品牌头 + 四入口 + 校园助手）、常驻吸顶的二级 Tab 条、内容 pager。甲维护**唯一**的收起进度与选中 Tab；内容域只上报"垂直滚动位置 / 是否在顶部 / 是否下拉"，⛔ 不得各自渲染第二条 Tab 导航。收起进度由滚动位置映射（上部高度区间内线性），**只有回到内容顶部并继续下拉超过阈值才展开**，中途反向轻滚不动。各 Tab 的位置/分页/筛选沿用既有二级状态存储；点击与横滑切换后按目标 Tab 自己的滚动位置重算收起进度（不沿用上一 Tab 的值）。
- **Touches**：广场壳（布局与收起状态）+ 公告板骨架（列表滚动上报，甲拥有）+ 二级 Tab 组件（吸顶语义）+ 导航状态存储（只读消费）。
- **Test seam**：**新增 1 个接缝**：`SquarePaneScroll`（内容域 → 广场壳的上报契约，纯回调，不涉 UI）。其余复用 **S-4 纯规则**（收起进度映射函数：滚动位置 → 0…1）与既有二级 Tab 状态用例。
- **Acceptance**：
  - [ ] 初始屏与参考截图的上下层级一致；向下浏览时上部整体离开视野、五 Tab 停在顶部安全区之下
  - [ ] 只有"回到内容顶部并继续下拉"才展开；中途反向轻滚、快速甩动后不出现反向跳位
  - [ ] 五个 Tab 均可触达；点击/横滑切 Tab 后各自滚动位置与收起状态正确；横滑不抢系统边缘返回手势
  - [ ] "减少动态效果"开启时，收起/展开**瞬时到位**且任务结果不变
  - [ ] 收起进度映射是**纯函数**且有表驱动用例（不依赖真机即可断言 0/0.5/1 三档）
  - [ ] 不出现第二条 Tab 导航；Tab 条不越过顶部安全区；底部内容不被一级导航遮挡

- **联动**：5 个内容域中**只有跑腿**（`ErrandScreens.tsx:98` → `ListScreen`）走上报骨架 → 上报**自动可用、对方零改动**；**树洞/万能墙**（`CampusScreens.tsx:329` 自持 `ScrollView`）、**今日**（`TodayPane.tsx:74`）、**食堂**（`FeatureScreen`）都必须各接**一行**上报 → 【搁置·待团队领导统一】（§6-L1）。甲不写乙丙的屏幕文件。（2026-10-30 更正：原写"树洞/万能墙/跑腿三个自动"不成立，见[阶段4-01 结论](阶段4-01-收起实现与手势选型结论.md) §4。）

## 4. Phases

> 顺序沿用团队领导 2026-10-29 确认的 **P0 优先**（A2-11 → A2-13 → A2-12 → A2-02 → A2-01）。风险最高的 A2-02 用"阶段首任务 spike"消化：先回答手势与实现方式，再写页面，避免后半程返工。

### Phase 1 — 发布一条线（安全区与提交位）

**Covers**: J2-1（P0）。

**Goal**: 从第 5 格进发布中心，任选一个发布类型，**键盘打开时能填完最后一项并直接提交**，提交位不遮内容、不多留白。

**Tasks**

- 盘点 6 个发布表单与全部弹层的现状（顶部/最后一项/提交/媒体层），出盘点表
- 在表单骨架加可选提交位模式，默认关闭（既有 7 处消费页零变化）
- 把发布宿主的提交动作接到唯一安全区容器的粘性底栏槽
- 核查媒体选择、图片预览、动作面板、Toast 的 insets 归属
- 用一张万能墙表单跑通端到端（提交中禁用、失败保留输入、成功回落到明确落点）
- 补齐非发布表单的零回归用例（注册 / 找回 / 资料 / 待办 / 食堂点评 / 菜品点评 + 排课导入的 `useForm`）与三种导航形态的截图清单

**Proof**: 万能墙表单在键盘打开时最后一项与提交同时可点；`verify:serial` exit 0；非发布表单消费方用例零失败；截图清单（无设备项标未验证）。
**Not here**: 发布表单的字段/校验/成功去向（域内已定）；媒体上传协议；二手发布的接线（丁的 A-7，押后）。

### Phase 2 — 「我的」一条线（加载与资料）

**Covers**: J2-2（P0/P1）。

**Goal**: 冷启动登录后第一次进「我的」就有完整资料，改完资料返回立即是新值 —— **不需要下拉刷新**。

**Tasks**

- 复现并写清"每次进入报错、刷新才恢复"的时序（会话水合 vs 取数）
- 把资料取数收成单一取数点：会话就绪后取、失败分区降级
- 保存资料成功后失效资料缓存，返回「我的」立即可见
- 按账号隔离缓存，退出/换账号清空
- 补三条生命周期的自动用例（首次进入 / 后台恢复 / 换账号）
- 逐页核对「我的」与资料编辑的四态与错误三要素

**Proof**: 三条生命周期路径无需手动刷新；保存失败不丢输入；换账号无残留；`verify:serial` exit 0。
**Not here**: 内容 Tab 的列表分页与业务（属丙/戊的数据）；今日课程取数（乙）；头像上传（历史遗留，另行排）。

### Phase 3 — 消息一条线（摘要 / 分类 / 跳转）

**Covers**: J2-3 · J2-4 · J2-5（P0）。

**Goal**: 一条评论通知在信箱里**能看见被回复了什么**，点进去到正确页面；目标失效时不泄露原文、不留错觉；分类角标与裁决口径一致。

**Tasks**

- 建服务端目标解析器注册表，先实现帖子/校园/匿名三类
- 通知响应增加来源摘要、被回复摘要、评论定位 id，并做权限与匿名裁剪
- 失效目标清空两段原文，只保留最小字段
- 按裁决口径改分类常量，并回归 Web 分类展示
- 建 App 侧唯一目标映射函数，替换现有 3 类社团分支
- 消息行接入摘要与失效说明态；聚焦刷新避免旧摘要
- 四类目标（帖子互动 / 评论回复 / 失效来源 / 二手私聊样例）联测与用例

**Proof**: 四类目标各演示一次；失效不留原文；`unread-summary.byCategory` 自洽；服务端用例 + Web 回归 + App 用例全绿。
**Not here**: 交易 Tab 会话化（押后）；已读回标通知（丁的服务端端点，押后）；评论落地滚动定位（丙）；二手/攻略/课评来源解析器（搁置）。

### Phase 4 — 广场一条线（收起与吸顶）

**Covers**: J2-6（P1）。

**Goal**: 在广场向下浏览内容时，品牌头与四入口整体收起、五个 Tab 停在顶部；回到内容顶部继续下拉才展开，五个 Tab 各自位置不丢。

**Tasks**

- Spike：在真机/模拟器上比较"动画高度"与"位移+裁剪"两种收起实现，并回答下拉展开用哪套手势 API
- 定滚动上报契约（内容域 → 广场壳）并把上报做进甲拥有的列表骨架
- 实现收起进度纯函数与状态机（滚动位置 → 进度；回顶下拉 → 展开）
- 改广场壳为三段式布局，接上 Tab 吸顶
- 处理横滑切 Tab、点击切 Tab、系统边缘返回、reduced-motion 四种情形
- 回写骨架规范 §5/§4.6 与页面清单，补"第二条 Tab 导航"的源码断言

**Proof**: 验收矩阵 A2-02 的五种演示情形可走通；纯函数表驱动用例绿；真机录像（无设备则记未验证）。
**Not here**: 乙的今日/食堂上报接入（搁置）；Tab 条的视觉取值（风格体系）；内容域的列表改造。

### Phase 5 — 启动一条线（图标与启动链路）

**Covers**: J2-7（P1）。

**Goal**: 冷启动直接进首屏，过程中不出现白屏、闪屏或图标跳变。

**Tasks**

- 接入启动画面（底色 + 图标 + 暗色变体）
- 衔接启动态与首屏，消除白屏/闪屏/跳变
- 三启动路径演示 + 图标资源清单 + 未验证项登记

**Proof**: 冷/热/深链各演示一次；三启动路径录像或截图；资源清单齐。
**Not here**: 品牌启动动效（等素材）；应用商店图标物料；真机机型矩阵。

### Phase 6 — 收口

**Covers**: J2-8 · 全部需求的证据归档。
