# 阶段2-02 · 资料取数收成单一取数点

## 1. 本任务的位置

- **Phase 2 我的加载与资料一致**，目标是「冷启动登录后首次进「我的」无需手动刷新」。
- **本任务把 J2-2 的取数时机收口**：一个 hook 负责会话门控、缓存、失败保留与重试；`MeScreen` 只消费它。
- **前置**：阶段2-01（红用例已就位）。**后置**：阶段2-03（保存后一致性）、阶段2-04（账号隔离）。

## 2. 开发者需要知道的

**先读**

- `app/src/__tests__/s2-06-me-profile.test.tsx` — 阶段2-01 留下的红用例（本任务的目标）
- `app/src/features/me/MeScreen.tsx:57-87` — 要替换的本地 `useState/useEffect` 取数
- `app/src/shared/queryClient.ts` — 全 App 单一 client（`getQueryClient()`）与默认值
- `app/src/features/me/profile.ts:47-63` — `normalizeProfile(payload)`
- `app/src/features/me/ContentPanes.tsx:1-40` — 四个内容 Tab 的取数门（本任务不改它们）

**已定**

- 用 TanStack Query（App 已有 `QueryClientProvider` 与 `getQueryClient`，⛔ 不新增第二套取数机制）。
- 资料真源 `getMe()`；失败**保留上一次成功的数据**，只标失败 + 给重试。
- 恢复期（`restoring`）与未登录（`signedOut/expired`）**不发请求**（`enabled` 门控）。
- 不做本地手工扣减/伪造数据；页面只展示。

**边界与接缝**

- 新增 `features/me/useMeProfile.ts`；改 `MeScreen.tsx` 的取数段与失败提示，不改页面结构与 Tab。
- 接缝：**会话 hook + getMe**；不新增端到端之外的接缝。

**运行**

- `cd app && npx jest src/__tests__/s2-06-me-profile src/__tests__/p2c-03-dashboard --ci`
- `cd app && npx tsc --noEmit`

**未知**

- 若 `MeScreen` 全量渲染过重，本任务的用例只覆盖 hook，并由源码断言保证 `MeScreen` 用 hook、不直接 `getMe`；如实写进提交说明。

## 3. 工作流

1. 读五个入口，用一句话复述本任务。
2. 建 `useMeProfile`：会话门控 + 缓存 + 失败保留 + 重试，先让阶段2-01 的红用例转绿。
3. 补用例 2（失败保留旧数据）与用例 3（重试后恢复）。
4. 让 `MeScreen` 改用它，源码断言：页面不再直接 import `getMe`。
5. 跑 `p2c-03` 回归 + `tsc --noEmit`。
6. 提交。

## 4. 测试用例

| 用例 | 输入 | 期望 | 接缝 |
|---|---|---|---|
| 1 | 会话 `restoring` | `getMe` 0 次 | 会话 hook + getMe |
