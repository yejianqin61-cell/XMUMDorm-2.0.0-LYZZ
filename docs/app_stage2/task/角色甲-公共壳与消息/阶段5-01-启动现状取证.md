# 阶段5-01 · 启动现状取证与资源清单

## 1. 本任务的位置

- **Phase 5 启动一条线**，目标是「冷启动直接进首屏，过程中不出现白屏、闪屏或图标跳变」。
- 本任务把「现在到底有什么、缺什么」钉成事实清单：splash 配置、图标资源实测、原生工程形态、官方口径与不可验边界 —— 后面三张卡都按这里的结论写。
- **前置**：无。**后置**：5-02（启动画面配置）、5-03（首屏衔接）、5-04（收口）。

## 2. 开发者需要知道的

**先读**

- `app/app.json:1-54` — 现状：有 `icon`（`:8`）与 Android 自适应图标（`:40-45`，含 `monochromeImage`），**没有 splash 配置**，`plugins` 里也没有 `expo-splash-screen`。
- `app/src/features/auth/SessionGate.tsx:61-90` — 应用内已有 `SessionSplash` 启动位（`bg-canvas` 底 + 品牌位 + spinner），native splash 之后要衔接的是它。
- `app/src/app/_layout.tsx:96-140` — 根布局；`configureAppApi()` 等模块顶层调用已有先例（`:41-51`）。
- `tokens/design-tokens.css` — `--color-bg-canvas` 暗 `#12141a` / 亮 `#f7f8fa`（splash 底色必须与首屏一致，否则收起时闪一下）。
- 官方 SDK 57 文档：`https://docs.expo.dev/versions/v57.0.0/sdk/splash-screen/`（配置插件字段、`preventAutoHideAsync()` 必须在模块顶层调用、Expo Go/开发构建**不能**验证启动画面）。

**已定（本卡给定，不重新讨论）**

- 图标「正式稿＝现有素材」是团队领导 2026-10-29 的决定（[实施计划 §5-Q3](实施计划.md:138)）；本轮**不新建、不改名、不重绘**任何图标，只做启动链路。
- 启动画面的品牌动效与正式素材后补（【搁置·等素材】），本轮不得用自绘动画顶替。
- `expo-splash-screen` 依赖已获批准（同上 §0-Q1）。

**边界与接缝**

- 只写文档（本卡）。⛔ 不改 `app.json`、不改 `_layout.tsx`、不装依赖 —— 那是 5-02 / 5-03。
- 资源清单以**实测**为准（尺寸、是否透明、内容是否为本项目品牌），不引用历史描述。

**运行**

- 本卡无代码用例；用 `node -e` + `sharp` 量尺寸（`app/node_modules/sharp` 已在仓内）。

**未知**

- 实测发现：四份图标资源**都是 Expo 模板占位图**（见 §3），与「已确认为正式稿」的印象不一致。本卡只记录事实，⛔ 不自作主张换素材；由团队领导决定是否在出包前替换。

## 3. 工作流

1. 读五个入口，一句话复述：把「冷启动会白/会闪」的现状与资源缺口写成清单。
2. 实测四份图标资源：尺寸、透明、内容（逐张看过）。
3. 记录原生工程形态：`app/android/` 存在但被 `app/.gitignore:41` 忽略（prebuild 产物、0 tracked），`app/ios/` 不存在。
4. 记录依赖现状：`expo-splash-screen` 未安装（`package.json` 与 lockfile 均无）。
5. 抄官方 SDK 57 的两条硬边界（模块顶层调用；Expo Go/开发构建不可验）+ 导出字段清单。
6. 写「会白/会闪」的触发路径结论（冷启 / 热启 / 深链各缺什么）。
7. 提交文档。
