# 阶段3-01 · 通知来源摘要的服务端投影

## 1. 本任务的位置

- **Phase 3 消息一条线**，目标是「一条互动通知能看见来源与被回复内容，点进去到正确页面；失效目标不留原文」。
- **本任务把 J2-3 的响应字段补齐**：`source_excerpt`、`reply_to_excerpt`、`target.comment_id`、失效清空、匿名裁剪。
- **前置**：无（甲主责的通用通知文件）。**后置**：阶段3-02（解析器注册表）、阶段3-04（App 展示）。

## 2. 开发者需要知道的

**先读**

- `routes/notifications.js:76-151` — 现有 `attachNotificationExtra` 的行装配与 `target` 组装
- `routes/notifications.js:215-255` — 列表 SQL：已 `LEFT JOIN posts`，但只取 `title`
- `routes/posts.js` 的评论通知写入（`treehole_comment` 的 `extra.content` 是**新评论内容**，不是被回复的那条）
- `__tests__/routes/notifications.test.js:1-70` — 服务端用例的 mock 方式（`database.query` 逐次返回）

**已定**

- 摘要由**服务端**生成并按查看者权限裁剪；`extra.content` ⛔ 不得当作"被回复的原评论"。
- 目标失效（帖子删除/隐藏/无权限）时 `target.available=false`，两段原文**清空**，只留类型与"不可查看"所需最小字段。
- 匿名域（树洞 / 万能墙）**不返回**真实作者身份。
- 本域（帖子类）摘要来自已有的 `posts` JOIN，⛔ 不为一行一查。

**边界与接缝**

- 只改服务端通知通用模块与路由；不碰丙丁戊的业务通知写入。
- 接缝：既有 `GET /api/notifications` 响应；**不新增接口**。

**运行**

- `npx jest --runInBand __tests__/routes/notifications.test.js`
- `npm run check:routes-cjs`

**未知**

- 现有用例用 `mockResolvedValueOnce` 逐次喂查询；新增"按评论批量取父评论"会多一次查询。若无法避免，**改用例的 mock 序列**（不作为失败掩盖），并在提交说明写清。

## 3. 工作流

1. 读四个入口，用一句话复述本任务。
2. 在列表 SQL 里补取来源正文（两个降级分支都要补）。
3. 写用例 1（有来源正文 → `source_excerpt`；长度有上限），红 → 绿。
4. 写用例 2（帖子已删除/隐藏 → `available=false` 且两段原文为 null），红 → 绿。
5. 写用例 3（匿名域不带 `from_user`；非匿名域保留），红 → 绿。
6. 写用例 4（评论通知带 `target.comment_id`；`reply_to_excerpt` 来自**父评论**，不是 `extra.content`），红 → 绿。
7. 跑通知用例 + `check:routes-cjs`，提交。

## 4. 测试用例

| 用例 | 输入 | 期望 | 接缝 |
|---|---|---|---|
| 1 | 帖子通知 + 帖子正文 200 字 | `source_excerpt` 存在且 ≤140 字 | `GET /api/notifications` |
| 2 | 帖子已删除 | `target.available=false`，`source_excerpt`/`reply_to_excerpt` 均为 null | 同上 |
| 3 | 树洞类 + 万能墙类 | 无 `from_user`；社团/系统类仍有 | 同上 |
| 4 | 评论通知带 comment_id，父评论存在 | `target.comment_id` 等于该 id；`reply_to_excerpt` = 父评论文本，≠`extra.content` | 同上 |
| 5 | 非帖子域（`extra.targetType=marketplace_item`） | 两段原文为 null（解析器未注册） | 同上 |
