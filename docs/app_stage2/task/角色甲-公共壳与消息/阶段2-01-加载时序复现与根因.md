# 阶段2-01 · 「我的」加载时序复现与根因

## 1. 本任务的位置

- **Phase 2 我的加载与资料一致**，目标是「冷启动登录后首次进「我的」无需手动刷新，资料保存后返回立即是新值」。
- **本任务把 J2-2 的症状钉成时序**：恢复期 / 已登录 / 失败 / 重试四个时刻，谁在什么时候发请求。
- **前置**：无。**后置**：阶段2-02（单一取数点）。

## 2. 开发者需要知道的

**先读**

- `app/src/features/me/MeScreen.tsx:57-87` — 现状：挂载即取数、无会话门、无缓存
- `app/src/features/auth/session.tsx:42-75,112-131` — 会话状态机与冷启动水合（`restoring → signedIn`）
- `app/src/features/me/profile.ts:47-63` — 载荷归一化（不抛，缺字段给空）
- `app/src/shared/queryClient.ts:26-32,64-71` — 全局缓存默认值与 `AppState → focusManager` 接线
- `app/src/__tests__/helpers/renderApp.tsx` — 唯一渲染入口与 `TEST_METRICS`

- 会话失效/登出由 `session.tsx` 统一清缓存（`getQueryClient().clear()`，见 `session.tsx:133-150`）。

- 页面渲染「资料卡 + 四内容 Tab」的结构不变（C-05 已裁决）。

**边界与接缝**

- 只写文档与一条红用例；不改实现（实现归阶段2-02）。
- 接缝：既有会话 hook + `getMe`，**不新增接缝**。

**运行**

## 3. 工作流

1. 读五个入口，用一句话复述本任务。
2. 画出四个时刻的时序：`restoring`（现在会发生什么）、`signedIn`（现在会发生什么）、请求失败、手动重试。
3. 写一条红用例：恢复期不得调用 `getMe`；会话进入 `signedIn` 后**恰好一次**。
4. 跑它，确认它现在是红的（这就是"每次进入报错、刷新才恢复"的根因证据）。
5. 把时序与红用例输出写进 `docs/app_stage2/task/角色甲-公共壳与消息/阶段2-01-加载时序.md`。
6. 提交（文档 + 红用例；接手者在阶段2-02 让它转绿）。
