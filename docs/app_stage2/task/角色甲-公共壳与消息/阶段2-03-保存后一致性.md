# 阶段2-03 · 保存后一致性（资料编辑复用同一取数点）

## 1. 本任务的位置

- **Phase 2 我的加载与资料一致**，目标是「资料保存成功后返回「我的」立即显示新值」。
- **本任务把 J2-2 的"保存 → 返回可见"接上**：编辑页与「我的」用同一份缓存，保存成功即失效。
- **前置**：阶段2-02（`useMeProfile` 已存在）。**后置**：阶段2-04（账号隔离）、阶段2-05（收口）。

## 2. 开发者需要知道的

**先读**

- `app/src/features/me/EditProfileScreen.tsx:85-107,148-157` — 现状：编辑页**自己**再拉一次 `getMe`，保存后直接 `router.back()`
- `app/src/features/me/useMeProfile.ts` — 阶段2-02 的单一取数点（本任务复用它）
- `app/src/features/me/profile.ts:45-58` — `profileToFormValues(payload)` 需要**原始载荷**（不是归一化后的 profile）
- `app/src/components/ui/Form.tsx:509-513` — 成功后 `onSettled` 的触发时机

**已定**

- 编辑页**不新增**第二个取数点：用同一 query（未命中时由 hook 发一次请求）。
- 保存成功后**显式失效**资料 query，然后按既有语义 `router.back()`；⛔ 不靠"下一页碰巧会重拉"。
- 提交体与字段上限保持现状（`PATCH /api/users/me`，服务端无长度上限）。

**边界与接缝**

- 改 `EditProfileScreen` 的取数段与 `onSettled`；不改字段、不改校验、不碰头像上传缺口。
- 接缝：既有 `Form` 的提交语义 + `useMeProfile` 的失效函数；**不新增接缝**。

**运行**

- `cd app && npx jest src/__tests__/s2-07-me-edit-consistency --ci`
- `cd app && npx tsc --noEmit`

**未知**

- 编辑页在资料取数失败时原本允许"进空表单"；改后要保证这条不退化（失败仍可编辑，保存照旧）。若做不到，保留原兜底并写进提交说明。

## 3. 工作流

1. 读四个入口，用一句话复述本任务。
2. 写用例 1（编辑页复用 hook：整棵树里 `getMe` 只被调用 1 次），红 → 绿。
3. 写用例 2（保存成功后 query 被置失效；再取数拿到新昵称），红 → 绿。
4. 写用例 3（保存失败：不失效、值保留、错误可见），红 → 绿。
5. 跑既有编辑页用例回归 + `tsc --noEmit`。
6. 提交。

## 4. 测试用例

| 用例 | 输入 | 期望 | 接缝 |
|---|---|---|---|
| 1 | 同屏渲染编辑页与资料探针 | `getMe` 恰好 1 次；编辑表单回填同一份资料 | useMeProfile |
