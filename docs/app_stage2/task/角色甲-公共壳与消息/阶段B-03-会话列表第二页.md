## 2. 开发者需要知道的

**先读**

- `app/src/features/mailbox/ConversationsScreen.tsx:45-67` — 现状：一次 `limit:100`，然后 `hasMore:false`。
- `app/src/features/mailbox/conversations.ts:35-84` — 行归一化与合并（`mergeThreadRows` 已去重排序）。
- `shared/api/marketplace.js:116-122` — `listMyChatThreads({limit, cursor})`。
- `routes/marketplace.js` 线程列表返回 `{ list, hasMore, nextCursor }`（丁已交）。

**已定**

- 游标由服务端给，客户端**不自己拼**；无 `nextCursor` 就停止请求。
- 合并去重与排序沿用 `mergeThreadRows`，不另写一份。
- 刷新（第一页）仍要能覆盖列表。

**边界与接缝**

- 只改会话列表与它的归一化辅助（甲域）；不动服务端。
- 接缝：`normalizeThreadRows` 旁的"页读取"纯函数（新增，可断言 cursor/hasMore）。

**运行**

- `cd app && npx jest src/__tests__/s2-24-conversations-cursor src/__tests__/p2b-03-conversations --ci`
- `cd app && npm run typecheck`

**未知**

- 若服务端在第一页不给 `nextCursor` 而是只给 `hasMore`，就按 `hasMore` 判到底，不猜游标。

## 3. 工作流

1. 读四个入口并一句话复述。
2. 写用例 1（页读取纯函数：有 nextCursor/hasMore 时原样给出；缺省时安全返回），红。
3. 加纯函数，绿。
4. 会话列表消费游标追加第二页（合并去重），补用例 2（第二页不重复、顺序保持）。
5. 补用例 3（无游标 → 不再请求）。
6. 跑用例 + typecheck，提交。
