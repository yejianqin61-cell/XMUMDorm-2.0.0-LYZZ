# 阶段2-04 · 账号隔离与登出清理

## 1. 本任务的位置

- **Phase 2 我的加载与资料一致**，目标是「换账号后不出现上一账号的昵称/头像/等级」。
- **本任务把 J2-2 的缓存隔离补严**：登录/注册也要清缓存，不只登出与过期清。
- **前置**：阶段2-02（缓存已存在）、阶段2-03（保存已走同一缓存）。**后置**：阶段2-05。

## 2. 开发者需要知道的

**先读**

- `app/src/features/auth/session.tsx:133-208` — `logout`/`markExpired` 已清 `getQueryClient()`，**`login`/`register` 没有清**
- `app/src/features/me/useMeProfile.ts` — 资料 query key 与失效函数
- `app/src/shared/queryClient.ts:37-42` — 单一 client
- `app/src/__tests__/p2c2-*` — 会话既有用例的写法（mock 登录接口）

**已定**

- 会话变更（登录/注册/登出/过期）**一律**清 query 缓存；这是"换账号"的唯一口径。
- ⛔ 不在页面里各自清缓存，也不按页面名黑名单清。
- 资料 query key 保持单一（不把账号名编进 key 充当隔离）。

**边界与接缝**

- 只改 `session.tsx` 的两条路径 + 用例；不改登录/注册的接口与错误口径。
- 接缝：既有 `login`/`register`/`logout` 入口；**不新增接缝**。

**运行**

- `cd app && npx jest src/__tests__/s2-08-me-account-isolation src/__tests__/p2c2 --ci`
- `cd app && npx tsc --noEmit`

**未知**

- 既有会话用例可能断言"登录只清 namespace 不清 query"；若冲突，以"换账号必须无残留"为准修用例，并在提交说明写清。

## 3. 工作流

1. 读四个入口，用一句话复述本任务。
2. 写用例 1（登录成功后 query 缓存被清空），先红。
3. 在 `login` 与 `register` 的成功路径补清理，让用例 1 转绿。
4. 写用例 2（登出后缓存为空、资料不显示），回归确认。
5. 跑既有会话用例与编辑页/我的用例回归 + `tsc --noEmit`。
6. 提交。

## 4. 测试用例

| 用例 | 输入 | 期望 | 接缝 |
|---|---|---|---|
| 1 | 缓存里有上一账号资料 → 登录成功 | 缓存被清空（`getQueryData` 为 undefined） | `login()` |
| 2 | 缓存里有资料 → 登出 | 缓存被清空，资料探针不显示旧数据 | `logout()` |
| 3 | 注册成功 | 与登录同口径清缓存 | `register()` |
| 4 | 会话过期 | 与登出同口径 | `markExpired()` |
