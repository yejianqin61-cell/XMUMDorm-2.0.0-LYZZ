# 阶段3-02 · 目标解析器注册表（给丙丁戊的接口）

## 1. 本任务的位置

- **Phase 3 消息一条线**，目标是「各域来源都能给摘要，但甲不替他们写业务 SQL」。
- **本任务把 J2-3 的联动接口固定**：甲提供解析器注册表与帖子类解析器；其余域后续各交一条。
- **前置**：阶段3-01（响应字段已存在）。**后置**：阶段3-04（App 展示）、阶段3-05（证据）。

## 2. 开发者需要知道的

**先读**

- `routes/notifications.js`（阶段3-01 后的投影段）— 字段已落地，缺口在"非帖子域没有来源"
- `docs/app_stage2/requirements/Stage2统一口径与接口契约.md` §互动消息 — 交接要求：丙交付树洞/万能墙目标，戊交付社团与课评目标，丁交付二手商品与会话目标
- `docs/app_stage2/task/角色甲-公共壳与消息/开发设计文档-甲.md` §6-L2 — 本项标【搁置·待团队领导统一】
- `services/notificationService.js` — 通知类型常量的唯一真源

**已定**

- 注册表在**甲的文件**里（通用通知文件由甲单写）；丙丁戊交"目标类型 + 失效样例 + 摘要来源"，由甲加解析器。
- 未注册的类型返回 `null` 摘要，App 用类型 + 标题兜底，⛔ 不抛错、不猜表名。
- 本轮**只注册帖子类**；其余类型登记为待补，不由甲擅自接管别人的数据契约。

**边界与接缝**

- 只改服务端通知模块；不碰 `routes/{marketplace,clubs,handbook}.js`。
- 接缝：`attachNotificationExtra` 的摘要解析入口；**不新增接口**。

**运行**

- `npx jest --runInBand __tests__/routes/notifications.test.js`
- `npm run check:routes-cjs`

**未知**

- 若某个域的目标同时有 `post_id` 与 `extra.targetType`，优先规则要先看代码再定；不要凭直觉。

## 3. 工作流

1. 读四个入口，用一句话复述本任务。
2. 在通知模块里建解析器注册表（类型 → 解析函数）与"未注册返回 null"的口径。
3. 把阶段3-01 的帖子类摘要改成注册表里的一个解析器（行为不变）。
4. 写用例：未注册类型 → null；已注册帖子类 → 正常（防回退）。
5. 写一页交接说明：丙丁戊各要交什么、加在哪、样例长什么样。
6. 跑用例 + `check:routes-cjs`，提交。

## 4. 测试用例

| 用例 | 输入 | 期望 | 接缝 |
