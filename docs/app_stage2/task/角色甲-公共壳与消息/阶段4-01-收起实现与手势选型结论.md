## 1. 结论先行

| 问题 | 结论 |
| --- | --- |
| 收起怎么实现 | **状态驱动的「外层裁剪高度 + 内层位移」**：外层 `height = H·(1-p)`＋`overflow:'hidden'`，内层固定 `H` 并 `translateY = -p·H`。⛔ 不用动画改高度 |
| 下拉展开用哪套手势 API | **只用滚动事件**（`onScroll` / `onScrollBeginDrag` / `onScrollEndDrag`）。零新依赖、不抢滚动 |
| 吸顶放哪 | Tab 条移入 `Screen` 的 `header` 槽（容器已施加 `headerPaddingTop`）→ **`Screen.tsx` 与 `TopTabStrip.tsx` 都不用改** |
| 收起状态归谁 | 只归广场壳（`SquareHome`）；pane 只上报数字，⛔ 不各自渲染 Tab 条 |
| 五个 Tab 能自动上报几个 | **1 个**（跑腿）。设计文档 §6-L1 写的"3 个自动"不成立，见 §4 |

## 3. 两方案对比与选型

| 维度 | A. 动画改高度 | B. 位移 + 裁剪（选中） |
| --- | --- | --- |
| 每帧代价 | 改真实布局高度：pager 与 5 个 pane 可能每帧重排 | 同样改外层高度，但内层只是 `transform`（不参与布局重算） |
| 抖动风险 | 高（头部内容会被压扁/裁剪错位） | 低（内层按自身高度整体上移，内容不变形） |
| 头尾顺序 | 裁剪底部 → 先消失的是底部入口与助手，品牌头最后消失（与"上部整体收起"相反） | 位移向上 → **品牌头先离开**，符合 A2-02b 的"整体向上收起" |
| 可测性 | 需要动画帧/假时钟 | 纯数字 `p` → 纯函数表驱动可断言 0 / 0.5 / 1 |
| reduced-motion | 要额外关动画 | 本来就没有动画（跟随手指/瞬时），直接满足 |
| 依赖 | 可能引入动画库 | 零新依赖 |

**选 B**，并把 `p` 的计算收进纯函数（4-03 的 `squareCollapse.ts`），页面只负责把 `p` 套进样式。

## 5. 回顶下拉的判定方案

**问题**：Android 的 `ScrollView/FlashList` 到顶后**不产生负偏移**（没有 iOS 的 rubber-band），所以"继续下拉"无法只靠 `offsetY` 判断。

**方案**（只用滚动事件）：

| 平台 | 信号 | 判定 |
| --- | --- | --- |
| iOS | 回弹期 `offsetY < 0` | `offsetY < 0` 即视为下拉 → 展开 |
| Android | 到顶后整段手势内 `offsetY` 恒为 `0` | `endDrag(offsetY===0)` 且本次手势起点也在顶部 → 松手展开 |
| 两端共同 | `beginDrag` 记录手势起点 | 起点不在顶部时，`endDrag` 绝不解发 |

- 进度 `p`：**只在下滑时**按 `p = clamp(offsetY / H, 0, 1)` 更新；反向轻滚**冻结**（A2-02c 的"中途反向轻滚不展开"）。
- 常量：`SQUARE_COLLAPSE_TOP = 0`（到顶阈值，单位 dp）、`SQUARE_PANE_PULL_EXPAND = true`（无需速度阈值，见上表）—— 速度符号假设（`velocity.y < 0` 表示手指下拉）**本轮不用**，避免把不可标定的单位写死。
- 待真机标定：`endDrag` 时手指已离开，展开为瞬时；若真机发现"点击/轻触也触发 begin/end drag"，再加最小位移阈值（登记为阶段4 收口项，⛔ 不预埋参数）。

**下拉刷新冲突**（A2-02c 末句）：上部已完全收起时，`ListScreen` 让出下拉刷新（4-02 的 `handle.collapsed`），先展开、再下拉才是刷新。
