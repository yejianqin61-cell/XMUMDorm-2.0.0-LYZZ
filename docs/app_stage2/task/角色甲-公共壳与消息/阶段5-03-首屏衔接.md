# 阶段5-03 · 首屏衔接（收起时机与减少动态）

## 1. 本任务的位置

- **Phase 5 启动一条线**第三卡：让原生启动画面在**首帧真的画好之后**才收起 —— 避免收起瞬间露出空白帧/闪一下；并让「减少动态效果」下不走淡出。
- 前置：5-02（配置存在，`expo-splash-screen` 已装）。后置：5-04（收口 + 证据）。
- 回退：删 `_layout.tsx` 的两处接线即回到系统默认自动收起。

## 2. 开发者需要知道的

**先读**

- `app/src/app/_layout.tsx:41-51`（模块顶层调用的先例）、`:96-140`（根布局组件与 Provider 顺序）。
- `app/src/design-system/theme.tsx:47,55,84-107` — `theme.reduceMotion` 来自系统「减少动态效果」，全 App 唯一来源。
- `app/src/features/auth/SessionGate.tsx:51-90` — 原生启动画面收起后，第一眼看到的是 `SessionSplash`（已是 `bg-canvas` 底），**不要**再造一个启动页。
- `https://docs.expo.dev/versions/v57.0.0/sdk/splash-screen/` — `preventAutoHideAsync()` **必须在模块顶层调用**（在组件/hook 里调用会太晚）；`hide()` 同步；`setOptions({duration, fade})`，`fade` 仅 iOS；官方要求"尽快收起"。

**已定**

- 收起时机 = **第一次 `useEffect` 执行时**（首帧已提交）+ `requestAnimationFrame` 再收一次兜底，另加 **2s 超时兜底**（组件没挂上也不至于永远卡在启动画面）。
- 「减少动态效果」开 → `setOptions({ duration: 0, fade: false })`；关 → 短淡出（iOS 才有效，Android 走系统自身退出动画）。
- ⛔ 不写自绘启动动画、不加 Lottie/Reanimated 启动动画（素材未到，宪法 7.3）。
- ⛔ 不改 `SessionSplash` 的视觉。

**边界与接缝**

- 新增 `app/src/features/launch/splash.ts`（纯胶水：hold / configure / release + `SplashRelease` 组件）；`_layout.tsx` 加两处接线。
- 接缝：`expo-splash-screen` 的三个 API（`preventAutoHideAsync` / `setOptions` / `hide`），测试里整模块 mock。

**运行**

- `cd app && npx jest src/__tests__/s2-15-launch-splash --ci`
- `cd app && npm run typecheck`

**未知**

- `jest-expo` 不提供 `expo-splash-screen` 的 mock → 本卡用例自己 `jest.mock`；若 `requestAnimationFrame` 在测试环境不触发，用例改用 `runAllTimers` 驱动超时兜底，⛔ 不为了测试改实现。

## 3. 工作流

1. 读四个入口，一句话复述：等首帧画好再收启动画面，并在减少动态时不淡出。
2. 建 `features/launch/splash.ts`：`holdSplashScreen()` / `configureSplashAnimation(reduceMotion)` / `releaseSplashScreen()` / `<SplashRelease />`。
3. 写用例 1（模块导入即调用 `preventAutoHideAsync` 一次），红 → 绿。
4. 写用例 2（挂载后 `hide()` 被调用，且只一次），红 → 绿。
5. 写用例 3（`reduceMotion` 时 `duration: 0, fade: false`；否则 `fade: true`），红 → 绿。
6. 写用例 4（首帧回调不触发时，超时兜底仍会 `hide()`），红 → 绿。
7. 在 `_layout.tsx` 顶层调 `holdSplashScreen()`、在 `ThemedShell` 里渲染 `<SplashRelease />`；跑用例 + typecheck + 既有 `p*` 用例，提交。
