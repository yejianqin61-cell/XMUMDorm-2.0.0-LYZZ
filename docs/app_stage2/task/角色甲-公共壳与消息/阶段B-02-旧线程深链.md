- **阶段 B 二手页面接线**。本任务让"通知里的会话链接"在会话不在首批列表时也能打开。
- **前置**：无。**后置**：无。

## 2. 开发者需要知道的

**先读**

- `app/src/features/mailbox/ChatScreen.tsx:96-104` — 现状：先拉首批会话列表，不在列表就判错误态（旧线程被拦死）。
- `app/src/__tests__/p2b-06-chat.test.tsx:221-234` — 锁定旧行为的用例，**必须一起改写**。
- `docs/app_stage2/task/角色丁-二手与私聊/给甲-Agent-剩余任务清单.md:36` — A-1 的验收句。
- 服务端消息端点：成功 200 / 无权 403 / 不存在 404（丁的交接，已合入）。

**已定**

- 客户端不再用会话列表做授权预检；**服务端消息端点是最终边界**。
- 403 → 权限错误；404 → 内容不存在；其它 → 网络类错误；都不能崩。
- 缺 `threadId` 仍直接进错误态（既有行为保留）。

**边界与接缝**

- 只改会话页与它自己的用例；不碰服务端与消息组件。
- 接缝：会话页首次装载（mock 消息端点返回三种结果）。

**运行**

- `cd app && npx jest src/__tests__/s2-23-chat-deeplink src/__tests__/p2b-06-chat --ci`
- `cd app && npm run typecheck`

**未知**

- 轮询只在拿到授权后启动：改成"首次消息成功即授权"，若 403 后仍启动轮询就是泄漏，用例要挡住。

## 3. 工作流

1. 读四个入口并一句话复述。
2. 写用例 1（不在首批列表但消息端点 200 → 可读可发），红。
3. 删预检、以消息端点结果决定授权，绿。
4. 补用例 2（403 → 权限错误、不启动轮询）、用例 3（404 → 不存在）。
5. 改写锁定旧行为的既有用例（说明为什么改）。
6. 跑用例 + typecheck，提交。
