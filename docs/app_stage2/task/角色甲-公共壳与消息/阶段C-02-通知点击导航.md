# 阶段C-02 · 通知点击的公共导航（R-2）

## 1. 本任务的位置

- **阶段 C 提醒与通知归口**。本任务把「本地课程提醒通知」的点击接到课表定位。
- **前置**：C-03（课表能收定位参数）可并行，但接线要在同一轮验收。**后置**：无。

## 2. 开发者需要知道的

**先读**

- `app/src/features/tools/reminders/navigation.ts:22-48` — 乙交付的纯函数（当前**零生产调用点**）。
- `app/src/app/_layout.tsx` — 根布局，已有 `SplashRelease`/`SessionGate` 等全局宿主挂载点。
- `docs/app_stage2/task/乙负责需求/交甲-A2-09c课程提醒点击接入.md:16-25` — 七步流程与复用点。
- `app/src/features/tools/timetable.tsx` 路由（C-03 的落点）。

**已定**

- 监听**只在根布局挂一次**；⛔ 不在页面里各挂一份。
- 载荷不属于本账号 / 不可用 → 静默忽略（纯函数已给三态）。
- 点击后跳 `/tools/timetable?week=<n>&course=<code>`，参数解释归 C-03。
- 冷启动（App 未运行）与前台两种都要处理。

**边界与接缝**

- 新增一个全局宿主组件（放 `features/notifications/`），根布局挂一次；不动课表内部。
- 接缝：宿主对 `expo-notifications` 的响应入口（测试里整模块 mock）与一个可注入的导航函数。

**运行**

- `cd app && npx jest src/__tests__/s2-28-reminder-notification-nav --ci`
- `cd app && npm run typecheck`

**未知**

- `expo-notifications` 在测试环境需要 mock；若 SDK 57 的 API 名与乙文档不一致，先按实际 API 写并记差异。

## 3. 工作流

1. 读四个入口并一句话复述。
2. 写用例 1（收到本账号载荷 → 导航到课表带参数），红。
3. 在根布局挂唯一宿主，接前台监听与冷启动取最后响应，绿。
4. 补用例 2（非本账号载荷 → 不导航）、用例 3（不可用 → 不导航）。
5. 跑用例 + typecheck，提交。
