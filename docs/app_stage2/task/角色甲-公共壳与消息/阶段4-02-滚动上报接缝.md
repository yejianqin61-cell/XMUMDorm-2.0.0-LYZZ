## 2. 开发者需要知道的

**先读**

- `app/src/components/ui/ListScreen.tsx:413-455` — 列表真实渲染分支；`onScroll` 已存在但只接了 `onScrollOffset`（26 个页面在用）。
- `app/src/features/square/SquareHome.tsx:129-139` — pager 每个 pane 是独立子容器（宽=屏宽），上报必须按 pane 归属。
- `app/src/features/errand/ErrandScreens.tsx:98` — 唯一走 `ListScreen` 的广场 pane（跑腿）。
- `app/src/features/campus/CampusScreens.tsx:329`、`app/src/features/square/TodayPane.tsx:74` — 自持 `ScrollView`，不会自动上报（4-01 已核实）。

**已定（契约，本卡钉死）**

```ts
type SquarePaneScrollHandle = {
  tab: string;              // 所属二级 Tab 键
  collapsed: boolean;       // 上部是否已完全收起（消费方据此让位）
  reportOffset(offsetY: number): void;
  beginDrag(): void;
  endDrag(offsetY: number): void;
};
function useSquarePaneScroll(): SquarePaneScrollHandle | null; // 无 Provider 必须返回 null
```

- `ListScreen` 是**唯一**自动消费点：有 handle 才接三个回调，并在 `collapsed` 时让出下拉刷新（避免"下拉展开"与"下拉刷新"同时触发）；无 handle 时行为与今天一致。
- ⛔ pane 不得自己渲染 Tab 条；⛔ 不新建第二个滚动状态存储。

## 3. 工作流

1. 读四个入口，一句话复述：为广场壳提供唯一滚动上报契约，且不影响其它 26 个 `ListScreen` 页面。
2. 建 `SquarePaneScroll.tsx`：Context + `useSquarePaneScroll` + Provider。
3. 用例 1（无 Provider：渲染与 `onScrollOffset` 行为不变），红 → 绿。
4. 用例 2（有 Provider：`onScroll` → `reportOffset`），红 → 绿。
5. 用例 3（`beginDrag`/`endDrag` 上报；`collapsed=true` 时不出下拉刷新），红 → 绿。
6. `SquareHome` 为每个 pane 提供 handle（只接线、不改视觉），跑用例 + `tsc`，提交。

## 4. 测试用例

| 用例 | 输入 | 期望 | 接缝 |
|---|---|---|---|
| 1 | 无 Provider 的 `ListScreen`（有数据） | `onScrollOffset` 仍收到 y；行为不变 | `ListScreen.onScroll` |
| 2 | 有 Provider，`onScroll({y:240})` | `reportOffset(240)` 调用一次 | 同上 |
| 3 | 有 Provider，begin/end drag | 依次 `beginDrag()`、`endDrag(y)` | 同上 |
| 4 | `collapsed=true` | 列表不再挂 `RefreshControl` | `ListScreen` props |
| 5 | 两个 pane 各自 handle | 上报只进自己的 tab，不串 | Provider |
