# 阶段1-01 · 发布表单与弹层盘点

## 1. 本任务的位置

- **Phase 1 发布一条线**，目标是「键盘打开时能填完最后一项并直接提交」。
- **本任务把 J2-1 的安全区现状摸清**：6 个就绪发布表单、它们的提交位、媒体与覆盖层。
- **前置**：无。**后置**：阶段1-02（提交位）、阶段1-04（弹层核查）、阶段1-05（端到端）。

## 2. 开发者需要知道的

**先读**

- `app/src/features/publish/registry.ts` — 哪些发布类型是 `status:'ready'`，以及它们如何映射到表单
- `app/src/features/publish/resolveDescriptor.tsx` — 字段描述符从哪里来、媒体字段如何渲染
- `app/src/components/ui/Form.tsx:428-445,519-596` — 表单接口与提交位现在在哪一段 JSX
- `app/src/components/ui/Screen.tsx:69-114,218-231` — 唯一安全区容器的 header/footer 槽
- `app/src/features/auth/` 与 `app/src/components/ui/Toast.tsx` — 覆盖层取 insets 的既有方式

**已定**

- 提交位改成**可选模式**，默认关闭，只给发布表单开（开发设计文档 §0-Q2 的提案 A）。
- 6 个就绪表单：wall / confession / clubActivity / clubPost / marketplace / errand（`registry.ts`）。
- ⛔ 不新建组件、不建第二套表单骨架（宪法 9.14 套壳禁令）。

**边界与接缝**

- 只写文档；不碰任何域的 `publishFields.ts`。
- 接缝沿用 S-2（表单 props → 状态）与 S-6（安全区容器），本任务**不新增接缝**。

**运行**

- `cd app && npx tsc --noEmit`

**未知**

- 是否有表单绕过 `Form` 自绘布局。若发现，停止并在任务书里记「未覆盖」，不要顺手改域文件。

## 3. 工作流

1. 读上面五个入口，用一句话复述本任务。
2. 读注册表，列出 6 个就绪表单及其描述符来源。
3. 逐表单记字段（名称、kind、是否媒体字段、是否必填）。
4. 追每个表单的媒体选择与预览：从字段渲染到最终弹层，记组件与行号。
5. 读 `Form.tsx` 的提交段与 `Screen` 的 footer 槽，判断当前提交位归属与键盘避让方式。
6. 清点 `components/ui` 里的覆盖层，逐个记 insets 来源（自读 / 容器注入 / prop / 写死）。
7. 把结果写成 `阶段1-01-发布表单与弹层盘点表.md`（表格，每行带路径:行号），提交。
