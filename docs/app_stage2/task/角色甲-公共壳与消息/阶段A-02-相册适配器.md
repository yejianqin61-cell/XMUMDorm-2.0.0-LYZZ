# 阶段A-02 · 相册适配器（R-5 底座）

## 1. 本任务的位置

- **阶段 A 校园内容一条线**。本任务为 R-5 提供唯一相册写入适配器：把系统图库能力包成丙的保存模块认识的三件事（读权限 / 请求权限 / 写入）。
- **前置**：A-01（依赖已装）。**后置**：A-04（路由注入）。

## 2. 开发者需要知道的

**先读**

- `docs/app_stage2/task/丙/校园内容交甲接线材料/09-当前图片保存模块交付.md:40-55` — 适配器三函数与 writeOnly 语义。
- `app/src/features/campus/treeholeImageSave.ts:6-20` — `TreeholeAlbumWriter` 端口形状与「只有真正写入才算 saved」。
- `app/src/features/campus/TreeholeImageSaveControls.tsx:9-14` — 注入需要的 `messages` 五条。
- `app/src/shared/` 现有文件 — 这是甲的公共接线层，适配器放这里。

**已定**

- 只做 `writeOnly=true` + 空 granularPermissions 的保存权限；不请求读取权限。
- 不可用（`isAvailableAsync` 为假）时**不注入**，不拿系统分享冒充保存（09 文档 :70）。
- 不把异常吞成成功；`saveToLibraryAsync` 完成才算 saved。

**边界与接缝**

- 新增 `app/src/shared/mediaLibrary.ts`（甲层）；不修改丙的保存事务与控件。
- 接缝：新模块的纯函数出口（权限读取 → 请求 → 写入的映射），测试用它。

**运行**

- `cd app && npx jest src/__tests__/s2-17-campus-album-adapter --ci`
- `cd app && npm run typecheck`

**未知**

- legacy 入口在 Jest 下需要整模块 mock；若 `getPermissionsAsync` 签名与 09 文档不同，按实际签名写并停下报告。

## 3. 工作流

1. 读四个入口并一句话复述。
2. 写用例 1（未授权且可再问 → 先请求；授权后写入一次，返回 saved），红。
3. 建 `shared/mediaLibrary.ts` 的最小实现，绿。
4. 加用例 2（永久拒绝 → permission-denied，不再请求）、用例 3（写入抛错 → failed），红→绿。
5. 加用例 4（`isAvailableAsync` 为假 → 适配器报告不可用），红→绿。
6. 跑用例 + typecheck，提交。

## 4. 测试用例

| 用例 | 输入 | 期望 | 接缝 |
