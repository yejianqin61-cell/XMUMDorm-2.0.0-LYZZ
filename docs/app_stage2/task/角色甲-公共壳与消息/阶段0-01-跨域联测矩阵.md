# 阶段0-01 · 跨域联测矩阵（A2-11 / A2-12 / A2-02 / A2-13）

## 1. 本任务的位置

- **阶段 0 联测与出包**：把 A/B/C/D 四阶段"跨模块"的验收面收成一张可复跑的矩阵，作为出包前的最后一道机器门。
- **本任务**产出 `阶段0-联测矩阵.md`：每个跨域验收项 → 对应用例文件与命令 → 本次退出码/用例数。
- **前置**：阶段 A–D 全部提交。**后置**：阶段0-02 出包、阶段0-03 真机清单、阶段0-04 总账。

## 2. 开发者需要知道的

**先读**

- `docs/app_stage2/test/Stage2验收矩阵.md` — A2-xx 的必测情形与证据存放口径。
- `docs/app_stage2/task/角色甲-公共壳与消息/实施计划.md:115-121` — 阶段 6 列出的三组跨域联测（A2-12 四类通知 / A2-02 五 Tab / A2-11 六表单）。
- `app/src/__tests__/s2-04-publish-wall-e2e.test.tsx`、`s2-12-square-collapse-shell.test.tsx`、`s2-31-mailbox-trade.test.tsx` — 三组联测各自的代表用例形态。
- `__tests__/routes/notifications.test.js` — 服务端通知一侧（分类、摘要、已读）。

**已定**

- 联测只**复用**已有用例与命令，⛔ 不为凑矩阵新写重复用例；发现真缺口才补一条用例并在提交里说明。
- 证据分三分：`✅ 机器` / `⚠️ 静态` / `❌ 未验证`；真机项一律 `❌`。
- 跨域项按"甲拥有的一侧"记：例如 A2-12 的树洞/万能墙来源缺丙的落点，记"甲侧通过、来源侧未验证"。

**边界与接缝**

- 只写甲侧文档 + 必要时补甲域用例；⛔ 不改乙/丙/丁/戊文件，⛔ 不动服务端契约。
- 接缝：既有用例文件与命令，不新增抽象。

**运行**

- `cd app && npm run verify:serial`
- `npm test -- --runInBand __tests__/routes/notifications.test.js`
- `npm run check:routes-cjs`

**未知**

- 个别联测项只有静态证据（如 Web 分类展示、丙侧树洞落点）→ 如实记静态，⛔ 不折算成"通过"。

## 3. 工作流

1. 读四个入口并一句话复述：只把已有机器证据按跨域验收面重排，不改行为。
2. 按 A2-11 / A2-12 / A2-02 / A2-13 四组列出验收项与对应用例。
3. 跑三组命令，记录退出码与用例数。
4. 逐项填结论（机器 / 静态 / 未验证），缺口单列。
5. 写 `阶段0-联测矩阵.md` 并提交。
