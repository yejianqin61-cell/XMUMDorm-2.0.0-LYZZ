# 阶段D-02 · 分类常量改裁决口径（R-17，D-6＝先改）

## 1. 本任务的位置

- **阶段 D 交易视图与收口**。本任务把服务端 `CATEGORY_TYPES` 改成 2026-10-28 已裁决的口径，让交易分类只剩私聊。
- **前置**：D-6 已拍板（先改，泛型 `marketplace` 暂挂互动并登记待样例）。**后置**：D-04 证据清单。
- 与 D-01 的关系：D-01 把 App 交易 Tab 换成会话列表；本任务让**服务端角标/分类**不再把想要与活动算进交易，两者合起来才「有角标就有列表」。

## 2. 开发者需要知道的

**先读**

- `services/notificationService.js:11-66,131-141` — `MODULE_MAP` / `MODULE_TYPES` / `CATEGORY_TYPES` 三层，以及 `getNotificationCategory` 的兜底（未命中 → `interaction`）。
- `__tests__/routes/notifications.test.js:87-117,367-383,453-463` — **三处锁死旧口径**的既有用例（活动在交易分类、清空交易带 `activity_register_success`），必须同步改写，否则本任务一定红。
- `frontend/src/pages/Mailbox.jsx:51-54,240-280` — Web 分类展示只读服务端给的 `category` 字段，不自己维护类型表。
- `docs/app_stage2/requirements/Stage2统一口径与接口契约.md:77-80` — 裁决口径与「不能仅凭名称算作聊天未读」的原话。

**已定**

- **D2-12（2026-10-28 领导裁决）**：商品想要归互动；活动报名与提醒归系统；交易仅私聊。
- **D-6（2026-10-31 领导裁决）**：按已裁决口径先改；泛型 `marketplace` 显式落互动，并登记「待丁存量样例确认」。
- `MODULE_TYPES.marketplace` **保留**三类（模块筛选 ≠ 分类），⛔ 不删任何通知类型。
- 泛型 `marketplace` 必须落进某个分类（否则 `byCategory` 求和 ≠ `total`，就是「有角标但列表空」）。

**边界与接缝**

- 只改服务端分类常量与三处锁旧口径的用例；⛔ 不动 Web 代码、不动 App 页面，也不动丁的服务端路由。
- 接缝：`CATEGORY_TYPES` 与 `getNotificationCategory`（`unread-summary` 的 `byCategory`、列表的 `category` 参数与行上 `category` 字段都由它们派生）。

**运行**

- `npm test -- --runInBand __tests__/routes/notifications.test.js`
- `npm run check:routes-cjs`

**未知**

- Web 没有前端单测框架：分类展示只能**静态核对**（Web 只消费服务端 `category`），证据按「静态」记，⛔ 不写成「Web 回归通过」。
- 若发现 Web 有按类型硬编码的分类表，登记为缺口，本轮不改他人的文件。

## 3. 工作流

1. 读四个入口并一句话复述：交易分类只剩私聊，想要进互动、活动进系统。
2. 先改用例到新口径（用例 1、3），红。
3. 改 `CATEGORY_TYPES`：`interaction` 加 `marketplace_want` 与泛型 `marketplace`；`transaction` 只留 `marketplace_chat`；`system` 并入 `MODULE_TYPES.affairs`，绿。
4. 补用例 4（`category=transaction` 的 SQL 只含 `marketplace_chat`）、用例 5（泛型 `marketplace` 的 `getNotificationCategory` 与求和自洽）。
5. 改用例 6（清空交易不再带 `activity_*`）。
6. 静态核对 Web 两处展示入口，跑用例 + `check:routes-cjs`，提交。
