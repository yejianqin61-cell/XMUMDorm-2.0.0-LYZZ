## 2. 逐项做法

### R-1 提醒首次授权与 30 分钟说明文案接线

- **Approach**: 把乙给的补丁落进词条与课表设置说明，同时保持「我的」设置页原说明不动；中英双字典同步，词条门禁用例补齐。
- **Touches**: 词条层、课表/提醒设置区。
- **Test seam**: 既有词条门禁 + 既有课表权限用例（扩两例）。不新增接缝。
- **Acceptance**: [ ] 首次授权说明出现「提前 30 分钟」的解释　[ ] 中英各一条用例通过　[ ] 「我的」设置页文案未被改动
- **Hard part**: 同屏会出现两套「提醒用途」措辞；哪一套留在设置页需要团队领导点头。

### R-2 课程提醒点击的公共导航

- **Approach**: 在根布局挂唯一一次通知响应监听，把本地提醒载荷交给纯函数解析，命中本账号的课程后跳到课表并带定位参数；忽略与不可用两类不跳转。
- **Touches**: 根布局、通知响应入口、课表路由。
- **Test seam**: 既有纯函数单测 + 一个根布局级用例（mock 通知入口），不新增接缝。
- **Acceptance**: [ ] 冷启动点击课程提醒能落到对应课程周次　[ ] 载荷不属于本账号时静默忽略　[ ] 不可用时给出可理解反馈且不跳错页
- **Hard part**: 冷启动与前台两种时序只有一套监听时都要覆盖；真机点击未验证。

### R-3 课程提醒目标与通知目标映射的唯一归口

- **Approach**: 划清两类输入的职责：服务端通知只走既有目标映射，本地提醒载荷只走提醒适配器；页面不得再自行解析通知数据；两处都指向同一条「目标 → 路由」结果类型。
- **Touches**: 信箱目标映射、提醒适配器、消息与课表相关页面。
- **Test seam**: 既有目标映射用例 + 源码断言（页面里不得出现第二处通知数据解析）。
- **Acceptance**: [ ] 页面层零处自行解析通知/提醒数据　[ ] 两类输入都产出同一种目标结果　[ ] 未知目标进入说明态而非盲跳
- **Hard part**: 两套实现语义相近但输入不同；归并时容易把服务端契约塞进本地载荷适配器。

### R-4 图库原生依赖与构建配置

- **Approach**: 按依赖准入流程引入系统图库模块，补权限用途说明与保存权限，并同步登记准入表；明确「变更须重建」。
- **Touches**: App 配置、依赖清单与锁文件、依赖准入登记。
- **Test seam**: 既有依赖准入门禁用例（每个依赖必须有登记行）+ 配置漂移断言。
- **Acceptance**: [ ] 准入闸门绿　[ ] 配置文件里权限用途齐备　[ ] 构建配置改动已登记为「须重建」
- **Hard part**: 准入登记漏行会让全量门禁直接红（上一轮已踩过）。

### R-5 图片保存入口与正式词条

- **Approach**: 详情路由把保存能力注入详情屏，预览里出现保存入口；三结果（成功 / 权限拒绝 / 失败）各有反馈；词条先入字典再被组件消费。
- **Touches**: campus 详情路由、图片预览与保存控件、词条层。
- **Test seam**: 既有保存事务单测 + 详情路由注入的渲染用例。
- **Acceptance**: [ ] 预览里出现保存入口　[ ] 三种结果都有可理解反馈且互不吞没　[ ] 词条中英同步、无内联三元
- **Hard part**: 入口默认隐藏，只有注入后才出现；漏注入在自动用例里不一定红，必须断言「注入后可见」。

### R-6 图片预览的安全区归属

- **Approach**: 二选一由团队领导定：复用丙的全屏预览并让它从唯一安全区容器取 insets，或换成甲的公共覆盖层宿主。选定后只保留一处 insets 来源。
- **Touches**: 全屏图片预览覆盖层、安全区容器。
- **Test seam**: 既有安全区守卫用例（⛔ 不得新增第三处直接读 insets 的调用点）。
- **Acceptance**: [ ] 顶部与底部控件不被状态栏/手势条压住　[ ] 全仓直接读 insets 的调用点仍只有两处　[ ] 关闭手势与返回不冲突
- **Hard part**: 换宿主会牵动手势与过渡；补 insets 改动更小但会让覆盖层继续自持一套几何。

### R-7 万能墙发布实时预览

- **Approach**: 发布容器在万能墙表单下渲染该模块的预览，值来自表单当前值；预览只消费表单值，不重复校验。
- **Touches**: 发布容器、万能墙发布描述符的消费侧。
- **Test seam**: 既有发布表单端到端用例（断言预览随输入出现/消失）。
- **Acceptance**: [ ] 输入正文后发布页出现模板预览　[ ] 清空后预览消失　[ ] 其它发布类型不出现该预览
- **Hard part**: 预览目前无生产消费者，属「接上才算活代码」；顺手要防它与表单值不同步。

### R-8 评论定位参数与定向展开

- **Approach**: 详情路由读取评论定位参数并向下传；评论线程支持定向展开到目标评论并在布局就绪后滚动到它；目标不存在时退回顶部并提示。
- **Touches**: campus 详情路由、评论线程公共件。
- **Test seam**: 既有评论线程用例 + 详情路由参数用例（新增参数断言）。
- **Acceptance**: [ ] 带定位参数进入时展开并滚到目标评论　[ ] 目标已被删除时不崩、给说明　[ ] 无参数时行为与今天一致
- **Hard part**: 甲侧已经发出定位参数，丙侧完全没消费；参数名与「谁在路由层转 prop」需要定。

### R-9 二手旧线程深链

- **Approach**: 会话页不再依赖「首批会话列表是否包含该线程」做授权，直接以消息端点的成功/无权/不存在三种结果决定页面状态。
- **Touches**: 私信会话页、会话数据层。
- **Test seam**: 既有会话页用例（**须同步改写锁定旧行为的用例**），不新增接缝。
- **Acceptance**: [ ] 首批列表不含的旧线程仍可打开　[ ] 陌生线程显示拒绝　[ ] 不存在的线程显示不存在　[ ] 全量门禁绿（旧行为用例已改）
- **Hard part**: 丁自己的旧用例锁死了预检行为，不改测试就一定红；这是本轮最容易"以为做完了"的点。

### R-10 会话列表第二页

- **Approach**: 会话列表消费服务端游标，触底追加并按线程去重合并，保留既有排序；无游标即停止请求。
- **Touches**: 会话列表页、会话列表状态。
- **Test seam**: 既有会话列表用例（补第二页与去重用例）。
- **Acceptance**: [ ] 第二页可见且不重复　[ ] 无游标时不再请求　[ ] 列表排序与刷新行为不变
- **Hard part**: 与「聚焦刷新」叠加时的竞态（新消息插入旧页）。

### R-11 商品编辑入口

- **Approach**: 详情按服务端能力字段显示编辑入口，仅卖家可见；编辑页回填既有字段与图片；保存失败保留输入。
- **Touches**: 商品详情、商品编辑表单、发布容器能力。
- **Test seam**: 既有二手详情/发布用例（补卖家/买家两态）。
- **Acceptance**: [ ] 买家看不到也进不去　[ ] 卖家编辑后详情立即可见新值　[ ] 保存失败输入不丢
- **Hard part**: 编辑复用发布表单时容易把「新建」的默认值带进来。

### R-12 我的想要

- **Approach**: 在「我的」内容区增加想要分页页签，接服务端想要列表，支持空态、失败重试与取消后刷新。
- **Touches**: 我的内容区、想要列表数据层。
- **Test seam**: 既有我的内容区用例（补想要页签）。
- **Acceptance**: [ ] 想要列表可打开且能翻页　[ ] 空态与失败可重试　[ ] 取消想要后数量与列表同步
- **Hard part**: 我的内容区页签与广场二级 Tab 是两套状态，别把两者混成一份。

### R-13 商品状态动作

- **Approach**: 详情与我的商品提供「标记已售」，仅卖家可用；成功后刷新详情、列表与未读相关缓存；重复操作给出明确错误。
- **Touches**: 商品详情、我的商品、二手数据层。
- **Test seam**: 既有二手用例（补权限与重复操作）。
- **Acceptance**: [ ] 仅卖家可操作　[ ] 成功后详情与列表都变已售　[ ] 重复操作有明确错误　[ ] 买家请求被服务端拒绝且页面有反馈
- **Hard part**: 服务端只允许在售 → 已售，反向与重复的反馈要分开表达。

### R-14 已读后未读汇总一致

- **Approach**: 会话读完与已读动作之后重取服务端未读汇总，不做本地扣减；角标清零依赖服务端把对应通知回标已读，这一点归属需拍板。
- **Touches**: 私信会话页、未读汇总数据层、全局角标。
- **Test seam**: 既有未读汇总用例 + 会话读完的集成用例。
- **Acceptance**: [ ] 读完会话后汇总重取（非本地减）　[ ] 重复已读不产生负数　[ ] 汇总与角标一致（若回标未实现则本项记未达成）
- **Hard part**: 回标缺口在服务端且契约判给丁；甲只能保证「重取」这一半。

### R-15 二手发布失败恢复

- **Approach**: 发布提交中禁用重复提交；失败时保留标题、正文、价格、分类与图片，用户可重试；成功后清空并回到明确落点。
- **Touches**: 发布容器、二手发布表单。
- **Test seam**: 既有发布表单端到端用例（补失败恢复）。
- **Acceptance**: [ ] 提交中不可再次提交　[ ] 失败后输入与图片仍在　[ ] 成功后才清空并返回
- **Hard part**: 与甲上一轮做的「表单提交态」是否已覆盖全部字段要逐项核对，别重复造状态。

### R-16 交易 Tab 会话化

- **Approach**: 交易分类只列会话（商品摘要、对方、最新消息、未读），通知不再混在交易页；需团队领导确认是否本轮做。
- **Touches**: 信箱分类与交易视图、会话数据层。
- **Test seam**: 既有信箱用例（补交易视图分类断言）。
- **Acceptance**: [ ] 交易页只出现会话　[ ] 未读与会话行一致　[ ] 点会话进入私信
- **Hard part**: 这是产品形态变更，不是接线；不做则 A2-12c / A2-06c 不得标完成。

### R-17 通知分类常量 `marketplace_want`

- **Approach**: 按契约把「想要」类通知从交易挪到互动；改完须回归 Web 与 App 的分类展示。前置是丁给两条存量样例。
- **Touches**: 服务端通知分类、Web 与 App 信箱分类展示。
- **Test seam**: 服务端分类用例 + Web 分类回归用例。
- **Acceptance**: [ ] 想要通知出现在互动　[ ] 交易仅剩会话类　[ ] Web 分类展示同步正确
- **Hard part**: 同一个常量被 Web 与 App 共用；样例未到就不要先改。

### R-18 甲侧词条与文档口径收口

- **Approach**: 本轮新增词条一次性入中英字典并过门禁；把四份交接里已过期的陈述在甲侧文档登记为「过期」，不擅自改他人文档。
- **Touches**: 词条层、甲侧任务/证据文档。
- **Test seam**: 既有词条门禁 + 文档链接自检。
- **Acceptance**: [ ] 新增词条中英同数、无内联三元　[ ] 甲侧文档列出所有过期陈述与出处　[ ] 不改乙丙丁戊文件
- **Hard part**: 词条分散在多个需求里，容易漏掉一条导致门禁红。

## 3. 阶段划分

> 排序理由：先把「有外部构建风险」的图片保存做完（依赖与重建最早暴露问题）；再做体量最大的二手接线（旧用例冲突最早暴露）；然后是提醒/通知（归并设计风险）；最后是需产品决策的交易 Tab 与收口。

### 阶段 A：校园内容一条线走通（R-4 / R-5 / R-6 / R-7 / R-8）

**Goal**: 详情预览里能保存图片、发布页能看到模板预览、通知里的评论定位能落到那条评论；全屏预览不被系统栏压住。

**Tasks**

- 引入图库依赖并补齐配置与准入登记
- 详情路由注入保存能力，预览里长出保存入口
- 入 5 条保存词条（中英同步）
- 定全屏预览宿主，保证 insets 只有一处来源
- 保存三结果端到端用例：注入后入口可见、三结果互不吞没
- 发布页接入万能墙实时预览（仅万能墙）
- 评论定位参数打通：路由传参、评论线程定向展开与布局就绪后滚动

**Proof**: 保存 / 预览 / 评论三类用例全绿；配置漂移与准入闸门绿；真机项列未验证。
