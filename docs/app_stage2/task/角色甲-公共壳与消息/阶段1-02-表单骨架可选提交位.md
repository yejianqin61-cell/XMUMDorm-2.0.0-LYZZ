# 阶段1-02 · 表单骨架的可选提交位

## 1. 本任务的位置

- **Phase 1 发布一条线**，目标是「键盘打开时能填完最后一项并直接提交」。
- **本任务把 J2-1 的提交位从滚动内容里拆出来**：新增可选模式，默认行为不变。
- **前置**：阶段1-01（盘点）。**后置**：阶段1-03（宿主启用）、阶段1-05（端到端）。

## 2. 开发者需要知道的

**先读**

- `app/src/components/ui/Form.tsx:428-445` — 表单 props，新增项加在这里
- `app/src/components/ui/Form.tsx:519-596` — 提交/取消按钮当前所在的 JSX 段
- `app/src/components/ui/Screen.tsx:84-114,218-231` — `footer` 槽与 `resolveFooterBottomPadding`（键盘/inset 合并唯一实现）
- `app/src/__tests__/p1-10-form-skeleton.test.tsx` — 表单骨架既有用例怎么起渲染树
- `app/src/__tests__/helpers/renderApp.tsx` — 唯一渲染入口与 `TEST_METRICS`（insets.bottom = 48）

**已定**

- 新 prop 默认 `'inline'`：7 个既有消费页（注册 / 找回 / 资料 / 待办 / 食堂点评 / 菜品点评 / 排课导入）行为零变化。
- 底部留白只由 `Screen` 的 footer 计算，⛔ 表单不自己加 `insets`。
- 主按钮、次按钮、提交中状态、离开确认（`AlertDialog`）语义全部不变。

**边界与接缝**

- 只改组件层的表单骨架；发布宿主在阶段1-03 才启用。
- 接缝：**S-2**（同一份 props → 状态机）+ **S-6**（footer 槽）；**不新增接缝**。

**运行**

- `cd app && npx jest src/__tests__/s2-01-form-submit-placement --ci`
- `cd app && npx tsc --noEmit`

**未知**

- footer 里放「主按钮 + 取消」两列是否会在窄屏挤压。若挤，先只放主按钮，取消留在页头，并在此处记录改动。
- 键盘事件的模拟方式若在 jest-expo 下不成立，改用 `resolveFooterBottomPadding` 的纯函数断言 + `screen-footer` 的 inset 断言，⛔ 不写假通过。

## 3. 工作流

1. 读五个入口，用一句话复述本任务。
2. 写用例 1（默认模式无 footer），`npx jest ...` 看它失败或先通过 —— 先确认基线。
3. 加 prop 与分支：`submitPlacement` 默认 `'inline'`；`'footer'` 时把动作行移进 `Screen footer`。
4. 跑用例 2（footer 存在），红 → 绿。
5. 加用例 3（提交中二次点击只发一次），红 → 绿。
6. 加用例 4（非发布消费方零变化），红 → 绿。
7. `npx jest src/__tests__/p1-10-form-skeleton --ci` 回归既有骨架用例。
8. `tsc --noEmit`，提交。
