# 交丙丁戊：通知来源解析器交接（阶段3-02）

**日期**：2026-10-29　**来源**：A2-12a「互动通知显示来源内容摘要」
**接口位置**：`services/notificationTargetResolvers.js`（**甲单写**通用通知文件；你们只提交样例与字段口径，由甲加解析器）
**当前状态**：已注册**帖子类**四种目标（`post` / `trending_post` / `campus_post` / `announcement`）；其余域显示"类型 + 标题"兜底。

## 1. 甲已经给了什么

| 能力 | 位置 | 说明 |
|---|---|---|
| 响应字段 `source_excerpt` | `GET /api/notifications` 每行 | 来源正文摘要，服务端截断 **140 字**（`SOURCE_EXCERPT_MAX`） |
| 响应字段 `reply_to_excerpt` | 同上 | 评论类通知的**被回复评论**摘要（取 `comment_id` 的父评论，⛔ 不是 `extra.content`） |
| `target.comment_id` | 同上，`target` 对象内 | 评论定位 ID（null 也返回） |
| 匿名裁剪 | 同上 | `treehole_*` / `like` / `comment` / `campus_*` 不返回 `from_user`；`trending_*` 保留 |
| 失效清空 | 同上 | `target.available=false` 时两段摘要强制为 null（D2-03） |

## 2. 你们各自要交什么

### 丙 —— 树洞 / 万能墙（`campus_post` 落点核对）

- **交什么**：确认 `campus_post` 在 App 的落点（契约 §路由映射标了"当前 `/campus/wall/[id]` 不可直接套用"）；给出 1 条"目标已删除"与 1 条"目标正常"的真实通知样例。
- **不需要**交摘要解析器：帖子类已覆盖（正文来自 `posts` JOIN）。

### 戊 —— 社团动态 / 攻略 / 课程测评

- **交什么**：`club_activity`、`club_post`、`handbook_article`、`course_review` 四种目标的**表名 + 摘要字段 + 失效判据**（哪个字段表示删除/隐藏），以及各 1 条正常/失效样例。
- 甲按样例加解析器；若某域摘要需要额外查表，用**批量接口**（一次列表只查一次）。

### 丁 —— 二手商品 / 会话

- **交什么**：`marketplace_item`、`marketplace_thread` 的目标字段（已有 `extra.targetType/targetId/itemId`）、摘要字段（商品标题/最新消息）、失效判据（已售/删除/无权限是否要区分）。
- ⚠️ 交易 Tab 会话化与已读回标仍按团队领导指示**押后**，不在本交接内。

## 3. 加解析器的两种写法（甲按你们的样例实现）

```js
// A. 行内：数据已经在通知列表的 row 里（如已经 JOIN 出来的正文）
registerRowExcerptResolver('handbook_article', (row) => row.article_content);

// B. 批量：需要额外查表时（⛔ 禁止一行一查）
registerBatchExcerptResolver('marketplace_item', async (ids) => {
  // 一次 IN 查询，返回 Map<id, excerpt|null>
  return new Map();
});
```

**约束**：解析器抛错只让该段摘要为空（不把列表打成 500）；摘要由注册表统一截断；未注册类型返回 null。

## 4. 验收口径

- 每个域交的样例要能直接写成服务端用例（`__tests__/routes/notifications.test.js` 的 row 形状）。
- 摘要缺失时 App 用「类型 + 标题」兜底 —— 这是**允许的降级**，不算缺陷；但**失效目标不得留原文**。
