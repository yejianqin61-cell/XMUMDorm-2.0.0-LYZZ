# 阶段A-04 · 详情路由注入保存能力（R-5）

## 1. 本任务的位置

- **阶段 A 校园内容一条线**。本任务把 A-02 的适配器与 A-03 的词条接到详情路由上，让保存入口真正出现。
- **前置**：A-01、A-02、A-03。**后置**：无（A-05 是预览安全区，与此独立）。

## 2. 开发者需要知道的

**先读**

- `app/src/app/campus/[id].tsx` — 现状只传 `postId`/`published`，`imageSave` 未注入。
- `app/src/features/campus/CampusScreens.tsx:87-100` — 详情屏已经接受可选 `imageSave`（丙提供的接缝）。
- `app/src/features/campus/TreeholeMedia.tsx:542,583-587` — 注入后详情与预览各自出现保存入口。
- `app/src/__tests__/p2x-treehole-image-save-ui.test.tsx` — 已有的三结果/共享忙态用例；本任务不重写它们。

**已定**

- 只有图库可用时才注入；不可用时保持「阅读照常、保存入口不出现」（09 文档 :14）。
- 保存函数必须**同一实例**（详情与预览共享同一个事务，避免重复下载写入）。
- 保留路由现有 `postId`/`published` 逻辑，⛔ 不建第二条详情路由。

**边界与接缝**

- 只改 `app/src/app/campus/[id].tsx`；丙的详情屏与控件不动。
- 接缝：路由组件传出的 `imageSave`（用 mock 详情屏捕获 props 断言）。

**运行**

- `cd app && npx jest src/__tests__/s2-18-campus-image-injection --ci`
- `cd app && npm run typecheck`

**未知**

- 若 `isAvailableAsync` 在测试环境返回真而 mock 未就绪，测试要显式 mock 适配器层，不测原生。

## 3. 工作流

1. 读四个入口并一句话复述。
2. 写用例 1（图库可用 → 详情屏收到 `imageSave`，五条文案来自字典），红。
3. 在路由里接可用性检查与注入，绿。
4. 写用例 2（图库不可用 → 不传 `imageSave`），红→绿。
5. 加用例 3（同一实例：多次渲染/往返不重建事务），绿。
6. 跑用例 + typecheck，提交。
