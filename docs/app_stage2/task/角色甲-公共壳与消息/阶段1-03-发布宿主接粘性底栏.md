# 阶段1-03 · 发布宿主接粘性底栏

## 1. 本任务的位置

- **Phase 1 发布一条线**，目标是「键盘打开时能填完最后一项并直接提交」。
- **本任务把 J2-1 的提交位真正挂到发布页上**：只有发布宿主启用 footer 模式。
- **前置**：阶段1-02（模式已存在）。**后置**：阶段1-05（端到端）、阶段1-06（回归）。

## 2. 开发者需要知道的

**先读**

- `app/src/features/publish/PublishFormHost.tsx` — 三个分支里哪个渲染 `Form`，门禁分支为什么不改
- `app/src/features/publish/usePublishForm.ts:141-152` — `labels`（含取消）与 `onSettled` 的装配
- `app/src/components/ui/Form.tsx:428-445` — 新 prop 的签名
- `app/src/__tests__/p2x-bing-publish-host.test.tsx` — 发布宿主现在怎么被渲染（桩与 mock 的既有写法）

**已定**

- 只有发布宿主传 `submitPlacement:'footer'`；其他消费页一律不传。
- 门禁拦住时仍走 `TermsGateNotice`（无 footer、无提交），⛔ 不给被拦页面一个能点的提交位。
- 不新增词条：提交/取消标签沿用宿主已有 labels。

**边界与接缝**

- 只改发布宿主的装配一行与必要样式；不碰域描述符、不碰 `Form` 的状态机。
- 接缝沿用 **S-2**（宿主 → 表单）+ 既有宿主用例；**不新增接缝**。

**运行**

- `cd app && npx jest src/__tests__/s2-02-publish-footer --ci`
- `cd app && npx tsc --noEmit`

**未知**

- 若既有宿主用例的桩不足以渲染真实 `Form`，用同一套 mock 方式补最小桩；⛔ 不为了跑通而改宿主的业务分支。

## 3. 工作流

1. 读四个入口，用一句话复述本任务。
2. 在 `PublishFormHost` 渲染 `Form` 的分支传 footer 模式。
3. 写用例 1（发布宿主渲染出 footer 与提交位），红 → 绿。
4. 写用例 2（门禁拦住分支：没有 footer、没有提交位），红 → 绿。
5. 写用例 3（从 footer 提交：域提交函数被调用一次），红 → 绿。
6. 跑既有 `p2a-04`、`p2x-bing-publish-host`、`p2y-d01` 回归。
7. `tsc --noEmit`，提交。
