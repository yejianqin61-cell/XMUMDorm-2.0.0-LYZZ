# 阶段0-02 · 统一出包（本地 Release APK）

## 1. 本任务的位置

- **阶段 0 联测与出包**：产出一个**包含 A/B/C/D 全部接线**的可侧载 APK，供真人体验验收。
- **前置**：阶段0-01 联测矩阵绿。**后置**：阶段0-03（真机清单）用它作为「构建号」。
- 产物不提交仓库（`app/android/` 被 gitignore，APK 不入库）；本任务只交付**构建记录**。

## 2. 开发者需要知道的

**先读**

- `docs/09-Deploy/release/App测试APK构建-2026-10-27.md` — 上一次出包记录、**Windows 本机 CMake/Ninja 阻塞**与已排除的嫌疑。
- `.github/workflows/app-apk.yml` — 团队已知可用路径（Linux runner：prebuild + `assembleRelease`，debug keystore 签名，`EXPO_PUBLIC_API_BASE_URL` 烘焙）。
- `app/src/shared/api.ts:15-23` — release 构建在**没有** env 时默认烘焙生产后端；开发构建才用 `127.0.0.1:4040`。
- `docs/app_stage2/test/角色甲-公共壳与消息/阶段5-证据清单.md:35-67` — prebuild 生成物核对口径与图标占位事实（C7）。

**已定**

- ⛔ **不 push、不触发云端工作流**（团队领导未授权；且云端 main 不含本批提交，打出来的是旧包）。
- 后端地址沿用上一版测试包：`https://xmumdorm-200-lyzz-production.up.railway.app`（release 默认值，无需 env）。
- 签名沿用 Expo 生成的 **debug keystore**（可侧载，⛔ 不上架）。
- ABI 沿用上次交付：`arm64-v8a,armeabi-v7a`。
- 若本机再撞 CMake/Ninja 阻塞：**如实记失败与日志**，不删原生目录、不安装系统组件、不改团队 CI。

**边界与接缝**

- 只动 `app/android/`（prebuild 生成物、gitignored）与 `docs/**`；⛔ 不改业务代码来迁就构建。
- 接缝：`npx expo prebuild --platform android --no-install` → `gradlew assembleRelease`。

**运行**

- `cd app && npx expo prebuild --platform android --no-install`
- `cd app/android && ./gradlew.bat assembleRelease --no-daemon "-PreactNativeArchitectures=arm64-v8a,armeabi-v7a"`
- 产物：`app/android/app/build/outputs/apk/release/app-release.apk`

**未知**

- 本机是否仍撞 `manifest 'build.ninja' still dirty after 100 tries`（上次 6m44s 必挂）。
- Gradle 需联网取依赖；离线会以依赖解析失败告终，届时如实记录而不是改成离线模式。

## 3. 工作流

1. 读四个入口并一句话复述：只出包与记录，不改业务代码。
2. 重新 prebuild（含阶段 A 新增的图库原生依赖与权限），核对 Manifest/colors/versionCode。
3. 跑 `assembleRelease`，保留原始输出到失败点或成功。
4. 成功则记：文件名、体积、SHA-256、包名/versionCode/versionName、ABI、签名、烘焙后端。
5. 失败则记：失败任务、原始错误、已排除项、下一步选项（⛔ 不擅自换通道）。
6. 写 `阶段0-出包记录.md` 并提交。
