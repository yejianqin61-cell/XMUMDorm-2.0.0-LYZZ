# 阶段2-01 · 「我的」加载时序：现状与根因

**日期**：2026-10-29　**基线**：`origin/main@8c477dbf` + 阶段2 开工
**结论先行**：A2-13a「每次进入报错、刷新才恢复」的根因是**取数没有会话门**，且**会话就绪后没有重取机制**；资料还有**两个取数点**（「我的」与资料编辑各一次）。

## 1. 修前时序（按源码核对）

| 时刻 | 发生什么 | 证据 |
|---|---|---|
| 冷启动，会话 `restoring`（令牌正在从 SecureStore 水合） | `MeScreen` 挂载即 `getMe()` | `MeScreen.tsx:69-83`（`useEffect(..., [nonce])`，无会话判断） |
| 令牌还没注入请求层 | `getMe` 无令牌 → 401 → 页面 `failed=true` → 显示"加载失败 + 重试" | `MeScreen.tsx:77` + `shared/api/request.js` 鉴权链 |
| 会话水合完成 → `signedIn` | **没有任何逻辑重取**（effect 依赖只有 `nonce`） | `MeScreen.tsx:83` |
| 用户手动点重试 | `setNonce(n+1)` → 重新取数 → 恢复 | `MeScreen.tsx:85-87` |
| 进入资料编辑 | **自己再拉一次** `getMe`（第二个取数点） | `EditProfileScreen.tsx:91-107`（修前） |

**症状复述**：用户看到的就是"每次进入报错，刷新一下才好"；而且两个页面各拉一次，失败口径也不同。

## 2. 修后时序（阶段2-02 的目标）

| 时刻 | 发生什么 | 落点 |
|---|---|---|
| `restoring` / `signedOut` / `expired` | **不发请求**（`enabled: signedIn`） | `useMeProfile.ts` |
| `signedIn` | 取一次；缓存 60s（全局默认）；之后同屏复用 | 同上 |
| 回到前台 | 该 query 打开 `refetchOnWindowFocus`，按 stale 重取 | 同上 + `shared/queryClient.ts:64-71` 的 AppState→focusManager |
| 取数失败 | **保留旧数据**、标失败、给重试 | 同上 |
| 保存资料成功 | 显式失效 → 返回「我的」立即新值 | `EditProfileScreen` 的 `invalidate` |
| 登录 / 注册 / 登出 / 过期 | 清 query 缓存 | `session.tsx` |

## 3. 红 → 绿记录（如实）

- 阶段2-02 的用例文件 `s2-06-me-profile.test.tsx` 在 `useMeProfile` 建立前**整文件失败**（模块不存在）——这是本轮的红。
- 修复后：`s2-06` 6 条全绿；其中"恢复期不得发请求""未登录不展示缓存"两条正是症状的机械复现。
- ⚠️ 未在**真机**上复现过"恢复期 401"（本机无设备）；根因结论来自源码路径，不是真机日志。真机证据留到本批统一验收。
