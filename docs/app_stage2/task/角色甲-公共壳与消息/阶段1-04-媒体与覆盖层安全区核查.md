# 阶段1-04 · 媒体与覆盖层的安全区核查

## 1. 本任务的位置

- **Phase 1 发布一条线**，目标是「键盘打开时能填完最后一项并直接提交」。
- **本任务把 J2-1 的弹层 insets 收口**：媒体选择、预览、动作面板、Toast 各自归位。
- **前置**：阶段1-01（盘点清单）。**后置**：阶段1-05（端到端联测）。

## 2. 开发者需要知道的

**先读**

- `app/src/features/publish/PublishMedia.tsx` — 发布表单的媒体字段渲染入口
- `app/src/components/ui/MediaPicker.tsx`、`InputSheet.tsx`、`ActionSheet.tsx`、`BottomSheet.tsx`、`Toast.tsx` — 覆盖层取 insets 的既有写法
- `app/src/components/ui/Screen.tsx:43-51` — `useScreenInsets()` 是覆盖层唯一合法的 inset 来源
- `app/src/__tests__/p2d-02-safe-area-10.test.ts` — 安全区 10 条清单里"覆盖层各自处理 insets（S7）"的既有断言
- `app/src/features/publish/PostTopicPicker.tsx` — 发布页里的另一个弹层入口

**已定**

- ⛔ 覆盖层不调用 `useSafeAreaInsets()`，只从容器注入的上下文或 prop 取（骨架规范 §6.1-S7）。
- ⛔ 不出现写死的 `paddingTop: 44` / `bottom: 24` 一类数值当布局依据（S1）。
- 本轮只核查与发布链路相关的覆盖层；发现其他域的同类问题只登记，不改。

**边界与接缝**

- 接缝：**S-7**（覆盖层 insets）+ 既有 `p2d-02` 用例；**不新增接缝**。
- 不碰各域的媒体字段定义与上传逻辑。

**运行**

- `cd app && npx jest src/__tests__/s2-03-publish-overlays --ci`
- `cd app && npx jest src/__tests__/p2d-02-safe-area-10 --ci`
- `cd app && npx tsc --noEmit`

**未知**

- 若某覆盖层确实自己读了 insets，先确认它是否被发布页使用；只改发布链路内的那一处，其余登记。

## 3. 工作流

1. 读五个入口，用一句话复述本任务。
2. 清点发布链路用到的覆盖层，逐个判定 insets 来源。
3. 写用例 1（源码扫描：清单里的覆盖层不 import `safe-area-context`），先红后绿。
4. 写用例 2（弹层在 `Screen` 内渲染时拿到 48 的底部 inset，而不是 0），红 → 绿。
5. 写用例 3（覆盖层不出现写死 inset 数值的源码扫描），红 → 绿。
6. 跑 `p2d-02` 回归。
7. 把盘点结论并入阶段1-01 的盘点表；`tsc --noEmit`，提交。
