# 阶段1-05 · 万能墙表单端到端

## 1. 本任务的位置

- **Phase 1 发布一条线**，目标是「键盘打开时能填完最后一项并直接提交」。
- **本任务把 J2-1 的证据补齐**：一条真实表单从填写到提交成功/失败都在 footer 模式成立。
- **前置**：阶段1-02（模式）、阶段1-03（宿主启用）。**后置**：阶段1-06（回归与证据）。

## 2. 开发者需要知道的

**先读**

- `app/src/features/campus/publishFields.ts` — 万能墙的字段与提交函数（本任务选它做端到端）
- `app/src/features/publish/PublishFormHost.tsx` — 端到端的入口组件
- `app/src/features/publish/usePublishForm.ts` — 提交失败如何变成表单错误、成功如何跳转
- `app/src/__tests__/p2x-bing-wall-publish.test.ts` — 万能墙发布既有断言（校验与提交）
- `app/src/__tests__/helpers/renderApp.tsx` — 渲染入口；`TEST_METRICS` 是外部给定的底部 inset

**已定**

- 端到端用**万能墙**一条，不重复给 6 个表单各写一套（其余靠阶段1-02 的通用用例覆盖）。
- 提交失败必须**保留输入**并给出错误摘要；成功按既有提交语义跳转。
- 关键词：`submitPlacement:'footer'` 只在这一条链路上验证，不改域的提交逻辑。

**边界与接缝**

- 只写测试与最小修正；不改域的描述符与提交函数。
- 接缝：**S-2**（表单状态机）+ 既有发布宿主用例的 mock 方式；**不新增接缝**。

**运行**

- `cd app && npx jest src/__tests__/s2-04-publish-wall-e2e --ci`
- `cd app && npx tsc --noEmit`

**未知**

- 万能墙的必填字段若包含媒体，需要桩 `expo-image-picker`；若桩成本高，改用纯文本字段那条（confession）并在任务书注明替换理由。

## 3. 工作流

1. 读五个入口，用一句话复述本任务。
2. 按既有 mock 方式搭渲染树：万能墙描述符 + 已接受条款的 viewer。
3. 写用例 1（填必填 → 点 footer 提交 → 域提交被调用一次），红 → 绿。
4. 写用例 2（提交失败 → 输入仍在 + 错误摘要出现），红 → 绿。
5. 写用例 3（提交中连点两次 → 只调用一次），红 → 绿。
6. 写用例 4（footer 的底部留白来自容器：48），红 → 绿。
7. 跑既有 `p2x-bing-wall-publish`、`p2x-bing-publish-host` 回归；`tsc --noEmit`，提交。

## 4. 测试用例

| 用例 | 输入 | 期望 | 接缝 |
|---|---|---|---|
| 1 | 填完必填，点 footer 里的提交 | 域 `submit` 调用 1 次；成功后按既有语义 replace/back | S-2 |
| 2 | 提交抛错 | 输入值不变；错误摘要出现；页面不跳转 | S-2 |
| 3 | 提交中连续点两次 | 域 `submit` 仍只调用 1 次 | S-2 |
| 4 | footer 模式 + `TEST_METRICS` | `screen-footer` 的 `paddingBottom` = 48 | S-6 |
