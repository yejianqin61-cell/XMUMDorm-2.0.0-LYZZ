## 2. 每项需求怎样实现？

### D-R1 商品发现与返回保位

- **做法**：保留现行列表，补齐缺失信息与状态回归，不重新设计已裁决布局。
- **范围**：二手列表、详情返回、模块缓存。
- **测试入口**：既有商品列表页面测试与真实服务端列表端点。
- **验收**：PRD 的 D-R1 商品发现与返回保位逐项满足。
- **难点**：筛选、刷新、返回位置与旧请求之间的竞争。

### D-R2 详情与想要

- **做法**：扩展详情模型承接权限与商品信息，保留既有想要不确定状态处理。
- **范围**：详情业务模型、操作区、想要列表数据。
- **测试入口**：既有商品详情页面测试及想要端点。
- **验收**：PRD 的 D-R2 详情与想要逐项满足。
- **难点**：响应丢失后的状态确认与账号切换。

### D-R3 发布与本人管理

- **做法**：复用公共表单与已有管理接口，补文本编辑与经确认的状态动作。
- **范围**：二手表单、本人管理数据、公共页面交接。
- **测试入口**：发布描述测试、编辑与状态端点、本人列表页面集成测试。
- **验收**：PRD 的 D-R3 发布与本人管理逐项满足。
- **难点**：下架语义未定，图片编辑没有现行接口。

### D-R4 从商品发起私聊

- **做法**：已有线程直接进入，首次联系先发首条消息，再使用服务端线程 ID。
- **范围**：商品咨询、会话上下文、甲负责的聊天页接线。
- **测试入口**：商品详情交互、首发端点与已有聊天页面测试。
- **验收**：PRD 的 D-R4 从商品发起私聊逐项满足。
- **难点**：旧会话预检、首发竞态、响应丢失与聊天文件归属。

### D-R5 会话列表与历史分页

- **做法**：扩展已有列表分页，保持原会话行，区分刷新、追加与历史消息游标。
- **范围**：会话列表 API、领域适配、甲的列表接线。
- **测试入口**：现有会话路由、消息游标和列表合并测试。
- **验收**：PRD 的 D-R5 会话列表与历史分页逐项满足。
- **难点**：同时间排序、旧线程恢复、新消息改变排序与 Web 兼容。

### D-R6 已读与交易契约

- **做法**：业务端点同步已读边界，甲接入两个未读真源及交易分类。
- **范围**：会话已读、业务通知匹配、公共消息交接。
- **测试入口**：已读路由行为测试、未读汇总及消息页集成测试。
- **验收**：PRD 的 D-R6 已读与交易契约逐项满足。
- **难点**：异步通知、并发发送和部分写入失败。

### D-R7 失效、权限与异常恢复

- **做法**：按商品、会话、身份三个状态分别处理，复用公共错误与安全区规范。
- **范围**：业务状态模型、异常输入、返回与恢复。
- **测试入口**：已有端点权限测试、页面失败交互及设备操作。
- **验收**：PRD 的 D-R7 失效、权限与异常恢复逐项满足。
- **难点**：产品失效规则待确认，不能把旧缓存当成当前权限。

## 3. 按什么顺序施工？

依赖顺序为：阶段一商品私聊闭环 → 阶段二商品管理 → 阶段三完整会话分页 → 阶段四已读与交易集成 → 阶段五验收。
阶段一可先做独立接口与商品逻辑；公共文件未分配单写者时，相关接线任务标阻塞。
每次开工先 fetch 并同步本人分支；按最新代码重读任务入口，不覆盖他人改动。

### 阶段一：买家能联系卖家并返回商品

**覆盖**：D-R2 详情与想要、D-R4 从商品发起私聊、D-R7 失效、权限与异常恢复。

**目标**：两个测试账号走通同一商品的首发、回复、重新进入及返回商品。

**前置**：准备本地隔离账号与商品；和甲确认聊天文件单写者；确认商品状态对首发的限制。

**任务**

- 跑通在售商品的一次首发、回复及返回商品，形成最小端到端样例
- 扩展详情模型以保留权限、配送信息和咨询所需状态
- 复用已有线程查询及首发接口，处理重复触发与不确定响应
- 接入卖家咨询列表和会话商品摘要，保留已有消息历史能力
- 替换首批会话列表授权预检，交甲接入服务端线程授权结果
- 验证游客、本人商品、陌生线程、失效商品及断网恢复

**证明**：验收清单中的“商品咨询”和“权限隔离”用例通过，并保留双账号录像。

**不在本阶段**：本人编辑、交易 Tab 改版、大量会话分页及全局角标。

**交甲**：详情动作契约、商品摘要字段、现有聊天页的补丁要求、路由参数与新增词条。

### 阶段二：卖家能发布并管理自己的商品

**覆盖**：D-R1 商品发现与返回保位、D-R2 详情与想要、D-R3 发布与本人管理。

**目标**：本人发布商品，编辑文本，执行经确认的状态动作，返回列表能看到真实结果。

**前置**：确认下架语义；甲确认编辑路由、本人入口与公共发布接线。

**任务**

- 走通发布、详情、本人列表与一次编辑保存，验证主路径的数据刷新
- 补齐字段回填、分类失效、提交锁及失败保留输入
- 接入确认后的下架或已售动作，保留服务端身份与状态校验
- 对接我的商品与我的想要入口，交甲合入公共个人区域
- 回归列表搜索、组合筛选、分页、详情返回与缓存失效
- 补齐图片、长文本、空态、权限及发布门禁的行为验证

**证明**：验收清单中的“商品发现”“发布编辑”“本人管理”“想要”用例通过。

**不在本阶段**：未经批准的图片编辑、支付、重新上架权限扩展。

**交甲**：编辑屏幕导出、入口表、列表刷新契约、业务表单描述和词条清单。

### 阶段三：旧会话和历史消息都能找到

**覆盖**：D-R4 从商品发起私聊、D-R5 会话列表与历史分页、D-R7 失效、权限与异常恢复。

**目标**：在超过 100 条会话中打开较早线程，翻看历史消息并回复。

**前置**：甲丁确认新增分页字段和稳定排序；本地准备大量会话及消息样例。

**任务**

- 贯通会话接口第二页到列表追加，证明旧线程可从页面打开
- 实现兼容旧调用的会话分页，校验非法游标和末页结果
- 保留服务端时间及线程 ID 顺序，修正客户端合并覆盖规则
- 验证重复时间、空时间、刷新重排和新消息到达时的去重
- 回归历史分页、前台轮询与发送并发，避免消息丢失或重复
- 核对卖家单商品咨询列表的上限与完整性，记录实测处理结果

**证明**：固定样例至少 101 条会话可全部遍历，每条恰好一次；动态变化另做刷新验证。

**不在本阶段**：更换聊天存储、建立新实时通道、无依据的索引或 schema 改动。

**交甲**：会话 DTO、分页请求响应样例、合并顺序、刷新规则及旧调用兼容结果。

### 阶段四：读完会话后角标一致

**覆盖**：D-R6 已读与交易契约、D-R7 失效、权限与异常恢复。

**目标**：有新消息时交易行和角标显示未读；读完后服务端与两个展示位置一致。

**前置**：甲确认通用分类接线；丁确认实际通知结构、时间精度与已读并发方案。

**任务**

- 贯通一条未读消息的读取、业务端点同步及甲页面角标刷新
- 实现当前用户当前线程的通知匹配，覆盖幂等和失败恢复
- 验证读取边界后新消息仍未读，异步通知不能制造永久旧角标
- 交甲接入会话行与汇总的重取，删除客户端手动扣减假设
- 交甲验证交易仅列会话、想要归互动及清空操作不删聊天
- 补齐 Web 兼容、跨线程、跨账号和管理员现行权限回归

**证明**：验收清单中的“已读一致性”和“交易接线”用例通过，附服务端与页面双侧结果。

**不在本阶段**：丁直接改通用通知文件、推送基础设施重建、未经确认的历史通知迁移。

**交甲**：已读响应、并发边界、分类样例、失效目标样例和原生路由映射表。

### 阶段五：收齐自动验证和设备证据

**覆盖**：D-R1 商品发现与返回保位、D-R2 详情与想要、D-R3 发布与本人管理。
同时复核 D-R4 从商品发起私聊、D-R5 会话列表与历史分页、D-R6 已读与交易契约、D-R7 失效、权限与异常恢复。

**目标**：非实现者能按验收清单重现主路径，明确哪些已通过、哪些仍未验证。

**前置**：四个功能阶段与甲的公共接线可用；准备规定系统版本及测试构建。

**任务**

- 演示商品到私聊到回复到返回商品，固定构建与双账号证据
- 运行完整 App 验证、lint、服务端针对性测试与差异检查
- 收集常规、长内容、空内容、加载失败及图片异常状态截图
- 复测四个系统版本的主路径、两种导航及键盘安全区
- 记录全部未验证项、缺陷与负责人，交非实现者复核
- 使用 easy-summary 汇总已交付、实际影响与仍开放事项

**证明**：验收清单全部有实测结论；未取得设备的行保持未验证，不能关闭全期交付门。

**不在本阶段**：自动上架、生产迁移、生产测试数据写入或未经授权推送。

## 每个阶段怎样交给执行者？

进入一个阶段时，用 `easy-task-act` 把该阶段全部任务写成 3–7 份任务书，再开始实现。
每份任务书固定需求名、允许路径、前置接口、状态矩阵、命令、设备证据和未验证项。
本计划没有提前批量生成所有阶段任务书，避免后续阶段依赖实际代码时内容失真。

每个有边界的任务独立本地提交，标题使用 `type(scope): 简短说明`，显式暂存路径。
推送与 PR 按团队授权流程；公共文件仍由单写者合入。
文档变更检查链接和代码事实；实现后的记录写实际输出，不复制历史测试数量。
