# 任务 03：首发竞态与重复触发

日期：2026-10-29　阶段：阶段一 买家能联系卖家并返回商品

## 1. 任务位置

- 阶段目标：首次咨询不会因重复点击或响应丢失生成错误会话。
- 本任务：复用线程查询和首发接口，固定重复触发行为。
- 边界：只改 marketplace API 适配与服务端竞态测试。
- 前置：任务 01、02 完成。后置：任务 04 会话摘要。

## 2. 开发信息

**先读**

- `app/src/shared/api/marketplace.js` — 首发和线程查询调用。
- `routes/marketplace.js` — 唯一线程约束与首发插入。
- `__tests__/routes/marketplaceMessages.test.js` — 消息授权和错误模式。

**已定**

- 同一商品和买家只允许一个线程。定义见 PRD D-R4。
- 客户端不猜线程 ID，必须使用响应值。
- 失败时保留输入，不自动重发。

**边界与接口**

- 触及 marketplace API 和首发路由测试。
- 不修改聊天输入框或通知公共文件。

**运行**

- `npm test -- --runInBand __tests__/routes/marketplaceMessages.test.js`
- `npm run check:server-load`

**未知**

- 若并发唯一键错误无法稳定归一化，停止并记录数据库错误码。

## 3. 工作步骤

1. 阅读本任务并重述：重复首发只能得到同一线程。
2. 复现双击和响应丢失两种输入。
3. 写重复首发和唯一键冲突测试。
4. 让适配层只消费服务端线程 ID。
5. 校验错误时输入和缓存状态。
6. 运行命令并提交本任务。

## 4. 测试用例

| 用例 | 输入 | 期望 | 接口 |
| --- | --- | --- | --- |
| 1 | 同一消息重复提交 | 一个线程 | 首发 |
| 2 | 并发首发两次 | 一个线程 | 首发 |
| 3 | 首发返回后查询线程 | ID 一致 | 线程查询 |
| 4 | 服务端错误 | 输入仍在表单 | API 适配 |
| 5 | 本人商品首发 | 返回业务错误 | 首发 |
