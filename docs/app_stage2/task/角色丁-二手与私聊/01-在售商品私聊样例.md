# 任务 01：在售商品私聊样例

日期：2026-10-29　阶段：阶段一 买家能联系卖家并返回商品

## 1. 任务位置

- 阶段目标：两个账号完成首发、回复、重新进入和返回商品。
- 本任务：固定一条最小服务端样例，证明接口链路可复现。
- 边界：只覆盖在售商品和已有接口；等待后续页面接线。
- 前置：本地测试数据库可用。后置：详情模型扩展。

## 2. 开发信息

**先读**

- `routes/marketplace.js` — 首发、回复和线程查询的实际返回。
- `__tests__/routes/marketplaceChatThreads.test.js` — 当前线程授权边界。
- `docs/app_stage2/test/角色丁-二手与私聊/验收清单.md` — 样例验收口径。

**已定**

- 首发使用商品线程接口。定义见 PRD D-R4。
- 首发后必须使用服务端返回的线程 ID。
- 本任务不改变公共聊天页面归属。

**边界与接口**

- 触及 marketplace 路由测试和测试夹具。
- 不修改甲负责的聊天 UI。

**运行**

- `npm test -- --runInBand __tests__/routes/marketplaceChatThreads.test.js`
- `npm run check:routes-cjs`

**未知**

- 若测试数据库无法创建双账号，保留阻塞证据并停止扩展接口。

## 3. 工作步骤

1. 阅读本任务并用一句话重述：证明在售商品私聊链路可复现。
2. 找到现有商品、用户和消息夹具，记录最小输入。
3. 为首发、回复、线程查询写失败测试。
4. 运行测试并只修复当前链路暴露的问题。
5. 保存请求、响应和线程 ID 的断言。
6. 运行命令并提交本任务。

## 4. 测试用例

| 用例 | 输入 | 期望 | 接口 |
| --- | --- | --- | --- |
| 1 | 买家首发一条消息 | 返回线程 ID 和消息 ID | 首发 |
| 2 | 卖家用线程 ID 回复 | 返回新消息 ID | 回复 |
| 3 | 买家重新查询线程 | 返回同一线程和商品 | 线程查询 |
| 4 | 买家读取商品上下文 | 商品状态仍为在售 | 商品详情 |
| 5 | 未登录首发 | 返回认证错误 | 首发 |
