## 二、甲需要完成的页面接线

请按顺序处理，不要重复改动已经通过的服务端契约。

| 编号 | 任务 | 具体实现 | 完成标准 |
|---|---|---|---|
| A-1 | 旧线程深链 | `ChatScreen` 进入旧线程时直接请求消息端点/线程端点做授权，不依赖首批会话列表是否包含该线程 | 旧线程可直接打开；陌生线程显示拒绝；不存在显示 404；首批列表缺页不误判 |
| A-2 | 会话列表第二页 | 在会话列表页面消费 `nextCursor`，触底或点击加载更多时请求第二页并合并去重 | 第二页可见；同一线程不重复；无 `nextCursor` 时停止请求；保留排序 |
| A-3 | 编辑入口 | 商品详情读取 `canEdit`，仅卖家显示编辑入口，进入编辑页回填已有字段和图片 | 买家不显示/不可进入；卖家可保存；失败保留输入并可重试 |
| A-4 | 我的想要 | 接入 `/api/marketplace/me/wants`，支持分页、空状态、加载失败和重试 | 列表能打开；翻页不重复；取消想要后刷新数量和列表状态 |
| A-5 | 状态动作 | 商品详情接入 `canMarkSold` 与 `markSold`，成功后刷新详情、列表和相关缓存 | 只有卖家可操作；成功显示 sold；重复操作有明确错误；买家不能修改 |
| A-6 | 已读后刷新 | 进入会话或执行已读后重新拉取服务端 unread 汇总，不做本地手动扣减 | 返回 mailbox/列表后未读数与服务端一致；重复已读不产生负数 |
| A-7 | 发布失败恢复 | 发布页提交中禁用重复提交；失败不清空标题、正文、价格、分类和图片 | 网络/服务端失败后输入仍在；用户可重试；成功后才清空并返回 |

## 三、甲完成后必须执行的验证

```bash
npm test -- --runInBand \
  __tests__/routes/marketplaceChatLifecycle.test.js \
  __tests__/routes/marketplaceChatMessages.test.js \
  __tests__/routes/marketplaceChatThreads.test.js \
  __tests__/shared/marketplaceApi.test.js
```

### 页面验收

- 双账号：账号 A 发布商品，账号 B 查看详情、发起私聊，A 回复，B 重进会话。
- A/B 均验证会话列表分页、已读刷新和未读数变化。
- A 验证编辑、我的想要、标记已售；B 验证这些入口不可越权。
- 验证旧线程深链：线程不在首批列表时仍可进入；陌生线程拒绝。
