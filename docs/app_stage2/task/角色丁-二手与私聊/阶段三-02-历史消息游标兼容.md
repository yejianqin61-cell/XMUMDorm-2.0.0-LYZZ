# 阶段三任务 02：历史消息游标兼容

日期：2026-10-29　阶段：阶段三 旧会话和历史消息都能找到

## 1. 任务位置

- 阶段目标：较早线程能完整翻看历史消息。
- 本任务：固定消息游标的非法输入、末页和旧调用行为。
- 边界：只改消息路由/API 测试，不改存储。
- 前置：任务 01。后置：任务 03 合并顺序。

## 2. 开发信息

**先读**

- `routes/marketplace.js` — 消息复合游标和页大小。
- `shared/api/marketplace.js` — 消息请求游标编码。
- `__tests__/routes/marketplaceChatMessages.test.js` — 现有 500 条样例。

**已定**

- 游标包含 `created_at` 与 `id`。
- 服务端倒序取页，响应消息升序。
- 非法游标不能访问消息表。

**边界与接口**

- 触及消息路由、游标适配和测试。
- 不建立新实时通道。

**运行**

- `npm test -- --runInBand __tests__/routes/marketplaceChatMessages.test.js`
- `npm run check:routes-cjs`

**未知**

- 若旧客户端传入非 base64 游标，必须明确兼容或拒绝。

## 3. 工作步骤

1. 阅读本任务并重述：历史游标不会重复或漏消息。
2. 列出游标编码和排序不变量。
3. 写末页、非法和重复时间测试。
4. 修复最小兼容缺口。
5. 运行 500 条样例回归。
6. 提交。
