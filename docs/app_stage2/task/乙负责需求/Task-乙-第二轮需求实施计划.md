# Stage 2 乙负责需求与实施计划

日期：2026-10-28　状态：待实施　负责人：乙

## 2. 逐项方案

### R-1 Moodle 登录与工作台

- 方案：先在问题设备和正常设备分辨证书、账号和会话问题，再完善同步、课程、资源详情及重登状态。
- 涉及：校方系统登录和 Moodle 模块。
- 验证入口：现有登录、同步和详情入口，辅以问题设备与正常设备的真实操作。
- 验收：记录设备、系统、网络、浏览器及错误码；可用设备能登录、同步、查看详情和恢复；错误原因可辨且 TLS 校验保持开启。
- 难点：证书链可能需要校方修复；真机与账号是否可用尚未验证。

### R-2 课前通知与权限

- 方案：沿用已有提醒计划与权限流程，补齐首次授权、调度、重排、失败恢复和通知跳转交接。
- 涉及：课表提醒、通知权限和甲负责的导航接线。
- 验证入口：现有提醒计划、调度与权限入口，以及设备通知送达和点击。
- 验收：默认开启；首次进入课表解释并请求权限；课前 30 分钟送达一次；课程变更后旧提醒取消或重排；拒绝后可进入设置；点击打开正确课程。
- 难点：前后台、锁屏、重启及系统容量限制须在真机验证；跳转目标须与甲对接。

### R-3 工具首页与课表

- 方案：核对摘要与完整课表的数据来源及时间计算，再调整信息呈现。
- 涉及：工具首页、课表和导入后的数据刷新。
- 验证入口：现有课程摘要和课表入口，加时间计算测试与状态截图。
- 验收：有课、无课、跨周、冲突和导入更新均正确；下一节课、周次、时间、地点和课程颜色一致。
- 难点：跨周和冲突场景可能受学期时间及本地时区影响。

### R-4 食堂体验

- 方案：沿现有找店、找菜与点评链路梳理页面和状态，修正视觉层级及安全区。
- 涉及：食堂首页、区域、商家、菜品、排行、搜索和点评；必要时涉及食堂接口。
- 验证入口：现有食堂页面及必要的服务端接口测试，并录制两条用户路径。
- 验收：搜索、排行、分类、收藏和点评可找到并使用；无图、空列表和失败时仍可操作；底部操作不被遮挡。
- 难点：共享广场目录中的食堂边界、数据缺失状态及跨成员入口接线。

## 3. 实施阶段

### 阶段 1：Moodle 登录原因可辨

覆盖：R-1 Moodle 登录与工作台。

目标：问题设备的登录失败有可复核原因，可用设备能进入课程并打开资源。

任务：

- 贯通一次登录、同步和资源详情，记录设备与结果。
- 对照问题设备与正常设备的 WebView、系统浏览器和网络表现。
- 区分证书、账号和会话错误，保留合规打开方式。
- 完善重登、同步和详情的状态与失败反馈。
- 整理自动验证、设备录像与未验证项。

证明：设备矩阵与错误日志可复核；正常设备的登录到详情路径通过。

本阶段不做：绕过 TLS 校验或假定校方证书问题已修复。

### 阶段 2：课前通知可送达并定位课程

覆盖：R-2 课前通知与权限。

目标：一次临近课程提醒能在设备上送达，并打开正确课程。

任务：

- 贯通首次授权、课程排程、通知送达和点击定位。
- 核对默认开启、权限拒绝和设置入口。
- 处理导入、编辑、删除、换学期及重复启动后的提醒更新。
- 处理调度失败、容量不足、重试与账号切换清理。
- 向甲交付学期、课程码、日期和开课时刻组成的稳定目标。
- 覆盖前台、后台、锁屏、重启与权限状态并记录证据。

证明：自动验证和设备日志可复核，通知只送达一次且跳转目标正确。

本阶段不做：代替甲修改公共路由或绕过系统权限。

### 阶段 3：工具摘要与课表一致

覆盖：R-3 工具首页与课表。

目标：用户在工具首页和完整课表看到同一课程及正确的下一节课。

任务：

- 贯通导入课程、首页摘要和课表详情的数据更新。
- 核对学期周次、跨天、跨周及下一节课计算。
- 处理无课、课程冲突及地点、时间、颜色显示。
- 验证五种指定状态并保存截图和逻辑测试结果。

证明：有课、无课、跨周、冲突和导入更新的截图与测试可复核。

本阶段不做：改变已裁决的导航结构。

### 阶段 4：食堂查找与点评可走通

覆盖：R-4 食堂体验。

目标：用户能从食堂首页找到商家或菜品，再收藏或点评。

任务：

- 贯通找店到详情和找菜到详情两条路径。
- 梳理搜索、排行、分类、收藏和点评入口及反馈。
- 完善无图、空列表、断网与加载失败状态。
- 检查详情底部操作与系统安全区。
- 向甲交付食堂入口和需要统一接入的词条。
- 记录两条路径录像、异常截图及相关测试。

证明：两条路径录像和异常状态截图可复核；相关自动验证通过。

本阶段不做：改动广场公共壳或其他成员的业务模块。

## 执行和验收约束

- 每项先核对现有代码并建立任务卡，写明允许路径、依赖、状态矩阵、自动验证、真机证据和未验证项。
- 公共路由、公共 UI 和词条由甲统一接线或指定单写者；新增路径先登记。
- App 改动合并前在 app 目录运行 `npm run verify:serial`；接口改动补服务端测试，记录命令和退出码。
- 真机主路径覆盖 Android 13、14、15 和 iOS；Android 覆盖手势与三键导航。缺少设备时明确记为未验证。
- 证据按验收矩阵脱敏保存；人工验收由非实现者复核。新产品选择交团队领导裁决。
- 后续使用 easy-task-act 展开并执行任务，阶段结束使用 easy-summary 汇报；按需要使用 easy-audit 复核。
