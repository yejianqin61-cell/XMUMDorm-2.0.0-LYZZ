## 怎样判定整轮可以交付？

14 组需求均有负责人、自动验证结果和真实设备证据；P0 主链路全部通过。P1 未通过项要有缺陷、复现步骤和重验记录。
主路径必须真机演示，边缘状态按模块抽样。验收设备至少覆盖 Android 13、14、15 各一台与 iOS 一台；Android 手势和三键导航均须覆盖。
记录设备型号、系统版本、构建号、语言、主题、字体缩放、权限与网络状态。
对“流畅”不凭空设 FPS 数字；录像逐帧检查吸顶逆跳、卡片重叠、白屏和点击失败。

## 哪些横向门槛适用于每个页面？

- 文案中英文均可显示；长文、空态、加载态、错误态均有可读内容。
- 触控命中区遵守[App 设计宪法第 7 条](../../app/constitution/App设计宪法.md)：Android 至少 48×48 dp，iOS 至少 44×44 pt。正文对比度至少 4.5:1，大字及非文本至少 3:1。
- 使用系统安全区，键盘、底栏、弹层和手势区不得遮住提交、返回及最后一项输入。
- 每条动效在系统“减少动态效果”开启时有静态替代；关闭动效不改变任务结果。
- 失败反馈包含发生了什么和下一步可做什么。服务端 401/403/404 和断网分别验证。
- App 代码合并前运行 `npm run verify:serial`（在 `app/` 目录）；变更接口时补对应服务端测试。记录命令、退出码、失败用例，不用“测试通过”代替证据。

## UI 和交互交付到什么精度？

- 每个被改动的列表与详情至少交付常规、长内容、空内容、加载失败四种状态截图；图片页补无图、多图和异常比例。卡片按内容自然增高，正文和操作不被截断。
- 列表行必须能分辨“内容是什么、来自谁或哪里、何时发生、下一步能做什么”；同一模块的列表与详情使用一致的类型标识和操作名称。匿名域只显示允许公开的身份。
- 搜索、筛选、点赞、收藏、报名、发送和保存图片的触发后状态必须可见；失败时能重试，且不把未成功的操作显示成已成功。
- 进入详情再返回，列表仍在原 Tab、筛选条件和可识别的内容位置；刷新后按服务端顺序更新，不以本地旧数据冒充新结果。
- 视觉资源、字体层级、间距和颜色沿用现有设计系统。甲在主测设备上给出各模块首屏并排截图；同级标题、卡片边距、底部操作和状态文案若出现明显不一致，合并前修正。
- 动效以录像验收：滚动时不遮挡内容、不反向跳位、不与系统返回或图片横滑抢手势；“减少动态效果”开启后所有入口仍可用。

## 证据怎样存放？

每个需求建立 `test/evidence/A2-xx/`，只存可共享的脱敏截图、录像和结果摘要。真实账号、令牌、学号与聊天隐私内容打码。记录模板：构建号、设备、系统、场景、预期、实测、结论、证据路径、复测人。自动验证结果附命令和退出码；人工验收由非实现者复核。无法取得指定设备时记录“未验证”，不能写“通过”。

## 本矩阵不裁决什么？

本矩阵不设虚构的统一 FPS、网络毫秒数或动效时长。具体动画曲线由甲在真机设计稿中给出，并经负责人审阅；性能退化按同设备、同构建流程对比记录。产品口径以[决策登记册](../requirements/Stage2待裁决登记册.md)为准。
