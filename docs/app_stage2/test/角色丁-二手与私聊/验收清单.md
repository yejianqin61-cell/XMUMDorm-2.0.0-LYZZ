## 怎样记录结论？

验收结论只使用通过、失败、未验证。失败保留复现和缺陷；缺设备或缺接线写未验证。
每条记录包含构建、基线、环境、输入、预期、实测、命令退出码或证据路径、复核人。
先在本地隔离库准备账号和数据，不能为验证向生产库造会话。

## 自动验证入口

在仓库根执行现有服务端测试，再按实现新增的测试文件补命令：

```bash
npx jest __tests__/routes/marketplaceChatThreads.test.js __tests__/routes/marketplaceChatMessages.test.js --runInBand
git diff --check
```

在 `app/` 执行：

```bash
npm run verify:serial
npm run lint
```

服务端现有测试主要覆盖会话行和消息游标，不足以证明发布、首发、已读并发已满足。
新增行为在实际端点或既有页面入口测试，不写只确认源码字符串存在的替代用例。
schema、SQL 时间和通知匹配另用本地真实表复验，mock 测试不证明真实查询可运行。
