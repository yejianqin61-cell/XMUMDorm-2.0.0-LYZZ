## 3. 可用通道与代价（未擅自执行）

| 通道 | 可行性 | 代价 / 前提 | 风险 |
|---|---|---|---|
| **A. Docker Linux 容器构建** | 本机有 Docker Desktop，但**守护进程未运行** | 需启动 Docker Desktop、拉含 Node/JDK/Android SDK 的镜像（数 GB，约 30–60 分钟） | 与 CI Linux 环境同构，成功率最高；不装系统组件、不改团队 CI |
| **B. push 分支 + 云端工作流** | 已存在 `.github/workflows/app-apk.yml`（`assembleRelease` + artifact） | **需团队领导明确授权 push**（本轮⛔ 未 push；云端 `main` 不含本批提交，需推到分支并指定 ref） | 最快（约 10–15 分钟），但会产生远端分支与一次云构建 |
| **C. Expo Go / 开发构建做功能验收** | 立即可用（`npx expo start`） | 不产出 APK；开发构建需本机先跑通原生编译（同样会撞本阻塞） | **不能验证启动画面与图标**（官方口径），也只能部分覆盖 A/B/C/D 功能 |
| **D. 安装新版 CMake/Ninja 后重试本地构建** | SDK 里只有 CMake 3.22.1 | 需 `sdkmanager` 安装新版（数 GB）并强制 Gradle 使用；RN 子工程不一定接受覆盖 | 实验性，可能再失败 1–2 轮（每轮约 5 分钟） |

**建议顺序**：A（不 push、不改系统、与 CI 同构）→ B（若领导愿意授权）→ D 兜底；C 只用于无 APK 时的功能抽查。
