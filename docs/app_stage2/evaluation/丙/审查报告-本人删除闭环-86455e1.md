### D-1 旧刷新可复活已删帖

- **现象**：订阅接收删除后的快照，却没有使删除前发出的 refresh 失效；旧响应仍通过 generation 检查并覆盖 rows。
- **复现**：窗口已有 40/39；发出刷新并延迟其响应；删除 40 成功；最后放行包含 40 的旧响应。
- **证据**：主 Agent 重跑下方无文件写入脚本，退出 0，缓存和可见 rows 都从 [39] 回到 [40,39]。
- **影响**：用户看到删除成功返回后，已删帖重新出现；重挂也可能读取被旧响应污染的缓存。
- **依据**：原任务书成功返回用例要求无已删帖、其他行保留；验收矩阵:30 要求刷新不冒充新结果及返回状态一致。
- **建议**：成功删除标记版本或废弃先发请求，并妥善解除请求/分页忙态；补“旧刷新最后返回”的页面行为断言。

任务总结:16、28 的无残留描述只对已测的普通顺序成立，不能当作所有异步交错都已完成的结论。
此处报告的是当前任务尚未闭合的既有竞态，不声称该刷新缺陷最初由本轮引入。

### D-2 HTTP 删除失败缺少正确恢复语义

- **现象**：catch 丢弃错误状态，只设 deleteError=true；401/403/404 与断网都显示“检查网络后重试”。
- **证据**：CampusScreens:214–215、353–355；`app/src/i18n/zh.ts:42`；测试:776–794 本轮重跑通过，但仅验证泛化失败提示。
- **复现**：已有 401/403/404 测试输入逐项进入同一个 notice，没有登录恢复、无权限或失效区别；读取固定源码即可复核。
- **影响**：登录失效时没有恢复入口；无权限或内容已消失时被引导检查网络，重试无法消除真正原因。
- **依据**：统一契约:127 要求 401 登录恢复、403 无权限、404 不存在/失效；验收矩阵:22 要求原因与下一步可理解。
- **建议**：在模块中保留错误类别，复用已有词条及动作，并把状态码用例改为验证对应恢复入口和页面状态。

可复查：`git show 86455e1:app/src/features/campus/CampusScreens.tsx`，及专项命令的 `--testNamePattern=删除未成功时保留详情和列表`。
403 也可能来自认证中间件；返工须依据实际服务端响应区分会话失效与作者权限，不把所有 403 强制登出。
