### D-3 登录返回仍禁删

- **现象**：401 后 setDeleteError('login')，菜单按该状态禁用删除；重新登录成功返回同一已挂载详情，仍显示过期提示且不能重新删除。
- **证据**：CampusScreens.tsx:100 只读取 handleAuthFailure，没有消费会话成功状态；:147–156 只在 postId/kind 改变时清除错误。
- **返回路径**：现有 app/src/app/login.tsx:65–68 成功后 router.back()；详情没有 focus 或会话恢复后的重新加载接线。离开并重新挂载详情可恢复，但登录按钮提供的直接返回路径未恢复。
- **复现**：实际详情组件接收 401 → 点击登录 → 模拟会话恢复并重渲染保留的详情 → 打开更多菜单，删除项 disabled=true。
- **结果**：主 Agent 独立复跑退出 1，1 失败/70 未选；not.toBeDisabled 失败，原始输出含 accessibilityState.disabled=true，耗时 59.351 秒。
- **影响**：用户完成登录仍无法继续当前删除操作；若换账号，沿用原详情本人标记也不足以判断新账号动作。
- **依据**：原报告 P-2 提供正确的失败恢复动作的“401 可登录恢复”；统一契约:127、验收矩阵:22 要求可执行的恢复下一步。
- **建议**：恢复会话并返回详情时重新获取内容与本人标记，再清理过期态；不要仅解除禁用而沿用旧账号权限投影。

这是一项本轮新增关联缺陷：65f4ef0 增加 login 状态及其持续禁用条件。保留 D-2 失败恢复未关闭，以本次 D-3 登录返回仍禁删具体说明剩余部分。
复现是组件级会话恢复模拟，API/路由替身配合真实登录页返回逻辑取证；不是设备或真实登录联调结果。
只读规格子 Agent 同样复现。其首个诊断启动方式错误已中止，不作为缺陷证据；上述主 Agent 有效复跑实际执行了目标断言。
