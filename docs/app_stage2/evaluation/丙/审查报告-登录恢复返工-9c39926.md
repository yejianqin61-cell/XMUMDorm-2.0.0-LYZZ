### D-4 迟到成功未使详情失效

- **复现条件**：同一账号、同一帖子，DELETE 在途时离焦并返回；新 GET 在删除完成前返回有效正文，随后旧 DELETE 返回 status=0。
- **现象**：列表快照写入 deletedIds=[40]，但没有 back/replace，正文和本人删除入口仍存在，且删除项已重新启用。
- **原因**：重聚焦使 generation 改变（:188），:266 因旧 generation 不匹配跳过返回；没有替代的当前内容失效处理，:288 清空操作状态后 :528 解除禁用。
- **证据**：主 Agent 只读探针先确认 deletedIds=[40]，再确认菜单项 not.toBeDisabled 成立，最后有效收尾断言失败：Expected true / Received false。
- **有效收尾判据**：允许已有返回导航、清正文或移除删除资格任一种；不是因路由替身没有卸载页面而误判。当前三者均没有发生。
- **影响**：同一成功删除在列表和详情得到矛盾状态；用户仍可再次发起对已删除内容的操作。服务端会拦截，但不能替代客户端成功收尾。
- **依据**：本轮重点第 6 项“成功、失败和页面离开均正确收尾”；返工任务书:42 的迟到回执处理、原本人删除任务书的成功返回要求。
- **修复方向**：保留对其他页面的迟到导航保护；确认当前仍是已删除的同一内容时，使其失效或按当前页面安全返回，不只更新列表和解锁。

这是本轮新增聚焦重读与 generation 保护之间的交错缺口，限于成功迟到分支，不重新审计整个内容模块。
原 D-2 失败恢复和 D-3 登录返回仍禁删的具体现象已修复；D-4 迟到成功未使详情失效另列，不将其写成原缺陷复发。
D-1 列表防复活未回归：探针前一断言 deletedIds=[40] 成立，原列表竞态用例也通过；问题在当前详情的失效接线。
