# 本地开发环境手册（Dorm）

**适用**：第一次在本机把 XMUMDorm 跑起来的人（含协助者 Agent）。
**日期**：2026-10-02　**版本**：v1.0　**维护**：仓库管理员；本文件是**入职指引**，与 [团队协作契约](团队协作契约.md) 配套（契约管规则，本文管"怎么跑起来"）。

> **一句话结论**：**五条命令能跑起来；卡住新人的只有一件事 —— 注册收不到验证码。** 那不是 bug，是**没配邮件服务**（`services/email.js:84-90`）。本文第六节给三条绕过路径。

## 一、最快路径（照抄即可）

```bash
git clone https://github.com/yejianqin61-cell/XMUMDorm-2.0.0-LYZZ.git
cd XMUMDorm-2.0.0-LYZZ
npm install                     # 后端依赖
cd frontend && npm install      # 前端依赖
cd ..
# 1) 在根目录创建 .env（内容见第三节）
npm run migrate:all                                  # 建库 + 首批 10 个迁移
node scripts/run-incremental-migrations.js           # 其余 72 个迁移（必跑）
npm run dev                     # 后端 → http://127.0.0.1:4040
# 另开一个终端：
npm run dev:web                 # 前端 → http://localhost:5173
```

**打开 <http://localhost:5173>。** 看到页面 = 前端通；页面能加载出数据 = 后端通。
**服务端日志出现 `✅ 数据库连接成功！` = 数据库通**（`database.js:66-75`）。

## 二、需要什么

| 项 | 要求 | 依据 |
|---|---|---|
| Node.js | **LTS**（【建议】20 或更高） | 仓库**未声明 `engines`**；这里不写死版本号。jest 30 需 Node ≥18 |
| npm | 随 Node | 唯一包管理器是 **npm**（有 `package-lock.json`，勿用 yarn/pnpm 混装） |
| MySQL | **≥5.7，推荐 8.0** | 迁移里用到 `JSON` 列（10 处）→ 必须 ≥5.7；**未**使用 `utf8mb4_0900_*`、`CHECK ()`、窗口函数、生成列 → 不必是 8.0 |
| 端口 | **4040**（后端）、**5173**（前端） | `server.js:62`；Vite 默认端口，`frontend/vite.config.js` 未改 |
| 邮箱服务 | **可选**，但**不配就无法注册** | 见第六节 |

## 三、`.env` 怎么配（本地最小集）

模板在根目录 **`.env.example`**（已入库）。**本地只填 `DB_*` 一类**。

| 变量 | 本地建议 | 作用 / 坑 |
|---|---|---|
| `DB_HOST` `DB_PORT` `DB_USER` `DB_PASSWORD` `DB_NAME` | `localhost` `3306` `root`（按本机改） 空 `jack_campus` | 不填时**默认值就是这些**（`database.js:26-31`） |
| ⛔ `DATABASE_URL` / `MYSQL_URL` | **留空** | **连接串优先级高于 `DB_*`**（`database.js:15,23-35`）。填了就会连到**云上库**，症状是"我改了数据但页面没变" |
| `PORT` | 可留空 | 默认 4040 |
| `NODE_ENV` | `development` | 决定：**关掉限流**（`server.js:82-93`）+ **注册验证码回传响应体**（`routes/auth.js:110-114`） |
| `ENABLE_BACKGROUND_JOBS` | **留空** | 只有 `=1` 才跑定时任务；**留空=本地不跑**（`server.js:211`）。开了会每分钟查库 |
| `PUBLIC_ASSET_BASE_URL` | 需要看图时填 | 图片 URL 前缀。不填 → 返回 `/uploads/xxx`，能看到本机上传的图，但看不到云上老图 |
| `JWT_SECRET` | 可留空 | 有内置回退值 `'your-secret-key-change-in-production'`，全仓一致，**本地能跑**。⚠️ **生产必须填**，否则任何人可伪造登录 token（见第九节） |
| `RESEND_API_KEY` / `SMTP_*` | 只有要注册才填 | 不填 → 发验证码接口 **500** |
| `OBJECT_STORAGE_*` | 可留空 | 留空时图片**写入本地 `uploads/posts/`**（`middleware/upload.js:88-114`） |
| `GITHUB_MATERIALS_*` `VAPID_*` | 不用管 | 未配置时优雅降级（M10 返回 `configured=false`；课前提醒不发） |

## 四、建库与迁移：**两条命令，缺一不可**

| 命令 | 它到底做了什么 | 覆盖范围 |
|---|---|---|
| `npm run migrate:all` | 建库 `jack_campus` + 跑**写死的 10 个文件**（`init-db.sql`、002–008、031、032） | **不是全部！**（`scripts/run-migrations-all.js:46-57`） |
| `node scripts/run-incremental-migrations.js` | 按序号跑 `migrations/0NN_*.sql` **全部 72 个**（跳过 `seed_*`） | 剩余全部（`scripts/run-incremental-migrations.js:54-59`） |

**为什么必须两条**：`init-db.sql` 只建 14 张表且**没有 `users.status` 列**，而登录查询会读 `status`（`routes/auth.js:538`）→ 只跑第一条，登录会报"字段不存在"。
**两条都可重复执行**：已存在的表/列/索引会被识别并跳过；末尾会打印 `汇总：成功 N，跳过 M，失败 0`。**失败数 > 0 就是没装好。**

> 迁移脚本会自动删掉文件里的 `USE jack_campus;`，并以**连接串里的库名**为准 —— 所以本地/线上可以共用同一份 SQL。

## 六、⚠️ 新人唯一会卡住的地方：**注册收不到验证码**

**原因（已核实）**：`/api/auth/send-verification-code` 会**先真的发邮件**；未配邮件服务时直接抛错 → 接口返回 **500「服务器错误，请稍后重试」**（`routes/auth.js:108,116-122` + `services/email.js:84-90`）。
**另一个坑**：验证码在库里是**哈希**存储（`email_verification_codes.code_hash`），**所以"去数据库里把验证码读出来"这条路走不通**。

**三条可用路径**：

| 路径 | 做法 | 代价 |
|---|---|---|
| **A（推荐）配一个邮件通道** | 填 `RESEND_API_KEY` + `RESEND_FROM`（HTTPS，免费额度够开发），或填 `SMTP_*` | 需要一个邮箱账号 |
| **B 用现成账号直接登录** | `node scripts/createAdmin.js` → 用户名 `admin` / 密码 `20061016`；登录框填**用户名**（登录同时接受邮箱与用户名，`routes/auth.js:515-546`） | ⚠️ 脚本里的密码是**写死的**，只能用于本地 |
| **C 自己造一个已验证账号** | 仿 `scripts/create-app-review-account.js` 的写法插一条 `email_verified=1` 的 `users` 记录 | ⚠️ 该脚本**加了 `.gitignore`（第 48 行），新人手上没有**；需要自己写 SQL |

> 启用路径 A 且 `NODE_ENV=development` 时，发验证码接口**会把验证码放进响应体**（`verification_code` 字段，`routes/auth.js:113`）—— 用它就能注册，不必真去收邮件。

## 七、常见故障

| 现象 | 原因 | 处置 |
|---|---|---|
| `ECONNREFUSED` + 提示确认 MySQL | MySQL 没启动 / 端口密码不对 | 启 MySQL；核对 `.env` 的 `DB_*`（脚本会打印这句提示） |
| `Table 'jack_campus.xxx' doesn't exist` / `Unknown column 'status'` | 只跑了 `migrate:all` | 补跑 `node scripts/run-incremental-migrations.js` |
| 迁移 `失败 N`（N>0） | SQL 与库版本不匹配 | 看失败文件名与报错；≥5.7 是硬要求 |
| 改了数据页面不变 | `.env` 里填了 `DATABASE_URL`/`MYSQL_URL`，连到了云库 | 清空这两项 |
| 图片全是 404 | `PUBLIC_ASSET_BASE_URL` 指向云端、或本机没有该文件 | 本地开发可留空走 `/uploads` |
| 注册接口 500 | 没配邮件 | 见第六节 |
| `EADDRINUSE :4040` | 后端已在跑 | 关掉旧进程，或改 `PORT`（前端代理也要跟着改） |
| 前端能开但接口 404 | 后端没起 | 先起 `npm run dev` |
| 感觉"很卡" | 开了后台定时任务 | `ENABLE_BACKGROUND_JOBS` **留空** |
| 依赖装不上 / 版本怪 | 混用了 yarn/pnpm 或删了 lock | 回到 `npm install`，不要改 `package-lock.json` |

## 八、不要做的事（边界）

1. ⛔ **不要提交 `.env`**、密钥、keystore、生产库导出（[团队协作契约 §7](团队协作契约.md)）。
2. ⛔ **不要用本地环境连生产库**；也不要为了"能跑"去手改线上 schema。
3. ⛔ **不要手改表结构代替 migration** —— schema 变更一律新增 `migrations/0NN_*.sql`。
4. ⛔ **不要 `git add .`**（见 [Git 协作手册](Git协作手册.md)）。
5. ⛔ 本文**不含任何真实密钥与生产连接串**，也不要把它们贴进任何文档或聊天记录。

## 九、需要仓库管理员定的三件事（本手册已按"当前事实"写好，但它们是隐患）

| # | 事项 | 现状 | 建议 |
|---|---|---|---|
| 1 | **`JWT_SECRET` 有内置回退值** | `process.env.JWT_SECRET \|\| 'your-secret-key-change-in-production'`（`middleware/auth.js:13` 等 6 处） | 生产**必须**配；建议在启动时检查：生产环境若未设置就**拒绝启动**，避免"忘了配 = 人人可伪造 token" |
| 2 | **`engines` 未声明** | `package.json` 无 `engines` | 加 `"engines": {"node": ">=20"}`，避免"我的机器能跑" |
| 3 | **MySQL 版本口径未统一** | 代码支持 ≥5.7，线上是 Railway MySQL | 团队统一用一个版本（建议 8.0），并写进本手册第二节 |
