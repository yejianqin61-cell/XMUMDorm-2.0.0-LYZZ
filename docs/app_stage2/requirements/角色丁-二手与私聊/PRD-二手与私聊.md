### D-R1 商品发现与返回保位

- 列表卡片保留现行分类与价格层级，长标题、无图和异常比例图片均可显示。
- 提交关键词时去除首尾空格；分类与售卖状态可组合，清除后回到默认结果。
- 切换条件从第一页重取；上一条件的迟到响应不能覆盖新列表。
- 追加失败保留已加载商品，在同一分页位置重试；刷新失败也保留已有内容。
- 从详情返回，恢复关键词、分类、状态与可识别的商品位置。
- 退出或更换账号后，不显示前一账号专属的缓存数据。

### D-R2 详情与想要

- 详情展示标题、价格、图片、描述、分类、配送方式、宿舍区域、卖家与售卖状态。
- “想要”与“联系卖家”分开；游客触发写操作时进入现有登录恢复流程。
- 以服务端权限决定编辑和状态按钮；隐藏按钮不能替代接口鉴权。
- 想要提交中禁用重复触发，以响应重取状态和计数；响应丢失时先确认状态再允许切换。
- “我的想要”数据复用已有接口；入口位置由甲接入现有个人区域，不新增一级导航。
- 举报沿用现有举报接口及权限，作为回归项，不扩展审核流程。

### D-R3 发布与本人管理

发布使用现有第五格发布中心，不在二手列表增设第二个发布入口。
本人管理复用“我的内容 → 二手 → 商品详情”，由详情提供编辑和状态动作。
相关公共入口和路由由甲接线，丁交付业务屏幕、表单描述和刷新要求。

| 字段 | 现行约束 | 编辑要求 |
| --- | --- | --- |
| 标题 | 必填，最多 120 字符 | 回填并允许修改 |
| 描述 | 必填，最多 3000 字符 | 回填并保留失败输入 |
| 价格 | 非负数；客户端最多两位小数 | 以服务端校验为准 |
| 分类 | 服务端启用分类 | 分类失效时要求重选 |
| 配送方式 | `pickup`、`delivery` | 使用已有中英标签 |
| 宿舍区域 | 共享枚举 | 禁止另写一份枚举 |
| 标签 | 客户端最多 10 个，每个 20 字符 | 提交前核对服务端规则 |
| 图片 | 最多 4 张，每张最多 8 MB | 当前编辑接口不支持替换 |

图片类型沿用 JPEG、PNG、WebP。发布可无图，图片临时文件不进入普通草稿持久化。
约束依据为 [发布描述](../../../../app/src/features/marketplace/publishFields.ts#L18)与[服务端上传限制](../../../../routes/marketplace.js#L27)。
图片编辑若纳入本轮，必须先确认需求并增加相容接口，不能通过现有 PATCH 假装保存成功。

发布或编辑提交中只允许一个请求；失败保留输入，成功后刷新详情、二手列表及本人列表。
条款未接受、账号受限和登录失效分别复用服务端门禁与公共处理，不替用户接受条款。
重复提交的网络不确定状态不得自动重试写入，先核实结果再恢复用户操作。

### D-R4 从商品发起私聊

买家在商品详情点击“联系卖家”，先查询自己与该商品的已有线程。
线程存在则直接进入；线程不存在则展示首条消息输入，发送成功后使用服务端返回的线程 ID 进入聊天。
查看商品或点击入口本身不发送默认消息。

- 同一商品与同一买家复用已有线程，不因重复点击生成第二条会话。
- 首条发送失败保留草稿；首条提交中禁用重复发送。
- 首条消息响应丢失后，先查询线程及消息确认结果，不自动补发相同文本。
- 卖家不能联系自己；本人商品展示咨询列表或进入已有买家会话。
- 会话顶部显示商品摘要与状态，提供返回商品的动作；冷启动只凭线程 ID 也能恢复上下文。
- 普通用户只读写自己的会话，线程详情由服务端验证；不能以列表首批是否存在代替授权。
- 消息沿用 1200 字符上限，空白不可发；发送失败保留草稿，不显示成功气泡。
- 复用现有前台且聚焦时轮询，离页和后台停止，不新增实时协议。

首发流程复用 [商品线程查询与发送](../../../../shared/api/marketplace.js#L75)。
唯一性已有[商品与买家联合唯一键](../../../../migrations/029_marketplace_chat.sql#L12)，仍须测试并发创建的实际失败行为。

### D-R5 会话列表与历史分页

- 买卖两侧统一为会话行，以 `thread_id` 去重；按最近消息时间和线程 ID 稳定排序。
- 旧会话发生新消息后，刷新到正确位置，不能继续按线程创建 ID 排序。
- 会话列表增加分页信息；超过 100 条的数据集能读到末尾，不提前显示“到底了”。
- 消息历史继续使用已有游标；历史追加、前台轮询和发消息的响应不会丢消息或重复上屏。
- 消息发送期间切线程或账号，旧响应不能污染新会话。
- 会话列表分页与消息历史分页使用各自游标，不能混用。

### D-R6 已读与交易契约

交易 Tab 只展示二手会话，甲接入页面与全局角标。丁交付数据、已读端点及测试样例。
商品想要归互动；`marketplace_chat` 通知供推送和角标；通用分类文件由甲修改。
历史泛型 `marketplace` 通知不自动当作聊天，交甲核对存量含义。

| 展示 | 唯一真源 | 更新时机 |
| --- | --- | --- |
| 会话行未读数 | 会话接口的 `unread_count` | 聚焦、读取及发送后重取 |
| 总角标与分类角标 | `/api/notifications/unread-summary` | 已读成功后重取 |
| 会话消息 | 线程消息接口 | 首次、历史分页及前台轮询 |

会话已读只作用于当前用户与当前线程，必须同时处理相应聊天通知。
不得把其他线程、另一参与者或已读边界之后的新消息标为已读。
重复调用要幂等；部分失败必须返回可识别结果，不能回复成功后留下长期不一致。

通知已读匹配复用 `extra.targetType=marketplace_thread` 和 `extra.targetId`。
当前通知结构见[业务通知写入](../../../../routes/marketplace.js#L130)；客户端不得按标题或对方名称猜线程。
交易 Tab 不调用通知“清空分类”删除聊天；批量已读由甲决定逐线程执行或隐藏该动作。

### D-R7 失效、权限与异常恢复

| 情形 | 用户可见结果 | 数据处理 |
| --- | --- | --- |
| 401 | 登录恢复入口 | 清理失效身份，保留允许的输入 |
| 403 | 无权限及返回入口 | 不继续读取受限内容 |
| 404 | 商品或会话不存在 | 不使用旧详情冒充当前内容 |
| 409 | 显示具体业务冲突 | 仅在接口实际返回时使用 |
| 断网或超时 | 保留内容并显示重试 | 写请求先确认是否成功 |
| 商品失效 | 类型与不可查看占位 | 清除不应展示的来源原文 |
| 会话无权限 | 禁止读写并返回列表 | 不因有本地缓存而放行 |

失效摘要按团队隐私规则处理；历史会话是否继续可读写，要按第 7 节确认。
已售、删除与无权限不是同一种状态，不能共用一个布尔量推断全部动作。
错误文案、空态及按钮交付中英文词条清单，由甲合入公共词条。

## 5. 接口框架

服务端仍使用 `{status,message,data}` 响应封套，App 消费共享请求层解包后的 `data`。
现有接口兼容 Web 调用；增量字段先交甲和 Web 使用方核对，不能直接改掉旧字段含义。

| 接口组 | 现行入口 | 本轮处理 |
| --- | --- | --- |
| 商品发现 | `GET /items`、`GET /categories` | 保留列表分页与筛选 |
| 详情 | `GET /items/:id` | 保留权限，补足聊天状态需要的字段 |
| 本人列表 | `GET /me/items`、`GET /me/wants` | 复用分页 |
| 发布与编辑 | `POST /items`、`PATCH /items/:id` | 复用，核对编辑边界 |
| 状态与删除 | `POST /items/:id/status`、`DELETE /items/:id` | 语义确认后接入 |
| 想要 | `POST /items/:id/want` | 保留切换与计数 |
| 商品咨询 | `GET /items/:id/chat/thread` | 查询当前买家线程 |
| 买家首发 | `POST /items/:id/chat/messages` | 复用返回 `thread_id` |
| 卖家咨询列表 | `GET /items/:id/chat/threads` | 核对大量咨询的完整性 |
| 我的会话 | `GET /chat/threads` | 增量分页 |
| 消息 | `GET/POST /chat/threads/:threadId/messages` | 历史及发送保持兼容 |
| 已读 | `POST /chat/threads/:threadId/read` | 同步线程与对应通知 |

表中业务接口统一带 `/api/marketplace` 前缀。

### 5.1 已定会话行与目标

会话行保留 `thread_id`、`item.id/title/available`、`peer.id/name/avatar`、`role`。
同时保留 `last_content`、`last_message_at`、`unread_count`，缺失摘要或头像使用明确占位。
商品目标使用 `marketplace_item + itemId`；会话目标使用 `marketplace_thread + threadId`。

甲把目标映射到原生路由；服务端现有 Web `targetPath` 继续供 Web 使用。
失效目标按统一契约返回 `available=false`，不得把 Web 路径直接推入 Expo Router。
丁交付正常、失效、无权三组样例，甲负责通用通知投影。

### 5.2 分页增量提案

【提案】会话列表保留 `limit`，增加不透明 `cursor`，返回 `{list,hasMore,nextCursor}`。
排序使用 `(last_message_at,id)`，游标处理相同时间与空时间；省略游标仍兼容旧客户端。
新增消息会改变会话排序，因此前台刷新首批并按线程去重；静态全量无遗漏与动态刷新分别测试。

新增分页契约未由团队确认；实施前由丁与甲确认字段、非法游标响应及并发刷新策略。
不为翻页复制聊天表。是否增加索引，须先在本地真实表上检查查询计划，再提出 migration。

### 5.3 已读增量设计门槛

【提案】服务端以同一读取边界处理角色已读时间和聊天通知，随后客户端重取两个未读真源。
实现前核对消息与通知时间精度、异步通知写入以及并发发送，防止读请求误吞后到消息。
如果现有字段不足以表达边界，先提交兼容方案与测试，不直接修改 schema 或放宽成功条件。

## 7. 哪些事项必须在对应实施前确认？

以下是待确认问题，没有改变团队已定目标。需要产品裁决的事项提交团队决策登记册。
仅文件归属和字段接线的问题由甲、丁协调；不要求整份 PRD 等待全部问题后才能进行独立工作。

| 问题 | 现状或冲突 | 建议与影响 |
| --- | --- | --- |
| 下架含义 | 接口只有在售、已售及软删除 | 先选已售、软删除或独立下架 |
| 失效后的聊天 | 已售仍可首发；删除后旧线程可发送 | 确认首发、历史读与回复各自规则 |
| 图片编辑 | PATCH 只处理文本业务字段 | 基础版保留旧图，扩展另确认 |
| 聊天文件单写者 | 业务归丁，现有文件在 mailbox | 甲接补丁或指定本批丁单写 |
| 新分页字段 | 当前仅 `limit` 与 `list` | 甲丁确认第 5.2 节提案 |
| `reserved` 历史状态 | 基础表枚举存在，App 模型拒绝 | 检查本地样例后定兼容展示 |

下架不得静默等同已售；普通卖家将已售改回在售的权限目前也未开放。
状态现状见[状态接口](../../../../routes/marketplace.js#L637)与[基础表枚举](../../../../migrations/026_marketplace.sql#L26)。
商品缺失后的历史读取策略不能从 `available` 单字段猜测。

## 8. 验证与交付门

按[实施计划](../../task/角色丁-二手与私聊/实施计划.md)逐阶段推进，以[验收清单](../../test/角色丁-二手与私聊/验收清单.md)记录证据。
主路径必须有买卖双账号、商品状态异常与超过 100 条会话的数据样例。
没有真实设备证据时只能标未验证，不能以模拟器或 mock 测试关闭真机验收。

App 变更在 `app/` 执行 `npm run verify:serial`，并运行 lint；接口修改补服务端行为测试。
测试用本地隔离数据，不使用生产数据库创建会话或补测试数据。
全期设备标准为 Android 13、14、15 与 iOS，含 Android 手势和三键导航。

每个完成项同时满足：批准路径、验证记录、文档同步、无密钥和他人改动、未验证项明确。
没有人日与发布日期承诺，先完成第一条闭环后再按实测估算。
