# App 首包体验：第二轮改进需求草案

| 属性 | 内容 |
| --- | --- |
| 类型与状态 | 需求来源草案；产品口径、接口与验收指标已由团队领导于 2026-10-28 确认，以 Stage 2 统一契约和验收矩阵为执行标准；不是排期或完成声明 |
| 日期 | 2026-10-28（Asia/Singapore） |
| 输入 | 所有者首次打包体验后的 14 组反馈；同日广场截图与滚动、单列瀑布流补充裁决 |
| 范围 | App 客户端；只在课程测评和必要数据契约处接入现有 Web/后端能力 |

## 这轮要达成什么？

把首次 APK 体验中的 14 组问题收束为可分工、可验收的改进项。优先保证登录、加载、通知、私聊、消息跳转和发布安全区等主链路可用，再统一内容页面的视觉与动效。甲乙丙丁戊各有独立主责；下表是**建议分工**，不是已批准的工期。所有验收以新构建的真机体验为准，旧计划的“已完成”不代替这次复验。

## 需求如何逐项验收？

状态约定：以下均为**待实施或待复验**。优先级是本草案建议：P0＝影响主要操作可用性，P1＝首包体验重点。每项的验收句是结果要求，不规定具体组件实现。

### A2-01｜图标与启动体验｜甲｜P1

- A2-01a：确定 App 图标的正式稿，并检查 Android 自适应图标、单色图标与 iOS 图标在桌面、设置、通知中的辨识度。
- A2-01b：设计启动阶段的品牌动效和首屏衔接；启动时不能出现白屏、闪屏或图标跳变。系统原生启动画面与进入 App 后的动效分别验收。
- 验收：冷启动、热启动、深链启动各演示一次；动画关闭或系统减少动态效果时仍可直接进入首屏。

### A2-02｜广场上部收起与五个顶部 Tab 吸顶｜甲｜P1

- A2-02a：广场分上下两部分。上部是品牌头、课表／校园攻略／二手／社团四个功能入口和校园助手；下部是“今日／树洞／万能墙／食堂／跑腿”五个内容 Tab 与各自的信息流。
- A2-02b：用户向下浏览当前 Tab 内容时，上部整体随滚动向上收起；五个 Tab 吸附在屏幕顶部安全区下方。继续滚动只移动当前内容，给信息流留出更大的可视面积。
- A2-02c：只有用户回到内容顶部并继续向下拉，上部才重新展开；中途反向轻滚不展开。下拉刷新若保留，应与展开手势分清触发时机。点击或横滑切 Tab 均保持上部状态与各 Tab 自己的滚动位置，横滑避让系统边缘返回手势。
- 验收：初始屏与所有者截图的上下层级一致；向下浏览可让四个入口和校园助手离开视野、Tab 吸顶；回到顶部能展开；Tab 不压住状态栏，五个 Tab 均可触达，过程无明显跳动。

### A2-03｜树洞信息流、详情与图片保存｜丙｜P1

- A2-03a：树洞信息流固定为**单列瀑布流**：卡片按内容自然增高，统一横向宽度；处理图片比例、长短正文、卡片间距和多图预览，不改成双列网格。
- A2-03b：重做详情页的信息层级，突出正文、图片、互动与评论；从列表进入、返回后保留位置。
- A2-03c：图片预览提供“保存到设备”入口，并反馈成功、权限拒绝和保存失败。
- 验收：纯文字、单图、多图、长文四类内容均可读；图片可保存后在系统相册找到；拒绝权限不导致页面卡死。

### A2-04｜万能墙 UI｜丙｜P1

- A2-04a：统一墙帖列表、详情和发布入口的排版与卡片视觉；不同模板仍能一眼区分。
- A2-04b：梳理点赞、评论、删除本人内容和失败反馈的可见状态，避免按钮“点了没反应”。
- 验收：模板内容、互动状态、空态与错误态在同一套页面视觉中成立；本人内容可按权限管理。

### A2-05｜食堂模块 UI｜乙｜P1

- A2-05a：统一食堂首页、区域、商家、菜品详情、点评的层级、图片与占位状态。
- A2-05b：确保搜索、排行、分类、收藏、点评入口易找到；修正详情页底部操作与系统安全区的关系。
- 验收：从食堂首页能走通“找店／找菜 → 详情 → 收藏或点评”；无图、加载失败、空列表时页面不塌陷。

### A2-06｜二手功能闭环与私聊｜丁｜P0

- A2-06a：逐项核对列表、筛选、详情、发布、编辑、下架、“想要”及本人商品管理；缺失能力补齐或明确入口状态。
- A2-06b：从二手详情能发起与卖家的私聊；会话携带商品上下文，返回后仍能找到该商品和会话。
- A2-06c：交易消息归入消息页的“交易”分类，并展示商品摘要、对方、最新消息和未读状态。
- 验收：买家和卖家各跑一次“商品 → 私聊 → 回复 → 返回商品”；无权限、商品下架、网络断开时有可理解的反馈。

### A2-07｜校园攻略 UI 与课程测评｜戊｜P1

- A2-07a：优化攻略首页、分类/搜索、文章列表与阅读页的层级、封面、正文和互动状态。
- A2-07b：接入 Web 已有的课程测评能力，复用既有课程测评数据与权限规则。覆盖学生与管理员现有 Web 功能，包括浏览、搜索、详情、发布、本人编辑/删除、评分、评论，以及管理员的既有管理操作。课程测评页内设仅管理员可见的“管理”入口，进入内容审核。
- 验收：同一条课程测评在 Web 与 App 可相互找到并按权限操作；未登录、空结果、删除/不可见内容有一致反馈；不新造一套测评数据。

### A2-08｜社团 UI 与动态信息流｜戊｜P1

- A2-08a：优化社团发现、社团主页、活动、帖子及成员区域的视觉与信息层级。
- A2-08b：社团动态固定为**单列瀑布流**：活动与帖子按内容自然高度混排，支持分页与返回位置保持；内容类型必须明确标识，不改成双列网格。
- A2-08c：搜索/分类、关注、报名、点赞、评论与管理操作给出成功和失败反馈。
- 验收：成员与非成员各走通发现 → 社团主页 → 动态详情 → 互动；长文字/多图/无图和空态都不破版。

### A2-09｜课前 30 分钟提醒与系统通知权限｜乙｜P0

- A2-09a：提醒默认开启，在课程开始前 30 分钟安排设备本地通知。用户首次进入课表时解释用途并触发系统通知权限请求。
- A2-09b：课表导入、修改、换学期或删除后，重排或取消旧提醒；重复启动不得产生重复通知。
- A2-09c：权限拒绝时显示当前状态和去系统设置的入口；点通知能进入相应课程或课表。
- 验收：用可验证的临近课程时间做一次前台、后台及锁屏送达测试，记录设备系统版本与权限状态。既有提醒计划代码需要真机复验，不能只凭单测判定送达。

### A2-10｜工具首页与课表显示逻辑｜乙｜P1

- A2-10a：优化工具首页的课表摘要、待办与校方系统入口，让今日课程和下一节课更易读。
- A2-10b：核对周次、星期、跨天、无课、课程冲突、课程地点与时间的显示；同一课程的身份色与详情信息保持一致。
- 验收：有课、无课、跨周、冲突课程和导入后更新五种状态均显示正确；工具摘要与完整课表指向同一份数据。

### A2-11｜全部发布页面的安全区｜甲｜P0

- A2-11a：盘点发布中心可进入的所有表单及其预览/媒体选择弹层；顶部标题、底部提交按钮、键盘与系统手势区域均按统一安全区容器处理。
- A2-11b：避免页面自行写死 inset 或重复加底部留白；发布草稿与返回确认不因键盘或弹层被遮住。
- 验收：至少在 Android 手势导航、三键导航和一台有顶部安全区的设备上逐页截图；键盘打开时仍可填写最后一项并点击提交。

### A2-12｜消息来源上下文与交易分类｜甲主责，丁交付交易数据契约｜P0

- A2-12a：互动通知显示来源内容摘要：原帖/墙帖/社团动态、被回复的评论，以及触发人的动作；摘要缺失时用明确的类型与标题兜底。
- A2-12b：点击通知进入对应内容或评论定位；来源被删除、无权限或不存在时展示可理解的失效页。匿名内容不能泄露作者身份。
- A2-12c：“交易”分类只展示二手私聊会话。交易通知只用于推送和角标；商品“想要”通知归互动，活动报名及提醒归系统。未读数与已读状态在列表和详情一致。
- 验收：帖子互动、评论回复、失效来源、二手私聊四类消息各做一次从列表到目标的跳转；Web 路径需映射为 App 路由。

### A2-13｜“我的”加载与基本资料｜甲｜P0/P1

- A2-13a（P0）：排查“每次进入报错、刷新才恢复”的原因；修复首次进入、登录状态恢复、切 Tab 返回与弱网重试的加载策略。
- A2-13b（P1）：优化“我的”首页内容层级、空态与错误态；基本资料页改善头像、字段编辑、校验、保存中与保存失败的反馈。
- 验收：冷启动登录后首次进入、后台恢复、退出重登均无需手动刷新；资料修改成功后返回“我的”立即显示新值，失败时不丢输入。

### A2-14｜Moodle 登录阻断与 UI｜乙｜P0/P1

- A2-14a（P0）：按设备系统版本、网络和 WebView/系统浏览器分别复现证书错误，确认是否与此前 Android 13/14 的证书链问题一致，并给出可用的合规修复或清晰降级。不得绕过 TLS 证书校验。
- A2-14b（P1）：登录成功后优化同步、课程列表、章节/资源详情和错误状态的 UI；保持退出、重进与重新登录的状态语义正确。
- 验收：至少覆盖一台问题设备和一台可登录设备；记录登录、重启恢复、同步和详情的结果。若校方证书链必须由校方修复，应给用户明确说明并保留受影响设备清单。

## 哪些前置关系需要先核对？

1. A2-12 的“来源摘要／评论定位”先核对后端通知字段，再由丙、丁、戊补各域目标，最后由甲接入消息跳转。
2. A2-06 的“交易”分类先跑通商品私聊会话，再接入消息页；不要让两个页面各维护一份未读数。
3. A2-07 先核对 Web 课程测评接口、权限与数据结构，再按同一业务契约接入 App。
4. A2-09 先确认真机通知权限与系统调度，再把提醒状态展示到工具页。
5. A2-14 先分清证书链、账号凭据、WebView 会话三类失败；UI 优化不应掩盖登录阻断。

## 本草案暂不做什么？

- 不重画底部一级五格导航，也不新增第六格；A2-02 调整的是广场内五个**顶部子栏目**的吸顶行为。
- 不重建课程测评数据库，不另建二手私聊系统；优先复用现有 Web/后端契约。
- 不用关闭证书校验来“修复” Moodle 登录。
- 不把本草案当作已实施、已验收或已确定工期的承诺；待团队估算后再拆任务和排期。
